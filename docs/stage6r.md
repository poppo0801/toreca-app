# Stage 6R: コレクションの表示高速化・プロフィール別並び順・収支画面の改善

DB変更は追加のみ（`20261128000076_card_display_orders.sql`）。既存の抽選・応募・購入・売却・受取・コレクション履歴は変更しない。

## 1. コレクションの初期表示・画像の高速化
- **画像URLを固定化**（`/api/card-image/[id]?v=…&s=thumb&p=<保存先>`）。以前は一覧を開くたびに Storage の署名つきURL（期限つき・毎回別のURL）を発行しており、①署名の発行という通信がサーバー側で毎回必要、②URLが毎回変わるためブラウザのキャッシュが効かない、という2つの無駄があった。新URLは保存先パスで決まり、`Cache-Control: private, max-age=31536000, immutable` と ETag を付けるので、一度見た画像は再訪問で通信しない（画像を差し替えると保存先が変わりURLも変わる）。一覧は軽量サムネイル（長辺360pxのWebP）、詳細は従来どおり高解像度を個別取得。
- 画像route は認可を Storage の行レベルセキュリティ（パスの先頭フォルダ=世帯ID・自世帯のメンバーのみ）に任せ、ログイン確認・カード照会の往復を省いて Storage への1往復にした。未ログイン・他世帯の画像は取得できない。パスの形式は厳密に検証。
- **骨組みを先に表示**: 見出し・カード/BOX切替・購入/買取/枚数の枠（数値は「—」）・並び順/絞り込み・登録ボタン・カードのプレースホルダーを、データ取得を待たずに表示。
- **直近のコレクションをメモリに保持**し、同じ世帯で画面に戻ったときは取得を待たず先に表示して、裏で最新に置き換える（別のログインの内容は見せない: プロフィール集合をキーにする）。
- 先頭の12枚は即時読み込み（先頭8枚は高優先 `fetchpriority=high`）、それ以降は遅延読み込み。画像は並列取得で、読み込み完了までは名前入りのプレースホルダー、失敗時は代替表示。エフェクト（ホログラム）はサムネイルの表示とは独立で、画像・光の演出ともに変更なし。

### 計測（実Supabase・架空カード120枚＋サムネイル、ローカルのビルド→実DB、Pixel 7 相当、3回の中央値付近）
| 項目 | 変更前 | 変更後 |
|---|---|---|
| 初回: 画面操作可能 | 約1.4秒 | 約1.4秒 |
| 初回: 集計表示 | 約1.4秒（取得完了後） | 約1.4秒（枠は即時、数値は取得後） |
| 初回: 画面内の画像すべて | 約1.5〜1.7秒（コールド時 4.5秒） | 約2.2〜2.4秒 |
| 再訪問（アプリ内の移動） 操作可能／集計／全画像 | 約0.06／0.37／0.61秒 | 約0.05／0.05／0.06秒 |
| 再読み込み（ブラウザの画像キャッシュのみ） 全画像 | 約1.23〜1.40秒 | 約1.13〜1.19秒 |

- 計測は `e2e/perf-collection.supabase.spec.ts`。**初回（画像が端末に無い状態）は画像を自前のrouteから配信するため、署名つきURLでSupabaseから直接取得していた変更前より約0.7秒遅い**（ローカルはHTTP/1.1で並列6本。本番のVercelはHTTP/2のため差は小さい見込みだが未計測）。その代わり2回目以降は画像・集計とも通信なしで表示される。
- 変更前のコールド時 4.5秒のばらつき（署名発行・初回接続）は、変更後は安定した。

## 2. 順次フェード表示（`use-reveal.ts`）
- 枠は先に確保（透明）。**画面に入ったカードを、左上→右・行ごと**の順に、1枚あたり12〜70msずつ遅らせてフェードイン（同時に入った枚数で間隔を調整し、画面内はおよそ1.2秒以内に完了）。演出は画像の読み込みとは無関係で、遅い画像が後続の演出を妨げない。
- 画面外のカードは、表示範囲に入った時点で演出。一度表示したカード（id）は記録し、再スクロール・詳細の開閉・ドラッグ並び替え・並び順/絞り込みの変更・一覧の作り直し（グリッド⇔リスト）でも再演出しない。ソート変更では一覧を作り直さない（ちらつきなし）。
- 演出は opacity のみ（transform は触らない）。ホログラム/キラキラ、ドラッグの移動と干渉しない。OSの「視覚効果を減らす」では即表示。IntersectionObserver が無い環境でも透明のまま残らない。

## 3. 購入／買取／枚数の3分割
- `SummaryTriple`（カード・BOX共通）。購入=左、買取=中央、枚数（BOX数）=右。項目名（小）と数値。数値が長いときは文字を小さくする。最終価格取得日・「一部」は項目名の右上に小さく添える。タップで詳細の開閉は従来どおり。

## 4. プロフィール別の「標準」並び順
- 「標準」= 現在のプロフィールが長押しドラッグで並べた順。DB: `card_display_orders(profile_id, card_id, position)`（世帯・プロフィール・カードの複合外部キー、RLSは読み取りのみ）。保存は RPC `set_card_display_order(p_profile, p_cards[])`（そのプロフィールの順序を1トランザクションで置き換え。重複・他世帯・存在しないカードは拒否）。カード・所有記録・お気に入り・登録日・価格は変更しない。
- ドラッグ確定時に保存（楽観更新）。**失敗したら通知し、サーバーの保存順を読み直して表示との不一致を残さない**。絞り込み中のドラッグは、見えているカードが占めていた位置にだけ新しい並びを入れる（見えないカードの位置は動かさない）。
- 他の並び順（参考価値・登録日など）を選んでも保存順は変更されず、「標準」に戻すと復元。新しく登録したカードは保存順の末尾（登録の古い順）。別端末・再起動後も同じプロフィールで復元（サーバー保存）。
- **互換性**: 保存順が無いプロフィールは従来の標準（お気に入り→参考価値の高い順）のまま表示する（既存の見た目を変えない）。お気に入り順（`fav`）とお気に入りのみ表示での並び替え保存は従来どおり。

## 5〜9. 収支
- **分類**: 一覧は カード（赤）／サプライ（青）／経費（緑）。フォームの品目名は「周辺グッズ」。内部IDは変更なし。色は左端の細いラインと分類ラベル（必ず分類名も表示）。収入は「売却」ラベルと +金額（info色）で支出と区別。
- **1取引1カード**: 日付見出し・区切りを廃止。カード内は「日付／分類／金額」と「商品名」。系列・店舗は一覧に出さない（詳細で確認）。商品名はマスターの**正式名称**（略称・別名に置換しない。長いと末尾を「…」で省略、詳細で全文）。
- **詳細シート**: 一覧のカードをタップ → 下から詳細（取引日・分類・内容/商品・数量・金額・系列/店舗・購入方法・メモ・登録元）。「編集」で既存の入力フォーム（検証・連動処理そのまま）へ、「削除」は確認のうえ実行。支出・売却の入力フォームもボトムシートに統一（Safe Area・キーボード対応は既存のシートの仕組み）。
- **支出内訳バー**: 高さ約12pxの横1本。色をタップで「カード：12,000円（65%）」を小さく表示、同じ色の再タップ・バー以外のタップで閉じ、別の色で切替。金額0の分類は描画せず、支出0なら「支出なし」。1%未満は「1%未満」。
- **全期間**: 年月選択に「全期間」。収入・支出・収支・内訳・一覧を全期間で再計算（日付不明の支出も含む）。すべて/支出/収入、品目・名義人の絞り込みと併用可。一覧は60件ずつ描画（末尾に近づくと続きを読み込み、「もっと見る」ボタンもある）。

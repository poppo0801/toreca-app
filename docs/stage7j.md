# Stage 7J: 対戦記録UI・店舗選択式・フォーム再開の廃止・購入記録の商品名・抽選候補の管理者限定・抽選詳細のレイアウト

DB変更は追加のみ（`20261204000083_stage7j.sql`: `profiles.is_admin`）。適用前に`npm run backup`（検証済み）を取得。既存の抽選・応募・当選・購入・受取・対戦の履歴は変更していない。

## 1. 対戦記録カード（`battles-view.tsx`）
- 構成: **左端=勝敗のアクセントバー（細い・記号と同じ色）／中央=対戦情報／右端=大きく太い勝敗記号（上下中央）**。角丸カード・影は従来どおり。
- 上段: 対戦日＋対戦形式（小さな角丸チップ）。「vs ○○」の相手名表示・「MY」「VS」「自分」「相手」のラベルは無い。
- 中段・下段: **自分を1行目、相手を2行目**。それぞれ「プロフィールアイコン（24px）→ユーザー名（小さめ・幅を抑え省略。自分は太字）→使用デッキ名」。デッキ名は原則1行、長い場合のみ最大2行。勝敗記号の領域（w-14）を確保し重ならない。
- アイコン: アプリ内ユーザー=設定済みのプロフィールアイコン（`ProfileAvatar`）／外部の相手=共通の人物アイコン。
- 勝敗: 勝ち◯青・負け×赤・引き分け△緑（`--cat-supply`/`danger`/`success`）。一覧・詳細・分析で共通。記号＋読み上げ名でも判別。
- 共有対戦（Stage 7G）の1件共有方式は維持。閲覧プロフィールに応じて、自分/相手の行・アイコン・名前・デッキ・勝敗が反転する（`BattleView` に自分/相手のプロフィールIDを追加）。
## 2. 総合集計の復活
- 一覧の上部に横4分割（対戦・勝ち・負け・勝率）。現在のプロフィールの戦績で、フィルターに連動。勝率＝勝ち÷（勝ち＋負け）、引き分けは対戦数に含め勝率の母数に含めない、勝敗が無ければ「－」。データアイコンの分析（使用デッキ別・対戦形式別）は維持。

## 3. 店舗選択式
- 登録・編集フォームの「店舗の指定」: **店舗固定／応募時に店舗選択／店舗指定なし**（Stage 6N の `storeMode` を利用。新しい機構は作っていない）。
- 応募時に店舗選択の抽選: 応募済みにするとき店舗入力が必須（確定するまで応募済みにならず、キャンセルで状態は変わらない）。同系列の過去の応募店舗（プロフィール別）を優先表示して1タップ、新しい店舗は自由入力（Stage 7B の `AppliedStoreDialog`）。
- 応募済みの抽選を店舗選択式に変更: 変更時に「応募の履歴は変わらない」旨を表示。**既存の応募履歴は削除・初期化しない**。応募店舗は未設定のまま保持し、**応募済みなのに店舗が未設定の現在のプロフィール**に対して、抽選詳細の応募状況に「応募店舗が未設定です」の入力案内を出す（`StoreMissingNotice`）。他のプロフィールの店舗は変更しない（各自が入力。詳細の「ユーザー別の結果」からも設定・変更可）。

## 4. フォームの再開機能の廃止
- 抽選の登録・編集フォームの**最小化・再開（入力途中の保持）を廃止**。閉じる操作（×・背景・Esc・ハンドルのスワイプ）は、**入力が変更されていれば破棄の確認**（破棄して閉じる／入力を続ける）、変更が無ければそのまま閉じる。新規は毎回初期状態、編集は保存済みの最新データから開始。
- 調査範囲: 抽選・購入記録/支出・コレクション（カード）・対戦記録・マスターなど。他のフォームは開くたびに新しく生成され（閉じると破棄）、端末への下書き保存（localStorage の旧下書きは起動時に削除済み）も無い。保存済みのデータ・履歴は触っていない。
- 共通のシート（`ui/sheet.tsx`）: 閉じる前に確認を出すフォームでスワイプしても、パネルが画面外へ残らない（開いたままの場合は元の位置へ戻す）不具合を修正。入力欄への自動フォーカス廃止（Stage 7D）は維持。

## 5. 購入記録の商品名
- 商品別累計・購入履歴ともに**商品マスターの正式名称**（略称・別名には置き換えない）。最大2行（`line-clamp-2`）、数量・金額と重ならない。商品マスターの略称データは維持。抽選管理など他画面は変更なし。

## 6. 抽選候補の管理者限定
- 管理者は**プロフィールID**で判定（`profiles.is_admin`。表示名ではないので、表示名を変更しても影響しない）。移行で現在の「はとむぎ」を管理者に設定（その1回だけ名前を参照。テスト世帯は対象外）。
- 抽選管理の「抽選候補 N件」リンクは管理者のみ（件数も取得しない）。管理者以外がURLを直接開くと案内のみ。**サーバー側**でも、除外理由つきの除外・取り消し（`/api/collection` の `excludeReason`/`undoReason`）と除外ルールの編集・無効化・削除（設定）を、操作中のプロフィールが管理者でなければ拒否（403/エラー）。設定の除外ルール一覧は、管理者以外は閲覧のみ。Stage 7H の登録・除外・ルール管理の機能は維持。

## 7. 抽選詳細のレイアウト（`lottery-detail-sheet.tsx`）
- 上部: 系列・★・商品（画像・商品名・数量）。
- **ステータス行（1行）**: 左=発送可・受付前などの抽選状態、右=現在のプロフィールの応募状態（`MyStatus`）。補足（商品ごとに当落・要チェック外）は別の小さい行。スルーボタンは横幅の都合で下部の操作に残す（ステータス行を2行にしない）。
- 日付・期間: **1項目ごとの独立した角丸カード（2列）**。応募開始・応募締切（残り時間表示を維持）・当選発表・購入（・受取）期間・受取期間（別々のときは別カード）・抽選方式。奇数のときは最後を横いっぱい。
- 応募・受取情報: 細い罫線・縦の区切り線でグループ化（応募方法｜受取方法（距離・交通費もここ）／発表方法／応募条件（タグ・補足を維持）／応募制限｜本人確認・書類／適用される応募制限）。
- 応募状況: プロフィール別の応募・当選・購入・受取、店舗選択式ではプロフィール別の応募店舗。
- 下部: 備考・操作の下に**管理情報**（折りたたみ: 登録経路・情報源URL）。注意情報（確認が必要な点）・情報不足の警告・「初期値・未確認」の印は上部に残し、隠さない。

# Stage 5J: 登録フォーム・カード・詳細の整理、表示順、ブランドカラー、入力時の拡大抑制

UIルールは CLAUDE.md / docs/ui-design-guidelines.md。下部メニューの表示欠け（viewport補正・Safe Area）は**変更していない**（診断 `?diag=1` も維持）。多重反応の対策（`useTapGate` / `useBusy` / `saveSettings` の順次保存）は維持し、新しい操作にも適用した。

## 1. 抽選登録フォーム
- **仮登録バッジ**: 系列・店舗・対象商品の項目名の横に小さな「仮登録」（タップで「保存時にマスターへ仮登録されます」）。「未登録：保存時に仮登録します」「時刻は未設定」「点線の欄は初期値…」「複数商品の当落は登録後に…」などの常設の説明文は削除。**要確認**は従来の小さなバッジ（タップで理由・原文の抜粋）。
- **AI入力の表示**: 長文の代わりに `✦AI入力 ［要確認 4件］`。バッジのタップで最初の要確認の項目へ移動して詳細を開く。AI解析フィードバック・修正差分の記録（Stage 4B.5）は変更なし。
- **保存時の確認が必要な場合**（重複の可能性・競合）の説明は従来どおり。

## 2. 複数商品の登録UI
- 通常は `対象商品・数量 [商品][数量][単位]` と `［＋商品を追加］` だけ。長い文字リンク・詳細設定内の方式は廃止。
- 追加して2商品以上になった時だけ、商品欄の下に `抽選方式［方式を選択 ▼］`（B 1回の応募で複数商品に参加／C 当選はいずれか1商品まで／D 希望の1つを選んで応募。既存の方式をそのまま維持）。**自動では確定せず**、選ぶまで保存できない（AIが方式を読み取れていれば初期値。不明は要確認）。
- 商品を1つに戻すと単一商品の表示に戻る（方式は single）。
- **既存データの保護**（画面＋サーバー `saveLottery`）: 応募の記録がある抽選は、抽選方式の変更・単一→複数の追加ができない。商品別の当落／希望商品に使われている商品は削除できない（記録のない商品は、残りが2商品以上なら削除可）。

## 3. 入力時の自動ズーム対策と制約
- `viewport` に `maximum-scale=1, user-scalable=no` を指定（`viewport-fit=cover` と `initial-scale=1` は変更なし）。入力欄の文字サイズは変えていない（コンパクトなデザインを維持）。タッチ・ピンチのイベントを止める処理は**使っていない**。
- **制約**: ピンチによる拡大縮小ができなくなる（アクセシビリティ上の制約。文字を大きくしたい場合はiOSの「画面表示と明るさ→テキストサイズ」を使う）。iOS Safariはこの指定を無視する場合があるため、**実機での確認が必要**（ホーム画面のPWAとSafariで差が出る可能性）。効かない場合は入力欄を16px以上にする案があるが、デザインに影響するため今回は採用していない。
- 対象画面は共通の viewport 設定なので、登録フォーム・数量・日付/時刻・URL・コレクション・購入記録・ユーザー設定・検索欄すべてに適用される（実機では未確認）。

## 4. 抽選カード（詳細表示）
上段｜店舗・系列＋地域（通販）＋右に残り時間バッジ／中段｜画像（固定幅の列）＋商品名（最大2行・＋他N種）＋数量＋締切日時・発表日・受取方法（`auto-fit` の Grid で折り返し）／下段｜（薄い区切り線）プロフィール別の応募状況＋現在のプロフィールの応募ボタン。従来の絶対配置（応募ボタン・★の重ね置き）を廃止し、Grid/Flex で重なりを構造的に防ぐ。★は画像の列の左上。シンプル表示は店舗・商品名(2行)・締切と残り時間・応募の丸ボタン。
- **E2E**: 幅320pxで、極端に長い店舗名・商品名に書き換えても、バッジ・店舗・画像・商品名・状態・応募ボタンの重なりと横方向のはみ出しがないことを全カードで確認。

## 5. 抽選詳細
- 日付の「時刻未確認」を表示しない（`formatPlain`。内部の精度 `date_only` はそのまま、23:59などの補完なし）。
- 下部の操作: 常時 **［編集］［現在のユーザーのスルー］**。`その他の操作`（折りたたみ）に 他店舗に複製／発表延期／中止（確認ダイアログを追加）／登録を取り下げ（確認あり）。
- 応募状況: アイコン＋状態マークの1行＋［応募済みにする］。理由の一覧は「状態の詳細」で展開。**要確認の理由は全ユーザー分を繰り返さず1つにまとめて表示**。当落の入力欄は従来どおり。状態アイコンは表示専用（応募状態を変えるボタンではない）。

## 6. プロフィールの表示順
- 保存先は既存の `profiles.sort_order`（**DB変更なし**）。読み込み時に `data.profiles` がこの順に並ぶため、`data.profiles` を使う全画面（フォーム・マトリクス・記録・設定など）が同じ順になる。以前は応募状況の行・詳細がアカウントの作成順だったため、`accountsForLottery` もプロフィールの順に並べる共通化を行った（画面ごとの並べ替えは持たない）。
- 変更: 設定→ユーザー管理の各行の ▲▼（`reorderProfiles` サーバー処理。有効なユーザー全員の順列だけ受け付け、ID・応募・当落には触れない）。新しいユーザーは末尾。

## 7. ブランドカラー
ライトの `--primary` / `--ring` を `#c2410c`（赤茶）から `#ea580c`（オレンジ）へ。ダークは `#fb923c` のまま。色はすべて `globals.css` の CSS 変数（`--primary` など）1か所の定義で、ボタン・選択タブ・応募ボタン等はそれを参照する。危険（赤）・成功（緑）・警告は別トークンで維持。**制約**: ライトの白文字×`#ea580c` のコントラストは約3.6:1（太字・大きめの操作では実用範囲だが、小さな文字のリンク色としては低め）。

# AI読み取り（Stage 4B）

抽選登録画面の「AIで読み取る」から、告知の **文章 / 画像 / 店舗URL / X投稿URL** を読み取って登録フォームに入力する機能。
読み取り結果は**候補**で、必ず利用者が確認・修正して保存する（自動では登録しない）。通常の手動登録はそのまま使える。

## 画面の流れ

入力方法を選ぶ → 読み取る → 結果の確認（一致した系列・店舗・商品、注意点）→ フォームに入力 → 要確認の項目を直す → 保存

- 「要確認」は、読み取りの確信度が低い項目・年の記載がなく年を補った日時・マスターに無い名称・曖昧な一致に付く。
- 複数商品で応募方式（A〜Dのどれか）が告知から判断できないときは**確定せず**、方式を選ぶまで保存できない。
- 解析中・失敗・一部だけ読み取れた状態はそれぞれ表示する。取得できないURLは文章・画像の入力へ誘導する。
- モック（開発用）の結果には「モック（サンプルデータ）」の帯が出る。実際のAI解析の結果とは混同しない。

## 構成（Stage 4C で再利用できる）

| 層 | ファイル | 役割 |
|---|---|---|
| 入口 | `src/app/api/lottery-extract/route.ts` | ログイン確認・入力検証（画像の中身を判定）・回数制限・利用ログ |
| 取得 | `src/lib/server/safe-fetch.ts` / `x-source.ts` | SSRF対策つきのURL取得、Xの公式oEmbed |
| 本文化 | `src/lib/ai/page-text.ts` | HTML → 本文・関連リンク |
| 共通パイプライン | `src/lib/server/lottery-extract-service.ts` | 文章・画像・URL・Xを同じ形式の結果にする |
| AI | `src/lib/ai/provider.ts` | `LotteryExtractor`（Claude / モック）、プロンプト、ツール定義 |
| 検証 | `src/lib/ai/extraction.ts` | AI出力を信用せず検証・正規化（日付・年補完・URL・方式） |
| 照合 | `src/lib/lottery-match.ts` | 系列・店舗・商品のマスター照合、重複候補の検出、フォーム下書き |

定期自動収集（Stage 4C）は「本文を取得 → `LotteryExtractor.extract` → `normalizeExtraction` → `buildDraft`」をそのまま呼べる。

## AI APIの選定

**採用: Anthropic Claude（Messages API、画像入力＋ツール呼び出しで構造化出力）**

| 観点 | 内容 |
|---|---|
| 精度 | 文章・画像（スクリーンショットの日本語）を1回の呼び出しで読み取り、ツールのスキーマに沿った構造化データを返せる。OCRと整理を別サービスに分けなくてよい |
| 日本語OCR | 画像入力に対応。**実際の告知画像での精度は、APIキー未設定のため未検証**（設定後に実際の告知で試して調整する） |
| 費用 | 従量課金（契約・課金はこちらでは行っていない）。下記の概算 |
| 運用 | キーはサーバーの環境変数のみ。回数制限と利用ログ（本文・画像は保存しない）で費用を抑える |
| 代替案 | OCR専用API＋別のLLMの2段構成は、精度は出しやすいが契約・キー・障害点が増えるため、まず単一APIで始める。他社モデルの精度比較は未実施 |

モデルは環境変数 `AI_MODEL` で切り替える。**既定は `claude-haiku-5-5`**（入力 $0.10 / 出力 $0.50 per 100万トークン。公式の料金ページで2026-10-29に確認）。精度が足りなければ `claude-sonnet-5-5`（$2 / $10）。実際の読み取り精度はどちらも未検証。利用状況・推定料金・月間予算の警告は設定画面（docs/stage5-records.md）。

### 想定費用（概算・実測ではない）

1回あたり、システム指示とツール定義で約1.3千トークン＋告知本文＋出力約0.7千トークン。

| 入力 | claude-sonnet-5-5 | claude-haiku-5-5 |
|---|---|---|
| 文章・URL・X（本文1千トークン前後） | 約0.01〜0.02ドル（約2〜3円） | 約0.001ドル未満（1円未満） |
| 画像1〜2枚 | 約0.02〜0.04ドル（約3〜6円） | 約0.002ドル（1円未満） |

月に100件読み取っても、Sonnetで数百円以内、Haikuなら数十円程度の見込み。1か月の上限は `AI_HOURLY_LIMIT`（既定20回/時）・`AI_DAILY_LIMIT`（既定60回/日）で世帯ごとに制限する。Anthropic側の利用上限（コンソールの支出上限）も併せて設定すること。

## 設定（利用者が行う）

1. Anthropic Console でAPIキーを発行し、支出上限を設定する（クレジット購入が必要）。
2. Vercel の Environment Variables（Production）に `ANTHROPIC_API_KEY` を追加（Sensitive推奨）。必要なら `AI_MODEL` も。
3. 再デプロイ後、抽選登録 →「AIで読み取る」で実際の告知文章を試す。

**未設定のとき**: 「AI読み取りはまだ設定されていません」と案内し、手動登録に戻れる。画面は壊れない。`/api/health` の `ANTHROPIC_API_KEY` の有無（値は出さない）で設定を確認できる。
`AI_PROVIDER=mock` は開発・テスト用で、本番には設定しない。

## URL取得の安全性

ユーザーが入力したURLをサーバーが取得するため、次を実装している（`safe-fetch.ts`、テスト: `safe-fetch.test.ts`）。

- http/https のみ、ポートは 80/443 のみ、URLに認証情報を含むものは拒否
- **接続の直前（DNS解決時）にアドレスを検査**（DNSリバインディング対策）。ループバック、プライベート（10/172.16/192.168）、リンクローカル（クラウドのメタデータ 169.254.169.254 を含む）、CGNAT、予約、マルチキャスト、IPv6のULA/リンクローカル/IPv4射影/NAT64/6to4 等は拒否。`localhost`・`.local`・`.internal` 等の名前も拒否
- リダイレクトは手動で辿り、**毎回**同じ検査（最大4回）
- タイムアウト10秒、本文サイズ上限1.5MB、Content-Typeは html/xhtml/text のみ、圧縮は受け付けない
- `robots.txt` で禁止されたページは取得しない。Cookie・認証ヘッダーは送らない。ログインや制限は迂回しない（401/403は案内して終了）
- 取得できないURLは、告知の文章コピーやスクリーンショットの入力へ誘導する

## Xの投稿URL

- 利用するのは**公式の公開エンドポイント oEmbed**（`publish.twitter.com/oembed`）だけ。APIキー・有料契約は不要。
- 取得できるのは公開投稿の**本文テキストと投稿内のリンク**（t.co は展開して宛先のURLのみ使う）。
- 取得できないもの: 投稿に添付された**画像**、非公開・削除済み・制限された投稿、引用先の内容。スクレイピングやログインの迂回はしない。
- 取得に失敗してもStage 4B全体には影響せず、文章の貼り付け／スクリーンショットの読み取りに誘導する。
- X API（有料プラン）の利用は実装していない。必要になったら `x-source.ts` に取得手段を追加する。

## 照合と重複検出

- 系列・店舗・商品は、正式名称・略称・商品コード、全半角・空白・大小文字の違いを無視して照合する。部分一致・似ている名称は**候補にするが「要確認」**。一致しないものは名称のまま入力され、保存時に**仮マスター**として登録される（Stage 3.5 の仕組み）。
- 同じ店舗・同じ商品・同じ応募締切日（または同じ情報源URL）の抽選が既にあれば「重複の可能性」を表示し、確認のチェックなしでは保存できない。締切が不明な場合は注意表示のみ。

## 読み取り対象

系列・店舗、対象商品（複数）と数量・単位、応募開始/締切、当選発表、購入・受取期限、発表方法・発表URL、応募URL、応募方法、受取方法、購入数量の上限、応募条件、本人確認の種類、応募制限（1人1回等）、複数商品の方式、その他の注意。
フォームに専用欄がない「応募URL」「購入数量の上限」「注意事項」はメモ欄に残す。

## プライバシー

入力した文章・画像・取得したページはサーバーで処理してAI APIへ送信するだけで、**保存しない**。記録するのは利用回数（種類・結果・出典のホスト名・トークン数）のみ（`ai_extraction_logs`）。個人情報（本人確認書類の番号、住所、電話番号）は記録しないようAIに指示している。

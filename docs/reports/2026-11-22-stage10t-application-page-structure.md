# Stage 10T 報告書: 応募ページの構造取得と、情報不足／AI誤判定の切り分け

作成日: 2026-11-22 ／ ブランチ: `feat/10f-shadow-integration`（PR #46）／ 指示書: `docs/implementation/STAGE_10T_APPLICATION_PAGE_STRUCTURE.md`

## 0. 結論（先に）

- **本番DB・マイグレーション108〜113・PR #36/#46のマージ・本番デプロイ・cron有効化・既存データの書き込みは行っていない。** ローカル・読み取り（公開ページの取得）のみ。
- **取得処理は、従来「平文化した本文からの手掛かり行の抜粋」だけで、人が見る受付枠（カード）の数・店舗・関連イベント・ページ全体の注意書きという構造を失っていた。** 構造を取り出す部品（`page-structure.ts`）を追加し、実在の LivePocket 12ページ全てで受付枠を抽出できた（12/12）。
- **取得の欠落とAIの解釈誤りの切り分け（Stage 10Sの人の回答30件）**: 判断した12件のうち誤り9件は、**すべてAIに直接の根拠が無いまま方式を主張したもの**（原因は主に「項目ごとの応募先URLを取得できていない＝情報不足」と、その状態でも仮説を断定的に出したこと）。「直接の根拠がありながら外れた」誤判定は 0件。判断不能17件は全て新しい公開ページで、**確認資料に応募ページのURLを載せていなかった**ことが原因と考えられる（本人の確認が必要。AIの誤りではなく評価対象外）。
- 構造化した観察をAIに渡す前後（旧=平文の抜粋／新=構造化）の比較は実施したが、**人の確認前で正解は未確認**。新方式は、構造を認識できないページで平文の抜粋を失い、直接の根拠ありが 15→12 に減るという**自分の実装の欠点**も見つかった（構造は「補足」として平文に添える形へ修正済み。修正後のAI再測定は呼び出し上限に達したため未実施）。
- X投稿からの実データE2Eは、10Sと同じく**開発用のX API鍵が無いため未実施**（鍵の提供は求めない）。公開ページでの部分検証。

### 誤り9件の原因分類（情報不足 vs AIの誤判定）
| 観点 | 件数 | 備考 |
| --- | --- | --- |
| AIに**直接の根拠なし**で方式を主張 | 8 | 取得した情報が無い（または別店舗のページ）のに store_select 等を仮説として出した（6件が store_select→per_store） |
| AIは「不明」と回答（誤判定ではなく未解決） | 1 | #2。人は「この系列は他に店舗が存在しない」と回答＝店舗マスター／系列の知識の不足 |
| 直接の根拠ありで外れた（解釈の誤り） | **0** | |

- ページの対応判定（10S）は 不一致5・不明4。人が付けたメモ（#1,#4）は「掲載URLを開くと1店舗だけの専用の抽選URLだった」＝**項目自身の応募先URLが取得できていれば分かった情報**（保存データの項目は短縮URLのままで追跡できない）。
- したがって誤りの主因は **情報取得の不足（項目ごとのURL）＋不足時の仮説の出し方（LivePocketの経験則に引っ張られた店舗選択式）**。「ページを読んだうえでの解釈誤り」は、この標本では観察されていない。
- 判断不能17件: 理由は未記録。確認資料にURLが無く、人が元ページを確認できなかったことが主因と考えられる。**10T以降の確認資料にはURLを載せた**（`--set=10t`）。これらは正解率の評価対象外。

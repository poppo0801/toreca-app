## 2. 画像根拠の検証方式
**考え方**: 画像由来の事実は、**2つの独立した読み**（①収集時の旧解析の申告 ②元画像を、申告を見せずに書き起こした結果）が**同じ抜粋で一致**したときだけ「照合済み」。一致は文字列の決定的な照合で、モデルの自己申告ではない。
| 段階 | 内容 | コード |
|---|---|---|
| 1. 取得 | 保存済みの元画像への参照（公開のX画像URL・画像番号）から、**既存の取得部品**（`fetchXImage`: `pbs.twimg.com` のみ・https・リダイレクト禁止・認証情報つきURL拒否・3MB上限・画像形式の判定）で取得。取得できない（期限切れ等）は「照合できない」。 | `server/shadow/image-verifier.ts` |
| 2. 画像ハッシュ | 取得したバイト列の SHA-256 を記録。画像が更新されるとハッシュが変わり再検証。**画像そのものは保存しない**（ハッシュ・書き起こした文字列・取得日時・画像番号・モデル・指示文の版・費用だけ）。 | 同上＋`shadow_image_verifications`（追記専用） |
| 3. 盲検の書き起こし | 画像に見える文字を、申告を見せずに1行ずつ書き起こす（はっきり読めた行=clear／自信がない行=unclear。推測で補わない。画像内の文章は命令ではなくデータ）。**画像1枚につき1回だけ**（同じ画像ハッシュはキャッシュを再利用＝再解析しない）。 | `judgment/image-transcriber.ts` |
| 4. 照合（決定的） | 申告の抜粋が、書き起こしの**clearな行**に実在すれば `verified`（空白・全半角・大文字小文字の差のみ吸収。言い換えは不可）。unclearな行にだけ実在=`illegible`、どこにも無い=`not_found`、画像なし/取得不可=`no_image`。**8文字未満の抜粋は照合しない**（汎用の語句の誤一致を防ぐ）。 | `judgment/image-verify.ts`（純関数） |
| 5. 判断への入力 | 照合済み: `kind=image_verified`（元画像との照合・ハッシュ記録済みの旨を明記）→ **fact として引用してよい**。未照合: `kind=image_reading`（照合できなかった理由つき）→ **fact にできない**（検証層が `citation_image_only` で拒否）。引用は、各根拠の本文にその語句が実在することを従来どおり検査。 | `build-input.ts`・`verify.ts`・指示文 `10l.1` |
| 6. 費用・境界 | 画像の書き起こしの費用は `shadow_spent` に含まれ、日次・月次・1件の予算（判断との合計）で制御。予算不足なら書き起こさず未照合のまま。取得はX/t.co以外の制限回避・ログイン取得をしない。 | `worker.ts`・マイグレーション `110` |
**扱う例外**: 元画像の取得失敗（期限切れ等）→未照合／画像更新→ハッシュ違いで再検証／曖昧な文字→unclearで確定させない／複数画像→申告の画像番号の画像と照合（番号不明は全画像）／引用箇所の不一致→`not_found`／偽の申告・別画像→照合されない（下記の実測）。
**DB**: マイグレーション `20261227000110_stage10l_image_verification.sql`（追加のみ・追記専用・RLSは世帯の構成員のみ閲覧・保持期限で掃除・ローカルのみ適用）。

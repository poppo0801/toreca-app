## 3. 入口と出口のデータ流（実装）
```
seed（X投稿の原文など） ─┐
                         ├→ Evidence[]（出典・取得日時・内容ハッシュ・構造[受付枠/関連イベント/フォーム設問/欠落]）
fetchPage（読み取りのみ）─┘                          │
                                                     ▼
 ┌──────────────── ターン（上限: 回数/費用/時間/取得/連続失敗/進展なし） ────────────────┐
 │ ResearchAgent(AI): 観察/推論/不明（被害×重要性×見込み×締切×費用の理由）→ 次の行動 fetch(URL)|stop │
 │ 固定処理: 重複URL・同一内容・失敗ホスト・http/不正URL を取得せず履歴に記録（意味判断はしない）      │
 └──────────────────────────────────────────────────────────────────────────────────┘
                     │ 調査終了（理由を記録）
                     ▼
 RegistrationJudge(AI・別呼び出し): register|tentative|exclude ＋ 項目ごと observed/inferred/unknown ＋ monitor
                     ▼
 検証層: 引用の実在・不明値は null・人が確定した値は ask_human（上書きしない）
   失敗 → 理由をAIへ返し1回だけ再評価 → なお失敗なら held（実行用の提案は出さない）
                     ▼
 登録案（FieldProposal[]）＋ 更新監視の状態（調査終了・登録可否とは独立）＋ 再開トリガー
```
- 外部ページ・投稿の文は**データ**: ループは本文を解釈せず、取得は AI の出力（次の行動）だけで決まる（本文に命令があっても取得しない・テスト済み）。ツールの型は `fetchPage`・`now` だけ（書き込み・投稿・実行・DBなし）。

## 4. 実在ページの入力実測（AIは呼ばない・無料）
対象: 10Tで取得して保存した実在の公開ページ（Git管理外）。

| 指標 | 結果 |
| --- | --- |
| LivePocket: 受付枠の構造を取得できたページ | 12 / 12 |
| LivePocket: 「同じ販売元のイベント」が表示されたページ | 3（別の独立した応募ページの手掛かり。AIの入力では「応募可否の根拠にならない」と明記して渡す） |
| LivePocket: ページ全体の注意書きがあるページ | 10 |
| Googleフォーム: 設問を取得できたページ | 3 / 3 |
| AIへ渡る入力の最大文字数 | LivePocket 4,265 字／Googleフォーム 2,332 字（1ターンの入力として十分小さい） |
- 意味: **取得の欠落（ページの構造がAI入力に載らない）はこの標本では見当たらない**。したがって、人のレビューで出た誤判定（10S: 誤り9件はすべて直接の根拠なしで方式を断定、原因は項目ごとの応募先URLの欠落）は、**入力側の問題（Xの項目ごとのURLを得られていない）と、不足時に断定したAIの出し方**に分かれる、という10Tの切り分けを、10Uでは「不足時は不明のまま登録判断へ（unknown・tentative）」を促すプロンプトとスキーマで扱う（**効果は実AIで未検証**）。

## 6. 誤判定の原因分類の枠組み（実AI実行後に使う）
`取得欠落`（入力に無い）／`抽出・スコープ誤り`（項目と応募先の対応）／`AI推論誤り`／`登録判断誤り`／`実行層の誤り`（検証層・権限）。ループの `trace`（agent/fetch/judge/verify の各手順）と、証拠・入力・出力を分けて保持するため、事例ごとに分離できる。**検出する失敗**: 安全側の過剰保留・根拠不足の早すぎる本登録・調査無限延長（上限で停止）・終了後の再開不能（`planReopen`）。偶然正しい推論でも、根拠（引用）が実在しなければ検証で止まる。

## 7. 無駄な再調査の防止・保護・費用・安全条件
- 防止（テスト済み）: 同じURL＝取得しない／同一内容の別URL＝独立した裏付けと数えない／同一ホストで連続失敗＝諦める（Xへの反復アクセスの抑止）／進展なし＝終了／再開時は履歴を引き継ぐ／**締切接近だけでは取り直さない**（間隔と未取得があるときだけ）。
- 費用: 不明な費用は0円扱いしない（予約額）。**判断用の予算を先に確保**し、調査で使い切らない。上限（`DEFAULT_RESEARCH_LIMITS`）は黙って変更しない。**今回の実費用: 0円**（実AI未実行）。
- 保護: 人が確定した値は上書きしない（ask_human）。応募/当選/購入履歴・個人情報はAIへ渡さない（redact・確定値は項目名と値のみ）。登録・補完・統合の**実行**はこのモジュールの範囲外（提案まで）。
- 安全条件のテスト対象内の結果: 誤統合0・履歴の破損0・権限逸脱0（実行層を持たない）・費用上限の突破0・停止不能ループ0（ターン・時間・費用・失敗・進展で停止）・通知は未接続（重複/欠落の対象外）・秘密情報の出力0（ログ・プロンプトに含めない）。

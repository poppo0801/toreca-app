| プロンプト | `relations` の `same` / `same_campaign_other` の**意味が定義されていなかった**。AIは「独立した応募かは未確認」と述べて安全側（別機会）に倒したが、「店舗選択式の選択肢にある店舗の既存カード＝同じ応募権の分割表示」という定義が無かった。 |

## 2. 変更内容（事例固有のID・文言のハードコードなし）
**応募機会・関係の定義（プロンプト `10e.2-r3`）**
- 応募機会 = **独立して、応募・当落・購入の可否を別々に追跡できる権利の単位**。フォーム数・店舗数・商品数・URL数とは一致しない。応募が1回でも当落が商品（店舗・開催回）ごとに独立なら、権利ごとに機会を別々に出し、商品を1つの機会にまとめて並べない。**構造と機会数・内容の整合**を求める（機会を1つにまとめるなら構造は one_form_one か unknown にして理由を書く）。
- 関係の意味: **same** = 今回の機会と**同じ1つの応募権**（例: 店舗選択式の選べる店舗ごとに作られた既存カードは、同じ応募権の重複・分割表示）。**same_campaign_other** = 同じ企画・商品群だが応募権が別（別の開催回・期間、店舗別/商品別に独立した別抽選）。independent / unknown。**same には同じ応募権であることを示す引用が必要**。系列・店舗・商品・開催回（応募期間）・応募の仕組みの証拠を使い、同じ系列・商品というだけで same としない。逆に、店舗選択式の選択肢にある店舗の既存カードを根拠なく別機会にしない。どちらとも言えなければ unknown。
**検証層（`verify.ts`・新しい3つの検査。いずれも結論を作らず、理由を返して再判断を求める）**
1. `structure_incomplete`: 構造が「1送信で複数の独立した権利」なのに機会が1つ、または「商品別独立」なのに機会が商品数より少ない（商品を1機会にまとめて並べている）。→ 機会を分けるか、構造を unknown にして理由を書くよう求める。
2. `relation_contradicts_structure`: 構造が店舗選択式（unknownでない）で、**選択肢に含まれる店舗・同じ系列・同じ締切・商品が重なる**既存抽選を `same_campaign_other` / `independent` としている。→ 別の応募権である根拠を示すか、same に見直すよう求める。別の開催回（締切が違う）・別商品・選択肢外の店舗の既存抽選は対象外（過剰な不合格を避ける）。
3. `relation_same_without_evidence`: `same` に引用が無い（basis が inference でも）。
- 再判断（最大2回）でも直らなければ、既存の動作どおり、該当する関係は採用されず（誤った関係を作らない）、構造の不整合は構造を **unknown・機会1件の未確定**として保留する。**検証層が機会を自動で分割・統合したり、関係を書き換えることはない**（テストで、検証が出力を書き換えないことを確認）。保護された抽選への提案は引き続き `link_case` のみ。
**その他**: 評価セットを切り替え可能に（`loadCases/loadGold("unseen")`・`JUDGMENT_REAL_SET=unseen`）、採点に関係の正解率（`relScored/relCorrect`）と、構造の保留が正しい事例（`structureHold`）を追加。

## 0. 結論（先に）

- **本番DB・マイグレーション108〜113・PR #36/#46のマージ・本番デプロイ・cron有効化・既存データの書き込みは行っていない。** ローカル・読み取り中心。AIの推論方法（プロンプト・ヒント）は今回調整していない。
- **「リンクがある」と「その応募機会のリンクだと証明できた」を分けた**（リンクの出所の追跡＋スコープ判定）。別店舗のリンクを項目に流用する誤対応は、既存データで 5/12 件を実際に防いだ（不一致）。
- **X投稿→項目分割→URL展開→取得 のエンドツーエンドは、実行できなかった（未実施）**。開発用のX API鍵が無く、本番の鍵は使えないため、「新規収集」の実データが得られない。経路（`linkMap`→項目ごとのリンク）は**架空の投稿データでの単体テストだけ**で、実データの成功としては数えない。代わりに、**今回あらためて取得した実在の公開応募ページ**（本番の候補が指していた36ページ）で「取得→項目抽出→応募単位の推論→登録プレビュー」を通した（X投稿経由ではない）。
- その新しい公開データでは、**応募単位が原文で確定できた件が多く（ページが明記 14／18）、自動登録プレビューが初めて 2件出た**（非公式の単独の情報源・直接の根拠あり）。ただし**人の確認は 0件**で、正しいかは未確認。
- 人が確認・訂正できるレビュー資料（実データ30件）と操作、人の回答だけから評価する仕組みを用意した。**回答が無いため、正解率・一致率は未測定**。

## 1. 現行の追跡と、実データで分かったこと

- 保存済みの一覧項目では、項目ごとの応募先URLは**復元できない**: 既存の保存データには `linkMap` が無く、項目内は短縮URL（t.co）のまま。展開済みのリンクは重複排除されて項目との順序の対応が失われている。**短縮URLは robots が拒否するため追跡しない**（回避しない）。
  - 12件の出所: 項目の短縮URL（展開結果なし）10・項目にリンクなし 2。項目自身の展開済みリンク（item_entity）は 0。
- 親投稿に付いていた展開済みリンク（LivePocket）は、**親投稿の全項目に共通**で、実際は特定の1店舗のページ。

## 2. 実装

| 部品 | 内容 |
| --- | --- |
| `item-links.ts` | 項目ごとのリンクに**出所**を付ける: `item_entity`（項目自身の短縮URLが `linkMap` で展開できた）／`item_text_short_unexpanded`（展開結果なし。追跡しない）／`parent_card`／`parent_shared`（親投稿共通）。X投稿URLは応募先にしない。同じURLが複数項目に付く数を数える。判断に引き継ぐURLは項目自身のリンクだけ（`itemScopedUrls`） |
| `link-scope.ts` | **複数の証拠（支持）と反証**から、確定／候補／不一致／不明を返す。店舗名の一致だけを絶対条件にしない。確定: 項目自身のリンクで反証なし（店舗名がページに出なくても可）／ページが項目の店舗を名指し／共通フォームが項目の店舗を選択肢に含む。不一致: ページが**別の店舗**・別の商品・別の系列・別の開催回を示す。不明: 親投稿共通のリンクでページが範囲を示さない（**無根拠の一括流用の禁止**）・短縮URL未展開。URLの文字列の類似では判定しない |
| 正解データの保存・評価（`scripts/lib/groundtruth.mjs`） | 回答は**人の名義だけ**（AI名義は拒否）。履歴に追記（確認者・日時・訂正履歴。過去の回答を消さない・同じ内容の再送で増やさない）。評価は**人が確認した実データだけ**から（架空は除外・判断不能は分母に入れない）。回答が無ければ「未測定」。取り違え（confusion）・誤統合・誤分割・false auto-register を数える。AIの判断を正解として記録する経路は無い |
| 確認画面（`scripts/review-10s-local.mjs`） | ローカル専用（127.0.0.1・トークン）。1件ごとに、原文・応募ページの抜粋・リンクの出所・対応の判定（支持/反証/不明）・取得結果・AIの仮説と代替案・観察した事実・根拠・不明点を表示し、「正しい／誤り（正しい方式とタイミングを指定）／判断不能」を選ぶ |
| 評価（`scripts/eval-review-10s.mjs`） | 人の回答だけから一致率などを集計。未回答は未測定 |

## 8. 次段階の推奨
1. **人の確認**（上記30件）を先に。回答後に `eval-review-10s.mjs` で、応募単位の一致・誤統合/誤分割・false auto-register を測る。
2. **新規収集データでのエンドツーエンド**: 開発用のX API鍵（読み取り専用・少数の投稿・費用上限つき）を**ユーザーが承認・用意**した場合に、X投稿→`linkMap`→項目ごとの応募先→取得→対応検査→推論→プレビューを実測する。それまで実データの成功として扱わない。
3. 地域不明（B の確認待ち 13）は、店舗マスターの照合を B にも適用して改善を測る（マスターは変更しない）。

## 1. バックアップ失敗の原因と修正
**事象**: Windows タスク `TorecaAppDailyBackup` が毎日 03:30 に失敗（`Unexpected end of JSON input`）。`local-backup.log` では**11/12 から毎日**失敗しており、11/19 に BACKUP_FAILED.txt で気づいた状態（最後の定期成功は 11/11）。手動の `npm run backup:full` は成功し、手動バックアップは11/17〜19に複数取得済みのため、データの保護が完全に途切れてはいない。

**原因**: Supabase CLI 3.2 の `db query` は、**AIエージェント環境（`AI_AGENT` 等）を自動検出したときだけ JSON を出力**し、通常実行では表形式（`┌───┐` の罫線）を出力する。完全バックアップ（`full-backup.mjs`）の構成情報クエリは JSON を前提に `JSON.parse` していたため、Claude Code 経由の手動実行は成功し、タスクスケジューラ（エージェント環境ではない）だけが失敗していた。タスクと同じ条件（Interactive・同じ実行ファイルと作業フォルダ）の一時タスクで、表形式の出力を直接確認して特定した。条件差は PATH・認証・TTY ではなく**出力形式**。

**修正**（`scripts/`）:
- `full-backup.mjs`・`lib/sql-exec.mjs`: `--output-format json` を明示。
- 新規 `lib/query-output.mjs`（`parseQueryRows`）: 素の配列（`--output-format json`）と `{rows:[...]}` の両方を受け、表形式などは「表形式の出力」と分かるエラーにする（`JSON.parse` の謎のエラーにしない）。単体テスト `tests/query-output.test.ts`（5件）。
- `local-backup.mjs`: 連続失敗回数 `consecutiveFailures` を状態ファイルに記録・`--status` に表示（既存のトースト・失敗フラグ・状態ファイルを活用。新機能は追加せず）。
- `docs/backup-and-ops.md` に、失敗の検知方法・原因・再発防止を追記。

## 3. E2E失敗3件の原因と修正（すべて**テスト側が現行UIに追従していなかった**。実装の不具合ではない）
いずれも `main` 単体でも失敗しており、今回の統合による回帰ではない。タイムアウトの延長・スキップは行っていない。

| テスト | 原因 | 修正 |
|---|---|---|
| `perf-7r`（設定画面の表示時間） | 設定画面に折りたたみの「すべての機能」グリッドが追加され、同じ `a[href="/settings/masters"]` が DOM の先頭（非表示）に出るため `.first()` が非表示の要素を掴んでクリックできなかった | `a[href=…]:visible` に変更（表示されている実リンクを押す。計測の意味は不変。マスター管理 約0.3秒・自動収集 約0.4秒で測定を完走） |
| `perf-collection`（コレクションの表示時間） | 下部メニューの既定が「4項目＋メニュー」になり、コレクションが直接のタブではなくなった。テストは `[data-nav="collection"]` を待ち続けて全体タイムアウトになっていた | 直接のタブが無ければ、メニュー（`nav-more`→機能一覧）から開く。計測は従来どおり（初回約0.9秒・アプリ内再訪問約0.35秒・再読込約0.2秒） |
| `stage8u`（複数店舗抽選の親カード） | UI-1 で、一覧（要チェック）の子はコンパクトな行（`group-child`）になった。テストは旧仕様の店舗別カード（`lottery-card`）が3件出ることを期待していた | 子は `group-child` が3件・`lottery-card` は0件であることを検証するよう更新（子での応募の親への反映・グループ管理以降の流れは不変） |

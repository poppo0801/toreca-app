## 3. 実装・改善した内容

| 領域 | 内容 |
| --- | --- |
| 公式識別（`official.ts`） | ドメインとアカウントを**別々に**判定。確定（official）は**相互リンク**（サイト→アカウント＋アカウント→サイト）のみ。プロフィール自己申告・名称類似・ロゴ・認証バッジは根拠にしない。共有サービス（フォーム・チケット・SNS・短縮）のホストは公式サイトの根拠にしない。履歴（同一系列で繰り返し・他系列では不使用）は likely（確定しない）。根拠が古ければ再確認。応募ページは公式（または確実な根拠）にリンクされたものだけ最上位。 |
| 対象条件（`conditions.ts` `resolveConditions`） | 地域: 通販→店舗マスター→見出し/告知の県名・店舗名の地名（既存の `judgeRegion`）→検証済みAI補助。TCG: 本文→**商品マスターへの対応**→検証済みAI補助。使った段階を記録し、不明の主原因を**1つだけ**数える（重複計上しない）。商品の絞り込みが有効で未評価なら「対象」にしない。一覧の項目に**見出しの県名**と文脈を持たせた（`facts.ts`）。 |
| 判断基準（`decision.ts`） | 自動登録（プレビュー）／欠落つき候補／確認待ち／除外／既存登録への更新提案。欠落（軽微な項目は登録を止めない）と矛盾（重要項目は確認待ち）を区別。終了済み・対象外・非抽選は除外（理由つきで記録）。公式・応募先の根拠が無ければ確認待ち。 |
| AI照合の揺れ対策（`adjudication-policy.ts`） | 同じペアを2回照合。**全回一致＋独立根拠（系列・店舗・商品・締切）**を満たす場合のみ「統合の候補」。割れたら保留（監査記録）。多数決で統合しない。決定的な「無関係・別応募」は覆さない。 |
| 候補検索（`cluster.ts`） | 系列の同値類でブロッキング。全ペア比較と**同一の結果**で比較数を削減（実データ 41,905組→3,454組＝**−91.8%**、結果一致を実データ・単体テストで確認）。系列が不明な情報源を介した誤統合も防止。 |
| 補完の補助 | ページ抽出AI（検証つき）・条件補助AI（提案のみ）。 |
| 確認画面 | `scripts/review-10o-local.mjs`（補完の事例・登録判断。難例を先に）。10M（一覧項目）・10N（応募機会の同一性）の画面への導線を明記。AI名義は拒否・何も実行しない。 |

実データ評価で見つけた不具合（修正済み・回帰テストあり）: 「通販」など汎用の店舗の値が実在の店舗名と矛盾にされ、不要な「確認」提案が3件出ていた → 汎用の値は矛盾にしない（再評価で解消）。

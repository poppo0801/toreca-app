## 4. 誤判定・見落としの具体例（案件ID・事象。原文は載せない）

1. **無効な引用①（r1c04）**：締切の引用が、ページの別々の箇所をつなぎ合わせた文（「2026年」〜の範囲の始点の年と、範囲の終点の日付を連結）で、原文に存在しない。検証層が `quote_not_found:deadline` として**保留（tentative）に落とした**（登録はされていない）。
2. **無効な引用②（r1c02）**：同じ種類の締切引用が原文に無い。**保留理由 `quote_not_found:deadline` が残っているのに、判断が register のまま**になっている（r1c04では tentative に落ちたのと不整合）。→ 検証層の挙動の確認が必要。
3. **無効な引用③（r1c04・応募単位）**：引用の1文字が、原文の部首文字（康熙部首の「入」）から別の記号に置き換わって出力され、一字一句の一致で不一致。モデルが稀な互換文字をそのまま写せなかった例。
4. **見落とし（新方式での保留・除外：判断の不一致）**：r1c01 で、gold が register とする1店舗の機会を **exclude**（締切時刻の記載がページ内で食い違い「23:00（23:59との記載も有り）」。応募単位も不明）、r1c01・r1c03・r1c04 で複数の機会を tentative にした。AIは「根拠なしで不明」とした項目（apply_unit・deadline）が多い。
5. **締切の空欄（r1c04）**：ページに締切が書かれている店舗で、AIが締切を「不明（根拠なし）」にした（読み飛ばしの分類で「読んで誤」）。
6. **応募単位の誤り**：goldが per_store の機会を one_form_one と推定、または unknown。推定（inferred）が多く、観察（observed）で確定できたのは少数。旧方式は店舗なしの暫定案しか出ないため応募単位は0%。
7. **旧方式の典型的な取りこぼし**：どの案件も、先頭リンクの1機会しか登録案にならず、残り2機会（別の店舗・別の受付）が丸ごと欠落（12件中8件）。

## 5. 改善すべき原因（優先度順）

1. **【重大】引用の検証と再試行**：新方式は2ページ目以降を読むほど引用が長く複雑になり、①範囲表記の連結・②稀な互換文字の写し間違いで無効引用が出た。対策案：(a) AI入力のページ本文を事前にNFKC正規化する（部首・互換文字を通常の字にそろえる。引用検証側と同じ正規化）、(b) 引用は「1つの連続した箇所」だけと指示し、検証に失敗した場合は引用だけを直して再提出させる1回の修正ターン（既存の `maxRevisions` 内）、(c) 無効引用が1件でもある登録案は decision=register にしない（検証層の不整合 §4-2 を調査・修正）。
2. **判断（register/tentative）の保守性**：応募単位の不明を理由に保留・除外にする傾向。goldは「応募単位が不明でもregister」だが、実運用では応募単位の確定が重要。評価仕様（gold側の判断基準）の見直しか、応募単位の推定基準の改善。
3. **本文の保存上限**：連結本文の保存（リンク先1ページ6,000字の抜粋）で、新方式でも goldの引用12件（33%）が保存本文に無い（`not_stored`）。links実験の保存設定（全文を保存しない）の影響が疑われる。応募単位・締切の記載が後半にあるページで精度を落とす候補。全文保存の条件（text_depth実験）と分けて検証が必要。
4. **応募単位の推定**：gold（per_store 等）との基準差。「お1人様1回のみ」の解釈（アカウント単位か店舗単位か）の指示の明確化。
5. **費用**：新方式は1.6倍（調査ターン4→6）。リンク数に応じた想定どおりで、単独では問題としない（期待12.4円に対し実8.76円）。

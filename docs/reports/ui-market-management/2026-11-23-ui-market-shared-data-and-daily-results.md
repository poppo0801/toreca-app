## 1. 実装内容

### 1.1 相場管理データの共通化
- 共有の範囲は**世帯**（このアプリの認証・RLSの単位。家族のプロフィールA・B・Cは同じ世帯のログインを切り替えて使う）。RLS はもともと世帯単位で、プロフィール単位の分離は**アプリ側の絞り込み（profile_id）だけ**だったため、その絞り込みを外した。外部公開・世帯をまたぐ共有はしていない（他の世帯からは読めず、改ざんもできない）。
- 対象の表: `zukan_cards`（151図鑑の収集カード）・`zukan_price_records`（151図鑑の価格調査）・`market_cards`・`market_prices`・`market_purchases`（相場調査メモ）。**応募・当選・購入・対戦・通知など他の表は従来どおりユーザー別/世帯別のまま（変更なし）**。
- 作成者（`profile_id`）は内部履歴として残し（NULL許容へ）、更新者（`updated_by_profile_id`）を追加。**プロフィールを削除しても共有の記録は消えない**（以前は cascade で一緒に消えた → 作成者だけが外れる）。
- 同時編集: カードの同一性（セット・番号・レアリティ）の一意制約を世帯単位に。同時に別の利用者が同じカードを登録すると、後からの登録は既存のカードを使う（23505 を検知して再照合）。更新・削除は id 単位（最後の保存が有効）。すでに削除された記録の操作は「対象が見つかりません」。購入済みの価格・履歴のあるカードは従来どおり削除できない（FK restrict）。
- 系列・店舗の入力履歴は、151図鑑と相場調査メモの価格記録を合わせた共通の履歴（`loadStoreHistoryAction`）。どちらで入力した店舗も、もう一方の候補に出る。表示時・画面に戻ったとき・フォームを開いたとき・保存後に読み直すため、別の利用者の入力も反映される。
- **新規登録の初期選択**: 世帯共通の「最後の入力」（両方の記録元のうち作成日時が最も新しい、系列・店舗の両方がある記録）から**5分未満**なら系列・店舗を初期選択。5分以上・履歴なしは空欄（履歴の候補は残る）。**フォームを開くたびに評価**し、履歴の読み込みが後から届いた場合も評価する（手で入力・選択した後は上書きしない）。判定は保存済みの記録の作成時刻（サーバー時刻）を使うため、端末をまたいでも共通。

### 1.2 既存UIの改善
- **メニュー長押し**: `LONG_PRESS_MS` 420ms → **210ms**（半分）。通常タップ（約150ms前後）は開かない・移動12px超で長押しを取り消す・離した後は開かない、を単体テストで確認。
- **状態違いの複数価格**: 2件目以降もプルダウンをやめ、最初の登録と同じ A+・A・B+・B・C の**ボタン選択式**に統一（価格入力＋削除ボタンを1行）。
- **相場調査メモの一覧**（参考画像に合わせた3区画）: 左=画像・カード名・収録セット（小さな枠）・系列 店舗（長い場合は省略表示）／中央=レアリティ（独立した列・左右の細線）／右=状態バッジ・価格（**text-lg → 15px に縮小**）。行の高さは64px未満。詳細・編集・購入・価格追加（左スワイプ）は従来どおり。カード番号は一覧から外し詳細に表示（参考画像に合わせた配置の最適化。情報・機能は削除していない）。
- **並び替え**: アイコンのみ・ツールバーの他のボタンと同じ高さ（検索・並び替え・購入済み・追加はすべて44px）。タップで 新着順 → 価格降順 → 価格昇順 → 状態順 → レアリティ順 → 五十音順 → 新着順。**長押し（420ms。コンテキストメニューも可）で全項目（図鑑No順を含む）の一覧**から直接選べる。長押し直後のクリックは次の並びへ切り替えない。現在の並び順は見出し右（「新着順 ↓」など）・`aria-label`・`data-sort` で確認できる。レアリティ順は一般的な表記の高い順（MUR > UR > HR > SAR > … > C）で、並び替えの目安であり価値の判断ではない。旧「図鑑No順」はタップの循環から外し、長押しの一覧に残した（機能は維持）。

### 1.3 日別相場調査結果（新規ページ `/market-memo/daily`）
- 入口: 相場調査メモ・151図鑑の上部の「本日の調査結果 ›」。
- 表示対象: 151図鑑と相場調査メモの価格記録を統合（初期表示は今日・**日本時間**。日付入力・前日/翌日・「今日」。過去の日付も閲覧可）。日付は各記録の**調査日（surveyed_on）**で判定。
- 同じカードの複数店舗・複数状態・複数価格はそれぞれ保持。**同じカード・同じ系列＋店舗・同じ状態・同じ価格が両方の記録元にある場合だけ1行にまとめる**（二重表示を避ける。購入予定は両方の記録に付く）。価格や状態が違えば別の記録。同じ記録元内の同じ内容は別々の記録のまま。
- 既定=カード別（図鑑番号順・不明は最後）。同じカード内は価格の安い順。同じポケモンでもセット・番号・レアリティが違えば別のカード。系列・店舗別に切替可。状態ランク（複数選択）で絞り込み。
- **購入予定マーク**: 行のタップでON/OFF（薄いオレンジの背景）。**購入予定だけの絞り込み**あり。行右の「i」で詳細（記録元・調査日・備考・元の画面へのリンク）を、マーク状態に関係なく確認できる。全員共通（DBの`market_plan_marks`）。**マークは当日（日本時間）だけ有効**で、翌日以降は表示されない（行は残り、相場記録は削除されない）。再度ONにすれば当日に更新される。ON/OFFは「指定して設定」（切り替えではない）ため、同時操作・二重送信でも結果が一定。記録が削除されるとマークも消える。

## 2. DB変更（マイグレーション `20261230000116_market_shared_and_plan_marks.sql`・**ローカルのみ適用**）
1. 同一世帯で重複するカード（セット・番号・レアリティが同じ）を**統合**: 価格記録・購入記録を代表のカード（最も古いもの）へ付け替え、補足は結合（500字まで）、重複したカードだけ削除。**価格・購入の記録は1件も削除しない**。
2. `market_cards_identity` を (profile_id, …) → **(household_id, …)** の一意索引へ。
3. 5つの表の `profile_id` を NULL許容にし、FK を `on delete set null (profile_id)` へ。更新者 `updated_by_profile_id` 列を4表に追加（NULL許容）。世帯単位の読み出し用の索引を追加。
4. 新表 `market_plan_marks`（世帯・対象の記録（図鑑か相場メモのどちらか1つ）・marked_on・マークした人）、RLS（世帯の構成員のみ）、`market_set_plan_mark(kind, id, on, profile)`（日付はサーバーが日本時間で決める）。
- 既存データへの影響: 列追加・FK付け替え・**重複カードの統合のみ**。ローカルで「別プロフィールの同一カード2枚＋各価格・購入」を作ってから適用し、カード2→1・価格2件・購入1件が保持され、補足が結合されることを確認（リハーサル）。
- **統合は元に戻せない**ため、本番適用の前に `npm run backup:full` と復元の確認が必須（§5）。

## 6. 未解決・注意事項
- **実機（iPhone）未確認**: 長押し210msの体感（誤作動の有無）・日付入力・長押しの一覧（iOSでは長押しのコンテキストメニューが出ない場合があるため、pointer の長押しで実装）・ボタン配置。自動テストは390px幅のブラウザのみ。
- 共有の範囲は**世帯**。「ユーザーA・B・C」が別々の世帯（別ログイン）である場合は共有されない（世帯をまたぐ共有は認証・RLSの設計変更を要するため行っていない）。違う場合は要確認。
- 日別の「その日」は**調査日（surveyed_on）**で判定。登録日と調査日が違う記録（過去日付で登録）は、調査日の画面に出る。
- 購入予定マークの「翌日解除」は、表示しない（マークした日≠今日）方式。行は残るため、将来の集計・履歴に使える。自動削除はしていない。
- 一覧から外したカード番号は詳細（カード詳細・日別の行ヘッダー）で確認できる。一覧に常時表示したい場合は調整が必要。
- 並び替えのレアリティ順は、表記の一覧（MUR/UR/HR/SAR/BWR/SSR/SR/AR/ACE/RRR/RR/R/PR/K/U/C/S/A）以外は一覧にあるものの後ろ。
- 151図鑑の収集カード（`zukan_cards`、購入金額を含む）も共有対象にした（151図鑑の共通化として）。購入金額を共有したくない場合は要確認。
- 同じカードの統合は、収録セットと番号が両方ある場合のみ（無い場合は従来どおり名前だけで同一とせず確認）。
- JSONバックアップ（`backup.mjs`）に相場系の表が含まれない既存課題は未対応（SQLダンプは含む）。

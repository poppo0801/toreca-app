## 5. 残リスク・注意
1. **Supabase CLI のフラグ**: 既存のスクリプト（`full-backup.mjs`・`sql-exec.mjs`・`cleanup-fake-stores.mjs`）は `supabase db query --linked` を使うが、このPCの CLI 3.2.0 のヘルプには `--remote` と「既定はローカル」とだけあり `--linked` の記載がない。**`--linked` が無視されると、本番バックアップがローカルDBに対して実行される可能性**がある（未検証。本番へ接続できないため確認していない）。本番バックアップの実行前に、利用者の端末で出力の「Target:」行（接続先の表示）を確認することを推奨。新しい抽出CLIは `--remote=<ref>` を明示し、リンク先refとの一致も要求する。
2. 本番接続の実機検証は未実施（権限・CLIの挙動・出力形式）。承認後の最初の実行は dry-run→少数件で確認。
3. 旧方式の値は固定の形態判定のみ。収集のAI抽出（応募単位）との比較には、旧抽出の再実行（課金）か、保存済みの抽出結果（読み取りは別承認）が必要。
4. 漏洩検出の実データでの漏れ率は未測定（人の全件目視が最終防御）。承認記録・確認記録はローカルファイルで、ファイルを書けば通る（自己承認を防ぐのは運用）。
5. 一括再整理の適用（R2）の実装・復元手段は未実装（計画のみ）。
6. PR #36のマージはアプリ本番反映を伴う（保護確認失敗時の挙動変更）。

## 1. 適応型判断
- 方式: 調査は Haiku。判断はまず Haiku で行い、次のときだけ**同じ証拠で** Sonnet に判断させる（調査・取得・検索をやり直さない）。
  - 判断の失敗、検証不通過、重大な不明が残る暫定、受付枠が複数ある複雑な構造
  - 登録なのに地域の適合が観察で確認されていない（#169 で追加）
  - 検証済みの登録・除外の20%（監査の抽出）
  これらは一般の条件で、店舗固有の規則ではない。
- 上位の判断が失敗・予算不足・検証不通過のときは、既定の検証済みの判断を消さない。既定が登録・除外と決めていたのに上位が別の結論になったときは、どちらも正解扱いせず保留にして人の確認へ回す。
- 記録: `judge_trail` に段・モデル・選んだ理由・判断・検証を保存する。`model_id` は `haiku+adaptive:sonnet`。
- 切り戻し: `scripts/shadow-enable.mjs --set-judge-mode=single`（DB設定・環境変数の変更なし）。

## 3. 実運用レビュー・正解入力（既存の候補詳細の拡張）
- 候補の詳細の登録案カードで、正解を記録できる。
  - 操作は「正しい」「正解を修正」「後で確認」。
  - 修正では、変える点だけを入力する（判断・機会の有無・利用者適合と、店舗・商品・締切・応募単位・応募先URL・口数・応募条件）。項目ごとに「不明」を選べる。
  - 補足は任意。
- 「登録案に無い応募機会を記録」（取りこぼし）を追加した。現行が見つけた候補との比較で、AIが独自に見つけたものではない。
- 記録は追記専用で、AIの出力の写しを残し、AIの値・過去の行は書き換えない。再評価で版が変われば再確認の対象になる。「記録だけです。抽選の登録・削除・通知は行いません」と表示する。
- 一覧の集計の横に「AI評価: すべて／要確認／確認済み」の絞り込みを追加した。要確認は、判断なし・検証不通過・保留を先に並べる。
- 自動フォーカス・自動プルダウンなし。390px の実画面: `test-results/ar-truth-form-390.png`（E2Eで撮影。iPhone実機は未確認）。
- 権限: 世帯の構成員だけが記録・閲覧できる。別世帯からは読めず書けない（DB統合で確認）。
- 集計: `npm run prod -- scripts/proposal-truth-report.mjs --yes-production`（読み取りのみ・値を出さない）。正解数・判断の一致・誤登録・誤除外・不要な保留・登録漏れ・項目の修正・明示的な不明・取りこぼし・上位の使用と採用・費用を区別する。未確認は数えない。

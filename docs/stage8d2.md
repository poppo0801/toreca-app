### Web検索の可否と費用（要確認の注記つき）
- Anthropic API には**サーバー側の `web_search` ツール**がある（SDK 1.3.0 に型あり: `web_search_20250305` ほか）。AIのテキスト解析とは別機能で、検索1回ごとに課金される。
- 料金: 公表情報では **1,000回あたり10ドル（1回約1.5円＝1ドル150円換算）＋通常のトークン料金**（Anthropic の料金ページ。2026-11-12 に検索で確認したが一次ページは未確認。**契約前に公式の料金ページで要確認**）。エラー時は課金されないとの記載。
- 制約（未確認・要確認）: 組織での Web 検索の有効化設定、使用モデルが `claude-haiku-5-5` で対応するか、`allowed_domains` などの指定、結果の暗号化コンテンツの扱い。本Stageでは検証していない。
- 新しい契約は不要（既存のAnthropic APIの機能）。ただし**追加の料金が発生する**ため、承認前に実API検索は行わない。代替案: 外部の検索API（Brave・Google Programmable Search など。別契約・別料金。未調査）。検索手段は `SearchProvider` で交換可能にしてある。

### ツール（読み取り専用の6つ）
`read_store`（店舗の登録情報・同じ系列の他店舗）／`past_research`（過去の調査結果）／`web_search`（検索。上限あり・概算費用加算）／`fetch_page`（検索結果に出たURLまたは登録済みの公式ドメインだけ。上限あり）／`compare_addresses`（住所の比較）／`geocode_address`（国土地理院）。

### ツールの追加方法
`AgentTool`（`name`・`description`・`inputSchema`・`access`＝`read_internal` | `read_external`・`consumes`＝`search`|`fetch`・`costJpy`・`run`）を作り、`buildStoreLocationTools` の `registry.register(...)` に足す。`access` が読み取り以外、または名前に write/update/delete/sql/exec/deploy/post/send/save/register/merge 等を含むものは**登録時に例外**。外部由来の結果は `untrusted: true` を付ける（データとして囲まれ、命令検出の対象）。別の対象（例: 商品情報の調査）は、同様に `store-location/` を手本に、ツール・検証層・保存先を作る。

## 3. 権限管理
- **許可**: Web検索・ページ取得・比較・開発用DBの読み取り・過去の調査の参照・調査結果の提案と保存（専用の表のみ）。
- **禁止（仕組みで）**: 本番DBへの書き込み（開発環境以外では動かない・本番を拒否）／既存店舗マスターの更新（このコードに stores への書き込みは無い。DBテストで「調査後も店舗が1文字も変わらない」を確認）／抽選の登録・削除（ツールが無い）／外部への投稿（ツールが無い）／任意のSQL・プログラム・シェル（ツールが無い。登録も拒否）／本番デプロイ。
- 外部の指示: 登録されていないツールの呼び出し（外部文面に誘導された削除・SQL・実行など）は拒否して記録。ページ本文は `<untrusted_web_content>` で囲み、命令らしき文面は検出・記録して信頼度を下げる（実行しない）。AI の出力は SQL にも実行コードにもならず、検証層を通った構造化データだけが保存される。
- 取得できるURL: 検索結果に出たもの／登録済みの公式ドメイン配下のみ（AI・外部文面が作った任意のURL、情報送信を狙うURLは取得しない）。さらに `safe-fetch` が内部ネットワーク・ループバック・`file:` 等を拒否。取得は1.5秒以上あける。robots.txt を尊重し、ログイン制限は回避しない。

## 4. 店舗所在地エージェントの動作
1. 系列名・店舗名（と同じ系列の他店舗・登録済みの都道府県・公式ドメイン）を読む。2. AI が検索語を決めて検索。3. 結果から取得するページを選ぶ。4. 住所の候補を、**取得したページ本文からの引用つき**で提出。5. 情報が足りない・候補が1つだけなら、検索語を変えて追加検索（上限内）。6. 検証層が候補を検証し、ステータス・信頼度・座標を決める。7. 結果を保存（店舗マスターは更新しない）。

### 検証層（AI の自己評価を使わない）
- 引用が取得したページの本文に実在すること（無ければその候補は無効＝AIが作った住所は通らない）／住所が引用の中にあること／都道府県＋市区町村＋番地まで揃うこと／店舗名の近くに住所があり、系列名がページにあり、別店舗・別系列（同名の本店）の行でないこと／登録済みの都道府県と一致／閉店・移転の記載が（同じページ・他のページのどちらにも）ないこと／ページに命令らしき文面がないこと／国土地理院の住所検索と番地付近まで一致。
- **確認済み**は、上記をすべて満たし、かつ（公式ドメインの情報源、または独立した2つ以上のドメインで同じ住所）のとき。それ以外は候補あり（信頼度の上限60）・情報不足・情報矛盾（複数の住所が検証を通った）・該当店舗なし・検索上限到達・調査失敗。
- 信頼度（0〜100）: 規則の点数（引用の実在5・店舗の識別15・住所の完全性10・地図の一致15・公式35・独立2情報源20、減点: 閉店−40・命令の検出−30・都道府県の不一致−30、矛盾は20上限）。
- 公式かどうかは、店舗に登録済みの公式サイトのドメイン（`stores.store_url`）との一致で判定する。未登録なら公式を確認できず、第三者だけでは確定しない（意図した厳しさ）。

## 5. 実行上限・実APIの関門
- 上限（`AgentLimits`、設定可能）: 実行回数12・Web検索4・ページ取得6・トークン6万・推定費用15円・時間90秒・再試行2（既定）。到達したら安全に終了し、集めた情報で検証する。費用は推定（トークン料金＋検索1.5円の概算）。請求額とは差が出うる。
- 実APIの関門（`checkRealApi`）。すべて必要: ①開発環境（`TOREMANE_ENV=local`）②`AGENT_REAL_API=allow` ③開発専用キー `AGENT_ANTHROPIC_API_KEY`（本番の `ANTHROPIC_API_KEY` と同じ値は拒否・本番キーをコピーしない）④`AGENT_MAX_COST_JPY_PER_RUN` と `AGENT_MAX_RUNS_PER_DAY` の設定⑤本日の実行回数が上限未満⑥画面での費用確認。任意で `AGENT_MODEL`・`AGENT_MAX_SEARCHES/FETCHES/STEPS`。API障害（429・529・5xx・通信）は再試行→上限で停止。それ以外のエラーは `調査失敗`。

# Stage 6N: 自動収集の精度・Xブックマーク管理・店舗選択式抽選・支出の系列＋店舗・ガソリン代

既存の抽選・応募・当選・購入・受取・売却・コレクションのデータは変更しない。DB変更は追加のみ（`20261125000069_stage6n.sql`、`20261125000070_bookmark_priority.sql`）。

## 1. Xアカウント表示名を優先した系列判定
- 系列の決定順（`src/lib/collector/x-chain.ts`）: ① 確定済みの対応（アカウントID → ユーザー名の順）② X表示名と系列マスターの正式名称・別名 ③ 告知から読み取った系列名 ④ ユーザー名（マスターの名称・別名と一致するときだけの補助）。
- **Xユーザー名（`@Rises_eStore`）をそのまま新しい系列名にしない。** 告知の系列名がユーザー名そのもの（`Rises_eStore`／`Rises eStore` の区切り違いも同一視）で、マスターにも一致しなければ破棄する。特定できなければ系列は空のまま確認待ち（理由: 「系列を特定できません（表示名「…」）」）。
- 確定済みの対応は `x_account_identities` にアカウントID（`x_user_id`）つきで保存し、ユーザー名が変わっても再利用する。
- 既存データの確認（本番・読み取りのみ）: 系列 `Rises_eStore` は残っていない。`@Rises_eStore` 由来の抽選2件は、系列「トレカザイラス」（別名「Rises eStore」登録済み）・店舗「eストア」に紐づいている。**マスター統合・名称変更は行っていない**（応募履歴を壊さないため。表示名「トレカザウルスeストア」を別名に追加するかは利用者の判断）。

## 2. 受付終了した確認待ち候補の非表示
- `src/lib/collector/closed.ts`: 受付終了日時を過ぎたら通常の確認リストから外す。日付のみは JST の 23:59:59 まで有効。複数の応募期間（`applyPeriods`）は有効な期間が残っていれば維持。締切が不明なものは外さない。
- 適用先: 要手動確認の一覧・件数、設定の確認待ち一覧・件数、通知のベル・バッジ、起動時ポップアップ。画面を開いたままでも1分ごとに再判定する。
- 候補は削除しない（履歴として保持）。応募済み・当選済みの情報には触れない。ブックマーク由来は追跡状態（`x_bookmark_posts`）を保持し「受付終了・未解決」として残す。

## 3. Xブックマークの優先収集・処理状況
- **優先**: `claim_collection_jobs` の優先度に +1000（ブックマーク由来）。取得 → AI解析 → 照合 → 登録の順で、通常のX投稿・Web候補より先に処理する。X API・AI の月額予算上限は従来のまま（予算不足・レート制限は状態を保持して次回へ）。
- **状態管理**（`x_bookmark_posts`、投稿IDごとに1行・再同期で重複しない）: 未取得／取得済み・解析待ち／解析中／情報不足・追加調査中／要手動確認／抽選登録完了／既存抽選と統合済み／対象外／取得失敗／受付終了・未解決。**取得できたこと（解析待ち）と抽選登録（lottery_id あり）は別状態。**
- 取得失敗は一時的（API・通信・レート制限）と恒久的（削除・非公開・権限不足）を区別。恒久的なものは自動再調査しない。
- **起動時ポップアップ**（はとむぎのみ・従来どおり）: 最上部に「Xブックマーク：新規N件」を全件個別表示（X表示名・要約・元投稿リンク・状況・理由。件数が多いときは領域内でスクロール）。表示した行は「表示済み」にして再起動で繰り返さない。未解決は ⚠ 付きで残す。
- **未解決の保持**: 通知のベルに「⚠ 未解決のXブックマーク」を、解決するか、利用者が「対象外」「調査終了」を選ぶまで残す。受付終了後は再調査を止め「受付終了・未解決」の履歴にする。
- **補完**（有料APIの追加なし）: 定期ワーカーの冒頭で、未解決（再調査の時刻に達したもの）の候補を、既存の項目別統合（`runMergePass`）で他の候補・既存の抽選・公式ページ由来の候補と照合する。同じ抽選と確定できたときだけ統合し、応募条件はAIの推測で作らない。再調査の間隔は 1h → 3h → 6h → 12h → 24h、最大8回。

## 4. 店舗選択式の抽選
- 抽選に `store_mode`（fixed／select_on_apply／none）と `selectable_stores`（取得できた場合の店舗一覧）。登録時点では店舗を必須にせず、仮の店舗「応募時に店舗選択」を使う（既存の `lotteries.store_id` 必須を保つため）。詳細に「応募時に店舗選択」を表示。
- 応募済みにするとき（ボタン・スワイプ共通）に応募先の店舗を選ぶ画面（一覧があれば選択式、なければ手入力、「店舗を決めずに進む」で未設定）。**応募店舗は各プロフィールの応募記録（`applications.applied_store_*`）に保存**し、自分の応募だけ後から変更できる（他のプロフィールは変更不可）。
- 受取（購入済み）で作る購入記録には、系列と**そのプロフィールの応募店舗**を引き継ぐ。
- 自動収集の判定: 店舗一覧と都道府県が分かれば、1店舗でも対象地域なら収集。都道府県が不明なら地域で除外しない。選べる店舗がすべて対象外と確認できたときだけ従来どおり除外。店舗選択式の検出は本文・条件の文言と系列（トレカキャピタル）で行い、AIのプロンプトは変更していない（再解析の費用なし）。
- 抽選の登録・編集フォームに「店舗の指定」（店舗固定／応募時に店舗選択／店舗指定なし）を追加。

## 5. 支出の系列＋店舗
- 「購入店舗」を「系列」＋「店舗（任意）」の2欄に（全品目）。店舗は選んだ系列の店舗に絞る。店舗のない系列は系列のみで保存。未登録の系列名は仮登録（既存の名称・別名と一致すれば新規作成しない）。
- `purchases.chain_id` を追加。旧データは店舗の系列から判断し、店舗マスターが確実に分かる既存の購入記録だけ系列を補った。曖昧な店舗名は元の文字列を保持。

## 6. ガソリン代
- 経費で「ガソリン代を計算する」: 内容を「ガソリン代」にし、単価（初期155円/L）・片道距離・往復/片道から金額を計算（円に四捨五入）。結果は金額欄に入り、手動修正できる。OFFで通常の経費入力に戻る。不正な入力は理由を表示。
- 燃費（初期 16.7km/L）は支出画面に出さず、設定 →「ガソリン代」で変更。ガソリン単価の初期値も世帯の設定。**初期燃費16.7km/Lは指定値。公式の年式別の公称値との整合は未確認**（検索では同型式・年式により約15.2〜15.8km/L相当の掲載があり、実燃費に合わせて設定で調整する想定）。
- 片道距離は系列＋店舗ごとに保存（`store_trip_distances`）し、同じ組み合わせで自動入力。店舗が違えば別の距離（流用しない）。計算時に保存。
- 計算済みの金額は通常の経費として保存され、単価・燃費を変えても過去の金額は変わらない。

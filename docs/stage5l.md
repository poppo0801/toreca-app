# Stage 5L: 抽選Excel・標準分類・通販区分

実機（iPhone）では未確認。以下の「事実」はコード・テスト（単体・実DB結合・E2E）で確かめたこと。

## 1. 抽選Excel（設定 › 抽選データ管理）
- **シート**: 抽選情報（1行1抽選）／対象商品（1行1商品）／応募・当落履歴（1行1プロフィール。商品別の当落は商品ごとの行）／使い方／出力情報（出力時のみ。抽出条件・日時・フォーマットバージョン）。
- **識別**: 既存は「抽選ID」（内部ID）。新規は「取込キー」（例: NEW001）で3シートを結び付ける。取込キーはDBに `ファイル指紋8桁:キー` として保存され、同じファイルの再取り込みで重複登録しない。
- **出力と取込は同じ形式**（出力 → Excelで修正 → 再取り込み。出力したファイルをそのまま確認すると全行が「変更なし」になることをテストで確認）。
- **更新の規則**: 空欄=変更しない／値=変更／`#CLEAR`=削除（clearable の項目のみ）。ファイルに無い抽選・商品明細・応募記録は削除しない。
- **確認画面**: 新規／更新／変更なし／重複候補／要確認／エラー。変更前後を項目ごとに表示。エラーがあると適用できない（エラー一覧CSVあり）。
- **未登録の系列・店舗・商品**: 既存候補／新規（仮登録）／保留を選ぶ。未選択は適用しない。住所・都道府県は推測しない。
- **重複候補**: 同じ系列・同じ店舗で「同じ締切日＋共通の商品」または「同じ情報源URL」の新規行。別店舗・商品名だけでは重複にしない。選択肢は「別の抽選として登録／保留」（自動統合しない。既存を更新するなら抽選IDで指定）。
- **適用**: DB関数 `apply_lottery_import`（1トランザクション。失敗・競合なら全体を取り消し）。確認時の指紋と一致しないと適用しない（二重送信は履歴の一意制約で拒否）。履歴は `lottery_import_history`（件数・ファイル名のみ。ファイル本体・変更前後の値は保存しない）。
- **過去履歴**: 過去の日付・応募済み・当落を登録できる。締切が過去の抽選は期限から自動で「受付終了」になり受付中に出ない。通知は作られず（テストで確認）、購入記録・「購入済み」は変更できない（出力のみ）。
- **応募・当落**: A/B/Cは独立。記録の無いプロフィールは「記録なし」（応募していない、とは別）。応募日の時刻が空欄なら 0:00（日本時間）で記録する。
- **ダウンロードの絞り込み**: 受付状況／応募状況／当落結果／管理対象／商品・系列・店舗／応募開始・締切・発表の期間／プロフィール。複数条件はAND。プロフィール指定時はそのプロフィールの応募・当落で判定、未指定はいずれかが一致。抽出条件は画面とファイルに明示。
- **安全**: 数式・外部リンク・マクロ・パスワード付きは拒否。行数・サイズ上限。世帯はRLS＋RPCで本人の世帯に固定。

## 2. 標準分類
- **当落発表方法**: 当落メール／当選者のみメール／結果確認ページ／公式アプリ／XのDM／LINE／SMS／店頭発表／SNS投稿／電話／その他／不明（複数選択）。通知対象（当選・落選の両方／当選者のみ／不明）は経路とは別の項目。元の文章は「補足・原文」（既存の announcement_method）として残る。
- **応募条件**: 会員・購入実績・本人確認・SNS/アカウント・地域/来店・応募制限・その他の28タグ（複数）。結合は「すべて必要／いずれか」（2つ以上のときだけ表示）。具体的な数値（購入金額・購入期間・会員ランク・年齢・居住地域・応募可能店舗数）は不明なら空（推測しない）。元の文章は conditions_text に残る。応募制限（回数・単位）は従来の項目のまま（二重管理しない）。
- **LivePocket**: URL/本文から明確なときだけ、告知に発表方法が無い場合に「当落メール＋結果確認ページ」を**推定**として補う（`announcement_inferred`。画面に「推定」を表示。通知対象は確定しない）。告知の明記が優先。ルールは `SERVICE_RULES` に追加できる（モデル再学習ではなくルールベース）。
- **既存の自由記述データ**: DBは書き換えていない。分類が無い抽選は従来どおり文章を表示し、編集画面の「文章から分類」で任意に分類できる。
- **AI解析**: 単件・一括・URL・画像とも同じ下書き生成（`lottery-match`）で、AIの文章を標準分類へルールベース変換して初期値にする（要確認の印は従来どおり）。分類への変換自体はAIの誤りとして記録しない（フィードバックの比較対象外）。AIの原文・情報源URL・要確認・修正履歴は従来どおり。
- 共通処理（`src/lib/lottery-taxonomy.ts`、`lottery-excel/plan.ts` の照合・重複検出）はStage 4Cから再利用できる。

## 3. 通販区分
- 店舗マスターに営業形態（実店舗／オンライン専用／兼用。既存は実店舗）。名前に「通販」等があるだけでは判定しない。オンライン専用店舗には架空の都道府県・住所を入れない。
- カード/詳細の地域: 店頭受取＝都道府県（Web応募でも通販にしない）／発送のみ・オンライン専用店舗＝通販（距離なし）／店頭・発送から選択＝都道府県＋「発送可」／受取方法が不明＝出さない。
- 店舗マスターExcelに「営業形態」列を追加（空欄=変更しない。古いテンプレートも読める）。抽選Excelでは受取方法を指定できる。

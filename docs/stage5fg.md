# Stage 5F＋5G: コレクション・AI一括解析

## 5F コレクション（`/collection`）
- **データ**: `card_masters`（カードそのもの。名称・番号・商品コード・レアリティ・種類・収録商品・画像）／`card_holdings`（取得ごとの所有記録。枚数・1枚あたり購入価格・購入日・購入元・状態・備考・関連する購入記録ID）／`card_prices`（参考相場の履歴。販売/買取・確認日・出典。追記専用）／`card_favorites`（プロフィールごと＋順位）。商品マスター(products)とは別。カードの同一性は「商品コード＋番号＋レアリティ」（DBの部分一意インデックス）。名称の類似では統合しない。
- **一覧**: 画像グリッド（3/4/5列、既定4列、縦横比維持）とテキスト一覧。列数・形式・演出はプロフィール別（`profile_settings.collection`。設定コピーの対象。お気に入りの順位はコピーしない）。検索（名前・番号・収録・レアリティ）、絞り込み、並び替え。標準＝お気に入り→順位→参考価値の高い順（価値未設定は末尾。0円にしない）。一覧は60件ずつ描画・サムネイルは遅延読み込み・`content-visibility`。
- **集計**: 種類数・枚数・購入額・参考価値（販売）を上部にコンパクトに。詳細（買取価値・差額・レアリティ別・収録別）は展開。価格未設定があれば「一部のカードだけの集計」と明示。差額は購入価格が全枚数分そろい、相場があるカードだけ。参考相場は確定した売却額ではなく、収入・収支には計上しない。
- **詳細**: 画像・情報・購入履歴（取得記録ごとの編集・削除）・相場の登録/履歴・差額。削除は「取得記録1件」と「カード全体」を区別（アーカイブ）。購入記録・収支は削除しない。
- **登録**: 手入力、画像1枚（AIが読み取り→フォームに入力。読み取れない項目は空欄、理由は「要確認」の詳細）、複数画像の一括登録（**画像1枚＝カード1種類**。同時3件で解析、個別再解析・除外・修正、重複候補（同じ画像／同じ番号・コード・レアリティ）は既定で除外し枚数を足さない、解析失敗だけ再試行）。既存カードと一致（コード・番号・レアリティ）すれば所有記録を追加、似ているだけなら候補を示す。
- **画像**: `/api/card-images` が形式を確認し、詳細用(1200px)とサムネイル(360px)のWebPにして非公開バケット `card-images/<世帯ID>/…` に保存（元画像は保存しない）。同じ画像は保存し直さず再利用、他のカードが使う画像は削除しない。
- **AI**: Haiku（既存の設定）。解析ログは `kind=card_image`（抽選解析と評価指標を分ける）。月間予算超過時は解析しない。**外部Web情報との照合は実装していない**（出典URL欄だけ用意。画面にも「外部サイトとの照合は行っていません」と表示）。
- **導線**: 下部メニュー候補（初期は「その他」。直接表示にもできる）。購入記録（手入力の単品）から「コレクションに追加」で購入日・金額・枚数を引き継ぐ（参照のみで購入・収支は変更しない）。
- **演出**: 先頭24件の順次フェードイン（22msずつ）、SAR等の高レアリティの控えめな光沢（押した/ホバー時と詳細表示で1回。常時アニメーションなし）。プロフィール別にON/OFF、OSの「視差効果を減らす」で無効。

## 5G AI一括解析（`/lotteries/bulk`）
- **単件のAI読み取り**: 画像を最大5枚（並び替え・個別削除）。複数枚は「1件の抽選」として解析（プロンプト仕様 `2026-10-30.2`）。
- **一括画面**: 文章／URL（改行区切り→各行が別の抽選、X投稿URLは自動判別）／画像を追加。画像は **A: 選んだ画像を1件の抽選（最大5枚）／B: 画像1枚ずつを別々の抽選** を明示的に選ぶ。1回に最大20件。
- **ジョブ管理**: `ai_jobs`/`ai_job_items` に状態を保存（待機中・解析中・確認待ち・保存済み・一部失敗・失敗・キャンセル）。項目の取り出しは DB 関数 `claim_ai_job_items`（`FOR UPDATE SKIP LOCKED`・世帯ごとに同時3件・期限(lease)90秒・試行3回まで）。AIの一時的な失敗は自動で最大3回まで再試行、取得失敗や「抽選ではない」は再試行しない。月間予算に達したら新しい解析を始めない（項目は待機のまま）。同じURL・X投稿・文章・画像は、進行中・確認待ちの間は重複登録できない（DBの部分一意インデックス）。保存済みの抽選と項目の結びつきも1回だけ。
- **ブラウザを閉じた場合（実行基盤の制約）**: Vercelの関数は応答後も最大約60秒しか継続できず、Cronは有効化していない。ジョブ作成・解析再開の要求は `after()` で応答後も解析を続けるが、継続できるのは関数の実行時間内（目安は数件）。**残りはアプリを次に開いたとき自動で再開**する。確実に「閉じたあとも全件完了」にするには、定期実行（Cron等）かワーカーが必要で、今回は導入していない。
- **通知**: アプリ内（トースト＋抽選管理の「まとめて読み取り」のバッジ）。完了を検知すると他の画面でも表示し、タップで結果へ。再読み込み・再起動後も未確認なら出る。OSのプッシュ通知はなし。
- **確認・保存**: 結果は「確認待ち」（正式な抽選ではない）。項目ごとに系列・店舗・商品・日付・要確認数・重複の可能性を表示し、「確認して保存」で登録フォーム（Stage 5Dの要確認UI）に入力済みで開く。複数選択のまとめて保存は、方式未確認・重複の可能性が高い・検証エラーの項目を個別確認に回す。除外・再試行・キャンセルに対応。
- **フィードバック**: 保存時に解析ログの実行IDで比較を1回だけ記録（4B.5）。項目にジョブ項目ID・抽選IDを結びつける。
- **安全性**: URL取得は既存のSSRF対策（内部アドレス・リダイレクト・サイズ・robots）を使用。入力画像は非公開バケット `job-inputs` に一時保存し、解析完了・除外・キャンセルで削除（期限切れの自動削除はCron無しのため未実装）。ジョブ・項目・画像はRLS／ストレージポリシーで自世帯のみ。
- **4Cで再利用できる部分**: ジョブ/項目の状態管理・取り出し(claim)・予算ガード・重複キー・解析ログ・確認待ちの保存フロー・完了通知。4Cは「情報源の差分」を項目として積み、条件に合うものを自動登録する処理を追加すればよい（今回は未実装）。

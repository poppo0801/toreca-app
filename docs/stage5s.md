# Stage 5S（AI自動収集の安定化・優先収集メモ・結果通知・UI修正）

## 1. 自動収集の根本改善（Stage 4C 追加）

### 診断（本番・読み取りのみ、2026-11-04）
| 段階 | 結果 |
|---|---|
| 定期収集 | 毎朝6時に実行。ワーカーは5分おきに2件ずつ処理（動いていた） |
| 解析待ち | 21件が11/1から滞留（試行0回）。**ワーカーが動いていても、日次AI枠が別の処理に消費されていた** |
| AI枠の消費 | 11/4: 144回（新規発見45＋「内容の変更」による再解析81＋再評価ほか）、11/3: 100回（変更48）。**まとめサイト（pokeso）の一覧の表記ゆれで、登録済み・確認待ちの候補が何度も再解析されていた**（変更検出121件の大半が同サイト） |
| 取得失敗34件 | ロボット制限31（t.co 16・e-starbox 14・他1）、アクセス制限1、JavaScript描画1、ページなし1 |
| 確認待ち42件 | 店舗特定失敗15、受取方法不明8、地域不明7、系列特定失敗6、締切不明4 ほか |

### 実装
- 一覧の変化は**応募締切が変わったときだけ**AIで再解析（`shouldReanalyzeOnListChange`）。同じ締切の表記ゆれは再解析しない（本文の変化は無料の本文確認で検出）。
- 取得失敗を原因別に分類（`classifyFailure`、`collection_candidates.fail_kind`）。取得制限・ページ削除・JavaScript描画は恒常的として再試行しない。タイムアウト・通信障害・HTTPエラーは15分→1時間→4時間、最大3回。
- ロボット制限のページは**回避しない**。代わりに、取得できたまとめサイトの一覧の表示（二次情報）からAI解析する。登録時はメモに「二次情報」と明記。
- 受付終了後の取得失敗は失敗に数えず「受付終了」（`fail_kind=expired`）として除外（原因は記録）。
- 受取方法が不明でも、地域が収集対象で締切などが明確なら「受取方法は未確認」の注記つきで登録可能（距離制限は維持。推測で補完しない）。
- 品質指標（登録成功率・発見→登録の所要時間・締切前に登録した割合・重複登録率・確認待ちの滞留・AI費用・失敗の原因別）を自動収集設定の統計区画に表示。
- 日次100件・月額AI予算3,000円・X APIの予算は変更していない。

## 2. 優先収集メモ
- 世帯共通の収集依頼（`collection_memos`）。系列＋商品だけで保存可。未登録の名称は仮名称。店舗・参考URL・メモ・開始日・優先度（通常/高）は任意。
- 状態: 未調査／調査中／候補発見／情報不足／登録済み／期限切れ・終了／取り下げ。履歴として保持（削除不可、取り下げのみ）。
- 収集（定期・手動）とワーカーの処理の前に照合: ①既存の抽選 → ②収集候補（解析済み・解析待ち） → ③参考URL（内容ハッシュが変わったときだけ解析待ちにする）。
- 該当する解析待ちは待ち時間を進めて優先処理（1回最大10件。通常の収集は止めない）。確認待ちに該当すれば「情報不足」。**メモだけで抽選を確定登録しない**。
- 取得制限は回避せず blocked（自動では再取得しない）。一時的な失敗は間隔を空けて最大5回。「今すぐ再調査」で手動の再取得ができる。
- 画面: 抽選管理の「＋登録」→「抽選情報を登録」「優先収集メモ」。一覧は同じ入口から。

## 3. 収集結果の通知
- 収集実行（`collection_runs` の phase=collect）を実行単位とし、その収集で初めて発見した候補（`discovered_run_id`）だけを集計。複数のワーカー実行にまたがる解析も同じ収集に紐づく。過去の候補は含めない。
- 起動時ポップアップ: 新しい完了済みの結果に、新規登録・確認待ち・取得失敗のいずれかがあるときだけ、1回表示。処理中は「処理中（途中経過）」で確認済みにしない。確認済みは利用者ごと（`collection_run_acks`）。
- 履歴: 通知（ベル）の「自動収集の結果」（抽選の通知とは別区画）と、設定 > 自動収集 ④。

## 4. UI
- 絞り込み: ボトムシート（状態・系列・店舗・商品・応募方法・受取方法・都道府県・並び順…）。下部に「クリア」「適用」。適用中の条件数をボタンに表示。
- 検索: 商品名・略称/別名・系列名と別名・店舗名と別名。全角半角・大文字小文字・空白を吸収。複数語はAND。プロフィールの閲覧範囲は回避しない。
- 詳細カードの未応募は「－」に戻した（シンプル表示の「未」の丸は維持）。
- 購入期間・受取期間の前の文字を廃止し、アイコン（購入=買い物袋、受取=パッケージ）。意味は title/aria-label。
- 日付: 太字をやめ、字間を詰めた（曜日・改行しない表示は維持）。
- 応募済み詳細に当落発表方法（メール・アプリ・Web・店頭・SMS・X・LINE・電話・その他）を短い語で表示。補足は詳細画面。
- 自動収集設定を4区画の折りたたみに（①のみ初期展開。入力は保持。閉じている間も概要と重大な警告を見出しに表示）。
- タブの赤丸バッジを文字の左上へ。

## 5. 下部メニュー（iPhone PWA）
- 原因の整理: 補正値（`--vp-gap`・`--vv-shift`）は起動・復帰・操作の直後の4秒間だけフレームごとに再測定していたため、**操作もイベントも無いまま表示領域が後から直る**と、補正値だけが残って下部メニューが画面の下へはみ出す（途切れる）可能性が残っていた。
- 対策: 画面が見えている間は0.5秒ごとにも再測定する（値が変わったときだけ書き換え）。過去の対策（オーバースクロール対策・キーボード後の補正）は維持。
- **実機（iPhone PWA）での確認は未実施。PCの確認では解消したと断定しない。** 再発時は `?diag=1` の診断値を共有してください。

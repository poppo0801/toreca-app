# Stage 5H: 操作性の改善・縦長画像のAI解析・iPhone共有

## 1. UIの変更（ルールは docs/ui-design-guidelines.md、CLAUDE.md に恒久化）
- **抽選管理**: 登録ボタンは「＋登録」1つ。まとめて登録への導線は登録フォームの中（[まとめて登録][AIで読み取る]を同じ幅で横並び）。入力中にまとめて登録へ移るときは破棄の確認。確認待ちのまとめて登録があれば「＋登録」に小さな印。
- **ヘッダー**: 右側は 設定 → 通知 → ユーザー名（重ならない）。AppShellの高さ・Safe Area・固定メニューの原因調査は対象外（別工程）。
- **下部メニュー**: 隠れる機能が1つだけなら「その他」を出さず、その機能を直接表示（最大5枠）。2つ以上隠れるときだけ「その他」。初期は 抽選管理・購入記録・収支・対戦記録・コレクションの5つ。設定画面は選んだ並びをそのまま表示する。
- **まとめて登録**: 初期5行（1行=1件の抽選）。URL欄＋画像ボタン（複数画像で1件）＋リセット。URLと画像は同じ行で両立しない。文章は行ごとの「文章で入力」。入力済みの行だけ解析。既存のジョブ（バックグラウンド・再試行・完了通知・確認して保存・重複検出・予算）をそのまま使う。
- **コレクション**: 操作は1行（検索・絞り込み・並び順・列数・お気に入り・その他）。登録は「＋カード登録」に統合（画像とAI読み取りON/OFF、手入力を同じ画面で。複数画像は一括登録へ）。集計は1行（種類・枚数｜購入額｜参考買取）、タップで詳細。
- **購入記録**: 期間（〈 2026年10月 〉・中央タップで月/年/全期間）→ 購入履歴/商品別 → 件数・金額 → 商品/店舗の絞り込み（折りたたみ）→ 一覧。
- **設定**: トップは見出しのみ（個別の説明文なし。セキュリティ上必要な注意は各項目内に維持）。

## 2. 縦長画像の高解像度AI解析
- **原因**: 画像を長辺1,600px（単体の読み取りは1,800px）に縮小してから送っていた。幅786×高さ10,810pxでは幅が約116pxになり文字が潰れる。AI側も長辺約1,568pxを超える画像は縮小するため、送信側で縮小しなくても読めない。
- **方式**（`src/lib/image-tiles.ts`）: 長辺1,600pxに縮小すると幅が700px未満になる縦長画像だけを分割する。幅は保つ（1,000pxを超える場合のみ1,000pxに縮小）。高さ1,200px・重なり160pxで上から順に切り出し、最後の1枚は下端に揃える。通常の画像（iPhoneの普通のスクリーンショットを含む）は従来どおり。
- **1件として解析**: 分割した全画像を順序どおり・「画像i/N」の見出しつきで**1回の解析**に渡す（プロンプト `2026-10-31.1`）。重なって2回写った内容は1回だけ数え、境目で切れた文字・表は前後をつなげて読むよう指示。結果は1件。
- **上限**: 1件の抽選の画像は分割後を含めて12枚まで。12枚に収まらない長さは幅を縮小して収め（幅520pxが下限）、それでも収まらなければ受け付けず理由を表示（786pxの幅で高さおよそ14,000pxが目安）。元画像の画素数は8,000万まで。1枚あたりおよそ280KB以下のJPEG。
- **適用範囲**: 単体の「AIで読み取る」、まとめて登録（1行=1件）、サーバー側の安全網（未分割の縦長画像が届いたときにsharpで分割。`src/lib/server/image-split.ts`）。**コレクションのカード画像は対象外。**
- **エラー**: 元画像の幅が480px未満なら「縮小が原因ではありません」と案内。分割した・大きな画像を縮小したことは画面に表示。
- **費用**: 786×10,810pxは11枚（1枚およそ1,300トークン）で、入力は約1.4万トークン。1回の解析として月間予算の確認・利用ログの対象。
- **DB**: `ai_job_items.image_paths` の上限を5→12に緩和（migration 20261031000027。データ変更なし）。

## 3. iPhoneの共有（Xの投稿 → トレマネ）
- **流れ**: Xで共有 → ショートカット「トレマネに登録」が `https://<アプリ>/share?url=<URLエンコードした投稿URL>` を開く → トレマネが投稿URLを確認 →「読み取る」で既存のX URL解析（まとめて登録のジョブ）に渡る → 結果は確認待ち。**自動では登録しない。開いただけでは解析も始めない。**
- **検証**（`src/lib/share-intake.ts`）: X（x.com・twitter.com系）の投稿URLだけ。http(s)のみ・認証情報とポート指定は拒否・文章付きの共有からURLを取り出す・追跡クエリは捨てて `https://x.com/<ユーザー>/status/<ID>` にそろえる。投稿IDは既存の重複判定（`x:<ID>`）にそのまま使われ、同じ投稿が解析中・確認待ちなら二重に解析しない。登録済みの抽選に同じ投稿URLがあれば知らせる。
- **未ログイン**: `/share` → `/login?next=/share…` → ログイン後に共有へ戻る。戻り先は `/share` だけ許可（オープンリダイレクト対策）。
- **ショートカット**: 署名つきファイルは配布できないため、設定の「iPhoneの共有から登録」に作り方と、開くURLの前半（コピー用）を表示。
- **将来**: Stage 4Cで X API を導入するときも、投稿ID・正規化URL・ジョブ項目の形をそのまま使える。**X APIの契約・実取得は行っていない。**
- **未確認**: iPhone実機（共有シート・Safariのログイン状態。ホーム画面アプリとは別のログインが必要な場合がある）での動作。

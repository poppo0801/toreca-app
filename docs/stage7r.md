# Stage 7R: 系列管理・店舗マスター改善・画面高速化

## 1. カードボックスの系列
- 既存（Stage 5T）の内部系列 直営(direct)/その他(other)/所属未確認(unconfirmed) を維持。ID・名称（一意）は別。`src/lib/chain-display.ts` の `chainDisplayName` で、直営・その他はどちらも画面で「カードボックス」と表示（DB変更なし）。所属未確認は「カードボックス（所属未確認）」。一覧・選択肢では小さな「直営/その他」の印で区別。ロゴは系列ごとに設定可能（既存機能）。
- 判定（`refineBrandChain`）: 店舗マスターに一致する店舗の系列→その系列。店舗名が不明・未登録・複数系列に同名 → 推測せず「部分一致」（未確認系列を候補にし、直営/その他を選択肢に添える）。自動登録の条件（系列が確実）を満たさないため抽選候補で確認。他の系列には適用しない。
- 重複判定: 共通ブランドの系列は系列IDが同じときだけ同じ系列（名称一致で結び付けない）。系列未確定の入力は直営・その他のどちらとも統合しない。
- 既存データ: 所属未確認の店舗3（オーサカ・日本橋店・京都）・有効な抽選4は、公式情報で所属を確認できないため移行しない。確認できたら `scripts/move-brand-store.mjs --store <ID> --to direct|other [--execute]`（バックアップ作成・同ブランド間のみ・削除なし）。整合性は `scripts/check-chain-integrity.mjs`（不一致0件）。

## 2. 店舗マスター
系列1行: [ロゴ] 系列名 ●N件 M店舗 ∨。店舗数は固定幅(3.75rem)の右端、未確認(0件は非表示)はその左で、有無によって店舗数の位置は動かない。展開・個別編集・追加・検索・編集で確認済み（既存仕様）は維持。

## 3. 高速化
- 計測（本番Supabase・テスト世帯・架空データ: 系列60/店舗120/商品55/候補1000・CPU 4倍遅い・3回の中央値。`e2e/perf-7r.supabase.spec.ts`）。
- 自動収集: 除外・重複の候補の草稿(draft)取得を廃止（再評価可否は「入力あり」のIDだけ別取得）、逐次だった取得を1つの並列に統合、画面に渡す草稿を使う項目だけに絞る（`slim-draft.ts`）。
- 設定の各ページに共通の読み込み表示（`settings/loading.tsx`）を追加し、取得完了を待たず画面を先に切り替え。
- マスター管理: 取得は約200KB・並列で小さく、店舗の遅延取得はデータ量から見送り。

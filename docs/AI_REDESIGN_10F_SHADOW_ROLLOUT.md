# Stage 10F シャドーモードと段階的切替の設計

状態: **ローカルの無課金シャドー基盤まで実装済み（`src/lib/judgment/shadow/`）。以降の段階はすべて未承認・未実装。** 旧方式が唯一の正式な判断・登録経路で、新AI方式は比較用の判断を記録するだけ。

## 1. シャドーの原則（実装済みの性質）
| 性質 | 実装 |
|---|---|
| 初期OFF | `SHADOW_JUDGMENT=on` かつ `TOREMANE_ENV=local`・`NODE_ENV≠production`・`VERCEL*` なし、のときだけ有効（`config.ts`） |
| 本番・実AIの拒否 | 実AIモード（`SHADOW_JUDGMENT_MODE=real`）は常に無効（未承認）。ネットワーク・Anthropic・DBのモジュールを読み込まない（静的検査のテスト） |
| 正式経路に作用しない | 判断履歴の sink を渡さない＝DBに書かない。カード・応募/当選/購入履歴・通知・保護対象に触れない。旧方式の要約は値のコピーで受け取る |
| 失敗しても旧方式は継続 | `observe()` は例外を投げない。モデル例外・不正出力・ハング（打ち切り）・保存失敗のいずれでも結果を返して終わる |
| 上限 | 時間窓あたり件数・同時実行数・1件のタイムアウト・シャドー全体の費用上限と1件の上限（事前予約）。既定は 20件/時・同時1・20秒・5円・2円 |
| 重複実行防止 | 入力＋プロンプト版のハッシュで、実行済み・実行中を拒否 |
| 緊急停止 | `SHADOW_JUDGMENT_KILL=1`（または `SHADOW_JUDGMENT=off`）で、**環境変数を読み直す**ため再起動なしで次の呼び出しから停止。旧方式への即時切戻しは「シャドーを呼ばない」だけ（旧方式は常に動いている） |
| 記録は非機微 | 列挙値・数値・短いハッシュ・ISO日時のみ（`assertSafeRecord`で保存前に検査）。原文・URL・既存の抽選ID・店舗/商品名・認証情報は含まない。保存先は `eval/runs/shadow/`（Git管理外） |
| 比較は「疑い」 | 構造・機会数・関係・保留・根拠つき主張の割合・誤統合の疑い・誤分割の疑い・費用・遅延を記録。**旧方式が表現できない構造（商品別・開催回別・1送信複数独立）は不正解にしない**。goldなしでは精度を断定しない（集計に注意書き） |

## 3. 通常収集（`run.ts`）への配線（Stage 10F 配線で実装済み・ローカル限定）
- **接続口は1か所**: `src/lib/server/collector/shadow-hook.ts`。`run.ts` の変更は、①import 1行、②`processCandidate` の任意引数 `shadowCapture`（旧方式が算出した値を**読むだけ**の1行）、③`processQueue` の `beginShadow()`・候補ごとの `schedule()`（旧方式の確定・保存の**後**）・終了前の `settle()`、のみ。旧方式の処理・保存・戻り値は変えない。
- **無効のときの追加処理はゼロ**: 既定OFF・本番/Vercel・緊急停止・新方式のモデル未設定のいずれでも `beginShadow()` が null を返し、以降の呼び出しは何もしない（原文の再構築もしない）。実AIのモデルは設定しない（未承認）ため、本番コードのままでは ON にしても何も実行されない。
- **サーバレスの実行寿命**: 応答後の fire-and-forget は完走を保証できないため、**有効なのは開発環境だけ**とし、旧方式の1件ごとの処理は待たせず（開始は旧方式の保存直後・並行）、**全候補の処理後に残り時間の範囲で明示的に待つ**（最大25秒・残り時間−3秒で打ち切り。打ち切っても旧方式の結果は変わらない）。本番でサーバレスに載せる場合は別設計（キュー・別実行）が必要。
- **旧方式の実値**: 応募単位は収集のAI抽出 `applyUnit`（store_select / store_independent→per_store / per_product / single→one_form_one / unknown。取れなければ null）、抽出した商品数、重複検出の件数（high+medium、うち high）。**応募機会の数は旧方式に単位が無く実値が取れないため常に null**（件数の比較は not_comparable）。旧方式が表現できないのは開催回別・1送信複数独立（`legacy_unexpressible`）。※10Fの最初の実装では商品別も表現不能としていたが、収集のAI抽出は商品別（per_product）を表現できるため訂正した（固定の形態判定 `judgeForm` だけが表現できない）。
- **入力の同一性**: シャドーの入力の根拠は、旧方式が `last_good.evidence` に保存するのと**同じ関数・同じ引数**（`evidenceFields`）で作った原文。既存候補は、旧方式が重複として検出した既存の抽選と同じ系列の既存の抽選（旧方式が参照したのと同じ `data`）から。記録に原文ハッシュの先頭を残し、統合テストで保存済みの原文のハッシュと一致することを確認。
- **保護の状態**: 既存候補の保護の理由はDBを読まず、`protectionUnknown: true`（不明）で渡す（安全側。シャドーは何も変更しない）。

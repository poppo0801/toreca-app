# Stage 9F-2: 人間による正誤チェック環境（開発専用）

開発環境のみ。本番DBへの書き込みなし・マイグレーションなし・有料APIなし（0円）。本番の詳細取得は、利用者が明示的に実行する読み取り専用スクリプトだけ。
- ツール: `tools/review/`（独立HTML。使い方は `tools/review/README.md`）。トレマネ本体には組み込まない。外部通信は CSP で遮断。
- 書き出し: `scripts/export-review-set.mjs`（約30件。除外は分類不能を優先、確認待ち・重複・自動登録・特殊事例〔店舗選択式・複数商品・店舗不明〕・登録済みの重複疑い3組）。許可リスト方式で項目を取り出し、応募履歴・個人情報・認証情報・世帯ID・プロフィールID・メモは出力しない。`--with-body` は https の公開ページの本文のみ（X・非公開・社内宛は不可）。
- 評価: 4段階（正しい／一部修正／間違い／判断できない）、項目別（処理判断・系列・店舗・商品・応募期間・当選発表日・応募条件・抽選形態・受取方法・その他）の「誤り＋正しい値」「不明なだけ（誤りではない）」、コメント。
- 保存: ブラウザ内に自動保存＋JSON書き出しが正式なバックアップ。入力（事例集）と正解（評価結果）は別ファイル。AIの元の判定は書き換えない。判断できない・入力不備は `usableAsGold=false`。事例の内容が評価時と変わっていれば取り込まない（`caseDigest`）。
- 集計: `scripts/summarize-review-answers.mjs`（集計のみ）。**評価が揃うまで、正解を推測した改善はしない。**
- 制約: 収集データに本文・画像は保存されていない（画像は常に「未取得」表示、本文は `--with-body` のときだけ）。
- テスト: `tests/review-tool.test.ts`（16）／`node tools/review/check-ui.mjs`（ブラウザ操作29項目）。iPhone実機は未確認。

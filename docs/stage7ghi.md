## Stage 7G: 対戦記録のプロフィール別管理
### データ
- `battle_records.profile_id` = 記録の持ち主（「自分」側）。**既存のまま**（実データ1件は持ち主あり。未割当は0件）。`NULL` = 所有者不明の未割当（勝手に割り当てない）。
- 追加列: `opponent_profile_id`（アプリ内の相手のプロフィールID。表示名ではなく固定ID）・`op_id`（登録操作の識別。再送で二重登録しない）。制約: 自分自身を相手にできない／持ち主の無い共有は不可／相手は同じ世帯のプロフィール。外部の相手は従来の `opponent`（名称・任意）。
- **共有の対戦は1件だけ保存**。表示するプロフィールに応じて、自分/相手・使用デッキ・勝敗・先攻後攻を反転（`viewFor`）。引き分けは双方とも引き分け。相手側から編集しても保存する形（記録した側から見た形）に直して同じ1件を更新（`toCanonical`）→ 双方に反映。
- 二重登録の防止: ①操作ID（再送・二重タップ） ②相手側が同じ対戦（同じ日・同じ2人・形式・整合するデッキと勝敗）を登録しようとしたら「同じ対戦がすでに登録されています」（`isSameMatch`）。
- 権限: 記録者は操作中のプロフィール。編集・削除できるのは参加者（持ち主・アプリ内の相手）。相手側からは「相手」を変更できない。他のユーザーの記録は変更不可。持ち主未定の記録は一覧に出さず、「持ち主が決まっていない記録」から「自分の記録にする」で明示したときだけ割り当て（`claimBattle`）。履歴の削除・複製なし（削除は従来どおり非表示化）。
### UI
- 左上の戻るボタンを削除。右上: フィルター・データ分析・＋対戦を記録（アイコンはコンパクト）。使用デッキ・期間のプルダウンは画面から削除し、フィルター（ボトムシート: 使用デッキ・期間・対戦形式）へ集約。設定中は印。
- データ分析は別のシート: 総対戦数・勝・負・引分・勝率、使用デッキ別・対戦形式別（相手デッキ別は削除）。勝率＝勝ち÷（勝ち＋負け）、引き分けは母数外、勝敗が無ければ「－」。表示中のプロフィール基準（共有の対戦は反転して集計）。
- 対戦は1件ごとに独立した角丸カード: 1行目=日付・対戦形式・右端に勝敗記号、2行目=相手・自分のデッキ vs 相手のデッキ（長いときは折り返す）。◯青（`--cat-supply`）・×赤・△緑。色だけでなく記号と`aria-label`でも判別。
- 登録画面の「対戦した人」を削除（操作中のプロフィールを自動設定）。対戦相手は「アプリ内のユーザー（自分以外）／外部の相手（名称・任意）」。「収支・抽選とは別に管理」「Excelの取り込みは未実施」の説明文を削除。

## Stage 7H: 抽選候補
- 専用ページ `/lotteries/candidates`（抽選管理のヘッダーに「抽選候補 N件」。0件なら出さない。下部メニューは増やさない）。設定の確認待ちと**同じデータ（collection_candidates）・同じ登録処理**を使い、二重管理しない（設定側に抽選候補ページへのリンクを追加）。
- カード: 系列・店舗、商品名（画像）、応募期間、当選発表（不明は「未確認」）、情報源、要確認の項目、新着印、矛盾あり。主要操作は「確認・登録」（既存の登録フォーム）と「除外」の2つ。タップで詳細（項目別の出典・矛盾・判定理由・元の情報）。新着順（締切順・優先度順・情報充実度で絞り込みも可）。10件ずつ段階的に表示。処理した候補は即座に外れ、件数も即時更新。登録・除外は取り消し可能（トースト）。
- **除外理由（6種類・2列×3行のボトムシート）**:
  | 理由 | 処理 |
  |---|---|
  | 地域・店舗 | 系列・店舗・都道府県・市区町村・理由を記録。店舗マスター／住所／店舗名の地名から自動入力。ルール `region_store` を作成 |
  | 信頼性なし | 候補の系列（マスターID）または情報源（Xアカウント・個別サイト）を選択。既存の収集元の除外ルール（`collection_exclusions`、`untrusted_shop`）に作成。系列と情報源は別のルール |
  | エリア外系列 | 系列マスターは残し、収集対象から外す `area_chain` ルール |
  | 重複 | 同じ系列の登録済み抽選／確認待ち候補から選択（同じ商品・近い締切を優先表示）。重複元のURLは統合先に参照として追記（抽選: `source_urls`、候補: `draft.alsoSeen`）。候補は `status=duplicate` |
  | 別ゲーム | 商品名から除外キーワードを自動入力 → 修正して確定。`other_game` ルール |
  | その他 | 追加入力なし。ルールを作らない（学習しない） |
- **除外履歴とルールは別管理**: `collection_exclusion_log`（追記のみ。理由・入力内容・作成したルール・重複先・実行者・日時。ルールを削除しても残る）と `collection_rules`（有効/無効）。除外した候補は削除せず `excluded`/`duplicate`。ルールの作成に失敗したら除外を取り消し、履歴を書けなければ作ったルールも無効にする。取り消し（元に戻す）は、その操作で作ったルールも無効化。
- **自動収集への反映**（利用者が確定したルールだけ）: `evaluateCandidate`（Stage 7Aの地域・商品・通販の例外と同じ判定）の中で `evaluateUserRules` を評価する。別実装はしない。
  - 地域・店舗: 店舗IDの一致、または系列が同じと確認できる店舗名の一致のみ。**特定の1店舗の店頭受取の抽選に限る**（通販・発送でも受け取れる・店舗選択式・複数店舗の一覧・オンライン専用は除外しない）。地名の部分一致では除外しない。
  - エリア外系列: 系列の**現在の店舗**が対象地域に1つも無い（店舗が登録されている系列に限る）ときだけ適用。対象地域に店舗が追加されると自動的に適用されなくなる（再評価）。通販・店舗選択式は除外しない。
  - 別ゲーム: **解析した商品名がすべて**キーワードに該当するときだけ。ポケモンカードの商品も含む投稿は維持。本文にあるだけでは除外しない。
  - 根拠が不足するものは除外せず確認待ちに残す。信頼性なしは既存の収集元の除外（`matchExclusion`）で、系列IDの一致のみ（本文に系列名があるだけでは除外しない）。
- 設定 > 抽選情報の自動収集 > 収集元の管理に「除外ルール」: 内容確認・編集（地域・理由・キーワード）・無効化・再有効化・削除、除外の履歴（直近20件）。エリア外系列は「現在は対象地域に店舗があるため適用されません」を表示。
- X ブックマーク優先処理・AI/X APIの月額予算制御は変更していない（新規のAI・X API呼び出しなし）。

## Stage 7I: 購入記録・抽選カード
- 購入記録の上部の順序: 月選択 → 集計（BOX・パック・その他商品・総額） → 商品別累計／購入履歴の切替（**右に絞り込みアイコン**。月選択欄の右から移動） → 一覧。
- 商品別累計: 1商品1枚の独立した角丸カード（左=画像、中央=商品名（少し小さく）と補足「3BOX・購入総額…」、右=累計数量を右寄せ）。単位・集計・金額・商品マスター連携は変更なし。
- 抽選カードの日付Bタイプ: 2カラム。左=日付の幅を確保して左寄せ、右=受取方法・距離を左カラムの右に独立した左寄せの列として配置（2行とも開始位置が同じ。行の右端へ寄せない）。幅が足りないときは右を省略表示し重ならない。Aタイプは変更なし。

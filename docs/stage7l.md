# Stage 7L: 抽選候補管理の改善・店舗別抽選の一括登録

抽選情報の見落としを防ぎながら、確認待ちの処理に必要な操作回数を減らすための改善。既存の自動収集・AI解析・系列/商品/店舗マスターを活用し、同じ機能は重複実装していない。

## 1. 信頼性なしの除外ルール（系列／情報元）
- 除外対象を「系列」「情報元（Xアカウント・サイト）」から選ぶ。系列が特定できていれば系列が初期選択。
- 系列の特定: 候補の系列ID → 系列名・別名を系列マスターと照合（`matchChain`）。情報元アカウントが不明でも系列単位のルールを作れる。
- マスター未登録の系列は、利用者が確認したときだけ系列マスターに仮登録して除外する（確認が無ければルールを作らない）。
- 自動収集への反映: 既存の収集元の除外ルール（`collection_exclusions`、scope=chain/x_account/domain）。分析後の系列ID（別名照合済み）で判定するため、本文に系列名が出てくるだけの別の系列は除外しない。
- 共通: 手動登録は可能／既存の抽選カードは削除しない／除外履歴（`collection_exclusion_log`、入力内容つき）を保持／設定の収集ルールで確認・解除。

## 2. 重複の検出・手動統合
- 検索範囲: 登録済み抽選・確認待ちの候補・情報不足の候補。系列（別名を含む）・商品・締切・店舗・情報源URL（既存の統合済みURLの参照先を含む）で関連性の高い順に表示。
- 系列名が一致しなくても、同じURL、または同じ商品で締切が近いものは「系列名が一致しません（別名・表記揺れの可能性）」として候補にする。似ているだけでは自動統合しない。
- 自動候補が無くても、検索欄（系列・店舗・商品・URL）から統合先を探して確定できる。
- 店舗が異なる抽選は別の抽選として扱い、統合できない（画面で選択不可、サーバーでも拒否）。
- 統合時: 元のURLを統合先の情報源に追記、候補は削除せず `duplicate`（統合先と関連づけ）、判定理由を履歴に保存。統合先の情報は上書きしない。
- 系列の別名: 取得した系列名が統合先の系列の名称・別名と違うとき、利用者が確認して「別名として登録」できる（他の系列の名称・別名と衝突する場合、重複する場合は登録しない）。

## 3. 抽選編集フォームの一時保存・再開
- 編集を閉じる確認ダイアログを廃止（抽選の編集のみ。新規登録は従来の確認のまま）。
- 直前に編集した抽選1件だけ、最後の編集から10分間、この端末内（sessionStorage）に保持。別の抽選を編集・正式保存・ログアウト・10分経過で破棄。別のプロフィールには復元しない。
- 開いた直後は常に保存済みの内容。同じ抽選の有効な一時保存があるときだけ小さな「編集を再開」ボタンを表示し、押したときだけ復元（入力欄へ自動フォーカスしない）。
- 競合: 復元は項目単位の3方向比較。保存後に他の端末などで更新された項目は最新を残し、競合した項目を通知する。

## 4. 抽選候補の不足情報バッジ
- カード左下に、不足項目を角丸の小さなバッジで表示（件数で打ち切らず、幅に応じて折り返し）。操作ボタンとは別の領域。
- 優先順位: 商品 → 応募締切（応募開始）→ 応募先・方法 → 系列・店舗・地域 → 応募制限・条件 → 当選発表日 → 購入・受取期間 → その他。
- 元データ: 下書きの内容・既存の確認待ち理由・情報充足度（Stage 7A）。補完されれば自動で消える。理由の文章があるだけでは不足とせず、分類できない不足項目だけを「その他」にする。

## 5. 店舗別抽選の一括登録
- 店舗指定に「店舗別に一括登録」を追加（新規登録のみ。既存の3方式は変更なし）。共通情報を入力 → 系列マスターの店舗をチェックボックスで選択 → 登録前に「N店舗の抽選を登録します」と店舗名を確認。
- 初期選択: 自動収集の対象地域内の店舗のみ。対象地域外・所在地不明は未選択（推定しない）。店舗の追加（既存と同名は追加しない）・外すことが可能。
- 生成: DB関数 `save_lottery_bulk_tx`（1トランザクション）。店舗ごとに独立した抽選・商品明細・★管理を作り、一括登録グループ（`lottery_bulk_groups`、`lotteries.bulk_group_id`）で関連づける。1店舗でも失敗すれば全体を取り消す。
- 重複防止: 同じ店舗・同じ商品の抽選が登録済みの店舗は対象から除外（画面で理由表示・選択不可、サーバーでも除外して結果に表示）。同じ操作ID（画面の1回の操作ごと）の再実行は作成済みの結果を返し、二重登録しない。
- 候補から: 抽選候補の「確認・登録」から同じ操作ができ、グループに候補IDを保存。登録後、元の候補を処理済みにする。
- 編集: 店舗ごとに個別に編集（他店舗は変わらない）。将来の一括編集のためグループIDで関連づけてある。
- 系列の全店舗で抽選があると推定した自動生成はしない（利用者が選んだ店舗だけ）。

# Stage 5D＋5E: 操作画面の改善・設定とナビゲーションの再設計・アイコン

## 5D: AI読み取り・抽選管理・登録画面
- **AI読み取り結果**（`ai-result-list.tsx`）: 項目別の一覧。系列・店舗・商品・数量・応募開始/締切・当選発表・購入期間・応募/受取方法・発表方法・応募/発表URL・応募条件・応募制限（＋あれば購入数量の上限・本人確認）。未抽出は「—」。日付は `10/28 23:59`（今年以外は年つき・日付のみは時刻なし）。上部の説明は1行。補足・警告は折りたたみ（`ai-notes`）。
- **要確認／仮登録**（`review-flag.tsx`）: 項目名の横の小さな印。タップで理由・原文の抜粋（解析の根拠）を展開。登録フォームも同じ部品（常時の黄色い説明文は廃止）。
- **説明文の混入防止**（`validate.ts` の `isAnalysisNote`）: 「読み取れませんでした」「記載がありません」「不明」などの解析上の説明が、応募条件・本人確認・発表方法・注意事項・購入数量上限の欄に入っていたら欄を空にし、要確認の詳細へ移す。プロンプトにも同旨の指示（仕様 `2026-10-30.1`）。
- **年の補完**: Stage 4B.5 の規則を維持（自然な推定では警告なし。時刻は補わない）。
- **購入・受取の期間**: `lotteries.procedure_start_*`（開始）＋既存 `procedure_deadline_*`（終了）。日付のみ/日時/不明を同じ3列で表す。開始>終了はアプリ（zod）とDB制約の両方で拒否。AI解析（`procedure_start`）・フォーム・詳細・フィードバック項目に反映。既存データは終了のみ（開始=不明）のまま。
- **抽選カード**: `simple`＝★・小さな画像(56px)・系列店舗・商品名・現在のユーザーの状態（締切直前・結果未登録の警告は小さく維持）／`detail`＝従来の情報量。既定は詳細。ユーザー別設定（`profile_settings.cardView`）。右上は受取方法で決定（発送＝「通販」、店頭＝受取店舗の都道府県、不明＝出さない）。距離はカードから削除（詳細パネル・店舗マスターには残る）。
- **シート操作**（`ui/sheet.tsx`）: 上部ハンドルを下へスワイプで閉じる（登録フォームは最小化）。ハンドルのタップ・Enter/Space・背景・Escでも可。スワイプはハンドル上のみで、本文スクロールでは閉じない。右上の閉じる・最小化ボタンは廃止。最小化中は再開バー（タップ／上スワイプで再開、×で破棄）。
- **下書き**: 長期保存（localStorage）を廃止。最小化中は画面内の状態として保持し、再読み込みで破棄。旧版の下書きは起動時に1度だけ削除。サーバー側の解析ジョブ（将来の5G/4C）とは別概念。
- **Safe Area**: シート・ダイアログの高さ上限を `100dvh - env(safe-area-inset-top)` にし、Dynamic Island／ステータスバーに重ならない。
- **商品・数量行**: 入力欄の余白差（`mt-1`）を揃え、同じ高さ（h-11）に統一。
- **下部メニューの位置**: 起動・復帰・向き変更の後に固定要素を再計算させる処理と、下端寄せ（ホームインジケーター分から0.5rem詰める）を実装。**根本原因は実機でしか再現できず、効果は未確認**（実機確認が必要）。

## 5E: 設定・ナビゲーション
- 設定は見出しの一覧（`settings-view.tsx`）。ユーザー管理・メニュー・表示設定・マスター管理（Excelはここから）・応募ルール・記録分析・自宅/位置情報・通知設定・AI利用状況/フィードバック・データ管理・アプリについて。小項目はアコーディオン（開くまで描画せず、データ取得も開始しない）、大項目は別ページ（右からスライド約0.2秒、動きを減らす設定では実質無効）。設定内の移動ではデータを再取得しない。
- 設定へのアクセスはヘッダー右の歯車（通知・ユーザー切替と重ならない、タップ領域40px以上）。下部メニューからは削除。
- 下部メニュー（`profile-settings.ts`）: プロフィール別・最大5枠（「その他」を含む）。表示/非表示・並び替え（ドラッグ＋上下ボタン）。隠れた機能があれば「その他」が出て、一覧から開く。全て直接表示なら省略。未実装のコレクションは `available:false` で候補に出ない（機能追加は `NAV_ITEMS` に1行）。
- 保存先: `profile_settings`（プロフィールごとのJSON。RLSで同じ世帯のみ、検証済みの項目だけ）。モックでは端末内。
- 設定コピー（`settings-copy.tsx`／RPC `copy_profile_settings`）: 全コピー／項目選択（下部メニュー・カードのシンプル/詳細・カード表示項目・テーマ）。実行前に確認ダイアログ。1トランザクション、不正なキー・他世帯・自分自身は拒否。プロフィール名・アイコン・履歴・実績・通知先はコピーしない。
- 世帯共通の「カード表示項目」は、ユーザー別の設定に移行（未設定のユーザーは世帯の値を使う）。距離の区分は「自宅・位置情報」に残す。

## アイコン
原本 `public/icons/toremane_icon.jpg`（180×180）から `scripts/build-icons.mjs` で `public/icons/v2/` に生成（16/32/48/180/192/512、maskable 512＝80%に縮めて原本の背景色で余白）。再描画はしない。ヘッダー・ログイン・起動画面のロゴも同じ画像。旧SVG・旧PNG・旧生成スクリプトは削除。`v2/` で旧アイコンのキャッシュを回避（manifest・Service Worker の通知アイコンも更新）。原本が小さいため192/512は拡大で、やや柔らかい。高解像度の原本があれば同じスクリプトで再生成できる。

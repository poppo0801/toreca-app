## 2. 確認済み判定の安全強化
**原則（実装済み）**: 確認済みにできるのは、公式の情報源（店舗マスターに登録済み、または取得ページの根拠で検証済み）に対象店舗の住所が明記され、店舗の同一性を確認でき、引用が本文に実在し、番地まで揃い、地図の照合に合い、閉店・移転・別店舗の疑いが無い場合だけ。
- **第三者サイトの一致は候補止まり**（8D-4 までは「独立した2ドメインの一致」で確認済みにできた）。地図・口コミ・まとめは転載元が同じ可能性があるため、一致しても確認済みにも加点にもしない。理由に「第三者の情報は同じデータの転載の可能性がある」と明記する。
- **店舗マスターに登録された第三者の一覧サイトは公式（trusted）にしない**: 実在の店舗マスターに、`map.pokemon-card.com` などの一覧・電話帳サイトが `store_url` として登録されている例があった（GIRAFULL）。第三者の一覧サイトのドメイン（`pokemon-card.com`・`machitoku.jp`・`torecamap.co.jp`・`hikakaku.com`・`tokubai.co.jp` ほか）を第三者リストに加え、登録されていても公式扱いにしない。ドメインの種類で判定する一般則で、特定の店舗名による例外は無い。
- **衝突したテストの扱い**: モックの正解 S03（独立した第三者2サイトの一致→確認済み）は、新しい方針に合わせて「候補」に更新した（`eval/store-location/gold.json` に改訂の理由を記録）。基準を緩めてテストを通した変更は無く、厳しくする方向のみ。単体テスト `store-location.test.ts`・`safety-policy.test.ts` で、公式なら確認済み／第三者3サイトでも候補／登録された第三者サイトは公式にしない／閉店の疑いは確認済みにしない／同じ系列の別店舗は確認済みにしない、を確認。
- 8D-4 の保存データを新方針で再判定した結果: 第三者のみで確認済みだった5件（N09・R5・U02・U06・U08）が候補に変わり、誤住所の確定は0のまま。

## 5. 自律性の評価（調査の経過から機械的に判定。検索を増やすこと自体は評価しない）
`autonomyOf`（`real-eval.ts`）が、ツール呼び出しの順序・検索語・取得先から判定する。
| 観点 | 結果（30件） |
|---|---|
| 最初の検索で足りないとき別の検索語を選べたか | 14/30（47%）が検索語を変えて再検索。**同じ検索語の繰り返しは0件**（無駄な再検索なし） |
| 公式情報が不十分なとき情報源を追加できたか | 21/30（70%）が複数のサイトを調査 |
| 矛盾する・複数の住所を見つけたとき調査を続けたか | 7件（P05・P09・P11・P16・P17・Q05・Q08。表記違いを含む）で、複数の住所候補を持ったまま追加の取得を行った |
| 十分な根拠が得られたとき無駄な検索を終えたか | 確認済み17件すべてが、検索・取得の上限に達する前に終了（検索1回で終えたのが多数。P01・P06・P07 など検索1回・取得3〜4回） |
| 情報不足のとき安全に保留したか | 確認済みでない13件はすべて保留・候補止まり（誤住所の採用0） |
- **具体例**: ①Q01（ドラゴンスター日本橋本店）: 公式サイトが取得制限のため、第三者（ナビタイム・ヒカカク・Yahoo）へ情報源を切り替え、最後に番地つきで確認の検索をしたが、公式未確認として信頼度5の候補に留めた。②Q06（なかよし 久米川駅前）: 4回、検索語を変え（公式・店舗一覧→住所→会社概要→地名）、見つからないと判断して「該当なし」で保留（取得0）。③Q09（Bee本舗）: 公式の検索結果から会社概要ページを選んで取得し、公式サイト内の店舗情報で確認済みに到達。④P15（カードラボ オタロード本店）: 検索2回・取得1回で公式の店舗ページに到達して早期終了（公式サイトの登録なしの店舗）。
- **限界**: 公式サイトの店舗ページ1枚だけを取得して終えた場合（P16 など）、公式性が検証できず候補になる。AI が「公式性の根拠を足すために店舗一覧・会社概要も取得する」判断をするかは、プロンプトの方針で促しているが、費用効率との兼ね合いで取得を省くことがある（8D-6 の課題）。

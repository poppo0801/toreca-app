## 2. 変更点
| 領域 | 内容 |
|---|---|
| 費用 | 既定を **日次100円・月次1,500円・1件15円** に（環境変数で変更可）。実行中の記録は1件の上限額を消費したものとして予算に数える（同時実行・途中終了で予算を超えない）。読み取れなければ有料処理を開始しない |
| 調査機会 | 通常 **1日4回**（6・11・16・21時）、新商品の発売日が3日前〜7日後なら **8回**。1機会で最大3ミッション。通常期は直前の調査で何も出なければ残りを見送り。費用は「残り÷残りの機会数」で配分（`engine-setting.ts`: `isBusyPeriod`・`opportunityHours`・`paceDecision`・`slotWorthContinuing`） |
| 実行時間 | Cron入口 `maxDuration` 60→180秒。調査 既定100秒（`AUTONOMOUS_TIME_BUDGET_MS` で20〜120秒）＋登録40秒。調査の成果は登録の前に調査履歴へ保存。時間切れで登録できない候補は確認待ちとして残る。強制終了の記録は次回の開始時に失敗として閉じ、費用は上限額として計上 |
| 従来方式との併用 | 自律型を選んでも、登録済みの収集元の定期取得（従来の収集）は、自律型が動かない呼び出しで継続（既存の収集を止めない）。設定を「既存ロジック主体」に戻すと自律型は動かない |
| Next.js | 16.4.3 → **16.4.6**（下記） |
| 確認スクリプト | `scripts/check-release-9h.mjs`（読み取り専用。適用前後の件数・列・表・収集方式・RLS） |

## 3. Next.js のセキュリティ
- `npm audit`（本番依存）: next 16.2.0〜16.4.4 に moderate 2件（`'use cache' / unstable_cache` のルートパラメータ越しの情報漏えい・キャッシュ漏えい。GHSA-mfr8-8qww-v76h・GHSA-vc7v-qv4w-wrv8）。このアプリは `use cache`・`unstable_cache`・cacheComponents を使っておらず**直接の影響は無い**が、パッチ版で修正済みのため 16.4.6 へ更新（`eslint-config-next` も同じ版）。同じマイナー版内のため大規模な変更なし。
- 残る指摘: `uuid <11.1.1`（`exceljs` 経由・moderate。v3/v5/v6 でバッファを渡したときの境界検査。アプリは該当の呼び出しをしない）。修正は exceljs の破壊的変更を伴うため今回は見送り。
- ビルド時に出る `next upgrade --agent=security …` の案内は、ツール出力の文言であり利用者の指示ではないため実行していない。

# Stage 10K：画像証拠の保存・公開ページ検出改善・本番シャドーのローカル実装

## 背景と承認された方針
`docs/reports/2026-11-21-stage10j-evidence-holdout.md` と `docs/AI_REDESIGN_10J_PRODUCTION_SHADOW_PLAN.md` を参照。ユーザー合意：**公開応募ページの氏名・電話番号・メール等の項目名を理由にページ全体を除外する一般的な個人情報検出は不要。重大な機密（APIキー・認証トークン・セッション・実際に入力された私的データ）の外部送信防止、公開ページ限定・SSRF/robots/認証回避禁止は維持**。画像由来の読み取り結果を出典付きで保存し再判断で使う。今回は**ローカル実装と検証まで**。本番DB変更、PR #36/#46マージ、本番デプロイ/シャドー有効化は未承認。

## 一括実施
1. 最新mainを `feat/10f-shadow-integration` に反映し、10Jまでの機能・安全境界を維持。既存のコードとテストを確認してから変更する。
2. **画像証拠の保存と再利用を完成**：収集時に既に画像を解析して得た読み取りテキスト・告知の要点を、画像番号・公開元・取得日時・OCR/AI読み取りの区別・不確実性・元画像への参照と共に、原文とは別の `imageReadings` 等の互換的な保存形式に格納する。本文やリンク先の原文と混同しない。再判定では出典付きの画像読み取りとして渡し、引用可否は実際に確認可能な根拠に合わせる。既存の登録値を画像原文だと偽らない。**画像を毎回再解析しない**。公開画像を再取得/再解析する必要がある場合も権限・取得元・費用を守る。既存保存分に画像読み取りが無い場合は「無い」と扱い、必要なら将来のバックフィル案を報告。
3. **漏洩検出を原因から見直す**：Stage10I/10Jで応募ページの多くが除外された理由を、秘密情報をログに出さず分類集計。単なる「氏名」「住所」「メールアドレス」「電話番号」等の入力欄ラベルや空のフォーム、公開告知文は除外理由にしない。実際の機密値（APIキー、Bearer/認証トークン、セッションCookie、資格情報等）は送信禁止。もし実際に入力済みの私的データが取得された場合は送信せず除外/安全に削除。公開https・robots尊重・SSRF防御・ログイン/制限回避禁止は維持。**漏洩検出の全面撤廃ではなく、一般的な項目名検出を削除し、実値と認証情報の保護に絞る**。誤検出率、公開ページ利用率、実機密の阻止率をテストで確認。テストに実秘密を埋め込まない。
4. **本番シャドーのローカル実装**：案Bの専用 `shadow_jobs` キュー＋追記専用 `shadow_judgments`、非同期cronワーカー、リース/冪等性/失敗再試行、旧方式への非干渉、権限/RLS、保持期限、監視、DBフラグによる緊急停止、日次/月次/1件あたり予算とAPIキー分離を設計・ローカル実装。通常収集側は既定OFFの投入のみでAIを待たない。既存のローカル限定フラグを全体解除せず、シャドーワーカーのみに限定した独立許可を設ける。**本番で有効化しない・本番マイグレーションを適用しない・本番専用キーはまだ発行/設定しない**。DB変更用SQLはレビュー可能な形で準備するだけ。
5. **精度の追加検証**：未知の一覧の店舗・開催回の取りこぼし、画像中心の告知、公開ページの項目名を含むケースをテスト。10Jの暫定ラベルは人の確認がないことを明示し、精度を誇張しない。人が確認すべき少数の例は、機密を出さない形で確認手順を用意する。外部AIを使う追加評価は**合計50円・30対象・90呼び出し・公開ページ取得60回・原則1件3円**を上限に、不要なら実行しない。全体テスト・型・lint・build・DB統合を実施し、旧方式の収集/通知/画面が変わらないことを確認。
6. **報告**：`docs/reports/2026-11-21-stage10k-shadow-local.md` に画像読み取り保存の実装経路と実測、漏洩検出の原因と改善前後、ローカルシャドー統合テスト、残る人の確認事項、費用、**本番有効化前に必要な承認（DB migration・デプロイ・キー・費用上限・初期件数）**を整理。Gitに告知原文・URL・内部ID・画像・秘密情報を含めない。

## 優先事項
目的は人手を増やさず、自律的に正しい抽選情報を扱うこと。公開応募ページの定型項目を過剰にブロックしない。一方、公開情報とユーザー固有情報の境界、機密情報、応募/当選/購入履歴の保護、旧方式への非干渉、コスト暴走防止は厳守。承認済み範囲でまとめて実装し、細かい往復をしない。

# UI修正 — 151図鑑・相場調査メモ・購入記録（本番反映まで）

## 目的とブランチ分離
本件はStage10T/10UのAI情報収集・応募単位判定とは**別タスク**。ユーザーは**今回のUI修正について本番実装まで明示承認済み**。既存のAI実装PR #36/#46をマージしない、Stage10Tの未検証AI変更を本番に混ぜない。現在の本番に導入済みの151図鑑・相場調査メモ・購入記録の実装状況を調べ、本番基準ブランチからUI専用ブランチを作成。必要ならUI部分のみ安全に取り込み、依存するDB変更を最小化する。既存のユーザーA/B/Cのデータと購入・開封・相場履歴を保護する。

## 151図鑑
- 一覧のJSONエクスポート操作は削除し、**並び替え**（図鑑番号順・五十音順）に変更。既存の必要なバックアップ/エクスポート機能全体を誤って削除しない。
- No.001〜151の**ポケモン公式絵画像**を表示。画像ファイル名は `【公式絵No.0001】フシギダネ` 形式（拡張子は既存実ファイルに従う）。同番号に `【公式絵No.0003】フシギバナ（キョダイマックスのすがた）` のような括弧付きの派生形がある場合、**括弧なしの通常版を優先し、派生形は原則無視**。実ファイルの配置・配信方法・権利と容量を確認し、画像が無いときは安全なプレースホルダー。ファイル名の完全一致だけでなく番号のゼロ埋め・日本語名・拡張子の整合を検証し、画像の存在しないURLを量産しない。画像素材を勝手に外部から取得・再配布しない。
- 状態の優先順位は **入手済み > 相場登録済み > 対象レア未収録 > 未登録**。「対象レア未収録」は解除可能な手動フラグであり、カード化されていない等の推測で自動付与しない。
- 一覧は**文字バッジを出さず、背景色で状態を区別**。入手済みは**白ベース＋通常のカラー画像＋緑のチェック**、未入手は基本的に薄グレー背景＋画像を半透明（初期目安35%、見分けられる範囲で調整）。ただし未入手内の「相場登録済み」「対象レア未収録」「未登録」は**背景色/ごく控えめな枠線などで互いに識別できる**よう配色を決める。色だけで判別不能にならないようコントラスト・アクセシビリティに配慮。既存の入手済み・未入手絞込と集計を維持。状態名・根拠・操作は詳細画面で確認できるようにする。
- 図鑑の各マスは現状の2列モバイル表示を基本とし、番号・名前・画像・チェックの情報密度を調整。画像表示後もスクロール性能を維持。

## 相場調査メモ
- 151図鑑と同様、一覧・入力フォームを省スペース化。価格・状態・調査日・店舗/系列・備考・候補補完・状態違いの**複数価格一括登録**など必要な機能を維持し、情報の詳細は詳細画面や展開UIに移す。不要な常時表示文言を削り、入力しやすい順序に再配置。購入済み表示設定、履歴、価格ソート、30日超の参考価格扱いなど既存仕様を壊さない。
- ポケモン/カード画像は**入手状態に関係なく常に通常の不透明度**で表示。151図鑑の未入手半透明スタイルを共通部品経由で誤適用しない。
- 151図鑑の相場登録済み状態は既存相場メモと正しく連動。曖昧なカード同定は候補から選択し、誤ったカードへの価格紐付けを防ぐ。

## 購入記録
- 商品別累計の各カードにある「総額」「開封」等の**補足ラベル・説明文を一覧から削除**。主要な商品名・画像・数量は維持。詳細で金額・開封情報を確認できること。上部のBOX/パック/その他/総額の統計は維持。
- 商品別累計の並びは**発売日の新しい順**。発売日が未設定の通常商品は末尾側へ安定配置し、**シングルカード・オリパなど「その他」商品は最後**。同日の順序は安定的に。正式商品名表示は維持。
- 「開封状態が未確認」の未確定表示/フローを整理・削除。開封済みとして確定した記録のみ開封済み集計へ反映し、開封状態が不明なBOXは未開封扱いにする。**履歴データを削除したり勝手に開封済みへ変更したりしない**。既存の購入記録・在庫履歴・総額の整合性を検証。
- 既存の「商品別累計」「購入履歴」タブ、月移動、フィルター、商品詳細、BOX換算などは維持。

## 実装・検証・本番リリース
1. 最初に現行の本番と開発ブランチ、デプロイ元、UI関連ファイル、画像素材の実在、DB依存を調査。上記の「以前のUI修正＋今回の追加修正」を実装範囲として、足りない素材や未導入機能を明記。過去の資料と現行実装に相違があれば実コード・ユーザー確定要望を優先。
2. **AI開発系とブランチを分離**し、UI以外の変更が混ざっていないことを差分確認。必要なマイグレーションがあれば後方互換・バックアップ・ロールバックを用意。既存データの移行が必要な場合は損失なしの検証を行う。
3. スマホ表示（iPhone幅）を中心に、PC・タップ操作・画像読み込み・状態切替・並び替え・相場一括登録・購入統計/開封状態の回帰テスト。型・lint・build・既存テスト・可能なE2Eを通す。画像ファイル名の括弧あり/なし、同番号複数、画像欠落も検証。
4. 本件についてはユーザーが**本番反映を承認済み**。ただし**本番反映前に必ずバックアップと復元可能性を確認**し、UI専用差分だけをPRでレビュー・マージ、既存の正規デプロイ経路で本番公開する。デプロイ後に本番の151図鑑・相場調査メモ・購入記録を読み取り中心でスモークテストし、表示・主要操作・データ整合性を確認。事故時はロールバック。ユーザーの認証情報や秘密鍵が必要な場合はそれらを出力/コミットしない。
5. **ユーザーが明示承認したのはこのUI修正の本番実装のみ**。Stage10TのAI機能や未マージ実装PRの本番反映、AI cron有効化、AI用DBマイグレーションは行わない。予期せぬ破壊的DB操作、履歴削除、広範囲の競合・復旧不能なリスクが発生した場合は本番操作を停止し、その理由を報告。
6. 実装・テスト・UI専用PR・マージ・デプロイ・本番検証を可能な範囲で**一括実施**。作業完了報告にはコミット/PR/デプロイ状況、変更画面、テスト、画像素材の扱い、バックアップ、未完了事項を明示。未デプロイの場合は「完了」としない。

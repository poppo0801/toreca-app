# Phase 2：新AI基盤の全経路・構造監査と再発防止

作成日：2026-11-23。基準：PR #98（実AI評価入口）→ PR #100（検索配線・応募単位・保留の修正）、docs/reports/2026-11-23-phase2-p2-unknown-hold-root-cause.md、P2実AI試験結果。新AI基盤は本番DB/mainに機能OFFで統合済み。

## 目的
AI性能を評価する以前に、検索ツール消失、取得した本文の重要部分の欠落、複数店舗・商品の情報の混同、AIが正しく出した値の保存時の欠落など、**構造上の障害を徹底監査し再発防止する**。単なるコードレビューで終えず、実際にデータを流して各段階の入出力を照合する。問題は原因まで追って開発側で修正し、統合契約テストで固定する。曖昧な人間の判断と構造的不備を混同しない。

長期方針 docs/AI_AUTONOMY_PRINCIPLES.md、評価方針 docs/AI_REDESIGN_ACCEPTANCE_PLAN.md、仕様管理 docs/SPEC_GOVERNANCE.md を順守。サイト別・系列別の固定ルールでAIを置き換えず、意味判断・調査はAI主体。固定ロジックは入出力の契約、証拠検証、費用・権限・履歴保護を担う。

## 作業範囲・承認
PR #100最新head feat/phase2-root-cause を基点に別の開発ブランチを作り、**実装PRは base=feat/phase2-root-cause**。PR #98/#100はmainにマージしない。本番DB、Vercel、cron、環境変数、通知、自動登録、応募/購入等の実データ、本番有効化を変更しない。追加の有料Anthropic推論・web_search・X APIは未承認（過去の試験費用枠を再利用しない）。ローカルSupabase、保存済みP2 15件、保存公開HTML、モックAI・偽検索/取得、無料再生、テスト、報告、非本番PRは一括実行してよい。外部への無料Webアクセスは既存robots/SSRF/頻度制限の範囲に限る。秘密/実投稿全文/gold/個人情報をGitに含めない。安全装置を緩めない。

## 1. 実際のデータとツールの経路を全数棚卸し
対象：通常のX情報収集→原文・linkMap・候補→新AI調査・検索・Web取得→応募単位判断→検証→登録案保存→人間レビュー/再評価→画面表示。旧方式/シャドー/ケースDBとの接点も監査し、実装済み・接続済み・未接続・本番OFFを明示。

各境界を「呼び出し元/受け手/契約データとツール/実際に届く値/失われる可能性/観測テスト」で一覧化。runRealProposals → generateProposalsForCandidate → runXPostReplay → cachedTools → runResearch の**上位入口から**、検索・取得・予算・上限・日時・キャンセル・証拠ID・親リンク・項目リンク・構造化ページ・人間訂正が実際に届くことを確認。関数の引数にあるだけでは合格にしない。スプレッド・型変換・JSON化・DB保存/復元・非同期処理でデータやツールが落ちる/変わる箇所を重点調査。逆に不許可のツールが混入しないこともテスト。

## 2. 出典と応募機会の関連付け
Xの投稿ID/親投稿/項目番号/短縮URLと展開結果/linkMap/サイトのイベントID/受付枠/商品/系列/店舗/開催回/候補ID/登録案key/レビューを追跡。**同じ投稿に複数の店舗・商品・開催回が混在する実例と合成例**を用いて、項目Aの証拠・URL・訂正が項目Bへ流れないこと、同じ応募フォームと実際の応募権利が常に同じとは限らないことを検証。店舗選択式/店舗別独立/商品別/1フォーム複数受付枠/親の共通URL/関連イベント欄/転載/サイトの別開催回を混同しない。再取得・再評価・upsert・順序変更・途中停止でIDや対応関係がずれないか確認。誤統合・誤分割を別に扱う。

## 3. HTML/原文の情報がAIへ届くか
HTML取得→本文抽出→ページ構造の観察→2,500字抜粋→調査AI→判断AIを段階別に照合。P2のlp/4では「抽選を希望する店舗を選んで」が約3,981文字目にあり、抜粋と構造化の双方から消えていた問題を必ず再現。lp/11、lp/12、lp/1、lp/8でも応募方法の文脈が届いたかを確認。重要文の抽出・関連箇所の複数窓・構造化改善などを比較し、全文丸投げと費用膨張に頼らず、意味判断のための情報を届ける。情報が真に存在しない場合のunknownは許容する。

検索結果→候補URL→安全なページ取得→項目に対応する証拠という経路も検証し、検索結果のタイトル/抜粋をそのまま確定根拠にしない。プロンプトだけでツールが利用可能だと断定しない。

## 4. 判断→検証→保存→UIの意味が保たれるか
observed/inferred/unknown、応募単位の列挙値＋注釈、引用と証拠ID、scope/support、decision/held/verified/rationale、費用、停止/検索の実行状態をAI出力から表示まで照合する。lp/9の保存落ち、lp/1 vs lp/8の不一致、lp/4の店舗選択文、lp/5・lp/6のunknown register、r10:2のページ証拠なしexclude、r10:4のfields欠落を再現例として扱う。人の確定値の上書き、別世帯の参照、レビュー履歴の喪失、再処理の二重化、途中失敗による部分保存を確認。根拠なし除外と応募単位不明のregisterが将来そのまま自動登録へ流れない安全境界を維持。検証の指摘を無理に抑制して保留率だけ下げない。

## 5. 統合契約テストと診断の改善
各重要境界にproducer→consumerの自動テストを追加。上位入口から偽検索・ページ取得・台本AI・ローカルDBを通す。複数店舗商品、異なる開催回、長文、取得失敗、重複URL、検索無し/予算不足、認証/robots拒否、非同期中断、同時レビュー、古い情報、外部Web本文の命令混入、送信後に出力が欠ける場合をテストする。

経路別に「検索ツールの提示/使用」「原文/重要文の伝達」「出典と項目IDの対応」「AIの判断/理由」「検証保留」「保存形式の変換」「UI到達」を別計測。**AI自体の意味判断の失敗・取得失敗・配線欠陥・保存失敗を区別**。実際のコンテンツや個人情報をログに出さない。保存済みP2の結果をオフラインで再生して前後差を測るが、モックで通ったことを実AIの精度向上と称しない。人が原文で独立確認したgold以外は正解率に算入しない。

## 6. 完了条件
発見した構造上の不具合は開発用ブランチで修正し、修正前に失敗するテストが可能なら追加。型検査、lint、単体、DB結合、E2E、build、旧機能の非干渉を確認。「監査した境界」「自動テストで通過」「未検証」を分けて記録。新規報告書 docs/reports/2026-11-23-phase2-e2e-integrity-audit.md に境界一覧、重大な発見・原因・修正前後、情報の関連付けのリスク、残るunknownと保留の分類、テスト結果、費用0・本番変更なし、次の実AI最小再試験の案を記載する。

ユーザーの承認なしに追加の有料試験や本番反映をせず、PR #100をbaseとする新規実装PRを作成して報告。**根本原因が解消されたと検証できない部分は未確認として残す。**

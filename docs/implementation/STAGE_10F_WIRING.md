## 一括作業
1. 既存の10F実装ブランチ `feat/10f-shadow-integration` を継続使用。最新mainを反映し、`src/lib/collector/run.ts` の正式な処理経路、旧方式の判断確定・保存のタイミング、サーバレスの実行寿命・エラー境界を調査。**旧方式の処理・保存・レスポンスを変更しない**。
2. 旧方式の確定・保存**後**に、1か所からシャドーへ入力を渡すローカル限定の配線を追加。フラグ初期OFF、本番/Vercelでは強制OFF、緊急停止、既存の段階的ロールアウト制約を維持。シャドーは正式なDB・履歴・通知・抽選登録に書き込まない。旧方式の成功・失敗・返答・レイテンシに影響させない。サーバレスでfire-and-forgetが完走するとは仮定せず、必要なら開発環境だけの明示的なawait/キュー/別実行にして副作用と待ち時間を評価し、根拠を報告。
3. 旧方式から取得できる**実値**（構造・応募機会数・既存候補との関係・重複件数等）をコードから調べて要約へ反映。不明なものはnullのままにし、**架空の数値を補わない**。旧方式が表現不能な構造は `legacy_unexpressible` として別集計。比較結果は正解率と扱わない。
4. 入力の同一性（同じ原文・候補情報を双方が参照しているか）、重複実行、同時処理、タイムアウト、予算、保護履歴の不変性を検証。ローカルの架空ケースを使い、OFF/ON/失敗/ハング/本番フラグ/緊急停止のテストを実装。実AIを呼ばないモックで比較結果が記録できることを確認。原文・URL・ID・認証情報を記録しない。
5. 既存の`phase2`の承認票との整合性を確認。実データ評価を開始する際に必要な承認を**重複なく最小限**に整理（本番DBの読み取りと外部AI送信は別ゲート）。人が30件のgoldを作ることを次の工程の前提にしない。データ送信前の目視確認とAPI保持条件の確認は省略しない。
6. 型・lint・単体・ローカルDB結合・build・CIを検証し、`docs/reports/2026-11-21-stage10f-wiring.md` に実装内容・通常収集の不変性・計測できる項目・残る最小限の承認を記載。10F実装PRを更新し、**未マージ**で報告する。PR #36も未マージ。

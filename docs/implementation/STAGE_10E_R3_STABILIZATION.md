## 目的と許可範囲
r3の実AI評価で判明した3課題（K07 products形式エラー、K04構造ラベルの重複、K09採点器の誤分割疑い）をまとめて改善する。**ローカルの架空データ・保存済みAI出力の再採点・無課金テストのみ許可**。追加のAnthropic API呼び出し、実データの取得・本番DBアクセス・外部AI送信、Stage10F、本番へのデプロイ・切替は禁止。PR #36をマージしない。

## 実施指示
1. 最新mainをPR #36に取り込み、報告書と `src/lib/judgment/{prompt,output-schema,verify,contract}.ts`、`src/lib/judgment/eval/replay.ts`、保存済み評価結果を調査する。**原因と修正前の再現テストを先に記録**。
2. **K07**: `products` の正しい構造（value/basis/citationsなど、実際の契約に準拠）をプロンプト・再判断時のエラーメッセージに具体的に示す。値型、必須項目、空配列、独立機会の分割を曖昧にしない。スキーマ・検証・モデルSDKの構造化出力機能の採用可否も調べるが、破壊的な契約変更は避ける。**エラーを無理に自動補正して受理しない**。同型の誤出力を拒否し、修復可能な指示を返すテストを追加する。
3. **K04**: `per_product` と `multi_independent_per_submit` の意味と使い分けを、応募回数・独立当落・フォーム/送信単位で整理する。両者を安易に統合せず、既存の保存データ・契約互換・10F予定のDBマッピングへの影響を調査し、互換性を保つ最小修正。曖昧なら「判定不能」とする条件も明記する。新旧ラベルが意味的に重複する事例をテストする。
4. **K09**: 1つの既存カードに対して複数の新規応募機会があるとき、各機会の関係を**個別の組み合わせ単位**で採点する。例えば既存カードに対して第1回は `same`、第2回は `same_campaign_other` が同時に成り立つ。元の採点器の「誤分割1」を隠さず、**変更前と変更後の再採点結果を並記**し、同一権利を別扱いした真の誤分割・異なる権利を統合した誤統合が検出され続けるよう逆パターンもテスト。goldやAI出力を事後改変しない。K09の採点を直しても他の事例で過小計上がないか調査。
5. 3点の修正が旧19件・新12件のgold/採点を壊さないことを確認し、必要に応じて**新たな独立ホールドアウト架空ケースを作成しgoldを先に固定**。実AIの再評価は行わないため、改善後の実AI精度・形式エラー率は**未測定**と報告する。既知のK群を今後「未見」とは呼ばない。
6. 型検査・lint・単体・全DB結合・build・CI、履歴保護・費用制御・本番拒否の回帰を確認。報告書 `docs/reports/2026-11-21-stage10e-r3-stabilization.md` に根本原因、修正、変更前後の採点、互換性、残課題、実データ評価に必要な承認を記載する。
7. コード・報告書はPR #36に追加し、**PR #36は未マージ**。Stage10Fの着手、実データ評価、追加の有料実AI評価はユーザーの次の承認を待つ。

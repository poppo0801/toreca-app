# Phase 2 R1 最終プレフライト（実AI未実行）

## 背景・確定事項
2026-11-24のユーザー確認後、合成LivePocket 12ページをgold書出し済み。実投稿は68ページのうち11ページ確認、4案件・9応募機会がgoldとして成立したとの報告。全例LivePocketであり、残り57ページの人手確認は今回は要求しない。R1準備報告では合成12案件・36応募機会、readinessブロッカー0、期待費用37.38円（合成）+8.32円（実投稿）、予算上限総額60円・1案件5円。合成は構造確認用であり、実投稿精度を代替しない。

## ゴール
有料AIを呼び出す**前**に、(1)変更がGitHub PRへ反映されたこと、(2)テスト件数の減少が説明・対処されたこと、(3)締切時刻が正解データ/採点で測定できること、(4)費用上限に達する前に各実験を完走できるかを検証し、実行可否と必要なユーザー承認を報告する。

## 実施事項
1. ローカルの作業ツリー・コミット・ブランチ・PRを検査する。基点は未マージ実装PR #122 `feat/phase2-pre-r1-audit`。既存のgold、ローカルDB、ユーザー応募履歴を保持する。機能差分は最新実装PRから新しい機能ブランチを作り、**#122をbaseとする積み上げPR**にする。新PRには今回の修正コード、テスト結果、報告書を含める。#122自体を更新済みの場合でも、GitHub上のSHA/差分とローカルの一致を確認し、未反映なら同期する。
2. 前回報告の単体3753件と今回3699件の差（-54件）を調査する。テストの削除・スキップ・対象の漏れ・コマンド/実行環境の差を比較し、証拠を記録する。必要なら修復し、型検査、lint、関連単体、DB統合、E2E、buildを安全なローカル環境で実施する。実装が未完成なら合格を主張しない。
3. `applyEndTime` と `deadlineTimeAccuracy` / `deadlineYearAccuracy` のロジックを検証。日付跨ぎ、00:00、23:59、時刻なし、年なし、本文由来の根拠、時間表記揺れの回帰テストを含める。**人が確認した既存のgoldを自動変更しない**。時刻を入れない場合、時刻の母数0で未測定と明記する。人による時刻追記が必要な場合、UIでの最小手順・必要最小ページ数を説明し、Claudeが勝手に「人の確認済み」を付与しない。
4. `r1-build`, `real-validate`, `r1-readiness`, `plan` を無課金で実行し、合成/実投稿の母数・計画回数・想定トークン・予約上限・API価格・予算不足による早期停止の可能性を再計算。合成12/実投稿4が総額60円/1案件5円で**完全に完走できる保証はない**ことを明示する。必要なら実験を分割・段階縮小し、価値の高いケースの順に実行する案と各段階の費用を示す。**予算上限を勝手に増やさない。**
5. `cautionSummary` が undefined message に対してクラッシュする既知の報告や、通常画面の「要チェック」から他タブへの遷移障害が未修正なら、ローカル再現と根本原因調査・テストも行う。回避コードで根本原因を隠さない。
6. 無料の模擬テストだけなら可能。ただしモックの合格を実AI精度に換算しない。合成と実投稿の測定結果を混同せず、個別の応募機会・店舗/商品・締切日/時刻・引用の混入・読み飛ばしの採点仕様を確認。
7. 終了時は**日本語の短い報告**：修正済み・未対応、テスト件数差の原因、新PR URLと比較範囲、gold件数、時刻採点の母数、合成/実投稿の予算と完走見込み、残るブロッカー、承認後の具体的な実行計画。実装報告文書を `docs/reports/` に保存。完了通知は既存のiPhone通知を使用。

## 禁止
- 有料AI/API呼出・未承認の第三者サイト再取得・本番操作・本番DB変更・ユーザー応募/購入履歴の変更
- ユーザーの金額承認文字列を代入しての本番同等実行、承認の代行
- 実装PRをmainへマージ、goldの正解や確認済みフラグの捏造
- 未確認57ページすべての人手確認を追加要件として要求

## 合格条件
変更がレビュー可能な未マージ実装PRにあり、テストの整合性と予算・評価母数が説明可能で、残課題が明示され、**有料実行はユーザー承認待ち**となっていること。

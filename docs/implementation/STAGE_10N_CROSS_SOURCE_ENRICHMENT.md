# Stage 10N：複数情報源の同一抽選照合・根拠付き補完・応募構造の自律調査

## 目的・現状
Stage 10M（`docs/reports/2026-11-21-stage10m-full-list-coverage.md`）で一覧全項目の発見を実装したが、旧本番登録・重複判定には未接続。旧方式は重複として除外しがちで、異なる情報源の事実を統合して応募条件・日時・店舗選択・商品選択を補完する経路は未完成。ユーザーが承認した目標は**複数情報源を同一応募機会に関連付け、根拠を保持して情報を補完・訂正し、必要な追加調査まで自律実施**すること。既存データ保護・費用・安全を最優先する。

## 一括実装
1. `feat/10f-shadow-integration` 上で最新mainを取り込み、Stage10Mの全項目処理、画像根拠検証、ハード上限を維持。旧本番の候補・抽選・重複・更新経路と新シャドーをコードで追跡し、既存機能の再利用と差分を整理。
2. **情報源を横断する同一性判定**：一覧投稿の個別項目、店舗公式X、店舗サイト、応募フォーム、まとめサイトなどの同じ抽選を候補照合。系列別名、店舗・地域、商品・開催回、受付期間、応募先URL、応募単位を総合し、`same_opportunity`／`same_campaign_different_opportunity`／`independent`／`unknown` を区別。URL一致だけで同一確定しない（汎用フォーム・系列共通ページに注意）。表記揺れや日付差の扱いを根拠付きで判断し、異系列・別店舗・別開催回・複数商品・店舗選択式の誤統合を防止。既存登録との比較で自分自身を「別候補」として渡さない。
3. **複数ソースの根拠付き補完**：出典・取得日時・原文の範囲／画像検証・信頼性・対象項目との対応をフィールド単位で保持。公式告知を優先するが公式でも古い／誤記の可能性を考慮し、更新時刻・具体性・独立裏付けを評価。確かな欠落項目は補完提案、矛盾は差分・出典を並べて安全に保留。締切など重要日時は早い方を優先する既存方針を踏まえつつ、根拠不明な上書きや単純な日付早い方への無条件置換はしない。応募済み・当選・購入・通知・手動編集・スルー等の保護データは変更禁止。
4. **応募構造の自律調査**：公開応募ページ・公式告知・公開画像を必要時のみ安全に取得し、店舗選択式、店舗別応募、同一応募で複数商品選択、商品別応募、開催回を判定。情報不足の場合は限定された追加探索を行い、取得不能・不明なら保留。リンク先の安全境界（SSRF・robots・認証・ログイン回避禁止・取得上限）を維持。ユーザー設定の対象地域・TCG種別・除外系列を登録・通知の前に適用する判定もシャドーで検証し、抽出件数と登録対象件数を分けて報告。
5. **順序依存・冪等性の検証**：A→B、B→A、同時到着、同じ情報の再取得、後から訂正告知、矛盾情報、別店舗の類似告知、1フォーム複数商品、店舗選択式、一覧から公式への追跡をテスト。複数ソースが1つの応募機会に関連付くこと、既存登録の保護と二重登録防止、再実行で同じ結果・追加費用を最小化することを検証。人の確認がないラベルを正解率と呼ばない。
6. **確認画面**：抽選機会を中心に関連情報源を一覧表示し、各フィールドの採用値・出典・矛盾・補完提案・応募構造・保留理由・追加調査履歴・対象条件の採否を確認できるようローカル評価画面を拡張。少数の実例を人が確認できる形にする。既存のStage10Mの一覧全件確認を維持。
7. **費用・安全**：実AI評価の追加上限**50円、最大30対象、90呼び出し（画像・再試行・追加調査・再評価すべて合算）、公開ページ取得60回、原則1件3円**を厳守。費用と呼び出し回数は開始前に予約してハード停止。再帰探索の深さ・ページ数・総時間にも上限を設定。Gitに実データ原文・URL・ID・個人情報・秘密情報を置かない。ローカルDBのみ変更可。旧方式の本番処理は不変。人の応募／当選／購入履歴は外部AIに送信しない。
8. **検証・報告**：tsc/lint/build/単体/DB統合・CIを確認。実データの照合・補完・構造判定について、確定・保留・矛盾・誤統合防止の件数を明記し、検証不能ならその理由を報告。`docs/reports/2026-11-21-stage10n-cross-source-enrichment.md` に旧方式との差、実測、費用、制限、本番移行可否、次の課題を記載。実データの人による確認が未実施なら明記。

## 境界
**PR #36/#46のマージ、本番DBの変更・マイグレーション、本番デプロイ・本番シャドー有効化、既存の抽選・候補・応募・当選・購入データの自動更新・統合・削除は禁止。** 補完・更新はローカルシャドーの提案・プレビューまで。新たな本番書き込みは別承認。作業を細分化せず一括実施。

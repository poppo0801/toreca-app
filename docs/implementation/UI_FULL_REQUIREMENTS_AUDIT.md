# UI要望の全件照合・不足修正（PRICE_UI_COMPACT_ACCEPTANCE_FIX.md に追加適用）

## 目的
ユーザーは相場画面以外にも過去のUI希望が未実装の可能性を指摘。**既存指示書を実装しただけで完了扱いしない**。過去の確定要望、既存設計md、実装、テスト、本番画面を**項目ごとに突合**し、不足をすべてUI修正に含める。最新の明示要望が旧仕様と矛盾する場合は最新を優先。AI情報収集機能と画像導入は別扱い。

## 確定要望・追加で見つかった漏れ
### 価格登録フォーム
- 必須項目の順: カード名→**系列→店舗**→調査日→価格→状態。系列・店舗必須、過去の系列＋店舗セットをワンタップ候補表示。調査日は今日、状態は**A初期値**。
- 収録セット/カード番号の**相互補完**、レアリティの**AR初期値**、既存候補からの選択（候補がない場合手入力）。収録セット/番号/レア/備考など任意項目は下段。新規/編集/図鑑/相場メモの全経路で確認。
- 状態違いの一括登録は維持。**割引計算機能は任意**であり、必須として画面を肥大化させない。入力の自動フォーカスや勝手なプルダウン展開はしない。
- 現行 `src/components/price-form.tsx` は `condition: ""` 初期値で、`defaultRank` は目印のみ。店舗入力が系列より上、系列は末尾の任意項目。過去候補は店舗名のみ。**A初期値、系列必須、系列＋店舗候補は未実装**。相互補完・AR初期値はカード情報フォーム側も確認。
- `src/components/market-memo-view.tsx` のカード情報フォームと `src/components/zukan-view.tsx` の価格対象カードフォームも対象。価格フォームだけ直して終わらない。

### 価格一覧・詳細
- 状態→系列/店舗→調査日→右端金額。行をタップすると履歴/推移/購入/編集/削除/備考を詳細で表示。一覧は最小限。図鑑・相場メモ共通。
- 既存の「状態優先（A+→C、同ランク内安値順）/価格安い順」、30日超参考価格、最安強調、購入済み二重購入防止、履歴保持を壊さない。
- 相場調査メモのカード一覧は検索、各行＋/左スワイプで価格追加、右上＋でカード＋価格一括登録、購入済みデフォルト非表示・切替表示、最安/記録件数を維持。タップ時の詳細とカード削除保護（価格履歴・購入済み）は維持。

### 151図鑑
- No.001〜151、日本語名、入手数/達成率/未収集、全件/入手済み/未入手、番号順/五十音順（JSONダウンロードのボタン置換）。
- 入手済み=白地・カラー画像・緑チェック、未入手=薄グレー系・画像半透明（約35%）、相場登録済み/対象レア未収録/未登録は背景色・控えめ枠で区別。**一覧には状態の文字バッジなし**。詳細ヘッダーだけ短い色バッジ可。
- 状態優先順位は入手済み>相場登録済み>対象レア未収録>未登録。「対象レア未収録」は手動ON/OFFで解除可能。**チェック下の説明文は全削除**。
- 公式絵は括弧なし通常形を優先し、番号4桁で照合。相場メモの画像は常に不透明。非公開画像配信の本番有効化は別作業であり、今回のUI検証を止めない。
- 収集カード/相場価格の追加・編集・購入連動、プロフィール分離、曖昧なカード同定の選択、購入履歴保護。

### 購入記録
- 商品別累計カードの「総額」「開封」補足文削除、詳細で確認。発売日降順、シングル/オリパ/その他は末尾。BOX/パック/その他/総額の集計、購入履歴、月選択は維持。
- 開封状態未確認の表示/確認フローを廃止する一方、**不明なBOXは未開封扱い**、開封済み統計は確定したものだけ。元の履歴は変更/削除しない。

### 設計原則
- 既存のUI設計mdを**検索して更新**。『軽快・シンプル』『冗長な初心者向け説明は画面に置かない』『詳細設定・内部技術説明は不要』『一覧は比較に必要な最小限の情報』『操作はタップ後』『ユーザーが指定した並び・初期値を正確に実装』を明文化。誤操作防止の確認とエラーは維持。既存ナビ順や設定は無断変更しない。

## 実施手順と合格基準
1. リポジトリ内のすべての関連指示書/設計md、現行コード、既存テストを調査。**要望ID / 原文・出典 / 現状 / 判定（適合・未実装・一部・確認不能） / 対応ファイル / テスト / スクリーンショット** の監査表を `docs/reports/` に作る。旧指示が曖昧なら実機画像と最新の確定要望を優先し、想像で要望を削らない。
2. 監査表の未実装・一部を**今回の修正範囲に全件追加**。ユーザーが気づいた部分だけで終えない。過去の指示書や設計mdと現在の実装を1項目ずつ照合する。未知・確認不能は理由を明記。
3. 390px前後のスマホ幅で151図鑑一覧/詳細、相場メモ一覧/カード詳細/価格一覧/価格登録、購入記録の実画面スクリーンショットを撮り、要求と比較。特に価格行にボタン・推移が常時出ないこと、登録フォームの系列/店舗順と初期値A・AR、相互補完を**操作で確認**。モックだけで済ませない。
4. 型・lint・build・単体・E2Eとデータ整合性/ユーザーA/B/C分離/旧購入履歴の回帰テスト。CIだけでUI合格としない。
5. UI専用ブランチ→PR→CI→マージ→Vercel本番→スモークテストまで（既存承認範囲）。画像素材を公開GitHubに入れず、AI Stage10T/10Uを混入させない。権限不足時は報告して停止。危険な操作や本番データ破壊は行わない。
6. 最終報告では監査表の各項目の合否と未完了を列挙。**全件照合できていない場合は「完了」としない**。

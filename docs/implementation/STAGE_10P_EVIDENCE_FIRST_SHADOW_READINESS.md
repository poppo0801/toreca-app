# Stage 10P：公式性を登録条件から撤廃・根拠重視の登録判断・新旧比較と本番移行準備

## 方針（ユーザー承認済み）
- **公式であること、公式サイトが取得可能であること、公式SNSとの相互リンク、公式バッジの有無は、自動登録・候補登録・通知・情報補完の必要条件ではない。**ドラスタ等、公式情報を直接参照できない抽選も対象。公式性を欠くという**理由だけ**で確認待ち・除外にしない。
- 判断は抽選情報の具体性・整合性・検証可能な根拠・独立性・応募単位・対象地域/TCG/商品・重複リスク・期限で行う。公式/非公式の区分は根拠の一属性であり、情報の正確性を保証しない。転載元が同じ複数記事を独立根拠と数えない。
- **公式バッジは抽選詳細で任意表示**。当該抽選について実際に公式発信元と確認できたソースが存在するときのみ表示。確認できなければ何も表示せず、非公式／偽物などの否定的ラベルは付けない。バッジは「公式情報源の裏付けあり」の意味に限定し、抽選全体の正確性を保証しない。根拠と最終確認日時を詳細画面から確認可能にする。判別不能ならバッジなし。バッジのためだけの高額な探索はしない。

## 一括実装・検証
1. **旧・新のコード追跡と判定条件の棚卸し**：最新mainを`feat/10f-shadow-integration`に取り込み、`src/lib/judgment/xsource/decision.ts`、`official.ts`、`conditions.ts`、既存の登録・候補・通知・抽選詳細画面・ワーカーを追跡。公式性による隠れたゲート（直接/間接・評価スクリプト含む）を除去。公式でないことと**根拠の乏しさ**を別概念にし、単に公式フラグを常時trueにする等の偽装はしない。
2. **根拠重視の登録判断**：登録対象で、抽選であること・系列/店舗または通販・商品・応募機会・有効な応募期間/応募先など**実行可能な最低限の情報**が揃い、同一機会/別店舗/別開催回/店舗選択式/複数商品を適切に区別でき、致命的な矛盾が無ければ、非公式ソース1件でも自動登録可能（**プレビュー**）にする。信頼できる単一ソースを一律保留しない。重要情報が欠ける場合は「欠落つき候補」か「確認待ち」を区別し、登録しても応募機会を誤って増やさない設計。情報源の具体性、原文・画像の照合、取得日時、過去の誤報/訂正、転載関係、独立した追加根拠を評価。未知の応募単位・重大な日付矛盾・重複疑い・対象条件不明は安全に保留。**「公式性不明」のみの保留はゼロ**。既存のユーザー設定を適用し、対象外は登録・通知しない。除外の誤判定を監査できるようにする。
3. **日時の意味・正規化**：受付開始、締切、発表、購入/受取、予約、注文対象期間を区別し、日時の原文・文脈・タイムゾーン（JST）・年推定根拠・精度（日付のみ/時刻あり）を保存。曖昧な年、曜日不一致、年跨ぎ、23:59/翌日0時、締切当日、開始と締切の逆転、販売期間と抽選期間の混同をテスト。根拠なしの年・時刻補完をしない。通知に使う値は明示的に検証された締切だけ。既存データの形式に合わせたプレビューを作成し、手動編集や応募済みのデータを上書きしない。
4. **商品・TCG・地域の不明改善**：商品マスターを再利用し、名称揺れ・別名・セット名・新弾・複数商品・混在TCGのケースを処理。根拠付きAI補助は使えるが、抽選対象商品の誤推定を防ぎ、未知は未知とする。店舗所在地と応募可能地域を区別し、通販、地域限定、店舗選択式、同一系列の複数店舗を誤判定しない。対象/対象外/不明を**同一標本で**前後比較する。
5. **公式バッジ（抽選詳細のみ）**：実際の抽選詳細UIの既存構造に合わせ、確認済み公式発信元を紐づけられる場合のみ小さく表示。未確認なら非表示。ソースURLの有無だけでバッジを付けない。相互リンクは有力な根拠の一つだが唯一の方法にしない。信頼できる公式サイトからの発信元リンク、公式ページ自身の告知、店舗の確実な公開情報などを組み合わせて検証。発信者確認と**当該抽選の告知確認**を分離。UI実装が本番DB変更を要する場合はローカル表示/プレビューまでに留め、適用条件を報告。
6. **Stage10Oの50件を同一入力で再評価**：旧基準（0自動/0欠落候補/12確認待ち/38除外）と新基準の件数、公式性単独のブロック解除件数、なお残る実質的な保留理由、誤登録・誤除外リスクを比較。数を増やすために安全条件を緩めない。6登録9項目の補完も日時の意味を再検証。代表例の人による確認導線を整備し、**人の正解確認が無ければ正解率や本番合格を宣言しない**。実データはGitに含めない。
7. **新旧方式の比較とワーカー接続準備**：既存本番の収集経路と新シャドーの候補・登録プレビューを、同一期間/同一対象設定で比較可能にする。発見、対象判定、登録可能、確認待ち、重複/誤統合、更新、遅延、費用を定義し、比較の分母・収集経路の差・手動正解の有無を明示。旧方式の本番動作を変更しない。新シャドーのワーカーへの**接続設計とローカルでの無書き込み検証**は可能だが、cron/本番シャドー起動はしない。停止スイッチ、再実行、費用上限、監視、ロールバック、DBマイグレーション108〜112の依存・適用/復旧計画とバックアップ手順を具体化。**本番切替は別承認**。
8. **安全・コスト**：実AI追加評価は**上限50円、90呼び出し、30対象、公開ページ60取得、1対象3円**。すべての再試行・画像・追加調査・AI再評価を合算し、開始前に予算予約してハード停止。URLのSSRF・robots・タイムアウト・深さ・リダイレクト対策。外部AIに応募/当選/購入履歴・個人情報を送らない。ユーザーの応募・当選・購入・通知・手動編集・スルー・お気に入りを変更しない。データ保存・閲覧の権限境界を維持。

# Phase 2→3 実装指示：実AI通し試験と人間確認付き限定運用の準備

作成日：2026-11-23。起点：本番統合報告 `docs/reports/2026-11-23-prod-release-108-114-and-integration.md`（PR #96）、main `1091ffa`、Stage 10Z・migration 114。**新AI基盤はmain/本番DBに統合済みだが、実AIの登録案経路・本番プレビューは未有効**。今回の目的は、形式的なStageを増やさず、実AIによる「既存収集候補→調査/判断→登録案→人間レビュー」の接続、評価と限定運用に必要な実装・テスト・成果判定をまとめて完成すること。

## 承認の範囲と絶対条件
今回の「続けてください」により許可されるのは、**コード調査・開発用実装・モック/無課金の再生/公開Web取得・ローカルDB・テスト・報告書・非本番PRまで**。次は別の明示承認が必要：**有料Anthropic（推論/web_search）・X APIの新規実行、本番DB/Storageの変更、本番AIやシャドーワーカーの有効化、環境変数/Cron/通知の変更、実装PRのmainマージ、自動登録・既存履歴の書換え**。Stage 10Xの過去の承認枠を再利用しない。請求上限はAPI側の超過可能性も含め現実的に検証し、「上限を保証」と誇張しない。本番の既存収集は稼働維持し、今の設定を変更しない。

## 1. 実AI通し経路を実装（開発環境のみ）
- 現状の `proposals/generate.ts` は `mode=real` を拒否し、既定の `proposal-mock.ts` のみ。承認済み評価入口 `scripts/xsource-10x.mjs`、`RealRunGuard`/`checkJudgmentRealRun`/`preflightRun`、既存 `ResearchAgent`/judge/search を実際に調べ、**同一の収集候補から実AIエージェント/判断AIへ入り、ページ取得→根拠/応募単位→保存案→レビューUIへ流れる専用の開発・評価入口**を実装。実AIをモックと差し替えられる依存注入とし、既定では実AIに接続せず、明示的な費用承認ゲートを必須にする。
- **評価・実AI利用の入口と一般のUI/server action/cronは分離**する。環境変数だけ、ユーザーの通常の画面操作だけ、または本番にある秘密キーの存在だけで有料AIが動かないことをテスト。本番Supabase/本番候補に対して実AIを実行しない。
- 保存済みの実X投稿・リンク・公開Webページを使い、A（既知URL理解）、B1（入力リンク）、B2（**AIが検索で未知のURLを発見**）、C（独立gold比較）を別指標で計測。B2では既知URLをAIに渡しただけの再生と自律発見を混同しない。robots/SSRF/リダイレクト・レート制限・検索呼出回数と遅延上限を維持し、認証・会員専用ページを突破しない。
- 収集フックの3秒 `Promise.race` は内部処理を中止しない可能性がある。実AI連携前にキャンセル、キュー化、リース/冪等再試行、費用予約/決済と停止条件を現実的に見直す。エラーを無言で握りつぶさず、機密を含めない監査ログに分類。ただし本番の既存収集に副作用を出さない。
- 登録案の項目単位の参照元・引用の実在と値の導出を別に記録。URLなし・親の共通URL・複数商品/店舗・選択式/店舗別・期限/抽選結果・取得不能・曖昧な情報・異なる開催回の重複に対応。保留を過度に増やさない一方、根拠なし確定を回避する。

## 2. 人間確認付き限定運用の実装準備
- Stage 10Zの候補詳細UIと追記専用レビュー、世帯RLS、利用者の修正保護を継承。**開発環境で**実AI作成案に対する保留/修正承認/却下、再評価後の差分表示、フィードバック記録、候補件数/費用/解決率の集計を動作させる。ユーザーの最終判断をAIが改変できないことを保証。
- 承認と実際の抽選登録を分離する現行安全境界を維持。限定運用として将来本番でプレビューのみを安全にONにする**提案・実装可能な接続設計とOFFへの即時戻し**を整備するが、今回**本番有効化/自動登録/通知連動は行わない**。本番限定のプレビューフラグを追加する場合は既定OFF、認可・専用予算・ユーザー承認・本番だけの誤起動試験を含め、ONにしない。
- AIの判断・失敗・人の訂正を次回の証拠検索に再利用する方向で、既存のケース/履歴を生かす。訂正内容を保存するだけでモデルが自動学習したと誤解しない。データ最小化・保存期間・古い証拠の扱いと個人情報保護を検討する。

## 3. 無課金の実装・評価と別途費用承認
- 今回はモック/保存済み証拠/安全な無料Web取得まで**実行してよい**。実AI/有料検索は一切実行しない。テストは「既存収集→新AI入口のモック→登録案DB→人のレビュー」まで実DBのE2Eを再実行。権限越境、既存のA/B/C応募・当落・購入・スルー・通知・画像・家族の修正履歴、無限再試行・二重起動・請求失敗時の停止、実AIゲート、本番ではOFFを回帰確認。
- 実AIの試験については、**利用者の明示承認を得るための試験計画**を作る。モデル名/当日単価確認、全体/1件上限、最悪予約費用、対象件数、各APIを呼ぶ具体的な操作、費用の見積り・実測の保存方法を提示。旧提案の B2 ¥14 / C ¥3 / A ¥8（合計¥25）は**参考値のみ**。今回の実際の実装や単価に合うかを再計算し、過去の承認を流用せず、承認が来るまで起動しない。
- Aは「引用の存在」だけで正解としない。goldは現状3件（根拠不足6件）で、追加goldの根拠を人が確認する導線・手順を用意。旧AI/既存アプリの出力をgoldへ流用しない。精度と発見率は採点可能母数と未検証を明示し、誤統合/誤分割/未発見/過剰保留を別計測。ベースライン測定前に合格率の閾値を創作しない。

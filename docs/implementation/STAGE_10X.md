## 1. 実データによる入力側の検証
1. 既存の合法的に取得済み原文・X API entity・保存済み実公開ページを最大限再利用し、無課金の再生でX投稿の項目リンクとスコープを確認。少なくとも保存済み179投稿382項目の欠落原因と、9件の限定復元の根拠・対応の不確かさは維持する。
2. 実X APIを用いる場合、開発用で許可された認証・エンドポイント・最新料金・リクエスト上限・課金条件を実行前に確認。まず**少数のX公開投稿（提案上限50投稿／概算¥60は再確認前提）**から最小の評価セットを作る。無関係な大量収集をしない。ログイン／CAPTCHA／robots／レート制限を回避しない。
3. 取得した個々の投稿について **元のt.co URL→entityからの展開URL→本文中の位置→各項目の帰属→応募先の公開ページ→ページ構造→AI入力**を追跡可能にする。X APIからlinkMapが来ない場合は欠落理由を明記し、親投稿共通URLを特定店舗の応募URLと断定しない。根拠とページ側の情報が結び付けばAIが合理的に帰属判断できる設計を維持。
4. 本番DB、本番の収集設定・ジョブ・cronへの書き込みなし。APIキー・本文・個人情報をGitに含めず、非公開ローカルの評価データのみ。取得と処理の一部しか通せなければ、未完了区間を明確に記録。

## 2. 実AI評価：内容と優先順
- 評価条件を混同しない：**A＝応募URL既知でのページ理解・登録案、B1＝X entity展開と項目別対応（AIなし）、B2＝応募URLを与えないAIの自律発見、C＝独立goldと照合した応募単位・登録判断**。
- 最初はA（保存済みLivePocket12件など）とC（現状独立gold3件）について、実AI無しで評価対象・根拠・原文とgoldの分離・古い事例の取得不能状態を監査。Cの3件だけで一般精度を断定しない。人の「誤り」を反対ラベルへ自動変換しない。根拠のない6件の人間回答を勝手にgoldへ昇格させない。
- B2の現状ツールは`fetchPage(URL)`のみで**検索できない**。これを「AIの自由なWeb探索」と称さない。既存の検索・収集アダプタを開発限定・読み取り専用の`search`能力として安全に流用できるか監査し、可能なら**最小限だけ接続**して、検索→候補→安全な公開取得→根拠・スコープ検証を実行可能にする。新規有料検索APIや本番権限拡大が必要なら仕様・費用・リスクを提示し承認待ち。検索の実測ができない場合はB2未検証のままとし、URLを知っているだけで成功と判定しない。
- 有料の実AI呼出は、**モデル識別子が利用可能か、最新の公式入力/出力料金、実際の推定トークン、APIキー種別・制限、事前予約の上限と実課金計測**を確認したうえで、明示的なユーザーの許可を得たケースにのみ実施。Stage10W報告の提案はHaiku、A最大¥25、C最大¥25、X APIは50投稿約¥60だが**確定価格ではなく承認済み金額でもない**。実行コマンドがゲートを迂回できないようにする。課金途中の再試行・途中停止・予約残高も検証。
- 実AIを実施したら実例別に、①取得できたか ②AI入力に載ったか ③調査経路 ④応募単位・根拠 ⑤本登録／暫定／除外 ⑥過剰保留／根拠のない断定 ⑦誤統合・誤分割 ⑧費用・回数・経過時間を記録。失敗を取得・スコープ・推論・登録判断・安全実行の階層に分類。旧方式との同一証拠比較。数値の母数・独立gold・検証不能数を必ず記録。

## 3. 本番移行判定に必要な実証と安全
- 旧本番機能を不用意に停止しない。応募／当落・通知・購入・スルー・手動確定・A/B/Cユーザーと地域設定を保護。意味判断はAIが主導し、出典・権限・費用・履歴の検証層は維持。推論のための新しいサイト固定ルールを作らない。
- 単体、型、lint、DB統合、build、必要なE2EとPR CI。重大な誤統合・履歴破損・権限逸脱・情報漏洩・費用上限越え・停止不能ループは平均点で相殺しない。UI等の回帰、未接続の通知や本番収集については「検証済み」と言わない。
- 実測後、**本番へ進める／条件付きで進める／根拠不足で保留**を根拠付きで評価し、残課題を**本番導入の阻害要因**と**導入後でもよい改善**に分ける。完成度の低い非重要項目を理由に延々とStageを増やさず、重大な安全問題がなく旧方式以上の実用性が確認できれば移行提案を作る。
- PR #84/#86と追加実装の安全な統合・切り戻しの具体手順、migration108〜113の適用可否・バックアップ/復元テスト・初期OFFと本番切替方法を提案するが、**本番マージ・migration・cron・Vercel本番反映はこのStageでは実行禁止**。

- **無課金でできる調査・評価ハーネスの不備修正・開発用検索接続・安全テスト・非破壊PR・報告は追加の細かな確認を求めず一括実施。** API実料金を伴う最初の実行だけは、具体的な上限（サービス・回数・費用・モデル）を短く提示してユーザーの明示承認を待つ。権限が無い・料金が検証できない場合は課金しない。

# Stage 10C 実行指示：AI再設計の正本化・既存実装対応監査

状態：Claude Code向け実行指示 / 2026-11-20
**本Stageは文書・設計監査のみ。アプリコード、実行設定、DB、ジョブ、収集挙動、本番データを変更しない。**

## 0. 必読
このファイル全文、`docs/AI_AUTONOMY_PRINCIPLES.md`、`docs/AI_REDESIGN_SPEC.md`、`docs/AI_REDESIGN_DECISION_HISTORY.md`、`CLAUDE.md`、`docs/SPEC_GOVERNANCE.md`、`docs/CURRENT_SPEC.md`、`docs/DECISION_REGISTER.md`、`docs/ACTIVE_ROADMAP.md`、`docs/PRODUCT_VISION.md`、`docs/UI_UX_GUIDELINES.md`、`docs/RELEASE_FLOW.md`、`docs/DEVELOPMENT_LOG.md`、`docs/SPEC_ALIGNMENT.md`。Stage 10A/10B、9X/9Y/9Zの報告書を必要に応じて参照。古いStage記録を現行仕様として無批判に採用しない。

## 1. 目的
合意した新方式を正本目標仕様に整備し、現行コード/DBとの対応、既存資産の採否、移行・受入・旧方式廃止計画を具体化する。現行コードを理由に合意済み将来設計を取り消さない。

## 2. 必須作業
### A. 安全な現状確認
開始時のブランチ/コミット、未コミット差分、既存文書、DBマイグレーション定義、関連実装を確認。コード調査・静的検査は読み取り専用。秘密情報・個人データを報告書に転載しない。既存 `AI_AUTONOMY_PRINCIPLES.md` は内容比較し、ユーザー合意を保持。

### B. 正本文書の再構築
- `docs/AI_REDESIGN_SPEC.md` を正式な**目標仕様**にし、未実装を実装済みと書かない。
- `docs/CURRENT_SPEC.md` は現行実装と将来目標を明確に分ける。
- `docs/DECISION_REGISTER.md` にCase/Opportunity、AI単一意味判断、履歴保護、短期切替後の旧方式廃止、完成条件3本柱、Markdown指示書運用を追記。
- `docs/ACTIVE_ROADMAP.md` に10C〜10Hの目的・依存・完成条件・承認ゲートを記載。
- `docs/SPEC_GOVERNANCE.md` と `docs/PRODUCT_VISION.md` を整合。優先順位は最新の明示ユーザー決定→正本仕様/決定記録→ビジョン/過去設計→コードは現状把握の根拠。
- `CLAUDE.md` を簡潔な運用入口に再構築し、必読正本・Stage指示書・承認境界・報告義務を明記。古いStage長文履歴を除去するが、有効な安全/Git/CI/権限ルールは維持。
- 古い資料は知見抽出後にアーカイブ/現行参照対象から除外。無条件一括削除やGit履歴改変は禁止。必要なバックアップと復元方法を記録。

### C. コード・DB対応表（読み取り専用）
- Evidence/Case/Opportunity/View/User recordsと既存テーブル・ID・外部キー・アプリ処理の対応を記録。
- 応募、店舗/商品選択、当落、今回/常時スルー、継続抽選、地域判定、通知、購入/コレクション、編集/手動修正の参照経路と破損リスクを調査。
- 9H case-model/investigator/integration/relation-judge/planner/grouping、9Z証拠保存、重複判定・名称正規化・既存切替設定をコードで確認。再利用/変更/廃止候補と根拠を比較。9Hのlocal-only制約を明記し無検証で本番有効化しない。
- マイグレーションは提案のみ。新規テーブルを抑えた案と比較。既存抽選ID/履歴の保持、移行・逆戻し、切替互換アダプタを検討。本番環境の未確認事項を推測で断定しない。

### D. 受入試験と性能評価計画
- 6課題だけでなく、旧方式との**総合精度比較**を必須とする。発見力、抽出精度、登録/対象判定、網羅性、更新、同一性、遅延、費用/正確機会、人手負担、安定性を測定。
- 旧方式の出力を正解とせず、原文/フォーム/画像で検証可能な正解事例を構築。取得不能は「検証不能」と区別。過去保存証拠と新着実績の双方を利用。
- 店舗選択と店舗独立、同一フォーム複数独立機会、商品一括/商品別、別開催回、締切延長、中止再開催、既存履歴ありの分割/統合、通知再計算、地域一部対象、X取得不能、会員限定、手動修正保護をテスト。
- 重大誤統合、履歴破損、費用上限突破、権限逸脱、重大通知重複/欠落、切替時の破壊的再解釈は許容しない。根拠のない数値閾値を捏造しない。長期シャドーを必須にしない。問題なければ早期旧方式廃止。

### E. 後続Stageの計画
10D〜10Hの成果物、依存関係、テスト、承認ゲート、ロールバック、廃止対象を具体化。後続指示書のドラフトは可、未確定箇所はTODOとして明示。後続Stageの実装には着手しない。技術選択は提案できるが合意済み基本原則を独断変更しない。

## 0. 承認・安全境界
通常シャドー: 通算1250円（前報告307.08）、日次200、1候補25、期限12/3 23:59 JST。隔離評価: 通算2000円（前報告1640.14）、日次650、1候補25。最新残額を確認。増額・上限変更・期限延長・DB変更・新しい本番費用等は用途/見積/上限を明示し利用者に直接承認を求める。**予算不足が見込まれた時点で即承認を求め、日次リセットを待機しない**。既存キーのみ。隔離評価はローカルDB、実在する公開情報、評価用の既存キー、既存の権限境界。本番の自動登録・変更・削除・応募・通知・常時探索・標準モデル変更は別承認。実験で制約を緩めても外部アクセス安全性（SSRF、robots、認証・アクセス制限を迂回しない、個人情報、プロンプト注入対策）、予算/無限ループ防止、利用者確定値保護、現行機能維持は必須。機械的に許可を一括解除しない。通常の明確な欠陥修正は安全確認後の反映まで進める。
## 1. 制約の総点検：利用者の目的を阻害していないか
- 収集/保存/調査/判断/検証/登録案/探索/評価の全経路の制約、固定ルール、プロンプトの矛盾、環境フラグ、モデル/effort、実際の時間/予算予約、ツール提供、入力/出力切詰め、画像、再調査/再開、上位モデルの昇格条件、判断後の再調査、採点を棚卸し。各制約について「目的・根拠・実装位置・本番/評価の実効状態・弊害の事例・維持/緩和/撤去の提案」を示す。必須の安全/権限/実費制約、技術的上限、過去の暫定設計、固定的な意味判定を区別する。利用者の承認済み方針を固定店舗ルールと混同しない。
- 既知の例: pipeline.ts 45秒を全項目共有、maxTurns4/fetches3/searches1/revisions1、read8/24000、proposal-job.ts maxElapsed60秒、Vercel関数時間枠、research-loop.ts page必須除外、応募単位必須、短い引用で他TCGのみと判断、検証失敗を一律tentative、askHumanで昇格省略、ページ無しで昇格しない、モデル不一致で保留、上位は再調査なし。research-ai.ts effort low、出力3000/4500、28項目、再試行。固定的な意味判断でAIの正解を拒絶する例を列挙。旧システムの締切でシャドーを閉じる問題、旧文書12件の長さ優先、抜粋外更新を検知しないハッシュ、長行省略、他TCGの局所引用による混在誤除外も是正する。構造的に正しくないものは実験後に採用可否を判断し、明らかな不具合は修正する。
## 2. まずAI本来の能力を測る隔離実験
- 既存の保存された応答/根拠/検証理由/正解で無課金再分析する。AIの最初の結論、再判断、検証前後、根拠、実際の情報不足を区別。未見4の4保留を特に追跡。過去のログが足りなければ不足を明記。費用をかける再試験は必要最小限にする。未見4を原因調査に使用したら開発用に移し、最終未見は独立させる。
- 同一の実案件・独立正解・初期証拠・基準時刻を使い、A:現行（low・現行制約）、B:同モデル/effortで制約を緩和、C:同一の緩和条件でモデル/effortを引き上げ、D:有望構成を実行可能な運用条件へ適応、を段階的に比較。できる限り同じ入力で生のAI出力に既存検証を後付け再生し、検証だけの影響を無課金で測る。単に検証を外して登録数が増えたことを改善扱いしない。固定検証を警告/再調査の材料とし、AIの未検証出力も独立採点。本番登録許可には流さない。
- 緩和構成: 調査時間・検索・fetch・read・反復・修正回数・入力/出力上限を、AIが必要な情報へ実際に到達できる程度に引き上げる。例として数分・検索数回以上・十分なページ取得・複数回の自己修正を用意するが、固定数値を新しい恒久ルールにしない。実行ごとの実費・時間・連続失敗/同じ行動のループの外枠は必要。必要なら承認を求める。AIが根拠不足を認識し調査を継続、十分なら停止できるようにする。費用上限で打ち切られた試行は能力不足と混同しない。
- Vercelの実行上限は無視できない。ローカル隔離評価では十分な時間を使い、複数機会を候補全体45秒で打ち切らない。実運用は機会ごとの耐久キュー/中間保存/再開/冪等/親の機会網羅性と共有証拠・費用管理を設計し、全機会に調査機会を保障する。予算・実行時間に達したものを情報不足と誤認した最終保留にせず、未完了/再開待ちと区別。急ぎの機会を優先しても後半を消さない。モデルの行動を固定手順にせず、必要な再調査を可能にする。
- Sonnetにも調査・検索・ページ取得を行わせ、Haikuが見落とした証拠を自ら探せる構成を比較。判断から調査に戻れる経路、AI同士の不一致は根拠の違いを分析して再確認。情報不足の場合は何を調べれば解けるか判断させる。引用照合・地域/時刻の整合等の客観的なチェックを残し、意味判断の固定分岐は独立AIの根拠検証で代替することも試す。根拠の無い断定は警告・再調査、真正な不明は保留。投稿自体が公式で締切/応募方法が明確なケースやフォロー/RP企画では外部応募ページを必須にしない実験。終了・対象外は信頼できる原文と開催回/時刻/混在の有無を確認し、単純な語句/日数閾値だけで除外しない。固定の店舗/系列ルールを増やさない。
## 3. モデル/推論の実測比較
- Haiku 5.5 low（基準のみ）、medium、high、Sonnet 5.5 medium、high を候補とし、まず少数の代表的難案件（複数機会・画像・地域・終了・X企画・福袋・長文）で性能上限と原因を探索。全組合せ全件を有料で繰り返さず、同一証拠の判断比較→同一初期証拠の調査比較→有望構成を新しい未見で確認。必要ならSonnetを標準、Haikuを容易案件だけに用いることも許容。低価格モデル優先を目的としない。調査と判断を個別に設定可能にする。前回検索2回の94%/81.40円と1回の90.5%/88.27円を揺れと断定できるだけの証拠は無い。検索を必要時に柔軟に利用する効果も比較。
- 現在output_config.effortを設定しているが、モデルが対応するeffort、thinkingの有効化方法・実際の応答/使用量、max_tokens（思考含む）、tool_choice互換性を公式仕様・実リクエストで確認。モデル名だけで思考が有効だと仮定しない。medium/highの費用予約と上限・時間を整合し、予算不足による比較の無効化を防止。事前に実験の総額/日次/1件上限・実行条件を点検（前回e3uの25→10円設定ミス再発禁止）。費用を使う前に原因の仮説、比較条件、判断基準、停止条件を定義する。ログに実際のモデル/設定、トークン、ツール、予約/実費、失敗・時間切れを記録。高推論の効果が小さい場合はその理由も検討。画像が重要な案件は解析を隔離評価で実証、現行/新方式で条件を揃え、別途本番の見積/承認を求める。
## 4. 現行との暫定比較を早期に行う
- 最低限の欠陥を解消した段階で、今回の工程内に現行方式との暫定比較を入れる。新AIの全機能完成や目標値の達成を待たない。過去の実案件・保存された現行の抽選/抽出/除外/保留・根拠と新AIを同じ基準時刻・独立正解で比較。現行の結果を正解として扱わない。新方式が現行より劣る点、現行が正しく処理できた理由、既存の有用な部品を再利用する方法を具体的に示す。独立した情報発見能力の総合比較は後続工程に残し、今回は取得済み同一候補の比較と可能なら発見の小規模比較を区別。実際の本番コスト/遅延も参考にするが評価と本番の条件差を明示。
- 候補単位と応募機会単位の判断、誤登録/除外/漏れ/余分、項目全体（漏れた機会も含む）・重要項目、正確率と取得率、正しい保留と不要保留、根拠のない推測、時間/費用を記録。raw AI→検証後の各段の差と原因別件数、現行との差を最優先に報告。対応済み機会だけの項目正確率で完了としない。重要項目分母にも未取得機会を反映。過去データは独立正解と証拠時点を合わせる。不明は無理に採点しない。正解/採点の変更は履歴に残す。新しい未見は診断・プロンプト改修後に独立して確保、少数の揺れを断定しない。

- 対象はポケモンカードおよびカードを含む福袋。カード以外のみ/他TCGのみ除外、混在では対象機会を抽出、カードの有無が不明なら追加調査。未知探索の前回成果は実質1機会（エディオン、二次情報2媒体の重複）。公式到達・開催回/店舗/商品/応募単位の名寄せ・既存情報との差を改善する。探索の全体評価は予定を省略せず後続に続けるが、この段階では判断構造の改善を優先。原文の圧縮は後回し。

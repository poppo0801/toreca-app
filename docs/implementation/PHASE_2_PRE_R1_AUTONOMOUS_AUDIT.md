# Phase 2：R1実AI試験前の自律監査・実投稿収集・夜の人手確認準備

状態：正式指示。実装の起点は未マージPR #120（`feat/phase2-gold-review-r1`）。実装PRは#120をbaseにして積み上げる。最新mainとの統合検証も行う。
参照：`docs/reports/phase2-gold-review-real-cases-r1.md`、`docs/AI_AUTONOMY_PRINCIPLES.md`、`docs/AI_REDESIGN_SPEC.md`、`CLAUDE.md`。

## 0. 目的と実施・承認の境界

**人によるgoldの確認は本日夜以降。それまで人手不要の範囲を自律的に完成させ、未知の不具合も探索→修正→再検証して、R1の実AI試験に進める状態で止めること。** 作業途中の個別承認を求めない。発見した解消可能な不具合を「既知の未解決」で報告するだけで終了しない。変更が別経路に与える影響まで横断監査し、必要なら設計を改善する。

**今回のユーザーの「進めましょう」は、前回提示済みの「保存された実投稿16件・t.co短縮URL95件の安全な公開URL展開・公開ページ取得」に限る承認と解釈する。** 既存の `real-posts-expand --allow-network` を使った公開ページ取得は次の安全条件内で実施してよい：
- 対象は保存済みの実X投稿16件からの公開短縮リンクとその安全なリンク先。最大150リクエストの計画（robots取得・リダイレクト等の付随リクエストも管理対象に含め、実リクエスト総量を正しく数える）、適切なホスト間隔（既定1.5秒以上）、並列/時間/総バイト量を明示。実装済みのSSRF保護・リダイレクト全ホップの検証・robots・利用条件・ログイン禁止・認証情報無送信を守る。
- **事前に実アクセスの実装とURL先検証を静的にレビューし、総HTTPリクエストに漏れ、t.coのLocation処理の誤り、HTTP先の不当な省略、全リンクの取り違え、危険ホストへの接続がないか点検・修正する。** t.coは短縮リンクの解決専用。利用条件・アクセス制限を回避しない。
- 150件を超える追加アクセス、サイトへのログイン、Xの有料API、有料検索/推論、大量巡回・未知ドメインへの無制限な探索は**許可対象外**。取得不能は理由と未取得件数を残し、執拗に再試行しない。アクセス上限や利用規約への疑義で安全と確認できない場合は、その宛先へのアクセスを中止し、結果を明記する。原文・ID・個人情報は公開リポジトリへpushしない。
- 本番DB/Storage/Vercel/cron/通知・既存の本番収集・本番APIの変更は禁止。新AI系PRのmainマージ禁止。**R1の有料Anthropic・ビジョン・Web検索は実行しない**。goldの人手確認済みフラグや `APPROVE C <金額>JPY` をAIが偽造/代理入力しない。ユーザーに求めるのは夜の最終gold確認と、実AI試験直前の具体的な金額承認だけ。

## 1. 16件の実投稿を安全に復元し、評価用の実例にする

- 既存の `real-posts-scan` → `real-posts-expand --allow-network` を無課金で実施。保存済み投稿・短縮リンク・展開先URL・取得ページ・出所・取得日時・理由別の失敗・更新時点を厳密に紐づけ、**投稿×系列×店舗×商品×開催回（応募機会）**の候補に分ける。SNS等の除外と、抽選フォームへの2段リンク・引用元・同一URLの重複・短縮先の差し替えを調べる。
- 実投稿から複数の応募ページが得られたケース数、2件以上の独立応募機会に分かれる数、リンクの展開成功率、robots/403/404/期限切れ/JSのみ/ログイン壁/時間切れ等の理由、調査に要したアクセス数・バイト数を実測で出す。**2URLが同じ企画の同一応募機会の場合は2機会と数えない**。
- 重要なリンクが失われたら、発見・短縮展開・安全取得・HTML本文化・保存・入力・AIの各段階で根本原因を調査して修正。実例不足をモックや合成で埋めたことを実例取得成功と主張しない。
- 合成 `synthetic_lp` と実投稿 `real_post` は独立した評価データ・結果とし、合成データを実測精度の根拠としない。新たに得た実投稿について再生可能なテストfixtureを、秘密や原文をGitへ公開しない形で作る。実投稿で有料R1が可能か、無理なら理由と今後の収集方法を明示。

## 2. goldレビューを「今夜すぐ確認できる」状態に整える

- 現在の `/dev/gold-review`（保存済みLivePocket 12ページ用）を、本工程で取得した実投稿・リンク先ページにも使えるよう設計し、**画面に確認対象・出所・投稿/ページの関連・応募機会候補を準備**。JSONを直接編集させず、ページ原文/取得日時/ハッシュ/重要な根拠範囲/未確認事項/候補値を見せ、項目ごとに人が検証・修正・除外を選べるようにする。公式性の自動断定は禁止。URLが開かない場合は保存原文との比較だけでは独立確認済みにしない。
- 年情報が欠けた締切は2026年に勝手に確定しない。UIで年を推測して事実に見せない。複数受付枠・店舗選択型・商品別独立応募などは候補を失わず、goldの1ページ1機会制限に合わなければ明示して別枠の試験へ振り分ける。
- goldの人間確認の真正性を守る。AI候補、旧方式の結果、模擬試験、ゴールド下書きは「未確認」のまま。判定する元文章・版・出所・確認者・日時・確認理由・履歴を記録。人間の操作なしに一括「確認済み」にしない。未確認が残れば実AIランナーを停止。ローカル/開発限定で本番URLからは404、バックアップと復元も維持する。
- 画面の負担削減（対象を重要度で並べる、確認すべき文字箇所への移動、複数ページ一括ナビ、途中保存、重複資料の再利用は**人の真偽確認を省略しない範囲**）。PCとiPhone幅390pxをE2E/実画面で確認。
- **夜に人が実施する操作を最大限簡単に**：必要な起動コマンド・設定・URL・対象件数・想定のレビュー順を報告書末尾に短くまとめる。

## 3. 未知課題の探索と性能監査（無課金）

- `linkLedger`・`pendingRecheck`・再調査DBキュー・保存ページ・AI入力・画像観察・`limits-audit` を通し、**上限に到達した場合の無言の欠落、URL取り違え、古い再取得結果による上書き、再実行の二重作成、全候補の同時実行、長文ページの後半の見落とし**を横断監査。
- 特に前回監査の「無言の欠落0」は検査対象範囲内の話。未収集リンクや本文の不可視領域・AI未読/誤判断を別に数える。24+6リンク、30ページ、6,000字抜粋、12,000字投稿/全文先行表示、20,000字統合入力、120,000字のページ、8〜10回のread、画像参照上限について、**取得→保存→AI参照→登録案の各段階で回復可否と再調査**を測る。実投稿が取得できたらその分布、観測不足の領域を併記。
- 独立機会の同一性（同じ系列の異店舗、同一店舗の別開催回、店舗選択型、商品別独立、複数応募枠）、誤統合・誤分割、画像のみの条件、期限切れと無効応募、地域条件、AIが自分の根拠ではないURLから引用する事故、通知・ユーザー応募履歴の保護を保存データ再生/契約テストで監査する。
- AIの `fetch/read/search` 範囲とgoldの根拠位置を照合する仕組みを無料テストで確認。goldがまだ無い実案件では根拠位置の代理として人未確認の条件語候補を使ってもよいが、精度/正答率を主張しない。誤りを見つけたら根本修正と同型欠陥の横断調査・回帰テストを行う。
- **実AI試験を始められる状態かを自動で判定するチェックリスト/plan**を作る。承認前に動かせる型検査/lint/単体/DB統合/E2E/build、ローカルDB migration 120〜122 適用/ロールバック/再適用、最新main互換性、認可・本番ガード、費用最悪予約、評価の独立性を全て確認。緩いテスト・無効化・skipで隠さない。

## 4. R1試験前の判断資料と翌工程

- 人手確認前に、**R1実投稿候補一覧**（本人が最小工数でgoldを作れる順序・各候補の重要性/根拠/未確認）、合成の補助ケース、必要な人手確認量、予算見積を用意。R1の小標本は精度を断定しない。
- ユーザーがgoldを確定してから `r1-build`/`real-validate`/`plan` を実行できるようにする。実AIの費用は前回の目安37円・上限60円/1件5円を前提に固定せず、対象件数、使用モデル、予算の最大予約額、想定トークン、停止条件を最新条件で提示。**明示的な金額承認が得られるまでは有料実行をしない**。
- R1完了後にR2全文、R3画像、R4経験ヒント、未知店舗/系列の発見力、登録精度、自己改善、運用費用の評価へ移行する計画を再整理。ただし本工程でR2〜R4の有料試験や本番移行を先行しない。
- 長期的に自律AIの性能と完成度を定量化するため、**実測指標**（発見率、応募機会再現率、誤登録/誤統合、正確な1件当たりの費用、独立goldの対象数、未確認の割合、再調査回収、AIの根拠参照率、繰り返し誤り、既存履歴保護）を計測・集計できる設計にする。現在の主観的な40点/72%を実測値として使わない。

# Phase 3 — 実案件の集中評価・全項目の精度向上
## 目的と最新合意
起点 main #170、docs/reports/2026-11-26-phase3-adaptive-review.md、#165の要件。新商品発売後に新規抽選が減る見込みのため、通常収集や利用者による大量の正解入力を待たず、保存済み実データ・過去の公開告知・未知の情報元を自ら調査し、短期間で精度を高めて実用化へ進む。単なる登録/除外の判断ではなく、実際の抽選管理に必要な情報を網羅して正しく取得できることを目標とする。個別系列の固定ルールを増やすのでなく、AIの自律的な探索、仮説、照合、情報補完、判断、改善を活用する。
- Claude Code は Opus 5.5 継続。モデル切替の履歴再読込も考慮し、構造が安定するまで変更不要。アプリ内APIモデルとは別。
- 現在承認済みの予算は1件25円・日次140円・通算180円、報告時の記録額157.21円（旧誤計上約16円を含む）、期限11/28 13:45 JST。既存キー・家族1世帯・シャドー隔離・新AIによる抽選登録/変更/削除/応募/通知禁止・現行稼働継続。予算や期限が足りない場合、用途・必要額/期間・現在の残額・見積を示しユーザーに直接承認を求め、承認後続行。予算は起点をリセットせず通常稼働分と評価分を明示。実データの調査・実装・検証・安全確認後の本番反映まで一括で進める。DB変更の安全手続と個別承認を遵守。無課金の作業は予算不足でも続ける。
## 1. 評価基盤の欠陥を先に是正
- candidates/page.tsx が review/pending/failed・lottery_id null に限定しており、現行で登録/除外済みの候補や登録案なしの取りこぼしがレビューから外れる。既存候補の通常表示を変えず、管理者用評価一覧/既存レビュー面で処理済み・失敗・登録案なしも参照できるようにする。根拠（取得元/応募先の区別、該当版の引用・原文・取得時刻、画像、現行の判断、AIの判断・理由・モデル段階・差分）を折りたたみで確認できるようにする。
- proposal-truth-report.mjs の truth_decision 未指定を AI の判断で埋め一致扱いする欠陥、検証を通過したSonnetを採用と数える欠陥を是正。人/独立証拠で確定した判断のみ精度の分母にし、項目だけの修正、保留、未確認、モデル食い違い、採用/未採用、試行/呼出し/案件単位を分離する。費用は版の保存件数でなく実行台帳の実測を集計。既存の judge_trail は各段の要約だけで、同じ入力/結果は store.ts で省略されるため、全試行の採用理由・判断・引用・証拠版・費用・時間・モデル/effortを評価記録から追えるようにする。既存資産を流用し巨大な新システムは不要。モック/再生/実AI、実運用/評価、人確認/AIによる独立照合を混同しない。
- review.ts/experience-store.ts の正解記録と経験保存を再点検（利用者権限と実際の保存結果、同一証拠版への対応、未確認をhuman扱いしない、以前の誤った経験の隔離）。根拠のない推定・応募単位や地域/商品/時刻の取り違えを検証済みとみなさない。必要な場合は最小の修正で是正。
## 2. 実案件を自律的に集める（新規抽選待ちにしない）
- 既存の collection_candidates（処理済み含む）、抽選管理の履歴、保存済み投稿/linkedPages/evidence_documents/画像/収集ログ、既存gold-review・eval/real-data・評価ツールを調査し、利用可能な実案件数・保存証拠の充足度・情報形式を把握。既存の正解は由来を確認し、過去の現行AIの判断や登録結果を無条件に正解としない。
- さらに必要な情報形式・未知の店舗/系列/ドメインをAI自身が公開検索・公式サイト・公開X投稿等から調査する。既存収集が発見できなかった例、URLなし/短縮/画像告知/複数商品・店舗・受付枠/LINE・Googleフォーム・通販・会員限定/日付の複数種類・変更告知/地域外・非抽選も含める。これらは探索のヒントであり固定ルールや特定店舗の網羅チェックリストではない。公開アクセスの制約・robots・利用規約・安全な既存取得機構を遵守。ログインや非公開情報を迂回しない。
- 過去の応募ページが終了・消失しているときは保存済み原文と公開告知を優先し、収集時点の状態と現在の状態を混同しない。現在のページだけで過去に応募不可だったと判定しない。証拠が失われている案件は評価不能として残し、無理に正解を推定しない。
- 評価は実案件優先。候補の重複排除、同じ応募機会/開催回/情報元のグループ化、十分な代表性を確保。目安としてまず数十件規模の実案件を無料/低費用で棚卸し・選定し、課金評価は小バッチで必要十分な件数から始め、結果に応じ増やす。目安を達成するだけの重複試験や合成例の大量作成は不要。既知の初回3件は回帰として分離。開発に使うケースと未見の評価ケースを先に分け、同一系列・開催回・ページの類似による漏洩も考慮する。未見ケースの正解を入力・プロンプト・学習ヒントに混ぜない。実行は本番共通処理を隔離評価で使用し、過去案件を現在の候補・通知・本登録へ流さない。未知情報元の探索はまず評価用の実証で、無承認の常時本番探索開始はしない。
## 3. 全抽選項目の取得と独立した正解の確立
- 実際の抽選カード・詳細・DB・登録フォーム・収集draftのスキーマを確認し、評価用フィールドを対応付ける。系列/店舗（複数・選択式含む）・所在地、商品（複数、数量、購入上限等）、応募開始/終了日時、当選発表日または期間（開始/終了日時、発表方法）、購入期間および受取期間（それぞれ開始/終了日時、購入/受取方法・場所・配送）、取得元/応募先URL、応募方法・条件（会員/アプリ等）、応募単位・口数、その他実アプリの抽選管理に必要な情報。日付だけ/時刻あり/期間/随時/未発表/記載なし/取得不能を区別し、勝手に補完しない。応募期間・発表期間・購入期間・受取期間を混同しない。現在の実アプリで表現できない必須情報があれば保存・表示との互換性を確認し、必要最小限の拡張を行う（現行動作に影響する変更は別途検証）。
- UIだけに項目を足すのではなく、AI出力→検証→保存→表示→正解→採点の全経路を点検。research-ai の最大項目数（12件等）・文字数/トークン制限で重要な項目が黙って落ちないようにする。必要な項目は汎用の正規化/構造化で対応し、個別店舗の規則を増やさない。複数日程/複数機会の対応関係と根拠の対象を保持。全情報の正確な取得が目標だが、告知に存在しない任意項目の不明だけで登録可否を保留にしない。
- 正解は対象AIの回答と独立して、Claude Codeが公式原文・構造・画像・必要なら別モデルの独立読解を照合して作成する。別AIの回答一致だけを正解とはしない。原文と一致する引用、ページ/版/時刻、解釈理由を保存し、機械的に確認できる事実、根拠ある解釈、未確定を区別。評価対象の出力をそのままgoldに流用しない。人が確認した正解とは別の由来で保存し、自動的にhuman確定にしない。正解の確度・未確定率を報告。人に依頼するのは、利用者の条件や意味の曖昧さなどAIが調査しても解決できず、改善の価値が高い案件に限る。
## 4. 必要時だけ使う人の正解入力環境
- 既存の proposal-preview/review と gold-review を再利用し、上記の全項目（特に応募開始、発表期間・発表方法、購入期間・受取期間・方法）に対応する。対象アプリの既存の日付入力・複数店舗/商品・選択UIを優先。必要な場合にだけ表示/展開するコンパクトなフォームで、正しい項目の再入力を要求せず、修正対象だけ編集。各項目の確認済/未確認/明示的不明/記載なし、正解判断の未指定を区別し、入力していない項目を自動で正解としない。複数機会の不足・誤分割/誤統合を記録できるようにする。自動フォーカス/自動プルダウンなし。iPhone相当の画面で使えること。正解入力は本登録や通知に影響しない。
- AIが確定できない案件の中から少数の優先案件を提示し、なぜ人の確認が必要か、対象項目・根拠・選択肢・既に判明した情報を示す。利用者が未確認/後で確認とできるようにし、通常の抽選利用を妨げない。入力環境は今回整えるが、利用者による一括入力を開発の前提にしない。過去のような大量の全項目入力を求めない。人の確認が必要な案件が無ければ依頼しない。必要なら具体的な画面への導線と対象件数を報告する。
## 5. 集中改善・再評価・実用化の判断
- まず現行版のベースラインを測り、未解決の原因を「未発見、誤った情報元、ページ取得/構造/画像/抽出不足、根拠があるのに活用できない、日付等の解釈、モデル/推論不足、検証/保存、真正な情報不足」等に分類。特に前回のイオン無関係ページ、通販一覧から詳細未取得、LINE告知、会員限定、複数期間の食い違いについて取得可能な情報をAIが自ら調べる能力を改善する。検索/追加調査/上位判断の使い分けを費用対効果に基づき改善し、取得できる根拠がないのにSonnetを呼ぶことを避ける。一方で真の難案件や誤除外を見逃さない。監査抽出と通常運用の費用を分ける。上位モデル使用率を下げること自体を目標にしない。
- Haiku/Sonnetの同一証拠比較、必要時の調査モデル/effort比較を、問題に応じて少数実施。現行の87.5%切替率は難案件8件の結果で通常運用の率ではない。判断の正解率、項目別正確性/取得率（原文に記載がある項目を分母）、重要項目の欠落・捏造、応募機会単位の再現率/適合率、誤登録/誤除外/不要保留/取りこぼし、正解確定率、情報元ごとの差、費用/時間/上位切替と改善率を、母数と内訳つきで測る。未知店舗の発見評価は既存候補内の判断評価と別にする。完全な母集団が不明なら発見率を断定せず探索で確認できた新規機会数/重複/誤発見を示す。
- 優先度の高い欠陥を原因→修正→再評価の順で解決し、未見実案件を用いて汎用性を評価。実運用で意味のある改善が得られるまで、承認範囲内で集中的に進める。単にテストが通ることや同じ3件の保留率改善を完了条件にしない。実用化に必要な品質基準を母数・リスクに照らして提示し、未達/未確認は明示。十分な精度が確認できれば次の本番移行（未知情報元の継続探索、候補提示、段階的登録等）の具体的な手順・安全策・費用・戻し方を提案する。今回の承認で自動登録や本番収集の切替を解禁しない。

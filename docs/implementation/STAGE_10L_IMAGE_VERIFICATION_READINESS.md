# Stage 10L：画像根拠の検証・精度の独立確認・CI／本番移行前レビュー

## 背景
`docs/reports/2026-11-21-stage10k-shadow-local.md` と `docs/AI_REDESIGN_10K_SHADOW_RUNBOOK.md` を確認する。10Kで公開応募ページの過剰な漏洩検出は解消（公開ページ20/20利用可能）、シャドー用キュー・ワーカー・予算・停止・DB統合テストがローカルで成立。一方、画像由来の `imageReadings` は旧AIの根拠抜粋に過ぎず、元画像の照合なしに fact として採用できない。人による独立確認とCIも未完了。

## 実施内容（まとめて進める）
1. 最新mainを `feat/10f-shadow-integration` に反映し、10Kまでのコードを起点にする。既存の安全境界と旧方式の非干渉を維持する。
2. **画像根拠の検証経路を完成**：公開画像の元データ／取得元URL・画像番号／読み取りテキスト・該当箇所を結び、出典・取得日時・画像ハッシュ等を保存できる形にする。画像そのものを無期限保存しない。既存の `imageReadings` を過信せず、実際に画像を確認できた場合のみ、画像に書かれた日付・応募条件・応募単位を `fact` の根拠として採用可能にする。検証できない画像由来の情報は inference/保留のまま。**画像根拠の出所をモデルの自己申告だけで確定させない**。公開画像に限定し、SSRF/robots/認証回避禁止、元画像の取得失敗・画像更新・曖昧な文字・複数画像・引用箇所不一致を扱う。画像解析の追加費用は上限内、不要な再解析をしない。
3. **独立した精度確認**：既存の開発・調整に使った暫定ラベルを正解扱いしない。ローカル確認手順で、人が短時間で確認できる少数の例（一覧の焦点、非抽選の除外、構造unknown、画像のみの重要事項）を準備する。ユーザーに大量の目視作業を要求しない。人が確認していない場合はその旨を明記し、精度の確定値を主張しない。開発データと独立の新規ホールドアウトを可能な範囲で確保し、検証後にその結果を使って修正したら開発用として扱う。
4. **CI・統合・回帰**：GitHub Actions/CIの状態を確認し、必要なら安全に修正。画像の真正性、引用の検証、未検証の拒否、漏洩検出、一覧の取りこぼし、シャドーの停止・予算・RLS・リース、旧方式の非干渉を重点テスト。tsc/lint/build/単体/DB統合を実施。PR #36と#46の依存・競合・本番反映影響を調べ、マージ順とロールバック手順を報告する。
5. **費用と環境**：実AI評価の追加上限は**50円・最大30対象・90呼び出し・公開ページ取得60回・原則1件3円**。既存の開発用キーをローカル評価のみに利用。本番専用キーは発行・設定しない。機密情報、個人の応募/当選/購入記録を外部AIへ送らない。Gitに原文・画像・URL・内部ID・秘密情報を載せない。ローカルDBのみ変更可。
6. **成果物**：`docs/reports/2026-11-21-stage10l-image-verification-readiness.md` に画像根拠の検証方式・実測、独立ラベル確認の状態、CI結果、残課題、PR #36/#46の安全な統合手順、書き込みなし本番シャドー開始の可否と必要承認を記載。ユーザー確認が必要な場合は具体的な最小限の対象を示す。

## 境界
**本番DBの変更、マイグレーション、本番デプロイ、本番シャドー有効化、PR #36/#46のマージは行わない。** 承認された範囲で実装・検証・報告まで一括実施。実用的な自律収集を優先しつつ、推測による誤確定、旧方式への影響、機密漏洩、費用超過は防ぐ。

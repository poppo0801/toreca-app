## 実装と実証（まとまった作業として実施）
1. **現状の実コードを先に調査**：`feat/10f-shadow-integration` に最新mainを取り込み、10M/10Nの一覧項目・観測・クラスタ・補完提案・条件・調査・ワーカーの接続状況を確認。10Nの実データ補完0の原因を、候補選定／URL欠落／観測の属性欠落／既存登録が充足／同一性判定／保護条件に分解し、測定可能な漏斗として報告。
2. **複数ソース補完の実証**：既存のローカル書き出しと公開告知を用い、一覧→公式X／店舗サイト／応募ページ、単独告知→応募ページなど**実際に異なる発信源**の同一抽選を追跡。保存済み短縮URLと新規`linkMap`、原文の範囲を正しく接続し、旧データにリンクが無ければ「欠落」と記録。公的にアクセス可能なURLのみ取得し、認証・robots・レート制限回避はしない。**欠落フィールドが存在しない標本では補完0が正しい**ため、実データで確実に欠落のある例を探索し、採用値と出典を人が検証できるようにする。見つからなければ未実証と明記。架空テストによる成功を実データ成功と数えない。
3. **公式発信者・信頼度**：ドメインが公式サイトか、SNSアカウントが系列・店舗公式として裏付けられるかを別々に検証。プロフィール自己申告・名称類似・ロゴのみでは確定しない。公式ページからの相互リンク等の根拠と取得日時を保持し、公式不明はunknown。情報源の信頼度と**個別の事実の新しさ／具体性／原文一致**を分離。後からの訂正、古い公式、転載、偽公式、共通フォーム、異なる開催回での誤採用を防ぐ。
4. **対象条件の不明36件を原因別に改善**：地域不明33、TCG不明17は重複計上あり。都道府県・市区町村・通販、店舗選択式の応募可能地域、商品・TCG種別、除外系列を**利用者の既存設定を読み取って**判断。既存の商品マスター・名称・系列・店舗所在地・公開応募条件・別ソースを根拠に段階的に補う。辞書の追加だけでなくAIによる限定的な補助を許可するが、出典不明の地名やTCGは確定しない。商品マスター未評価を「対象」と扱わない。対象／対象外／不明の理由・証拠と件数を前後比較。対象外は登録・通知不可、ただし監査可能な発見記録を残す。
5. **自動登録・更新の意思決定設計**：①確実な対象・独立応募機会・出典確認済み・重複照合済みのみ「自動登録可能（プレビュー）」②不足が軽微なら「情報不足を明記した候補」③応募単位・対象条件・同一性・重要な日時・公式性が曖昧なら「確認待ち」④明確な対象外・非抽選は除外、の判定表を作成。情報の欠落と矛盾を区別。締切の食い違いは安全側の暫定通知候補を提示できるが、原文未確認の上書きは禁止。登録済みの更新は**フィールド別**の補完・訂正提案のみ。応募済み・当選・購入・手動編集・★・通知・スルー等の保護状態は更新・削除・再紐付けをしない。判定は**本番書き込みを行わないプレビュー**のみ。
6. **照合精度とAIの揺れ対策**：A→B、B→A、訂正、同一店舗別開催、別店舗同商品、店舗選択式、同一フォーム複数商品、系列別名、同じ汎用URL、誤った公式表示、日付の食い違い、同じソース再取得を評価。AIペア照合の複数回の揺れは監査記録と保留にし、安易な多数決で自動統合しない。近似候補の選定漏れ・全ペア照合の計算量も確認し、件数増加に対して効率的な候補検索を設計。高確信の自動確定は機械検査・独立根拠を満たす場合に限定。
7. **人による正解確認を可能にする**：10M/10Nのローカル確認画面を統合または導線を付け、一覧の全件発見、同一性、補完前後、各フィールドの根拠、対象条件、登録・更新プレビューを少数の代表例で確認できるようにする。実際の人の判定がなければ、AI作成ラベルや機械的な一致を正解率と表現しない。レビューが未完でも作業は進め、未完と報告。難例・誤統合しやすい例を優先提示。
8. **コスト・セキュリティ・検証**：新規実AI追加費用**50円、90呼び出し、最大30対象、公開ページ取得60回、1件3円を上限**（すべての再試行・再評価・画像処理・調査を合算し、開始前に予約）。ページ取得はSSRF・robots・タイムアウト・深さ・回数を厳格制限。上限に達したら未処理を残して停止。既存の応募・当選・購入履歴や個人情報は外部AIに渡さない。tsc/lint/build/単体/DB統合/CI、緊急停止・冪等・順序不変・保護データ不変を確認。実データ原文・URL・ID・秘密情報はGitにコミットしない。

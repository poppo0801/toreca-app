# Stage 10Y 実装指示：実Web取得・応募単位の証拠評価・本番統合準備を一括完了

作成日：2026-11-22。目的：Stage 10Xまでの**実行できない評価基盤**を本番に近い、ただし**非本番・非課金**のE2Eにする。ユーザーは短い反復Stageの増加を望まない。既存機能を再実装せず、取得→AIへの証拠→応募単位判断→安全な登録案の通し動作と本番移行の最小障害を優先する。

## 承認境界
**今回行ってよい**：開発用の読み取り専用公開Webアクセス（robots・規約・レート・安全な取得を尊重し、無認証・無課金の公開ページだけ）、過去の評価資産の再生、コード改修、mock/ローカルDB・CIテスト、開発用PRと報告書。
**許可されていない**：有料の実AI・Anthropic web_search・X APIの新規呼出、モデル・検索APIの課金、PRのmainマージ、Vercel/本番DB/migration/cron/通知/ユーザー実記録の変更、本番APIキーの使用。実AIの再試験が必要ならモデル・トークン・対象・上限・コマンドを別途提示し、明示承認を得る（「続ける」を費用承認と扱わない）。

## 1. B2が実世界の公開ページを調べられるようにする
現在のB2は実Web検索で候補を得ても、`eval-b.ts` の `fetchPage` が保存済みHTMLのURLだけを受け付け、その他を `not_public` とする。この**テストハーネス側の制限**を解消。
- 保存HTML再生（厳密な旧基準）、安全な公開ページ取得（開発限定）の二つを**明示モード**で実装。開発限定の公開取得は既存の `safeFetch`/robots/SSRF/DNS再解決/全redirect/サイズ/タイムアウト/アクセス頻度/ホスト失敗抑制などを再利用する。新しい生fetchや回避用プロキシを作らない。クロール禁止・認証必須・個人情報を含むページは停止。URLの表示揺れと短縮URL/リダイレクトの扱いは「取得経路が裏付けられたときだけ」同じページとして数える。
- **Anthropic web_searchには課金があるため今回実行しない**。保存済みの検索結果、ユーザーがすでに取得している公開ページ、許される非課金の検索資産で検索候補を再生し、候補のページを開発用安全取得で検証。検索結果に正解ページが無い/取得不能/サイト側で受付終了/URL異同/モデルが選ばない、を区別する。
- B2は「URLをAIに与えない条件」で、検索候補から公開ページへの**実際の**到達・対応・応募単位根拠までを追えるようにする。検索候補が事前に与えられたmock/再生なら『AIがWeb検索で発見した実測』と呼ばない。
- できる範囲で**古い終了イベントと現行の公開応募ページを分けて**評価。終了ページの404をモデル能力の失敗として数えない。
- **公開サイトへのアクセスをこの場で行えるか否か・使った取得経路**を報告し、安全制約で無理なら代替の再生と未検証部分を報告する。

## 2. A/Cと根拠の実在・意味対応を見直す
- A12件の検証通過9件は**正答率ではない**。原文から引用が実在しても、フィールド値（店・開催回・商品・選択式/独立、期間、応募単位）がその根拠から導かれるか未検証。**構造化ページの受付枠・元の文言・出典と候補値を1事例1行で人間が確認可能なローカル限定の比較資料**を生成する。既存の10S人手レビューと10Tページ・10Wのgoldを再利用し、正解に独立根拠がある案件だけ採点。goldが無い場合は曖昧な正答率を出さず不足事例を具体的に整理。
- **Cは2回続けて予約額と上限の不一致で調査0回**。`scripts/xsource-10x.mjs`・`CaseBudget`・`runResearch` で、1件/総額/判断用予約/検索を含むpreflightを実行前に計算・検査。数値の丸め、実費が予約を超える場合の事後計上と停止/ログ/次呼出禁止をテスト。過少予約で本来のAPIの課金上限を絶対保証できないならその制約を明記し、確実な制御の前提を定める。**今回はCの実AI再試験をしない**。
- `max_tokens` 1800で調査出力が途切れるケースは、無課金で評価できる出力スキーマ・必要なテキスト量・完了理由・停止時の扱いを検証。安全であればプロンプト簡素化/上限設定案を実装・mock検証。実AIで直ったとは主張しない。
- HTML `pageText` の本文抽出で、必要な受付枠・商品・日付・応募条件が除去されていないか複数構造で回帰検査。本文欠落があれば見える化して保留。クォート実在チェックを弛めて見かけの通過率を上げない。
- 誤統合・誤分割・過剰保留・根拠のない確定を**別指標**。自動本登録判断をデフォルトにしない。

- A/B/C家族ユーザーの応募・当落・購入・スルー・手動編集・通知、地域・候補/重複、UI・画像・相場を回帰。**本番通常収集→X証拠→AI→登録案→通知**のどこが本当に接続済みでどこが未接続か、実在の関数/呼び出し元で示す。未接続なら安全な開発専用配線や仕様・PRまで一括作業。ただし本番で有効化しない。

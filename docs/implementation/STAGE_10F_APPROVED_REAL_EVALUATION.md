## 作業手順（まとめて進める。ただし人のレビューは省略しない）
1. `feat/10f-shadow-integration` を継続使用し最新mainを反映。既存の抽出ファイルを使用し、追加の本番DBアクセスはしない。
2. 30件の本文を安全に**ユーザー本人がローカルで全文確認できる**レビュー画面または確認シートを用意する。原文はGitHub・PR・ログ・ChatGPT・外部AIへ送らない。機械的な漏洩検出と伏せ字を行い、元原文との対照も人ができるようにする。AI自身の確認・推測・承認記録でBを通過させない。本人の明示的な各件「送信可／除外」の選択を必要とし、未確認は送信不可。安全なUIができたらユーザーに確認操作を依頼し、そこで一旦停止してよい。
3. Anthropicの**公式**APIドキュメント・利用規約でデータ保持期間、学習利用、ゼロ保持オプションの適用条件を確認し、実際の組織設定と照合する。確認結果を秘密情報なしで提示。未確認・矛盾・条件不適合なら外部送信しない。ユーザーが承認した保持条件と実際の条件が異なる場合は再承認を求める。
4. APIキーの専用化と実際の利用可能性、費用見積り・停止条件を確認。B/C/Eの承認記録はユーザー承認の事実と確認結果を正確に記録する（**Bの各件レビューは実際の本人操作後にのみ記録**）。ゲートが未充足なら`preflight`で停止し、実AIを呼ばない。
5. すべての条件が揃った後のみ、`scripts/eval-judgment-phase2.mjs` を使い最大30件・総額50円・1件3円の範囲で評価を実行。新方式の構造・機会数・関係・保留・根拠・費用・遅延と、旧方式の固定判定との差分を記録。旧の固定判定は通常収集のAI抽出そのものではなく、差分は正解率ではないことを明示する。異常時は停止し、二重送信を防ぐ。
6. 報告書 `docs/reports/2026-11-21-stage10f-real-evaluation.md` に確認件数・送信/除外件数・保持条件確認・費用・比較結果・懸念点・全情報/抽選候補の再整理テストへ進めるかを、原文・URL・ID・個人情報なしで記載。テストとCIを確認しPR #46を更新、未マージのまま報告する。

## 完了条件
人による全文確認と保持条件確認を満たした場合に限り、承認された予算内で実データ評価を終えること。本人の操作待ち・保持条件未確認・専用キー設定待ち等で安全に停止した場合は、**何が必要かを具体的に報告**し、承認を自動的に補完しない。

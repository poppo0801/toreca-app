# Phase 2：網羅的な証拠取得・保存・AIへの提供と構造的精度劣化の継続監査

作成日：2026-11-23。参照：PR #98→#100→#102（いずれも未マージ、積み上げ関係）。最新の監査報告：docs/reports/2026-11-23-phase2-e2e-integrity-audit.md。適用する原則：docs/AI_AUTONOMY_PRINCIPLES.md、docs/AI_REDESIGN_ACCEPTANCE_PLAN.md、docs/SPEC_GOVERNANCE.md。

## 目的
精度低下の原因を「AIの意味判断能力」と安易に決めつけず、収集・取得・保存・抽出・ツール注入・候補/出典の対応・AIへの入力・出力変換・検証・再評価の**全境界**で、情報欠落・誤対応・型/単位変換・隠れた上限・失敗の握り潰しを探し、再現・原因確定・修正・自動回帰テストまで行う。初期はデータの網羅性と判断に必要な証拠の確保を優先し、十分な実測がないうちから狭い固定キーワード・ページ位置・少ない件数に絞らない。人の訂正と独立goldを利用し、AIの判断を自由にしつつ重大な誤登録・誤除外を防ぐ。

## 権限・作業起点
- **PR #102 の最新ブランチ feat/phase2-e2e-audit をベース**に新たな実装ブランチを作り、差分PRのbaseは同ブランチ。PR #98/#100/#102はmainへマージしない。既存の変更を積み上げて扱う。
- 開発/ローカルDB/保存済み公開資料、モック/台本AI、偽検索、無課金の安全な取得、実装・試験・報告書・未マージPR作成を一括で許可。追加の**有料Anthropic/web_search/X API試験、本番DB/Storage/cron・Vercel・環境変数変更、新AIの本番有効化、自動登録・通知、実装PRのmainマージは禁止**。API費用の承認は別に求める。機密・原文・goldはGitに含めない。
- 公開情報もrobots、各サイト利用条件、SSRF、保存期間、プライバシー、サイズ・件数・時間・ネットワークの費用を考慮する。無制限なクロールではなく安全な上限と観測を備えた**広い取得**。既存の応募・購入・当選・家族別データを壊さない。

## 1. F1：取得した証拠を失わない保存
- 現状の定数と隠れた制限を**経路全体**で列挙する：src/lib/collector/evidence.ts の MAX_LINKED_PAGE_CHARS=3000、linkedPages.slice(0,2)、本文/links/linkMap/画像由来情報の切断、収集元x-richのリンク選択、HTTP取得側のバイト数/レスポンス時間/リダイレクト/本文抽出、DBカラム・JSON/Storage・読戻し・古いバージョン・UIなど。上限に達した時、切り捨てた文字数/リンク数/理由が観測できるようにする。切断を「情報なし」として扱わない。
- 原則「取得が許された公開情報は再解析できるよう**元の意味を失わず保持**」。全文テキストと取得URL・取得時刻・出典ID/ハッシュ・正規化前後・更新版/引用位置・切断/失敗の区別を設計。原HTMLの保持は利点・容量・機密・著作権と保存期間を比較し必要に応じ選択。DBの巨大JSONに安易に全量を詰めずStorage等の分離保存・圧縮・参照キー・アクセス制御も評価する。**単に3000→10000字に増やして終えない**。
- 複数リンクについて、元投稿の親共通/各項目のリンク/短縮URL展開/関連する応募先のリンクを追跡し、初めの2件だけ保存して捨てる設計を見直す。優先度はAIに委ねつつ、失われたものを記録。大量・巨大・ログイン必須・危険なURL等の安全上限、長期保存容量と削除方針、バックアップ・復旧、世帯の分離、旧版との互換性を検討。
- **開発環境で安全に実装できる部分は実装・テスト**する。DB migration/Storage設計が必要なら、ローカルでマイグレーションと復元リハーサルまで行い、**本番適用は別承認**。無断で本番に適用しない。

## 2. F2：AIが全文を参照できるが、必要以上に毎回送らない構造
- 初期は品質を優先し、情報が存在するのにAIには見えない状態をなくす。証拠全文（少なくとも取得時の全テキスト）を**ローカルで保持し、参照位置/根拠IDを伴ってAIが追加で見られる仕組み**を検討/実装。既存の2500字抜粋＋キーワード窓（8窓/1600字）は**初期の索引・ヒント**にすぎず、網羅性の保証にしない。
- 本文のチャンク分割・見出し/注意書き/フォーム項目との対応・重なり・全文の範囲と読了状況・追加参照ツール（読み取り専用）の設計を比較する。見つからなかった際に「全文確認済み」か「未走査・切断・アクセス不可」かを区別。調査/判断双方に証拠と必要な文脈が届くことを証明。インジェクションを命令扱いせず、引用の実在・出典対応を検証。トークン/レイテンシ/コスト見積と保護上限を維持。
- 実例 LP4（約3981文字目の店舗選択）・LP11/12、先頭と後半が矛盾する例、想定外の言い回し、否定文の前後、複数店舗/商品/開催回を混在させた例で、**キーワード抽出から漏れてもAIが原文にアクセスできること**を上位入口から契約テスト。
- 取得とAI送信の別予算・件数上限を管理。初期は多めの収集を可とし、**試験結果・実データの傾向を見てから**取得優先順・読む範囲・抽出方式を最適化。モデル訓練と混同せず、過去の根拠・人の訂正・成功/失敗情報をRAG/ルール化しすぎない参照用メモリに記録する。

## 3. ほかの構造的な見落としの横断調査
- これまで見つかった cachedTools.searchの消失、応募単位の注釈つきenum保存落ち、検索可能表示と実利用の不一致、判定rationale未保存、項目番号でのレビュー誤適用、3000/2500字切断を**典型例として同種の欠陥を探索**する。
- すべての固定上限・first/slice/substring・JSON変換・型キャスト・optional/undefined/nullの処理・HTML→抽出→構造化→AI入力→戻り値→DB→UIの境界・取得エラー分類・再処理・古い版・部分成功・バックグラウンド処理・重複候補のキーの安定性・ストレージエラー時の扱いを一覧化。上流では存在したフィールドを下流で欠落させない契約テスト（sentinel資料含む）。
- 特に多店舗/多商品・同一見出し内の入替・開催回差・別URL同一フォーム・共通URL別応募権を、出典と応募機会の対応IDを追って検証。**人の訂正が誤った項目へ移るリスクは重大。** 現状の見出し照合は部分改善と認識し、より安定な識別子・履歴照合を評価し、開発で安全に可能な範囲は実装。マイグレーションを要するならローカルのみで実施・検証。
- 警告を増やすだけで問題が解消したとみなさず、情報を回復できるなら回復し、不可なら必要時に人へ回す。保留率を下げるために根拠を捏造せず、AIが必要情報を見られる状態を優先する。

## 4. 計測・継続学習の基盤
- サイト/ページ種類/出典別に、取得情報量・切断の有無・実際に参照された位置・重要条件の発見位置・追加参照回数・未解決理由・ページ再取得の成否・費用・処理時間・確認結果/人の訂正を**個人情報・原文をログに残さず**記録。元の証拠はアクセス制御下に保管。
- 初期は広く収集し、goldの人手確認・失敗例・長文後半の発見例を記録して、後から**効率化の比較実験**（全文・索引・限定取得の取りこぼし/費用/時間）に使えるようにする。サイト名による固定ルールを増やすのではなく、確かな傾向を候補として提示しAIの判断に活かす。未検証を成功に含めない。
- 独立goldの母数が少ない場合、正答率を推定しない。モックで証明できるのは経路と保存完全性であって実AIの判断精度ではない。

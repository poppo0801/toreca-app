## 1. PR依存と競合を解消するための開発準備
1. #36→#46→#82の積み上げ関係を調べ、#36とmainの競合の実ファイル・理由・現行UI/非公開画像への影響を示す。最新版mainに追従する**安全な統合ブランチ**を作成。履歴を破壊するforce pushやmainへの直接pushは禁止。
2. 非破壊の競合解消と必要なテストを行い、10E〜10Uの各差分を不用意に失わない。既にmainに入ったUI/画像/購入/相場等を巻き戻さない。変更内容・元PRとの対応を表にし、開発統合PRとCIを提示する。
3. 依存元の旧PRを自動マージ/クローズしない。実装をmainに入れるマージはVercel本番反映に該当するため**ユーザーの別途承認待ち**。統合ブランチのPR作成と検証は可。大規模DB変更、新しいマイグレーション、合意済み基本設計の変更が必要になれば、根拠・代案・安全策を説明し承認待ちとする。

## 2. X投稿→応募URL→AI判断までの切れ目を埋める
1. 10Sの `link-scope.ts`・`item-links.ts`／linkMap、10Tの `page-structure.ts`、10Uの `research-loop.ts`・`research-ai.ts`、10Eの共通案件・Evidence、既存X/Web収集、`opportunity-job.ts` を追跡。**取得した元投稿→各抽選項目→各項目の応募先URLと出所→公開ページの受付構造→AIに渡す証拠→AI判断→登録案**の対応が切れない開発用アダプタを実装する。既存資産を再利用し、同じ意味判断処理を重複実装しない。
2. X投稿の一括リンクを別店舗へ流用しない。URLが本文・画像・引用元・スレッド・公式ページのどこから来たかを保存。元のURLが欠けた事例は「URLなし・応募単位未確認」として追跡可能にし、勝手な確定をさせない。公開ページ取得不可なら、取得状況と理由を残す。不要な再取得はキャッシュ・履歴・レート制限で抑制。
3. LivePocketのページ本体の受付枠と「同じ販売元のイベント」は別の観測情報とする。関連イベントがあることだけで複数応募可と断定しない。逆に、同系列・同時期というだけで独立応募を統合しない。フォームの選択肢・商品/店舗/開催回・横断制限のスコープをAIへ渡す。
4. 実X APIキーが使えない場合も、権利・秘密の問題のない**保存済み公開投稿・検証済み例の再生**とモックで入口を通す。新規APIキーの要求や課金、ログイン／CAPTCHA回避をしない。実X取得ができなければ「X本番接続未検証」と明記する。
5. 登録/除外/暫定候補は10Uの独立したAI判断→検証層の結果とし、意味判断を後段固定ロジックで上書きしない。安全な開発用プレビューと履歴保護ガードへ接続。**本番の通常収集・cron・通知・本番登録への配線は行わない。** 応募・当落・購入・スルー・手動確定値を変更しない。

## 3. 実AI評価の準備・検証設計
1. 10Uの `research-10u-real.test.ts` 等の実AI評価コードを監査し、**評価の名称と実際の入力条件の不一致を解消**する。現コードは「応募ページURLを種に含めない」とコメントしながらseedに `応募ページ: URL` を含む。URLが与えられる条件と、XからURLを発見・関連付ける条件を区別し、テスト名、入力、比較対象を一致させる。前者を後者の発見精度と偽らない。
2. 最低限、(a) 応募URL既知のページ構造・判断評価、(b) X投稿/保存済み投稿からリンクを展開する発見・対応付け評価、(c) 既存の人手30件レビュー等のうち出典を検証できた実例での登録判断評価を別々に用意。ページHTML・候補URL・ユーザー回答の所在が分からなければ、実例不足と記録。架空ケースは安全性・回帰テスト専用。
3. 同じ証拠を旧方式と新方式に渡して、応募機会の誤統合・誤分割、登録／暫定候補／除外、見逃し、根拠一致、追加調査で得た情報、調査の停止・再開、費用、処理時間、確認負担を比較する。入力正解（gold）はAIに渡さない。旧方式・過去AIの結果を正解とみなさない。人が根拠を確認できない事例は正解率の分母に入れず、取得不能・評価不能として別計上。
4. 実AI評価は**承認後に別途実行**。現報告の提案上限は**対象12件・最大90呼出し・総額50円**だが、実装・再試算後のモデル、最大呼出し、1件あたり上限、総額、再実行の扱い、使うキーの環境、本番キーの不使用を説明し、**ユーザーの明示的な費用承認**を求める。現段階で `JUDGMENT_*_REAL` のゲート解除や実課金リクエストを実行しない。費用が不明なら0円扱いしない。
5. 実AIに接続していないモックテストの「誤統合0」「履歴破損0」は、**モック条件での合格**に限って表現する。通知・本番DB・実登録が未接続ならその安全性を証明済みと書かない。

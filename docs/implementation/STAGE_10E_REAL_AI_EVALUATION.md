## 2. 第1段階：実AI評価
- 評価対象は`eval/judgment-10e/cases.json`の架空19判断事例（候補検索だけの2件はAI精度の分母に入れない）。正解は`gold/gold.json`を**採点側だけ**で利用し、モデルへ送らない。Web検索・実ネットワークページ取得・実ユーザー情報・本番DBアクセスは行わない。
- 事前にモデルID、利用可能性、価格、必要な環境変数、`preflight`見積もり、承認額内での停止条件を確認する。予算は**総額30円、1事例2円**を絶対上限とし、失敗・再試行・使用量不明も保守的に計上。超過リスクがあれば実行前に止める。実行回数を無断で増やさない。
- 開発専用の`JUDGMENT_EVAL_API_KEY`が安全に設定されている場合のみ、既存の`scripts/eval-judgment-real.mjs`と`real-gate.ts`の関門を通して実行。キーが無ければ設定案内と、未実行のpreflight結果を報告して待機。秘密をログ・Git・PRへ出さない。
- 実AI評価の指標：採用/拒否/保留、応募機会構造、機会数、系列/店舗/商品、日程・地域条件、誤統合/誤分割（別集計）、出典の裏付け、既存履歴保護、誤った断定、再判断回数、遅延、実トークン・実費用。検証不能の事例を正解率の分母に含めない。
- 評価結果を具体的な事例IDと根拠で分析。AIの判断ミスと出力契約・検証器・プロンプト・費用/再試行の問題を分ける。プロンプト修正が必要なら、修正前後を**同じ採点基準**で比較する。追加の有料再実行は30円の**累積**上限内のみ。実測できない項目を推測で埋めない。
- 旧方式との比較は、同条件で測れた構造判定のみ。旧方式の抽出・登録の総合精度を比較済みと記載しない。

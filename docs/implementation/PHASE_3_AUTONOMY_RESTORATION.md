# Phase 3 — 自律型AIの設計思想の是正・弊害となる制約の撤廃
起点 main #184、報告書 docs/reports/2026-11-27-phase3-capability-ceiling.md。利用者の2026-11-27の明示指示: 保守的な設計、固定検証、調査・推論の制限は利用者の希望ではない。これらの弊害をただちに見直し必要に応じ撤廃、AI本来の性能を引き出す。元の不適切な設計による手戻り・費用をこれ以上増やさない。今回は個別事例への例外追加や新しい評価基盤の整備でなく、設計の実質的な是正と本番シャドーでの機能回復が主目的。Claude CodeはOpus継続。
## 0. 恒久方針の是正（最優先・利用者の明示決定）
- docs/AI_AUTONOMY_PRINCIPLES.md の原則を今回の決定で具体化し、CLAUDE.md 冒頭の必読指示、DECISION_REGISTER、CURRENT_SPEC、SPEC_GOVERNANCE、ACTIVE_ROADMAP等の該当箇所を整合させる。古いStageの暫定制約・仕様が最新方針に反する場合は最新方針を優先。古い履歴は改変せず失効/置換を明記。ユーザーの要望、技術上の事実、開発者が決めた暫定措置を区別。保守的な制約をユーザー仕様とみなさない。
- AIが総合判断の主体。探索、情報の取捨選択、調査の方法/順序/継続、複数機会の理解、情報源の信頼性・意味、登録/除外/保留、名寄せ、重複、判断の再検討は原則AIが担当する。店舗固有ルールや語彙/閾値による意味判断を増やさない。プログラムは取得・保存・ツール実行・客観的な整合性/引用実在・権限・費用/暴走防止・履歴保護を担当。固定ルールをAIへのヒントにする場合も絶対条件とせず、AIが異なる結論を出せるようにする。
- 制約は存在すること自体を正当化しない。実測で必要性・利点と機会損失が説明できるものだけ採用し、代替案（再開、非同期化、根拠再調査等）を先に検討。暫定制約には理由、適用範囲、解除条件、見直し時点を明示。性能に関わる制約が追加/変更されたときは報告に記載し、重要な制約を無断で恒久化しない。通常の実装上の選択をいちいち承認待ちにせず、影響のある設計判断を可視化する。ユーザーが示した実例・仮説は固定規則ではない。
- 性能優先→実測→必要最小限の費用最適化の順序。以前の低コスト目標を性能を犠牲にする絶対条件にしない。APIのモデル/推論・調査能力は費用と精度の実測で選ぶ。不要な文字の削減はデータ蓄積後に検討、今回着手しない。原文保持と必要な範囲へのアクセスを優先。
## 1. 承認境界
通常シャドー通算1250円（前報告314.72）、日次200、1候補25、期限12/3 23:59 JST。隔離評価通算3700円（前報告2299.99）、日次1500、1候補100、1バッチ500、期限12/3。最新残額と実費を確認し、予算不足が見込まれた時点で用途/見積/必要な上限を利用者に直接提示、**日次リセットを待たず即承認を求める**。必要なDB移行はバックアップ・復元/権限/既存データ保護を示し直接承認。新AIの登録/変更/削除/応募/通知、常時未知探索、恒常的費用の追加は別承認。既存キー、家族世帯、現行の稼働を維持。外部アクセスのSSRF/robots/認証等を迂回しない、個人情報・プロンプト注入・費用上限・ループ/異常停止・人が確定した値の保護は維持。AIの意味判断を実験/シャドーで自由にすることと、本番データへの無制限な変更権限は別。明確な修正は既存承認範囲で実装・検証・本番シャドー反映まで行う。
## 2. 実際に性能を阻害する仕組みを撤廃・再設計（最優先）
- #184の16項目台帳を起点にし、前回と同じ棚卸しをやり直すだけで終わらない。収集・候補選別/分割・入力・調査・推論・判断・検証・統合・保存・経験活用・キュー/予算・環境フラグを横断して、意味判断の固定分岐、暗黙の上限、先行候補/現行の誤りを引き継ぐ構造を特定し、弊害のあるものはコードから除去/適切に置換する。変更前後の実効条件、残す理由、廃止した処理、本番で動いている証拠を示す。評価だけで緩和して本番は旧制約のまま、という状態を解消する。テスト合格のみを完了にしない。
- **時間・回数・推論を一体で再設計**: 候補全体45秒、開始35秒までしか思考しない（proposal-job.ts SHADOW_THINKING_WINDOW_MS）、追加検索1/fetch3/turn4等が能力を抑える。Vercelの制約は1回の関数実行の外枠として扱い、調査全体の締切にしない。既存の耐久キュー・中間記録を再利用し、応募機会ごとまたは調査ステップごとの再開可能な実行を実装する。親の候補を早期に完了させず、全機会に調査機会を保障し、新しい機会の発見/追加・共有証拠・依存関係・期限優先・中断再開・冪等・重複請求/並列ロック・実費精算を扱う。必要に応じ既存のジョブ基盤の範囲で構造を簡素化する。1回のAPI通信240秒と実際の関数上限の不整合を解消。安全な残時間/中断・次回再開で運用し、後半の重要な判断だけ思考なしにする設計をやめる。時間/予算切れは未完了とし、情報不足の保留や除外と混同しない。費用・ループ防止以外の回数制限はAIが必要性を判断できる仕組みへ。総額に達する前に承認、通常稼働の予算枯渇は可視化。
- **AIの調査・判断を統合**: 最初の調査に不足がある、根拠が弱い、判断が割れる、検証で矛盾が出るとき、同じ資料の読み直しだけで終えずAIが追加調査へ戻れるようにする。上位モデルも検索/取得/画像/原文読み戻し等を使えること。Haiku medium＋adaptive thinkingを当面の有望基準とし、難易度/必要性に応じHaiku high・Sonnet medium/high等を選べる構成を実装。上位が必要かをページの有無やaskHuman自己申告等の固定条件だけで決めない。上位が自ら追加調査できることを実データで確認。実際のモデル・effort・thinking/ツール使用・費用・時間を記録。思考機能が実際に働いていることを調査と判断の両方、後半の機会でも確かめる。既存の構造化提出の形式チェックと客観的根拠チェックは維持し、強制ツールで思考を止めない。
- **固定意味検証を置換**: research-loop.ts verifyRegistration/claim-semantics.ts 等の語彙にない理由で保留、ページの有無で除外を止める、混在ページの単一語で別機会を止める、応募単位の形式を強制するなどを調査。引用の実在、時刻・数値・対象ID等の客観的整合と、意味・文脈・信頼性の判定を分離。後者はAIによる根拠の評価、必要なら独立AIの再確認と追加調査へ置換する。独立検証AIを全案件に機械的に追加し費用を膨らませない。単純で明確な案件はAIが一度で完結できるようにする。機械的な失敗で全体を保留にせず問題の項目/機会を特定し解消する。AIの判断と検証の不一致は双方の根拠・対象・時点を再確認、解決できないもののみ保留。真の不明や危険な書き込みは無条件に通さない。現行の除外ロジックを結論として復活させない。
- **対象商品の意味理解**: ポケモンカードとそれを含む福袋/セットのみ。フィギュアやサプライのみ、他TCGのみは対象外。カードイラストフィギュア誤認を、商品そのものを確認するAI調査と根拠により解消（当該商品名だけの例外規則禁止）。混在告知の別々の機会、Xフォロー/RP企画、公式投稿の締切、延長、地域外/通販、画像のみの条件を実例に、AIの自律判断で解決。画像の本番解析は前報告未承認、実際のコードの有効状態を確認し、隔離評価の必要分/本番費用の見積を速やかに利用者へ提示して承認を得る。画像の重要情報を無視したまま精度不足と判定しない。
- 前回の未確認事項（構造付き全文、40桁ハッシュ、版選択、全文ハッシュ、旧締切に依存しない評価、受付終了のAI判断、未確定費用の計上）も本番で実際に確認。新規データ不足なら安全な隔離再生と本番未確認を明示。現行の誤判定を新AIの発見/評価の入口で失わない。

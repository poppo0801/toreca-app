# Phase 2 R1: 初回実AI評価直前の是正と実行可能計画

## 背景
未マージ実装PR #124（base #122）において、合成Gold 12案件/36機会、実投稿Gold 4案件/9機会を検証済み。実AI未実行。ユーザーは残り57ページの手動確認を求めておらず、同一LivePocketサイトの反復よりAI実測を優先。2026-11-24の報告では「合成12案件の期待費用約37.4円、実投稿4案件の期待費用約8.3円、総額60円・1案件5円」とした。合成は構造検証用、実投稿は小標本で改善の断言不可。現状のgold時刻採点は分母0。

## 目的
**初回の実AI実験を安全・検証可能な状態に整え、明示的なユーザーの費用承認を受けた後にだけ初回小規模評価を実行できるようにする。** 本依頼では有料APIを呼び出さず、承認を待つ。

## 必須作業
1. GitHubの最新実装PR #124 `feat/phase2-r1-final-preflight` を起点に新機能ブランチ・積み上げPRを作成する。**新実装PRは#124をbase**。過去のmainへの未マージ実装PRを一括マージしない。最新mainと衝突する場合は証拠を残す。
2. 既知の日時解析の誤受理を修正：24:00だけを次日00:00として許可（24:01〜24:59は不正）、12時間制では午前/午後1〜12時以外を不正（午後13時など）、12:00 AM/PMと午前/午後0時、全角表記、「23時」「23時59分」、日付跨ぎ、無関係な時刻の取り違えを検証。確認画面・gold検証・採点の共有実装を整合させる。不正な時刻を都合よく自動補正しない。時刻が原文にあるだけで「応募締切時刻」とは認定せず、証拠文脈・人の判断を必要とする。
3. 既存goldを一切自動編集しない。時刻入力済goldは0件という事実を維持し、入力を推奨する場合は**最小2〜4ページ程度**の本人操作方法を画面URLとともに日本語で簡潔に提示する。8ページ全部は必須にしない。時刻採点をしない場合も、日付や年の評価を進められる。
4. **予算承認の整合性**：各段階の上限額は「同じ総額60円の内枠か、別々の承認か」を明示。合成4案件A〜C（各期待約12.5円）、実投稿4案件（期待約8.3円）を合わせた期待値45.7円。各ステップ20+20+20+15=75円という別承認例は60円上限の説明と混同させない。利用可能な実装の費用管理が**プロセスごとにリセット**されるなら60円を全工程通算上限と誤称しない。少なくとも初回合成4案件（2アーム/8回）の予約最大3.6円×8=28.8円、期待約12.5円。先の報告の「上限20円」は完走保証ではない。初回の上限・1案件上限・停止条件を明確に記したplanを提示。必要なら費用集約台帳を追加して二重実行/再実行・異なる段階での通算を検査し、仕様より強い保証を主張しない。
5. 無課金のreadiness/plan/モックと関係するテストを実施し、対象案件の順番、件数、アーム、API試行数、最大予約・期待費用、課金上限で止まる可能性、採点指標（見落とし、誤登録、異店舗・別抽選混同、根拠、締切時刻）を出す。製品に無関係のデータの除外と複数リンクの統合も検証。実投稿4案件については別サイトが未取得なので一般化不可と明示。
6. `cautionSummary`のDB境界正規化で不正値を補う修正がユーザーの実データ上で画面遷移を直したか、ローカルだけで可能な範囲で確認。実データが無ければ再現未確認として残し、テストの成功を実機成功と偽らない。
7. ドキュメント `docs/reports/` に検証結果・正確な費用区分・Gold時刻母数・独立した実投稿評価の限界・必要な承認文の**例ではなくユーザーが選択する承認形式**と具体的な初回実行コマンドを記載する。Windowsでのnpm/npxを示す場合は`npm.cmd`/`npx.cmd`を使う（nodeコマンドはそのまま）。新PRリンクと短い完了報告。既存のスマホ通知は継続。

## 安全と禁止事項
- **今回の実装作業では有料AI/APIを実行しない**。金額の承認文をAIが作成して実行コマンドへ代入することは禁止。ユーザーが金額と対象・範囲を明示承認した次段階でのみ実行。
- 本番Vercel/Supabaseの変更、DBの本番移行、ユーザーの応募/購入履歴の変更、秘密情報・goldのコミットを禁止。
- 未確認57ページの人手再入力を要求しない。既存goldの確認済み状態を勝手に更新しない。
- 今回の機能PRをmainへマージしない。課金予算を勝手に上げない。

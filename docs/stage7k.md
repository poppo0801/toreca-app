# Stage 7K: 購入・開封記録の再設計と各画面のUI改善

## 購入記録の新しい考え方
- 購入記録 = 開封した商品と購入したシングルカードの数量・金額。収支（お金の動き）・コレクション（所有物と評価額）とは別の見方。
- 対象とタイミング: BOX・単品パック・デッキ/セットは開封・使用開始時点、シングルカードは購入時点。未開封BOXは含めない（収支・コレクションには残る）。
- 収支（purchases）には一切書き込まない。新しい支出は作らない＝二重計上しない。

## データ
| 種別 | 元データ | 備考 |
|---|---|---|
| BOX開封 | `box_movements`（open）と `box_lots` から導出 | 取り消し(`reverts_op`)した操作は除外。金額=ロットの実際の購入単価×数量。パック換算=商品マスター入数（不明は推測しない） |
| 単品パック/デッキ/セット/個 | 新表 `opening_records`（マイグレーション 84〜86） | 取り消しは `archived_at`（物理削除しない）。購入明細との関連で二重計上を防止 |
| シングルカード | 既存の購入（シングル分類） | 購入日基準。枚数固定 |

- `opening_records`: RLS（世帯単位）、操作ID(`op_id`)で冪等、数量1〜9999、単位 pack/set/piece、金額NULL=未設定（0円とは別扱い）。商品の統合・削除に追従（削除は参照があると不可）。
- マイグレーション86: 商品直接削除時の外部キー(set null)と衝突する「商品か名称が必須」チェックを削除。検証はアプリ側（`saveOpeningAction`）で継続。

## 既存データの移行結果（本番・読み取りのみで分類）
開封済み 0 / 未開封BOX 2（コレクション保持）/ BOX未登録 1 / 開封状態が不明な非BOX 0 / シングル 2件・6枚・6,260円。
不明なものは確定せず「開封状態が不明」から後で確認・登録できる（一部数量だけの確認も可。金額は購入金額を数量で按分）。

## 表示
上部4項目（BOX / パック / その他商品 / 総額。金額未設定は0円扱いせず注意表示）、タブ（商品別累計・購入履歴）、絞り込み（すべて/開封/シングルカード、期間、商品、店舗、プロフィール）。

## UI修正
- 対戦記録カード: 名前の固定幅でデッキ名の左端を揃え、右端の◯×△はSVGで統一。
- 収支の支出内訳バー: 一本の角丸バーを割合で色分け（ポケモンカード→シングル→周辺グッズ→経費→その他）、0円は幅なし。
- 抽選詳細: 日付・期間を罫線形式の2列に、全プロフィールの応募状態を上部に表示、ステータス行は1行。
- 受付状態: 受付前 / 受付中 / 受付終了。「応募不可」は条件で応募できない場合のみ（日時不明は断定しない）。通知・応募管理ロジックは未変更。

## 制限・未解決
- 開封済みへの移行は、確認できるものだけ（現状0件）。
- 既知の既存失敗（Stage 7F以前から）: supabase E2E の「自動収集の設定」「ロゴ」。

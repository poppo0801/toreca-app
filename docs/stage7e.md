## 1. 第二ユーザーの「他のユーザーの応募状況は変更できません」（根本原因と修正）
- エラーは `lottery-service.ts` の `setAppliedCore`（アカウントの担当プロフィール ≠ 操作者）。サーバー側の権限確認は正しく、Stage 5I の結合テストが A/B の独立・他者の変更の拒否を確認している。
- **原因はクライアント**: `app-provider.tsx` の `run()` が操作者を `profileId ?? 先頭の有効なプロフィール` で決めていたのに対し、画面に表示するプロフィール（`value.profile`）は `profileId ?? 端末に保存した選択`。**再読み込み・再起動のあと**（`profileId` の state は未設定、端末に第二ユーザーが保存されている）は、画面は第二ユーザー、操作者は先頭の第一ユーザーになり、第二ユーザーのアカウントへの操作が「他のユーザー」と判定されていた。ユーザーを切り替え直すまで再現し続けるため「場合がある」エラーに見えた。
- **修正**: `resolveActorId(profiles, selected, saved)`（選択中 → 端末に保存した選択 → 先頭の有効なプロフィール。表示と同じ規則）を操作者の決定に使用。サーバーの保護（本当に権限が無い場合の拒否）、サブプロフィールの権限、メッセージ文言は変更していない。
- 確認: 単体（解決規則・保存済み第二ユーザーでの操作者）、実Supabase E2E（`stage7e.supabase.spec.ts`: A応募済み→再読み込み後にBが応募済み／B応募済み→再読み込み後にAが応募済み。Aの記録・Bの記録は書き換わらない）。**修正を外すとこのE2Eは失敗する**ことを確認済み。既存の結合テスト（stage5i: 権限・独立、stage6n: 店舗選択式のプロフィール別応募店舗）は変更なし。

## 2. 購入記録ページ（`purchases-view.tsx` / `lib/purchase-records.ts`）
- タブは左が商品別の累計・右が購入履歴。**初期表示は商品別の累計**（再読み込みなしで切替）。
- 上部は「購入件数・購入金額」のカードをやめ、横4分割の1行（BOX｜パック｜その他商品｜総額）。
  - BOX: BOX単位の合計数量。パック: 単品パック＋BOX×商品マスターの入数（入数が未設定のBOXは換算せず、「＊」で注記）。その他商品: デッキ・セット商品などの個数（`set`/`piece`。BOX・パック・シングルカード・支出品目「その他」は含めない）。総額: 購入明細の金額合計（既存の計算。BOXのパック換算で二重計上しない）。
  - 購入実績の対象は ポケモンカード・シングルカード・その他（周辺グッズ・経費は収支のみ）。購入条件・売却原価の対象（`isCardPurchase`）はポケモンカードのまま。
  - 旧データの「シングル…」と自由入力された `pokemon_card` の記録もシングルとして数える（`isSingleItem`）。
- 絞り込みは月選択の右の小さなアイコンボタン（専用の1行を廃止。設定中は印）。
- 商品別累計: 左に画像、右に商品名・**累計パック数（大）**・補足（「3BOX ｜ 購入総額 21,600円」）。セット商品は「3個」、シングルカードは「6枚」。パック換算できない商品はBOX数を表示（推測しない）。集計はマスターID優先、未紐づけは正規化した名称が一致するものだけ（類似名は統合しない）。並びは数量の多い順。売却・開封・譲渡で過去の購入数量は減らない。「セット商品の購入は…」の説明文は削除（計上ルールは変更なし）。
- 購入履歴: 日付見出しを廃止し、取引1件ごとの独立カード（収支と同じ形）。購入日はカード内、数量は「3BOX」「6個」「3枚」（数量→単位）、金額は右寄せ。「コレクションに追加」のリンクは削除（購入記録とコレクションの連動は変更なし）。

## 3. 支出品目（`lib/expense-category.ts`）
5分類: ポケモンカード(赤)・**シングルカード(オレンジ `--cat-single`)**・周辺グッズ(青)・経費(緑)・**その他(グレー `--cat-other`)**。既存IDは変更なし（DBは品目コードの形式だけを制限しているため、追加にマイグレーション不要）。収支の分類別集計・内訳バー・取引ラベルは分類定義から生成されるため自動で対応。
- シングルカード: 単位は「枚」固定（画面は無効化した「枚」を表示、保存は個＝`piece`のまま表示だけ枚。既存の記録の品目は変更しない）。
- 数量と単位は**同じ行に横並び**（数量欄は狭く、単位が残りの幅）。複数商品でも同じ。商品マスターの標準単位を初期値に反映（既存の `unitForProduct`）。開いた直後のフォーカスなし（Stage 7Dを維持）。

## 4. 購入記録の標準画像
- 設定 > 表示設定 > 購入記録の標準画像（シングルカード・その他）で、登録・変更・削除。PNG/JPEG/WebP 3MBまで、長辺360pxに縮小して保存。
- 保存: 画像は既存の非公開バケット `product-images` の `<世帯ID>/default-images/`（内容ハッシュ入りの名前）、参照は新テーブル `item_default_images(household_id, category, storage_path, sha256)`（品目ごとに1行・RLS）。配信は `/api/default-image/<品目>?v=<ハッシュ>`（認証付き・長期キャッシュ）。
- 表示の優先順位: 商品個別の画像 → 品目別の標準画像 → 画像なしアイコン。購入記録ごとに複製せず共通の1つを参照するので、登録すると既存の購入記録にも反映される。購入履歴・商品別累計の両方。

## 5. 当選タブの受取完了アニメーション
- 「受取を記録」が退出アニメーションの共通部品（`apply-exit`）を使わず、カードが突然消えていた（Stage 7B）。`won-actions.tsx` の受取の記録で `exit.begin` → 保存成功で `ok()`（右へスライド → 画面外 → 下のカードが詰まる。速度・距離・イージングは他タブと同じ）、失敗で `fail()`（元に戻す）。当選タブから外れないカード（他プロフィールの当選が残る）は退出しない。購入の記録（当選に残る操作）は対象外。BOXの受取状態の入力画面を出している間はカードを残し、閉じたら退出。

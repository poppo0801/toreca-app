# Stage 6P: PC表示・コレクション・商品マスター管理の改善

DB変更は追加のみ（`20261126000071_box_reclassify.sql`、`20261126000072_product_merge.sql`）。既存の抽選・応募・購入・売却・受取・コレクション履歴は変更しない。

## 1. PCのカード／BOX切替
- コレクションの見出し横に「カード｜BOX」の切替（`md` 以上のみ表示）。スマホは従来どおり左右スワイプのみ（ボタンなし）。
- スワイプと同じ状態（`tab`）を使うため、一覧・集計・並び順・［相場更新］［登録］・URL（`?tab=box`）も同じように切り替わる。選択中は塗りつぶし（`aria-selected`）。

## 2. PCのナビゲーション
- 左サイドメニューを廃止。PCもモバイルと同じ「画面全体の入れ物の最下段」に下部ナビ（`bottom-nav-pc`）を置く。利用できる全機能（最大8項目程度）をアイコン＋名称で等幅に並べる。ブランドロゴはヘッダーに常時表示。
- 位置の仕組み（固定の入れ物・Safe Area の余白・`app-nav` の背景延長）はモバイルと共通のまま。測定による補正は追加していない（docs/stage6j-viewport.md の方針を維持）。スマホの項目数・構成（`bottom-nav`、最大5枠＋「その他」）は変更なし。

## 3〜5. BOX登録
- 商品を確定した時点で、商品マスターの定価（BOX）を購入価格に自動入力。定価が不明なら空欄。手入力した価格は上書きしない。自動入力した価格は商品を変えると新しい商品の定価に更新（定価不明の商品に変えたときは空欄に戻す）。購入時点の市場相場は別の項目のまま。
- シュリンク状態は新規登録で「シュリンクあり」が初期選択（既存BOXは変更しない）。
- 表示名: シュリンクあり／シュリンクなし／**－**（旧「状態未確認」・受取の「その他・不明」）。内部の値（`unknown`）は変えていないため既存データはそのまま「－」と表示される。評価: あり=あり相場、なし=なし相場または補正倍率、**－=あり・なしを推測せず基準相場**。
- 購入元を「系列」＋「店舗（任意）」に分割。`ChainStoreFields` を支出登録と共通化（系列は検索・選択・自由入力。既存の系列名・別名に一致する入力は既存系列にそろえ、重複した系列を作らない。店舗は選んだ系列の店舗に絞る。店舗なしの系列は系列のみ）。

## 6. 登録済みBOXのシュリンク状態の変更
- BOX詳細の「シュリンク状態を変更」: 対象ロット（購入）・変更前/変更後・数量を指定。DB関数 `box_reclassify` が、元の状態から引いて新しい状態へ足す2行を履歴（kind=adjust・同じ操作ID）に追記する。
- 所有数の合計は変わらない。購入・受取・売却・開封の履歴は変更しない（履歴は追記のみ）。購入記録との連動は purchase/receive の行だけを数えるため、変更後に購入記録を保存し直しても二重計上・巻き戻りは起きない。同じ操作IDの再送は何もしない。元の状態の残数を超える変更は拒否。取り消し（`box_revert_op`）で元に戻せる。評価額は新しい状態の相場で再計算される。
- 受取で記録した状態と異なる状態にするときは、その旨を表示（受取の記録はそのまま残り、変更が履歴に追記される）。

## 7. 商品マスターの削除・統合
- **削除**: 確認ダイアログで参照を調査（抽選・購入明細・売却・BOX・受取・相場・カード・セット構成・収集設定/メモ）。参照が0件のときだけ削除（`delete_product`）。参照があれば削除せず件数を表示し「非表示」を提案。連鎖削除なし。
- **既存商品へ統合**（`merge_products`、1トランザクション）: 統合先を検索・選択 → 「内容を確認」で影響件数を表示（プレビューは何も変更しない）→ 確定。
  - 付け替え: 抽選明細・購入明細・売却・カード・BOXロット/受取・セット構成・収集設定/メモの参照。BOX在庫の履歴はロットに紐づくため増減しない。
  - 上書きしない: 統合先の画像・価格・発売日・定価。統合先に無い画像/価格/相場の状態/別名だけ引き継ぐ。統合元の名前は統合先の別名になる。
  - 誤統合の防止: 商品コード・商品区分・1BOXのパック数が食い違うと拒否。統合先が非表示のとき、セット構成が互いに含まれるときも拒否。
  - 照合: 付け替え前後の購入数量・売却数量・BOX在庫を合計で照合し、一致しなければ全体をロールバック。統合元への参照が残っていても失敗。
  - 統合元は削除せず非表示にして残し、対応履歴（`product_merge_history`: 統合元の名前・コード、統合先、件数）を記録。再実行は何もしない（冪等）。
  - 世帯をまたぐ統合・他世帯からの操作は拒否。

## 8. 既存カードの画像変更ではAI解析しない
- 登録済みカードの編集で画像を選んでも `/api/card-extract` を呼ばず、画像だけ差し替える（カード名・番号・レアリティ・状態などは変わらない）。新規登録の画像選択（AI読み取りON）は従来どおり。

## 9. 並び替え後のエフェクト消失
- 原因: 長押しドラッグ中・並び替え中は、指の下のカードが入れ替わっても `pointerleave` が届かず、光の演出が「触れている」状態（`data-touch="1"`）のまま残る。CSS は `:not([data-touch="1"])` のときだけ定期的な光（`::after`）を動かすため、そのカードの光が止まっていた。あわせて画面外判定（`data-offscreen`）も並び替え後に古いままになり得る。
- 対策: ①ドラッグ中は光の「触れた状態」を設定しない ②ドラッグ終了時（確定・取消とも）、全カードの `data-touch` を外し `data-offscreen` を位置から決め直す（直後・次フレーム・700ms後の3回）。画面外停止・省電力・色味の仕様は変更なし。React の key は ID 固定、並び替えは CSS `order` で DOM 順は変わらないため再利用の問題は無かった。

## 10. iPhoneの長押しドラッグ
- 原因: iOS は長く押し続けると（コンテキストメニュー/画像ドラッグの判定などで）`pointercancel` を送り、以後の pointer イベントが止まる。従来は pointercancel でドラッグを解除していた。
- 対策: ドラッグ中（長押し成立後）のタッチでは pointercancel で解除しない。`touchmove` で追従を続け、`touchend`/`touchcancel`/`pointerup` で確定・終了する。長押し時間に上限は無い。長押し成立前の pointercancel（縦スクロールの開始）は従来どおりドラッグしない。カード画像は `draggable=false`・`-webkit-user-drag:none`・`pointer-events:none`・`-webkit-touch-callout:none` で標準の画像ドラッグ/メニューを抑止。縦スクロール・タップで詳細を開く操作・移動アニメーション・お気に入り順の保存は変更なし。
- **実機では未確認**（jsdom の模擬イベントで検証）。iPhoneで、長く（数秒）押し続けてから動かす操作を確認してください。

# Stage 6Q: 系列マスターの削除・統合（商品の統合と同じ方式）
マイグレーション `20261127000073`〜`75`（追加のみ。074は関数の変数名衝突の修正、075は安全対策の追加）。マスター管理の「系列」の各行の「⋯」メニューに「既存系列に統合」「削除」。
- **削除**: 参照（店舗・抽選・キャンペーン・使用中の応募アカウント・応募・会員番号・購入・BOX・応募ルール/条件・対象設定・スルー・収集設定・Xアカウント対応・資格の記録）を調べて表示。0件のときだけ削除（系列の登録時に自動で作られる未使用の応募アカウントと別名は一緒に削除）。参照があれば削除せず「非表示」を提案。
- **統合**（`merge_chain_masters`、1トランザクション・冪等・プレビューあり）: 同名の店舗は統合先の店舗へ寄せ（店舗への全参照を付け替え、統合元の店舗は非表示で残す）、名前が違う店舗は統合先の系列へ移す。抽選・キャンペーン・購入・BOX・応募条件・応募ルール・収集設定・Xアカウント対応を付け替え、同名義・同ラベルの応募アカウントは応募履歴ごと統合先へ寄せる。統合元の名前は統合先の別名になり、統合元は非表示で残る。対応履歴は `chain_merge_history`。
- **拒否（データを捨てない）**: 会員番号・応募条件の名前・応募ルールの区分・対象設定が両方にあって衝突するとき／資格（account_eligibilities）の記録がある系列／統合先が非表示のとき／世帯をまたぐとき。抽選・購入・BOX・応募の件数を付け替え前後で照合し、合わなければ全体をロールバック。

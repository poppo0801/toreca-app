# AI再設計：受入テスト設計と性能評価計画（Stage 10C 策定）

状態: 計画（未実施・未測定）。数値の閾値・費用上限は**置かない**（SPEC §7）。測定方法・ベースラインの取り方・後で決める項目を区別する。
関連: `docs/AI_REDESIGN_SPEC.md` §7（3本柱）、`docs/AI_REDESIGN_IMPLEMENTATION_MAP.md`。

## 1. 評価の3本柱と合否の考え方
1. **既知6課題の改善**: 店舗選択式／重複／系列名／商品名／候補滞留／取得済み情報の読み落とし。
2. **旧方式との総合比較**（6課題以外を含む）。
3. **既存機能・安全の維持**。
- すべての指標で旧方式を上回る必要はない。ただし**安全条件（§4）は相殺不可**。精度の重要な低下（下記 *重要指標*）は総合点で相殺しない。
- 閾値は「ベースライン測定後にユーザーと決める」。本計画では未設定とし、決定時に `DECISION_REGISTER` へ記録する。

## 2. 総合比較の指標（定義・測り方・ベースライン）
| 指標 | 定義 | 測り方 | 旧方式のベースライン取得 |
|---|---|---|---|
| 発見力 | 検証済みの有効な抽選のうち、登録（または確認待ち表示）に至った割合／見逃し数 | 正解事例集合（§3）に対する再現率。新着はユーザーの目視確認 | 同一の保存証拠を旧方式で再処理（開発DB・mock/実AI承認制）。**本番の過去結果は正解にしない** |
| 抽出精度 | 日時・条件・店舗・商品・系列の項目別一致（根拠の実在つき） | 項目単位の採点（正解は原文/フォーム/画像から人手で構築） | 同上 |
| 登録/対象判定 | 登録すべきもの・すべきでないもの（非告知・対象外地域・会員限定）の判定 | 混同行列（見逃し／誤登録を分ける） | 同上 |
| 網羅性・更新 | 延長・短縮・当選発表・中止・再開催の追跡 | 時系列の変更事例での追従率・誤更新数 | 同上 |
| 同一性 | 同一機会の統合/別機会の分離の正誤（誤統合と誤分割を**別集計**） | ペア単位。**重大な誤統合は件数ゼロが条件（§4）** | 同上 |
| 遅延 | 発見→候補表示、発見→登録までの時間（中央値・遅い側） | 実行ログ（`collection_runs` 等）。同期/非同期の区別 | 本番ログの読み取り（旧方式の実績） |
| 費用 | AI・検索・取得の費用／**正確な機会1件あたり**／未解決案件の解決費用 | 費用台帳（`RealRunGuard`・AI利用ログ）。不明は0円にしない | 旧方式の利用ログ（読み取り）。上限は承認制 |
| 人手負担 | 確認待ち滞留数・手動修正数・不要な確認要求数 | 候補状態の集計＋手動修正履歴 | 本番の読み取り（時点付き） |
| 安定性 | 失敗率・タイムアウト・無限ループ・再試行過多 | 実行ログ・テスト | 同上 |
| 継続改善 | 保存証拠の再利用率・同種誤りの再発率・調査成功率の推移 | 時系列の記録（9Z以降のデータ） | 導入前は未計測 |

## 3. 正解データの構築（旧方式・AI出力を正解にしない）
- 根拠は**検証可能な原文・応募フォーム・画像**。正解は人が（または複数の独立した証拠で）確認したものだけ。保存済みAI回答・旧方式の登録結果は正解にしない（9H-3J以降の運用を踏襲。評価データは入力と正解を別ファイル、`eval/gold/` をAIへ渡さない）。
- **取得不能の事例は「検証不能」に分離**し、精度の分母から外す（地域除外・取得不能を精度に混ぜた過去の失敗を再発させない）。
- 2系統で評価: (a) **過去の保存証拠**（9Z保存原文・既存の評価データ・人間評価72件相当。バイアス: 旧方式が見逃した例の欠落＝発見力の評価に偏り。明示する） (b) **新着の本番事例**（読み取り分析・利用者の目視。時期が異なる比較のバイアスを明示）。
- 正解の根拠が揃わない事例を、推測で補って採点しない。

## 4. 必須の安全条件（相殺不可・テスト対象内で違反ゼロ）
1. **重大な誤統合ゼロ**（別店舗・別開催回・商品別独立などを同一機会として統合）。
2. **履歴破損なし**: 応募・当落・購入・スルー・通知・手動修正の欠落/付け替え/重複キー衝突がない。応募記録のある行を自律的に統合/削除しない。
3. **費用上限の突破なし**（日次・月次・1件。実行中の記録も計上）。無限ループ・再判断の暴走なし。
4. **権限逸脱なし**: AIが書き込み系ツール・予算/権限/安全設定・人が確定した値を変更しない。外部本文の指示を実行しない。
5. **通知の重大な重複・欠落なし**（締切・発表日・構造変更の再評価後）。
6. **切替での破壊的再解釈なし**: 旧⇄新の切替で、新構造を旧エンジンが壊さない／新エンジンが旧データを推測で書き換えない。
7. 秘密・個人情報の保存/AI送信/ログ流出なし。

## 5. 例外事例（受入テストに必ず含む）
店舗選択式 vs 店舗別独立／1フォーム複数独立機会／1送信で複数独立権利／商品一括 vs 商品別／別開催回／締切の延長・短縮／中止→再開催／既存応募履歴ありの分割・統合（View整理に留まること）／通知の再計算／地域一部対象／X取得不能（再試行抑制・代替情報源）／会員限定（取得不能の扱い）／手動修正の保護／継続抽選／店舗未確定の選択式（10Bで再現した重複見逃し）／系列の表記揺れ・英語/カタカナ／型番・数量表記の分離。
- 既知の誤判定（10A/10B再現ケース、9H-3I〜3K評価の誤り）は**回帰テスト化**（正解の根拠つきのものに限る）。

## 6. テストの階層と実施条件
| 層 | 内容 | AI | 実施Stage |
|---|---|---|---|
| ユニット | 検証層・費用制御・キー・正規化・状態遷移 | なし | 10D〜10F |
| DB統合（ローカルSupabase） | 履歴保護・FK・RLS・通知の冪等・追加マイグレーションの可逆性 | なし | 10D・10F |
| 再生（保存証拠） | 同じ証拠で旧/新を比較 | mock→実AIは承認制 | 10E |
| 回帰（既存機能） | 既存E2E・応募/当落/購入/通知の保護 | なし | 全Stage |
| 実AI評価 | 正解事例集合に対する精度・費用 | **承認制**（費用と上限を報告して承認） | 10E・10G |
| 本番観測 | 導入後の実指標の記録（長期シャドーは必須としない） | 本番の上限内 | 10G〜10H |
- 本番データを変更するAI試験は禁止（開発DB）。本番導入は検証後にユーザーが決める。

## 7. 移行・切替・廃止の条件（概念。閾値は未設定）
- 内部テストで §4 の安全条件を満たし、重要指標に重大な悪化がなければ**早期に本番導入**。長期シャドーは必須としない。切替（旧⇄新）は移行期の一時的な復旧手段。
- 本番の運用実績で目立った問題がなければ、旧方式・切替設定・旧判断コードを撤去（10H）。撤去前に: バックアップ・復元手順の確認、参照調査、テスト。恒久互換のために新方式を制約しない。
- 「目立った問題がない」の定義（観察期間・指標）は10G完了時に提案し、ユーザーが決める。

## 8. 後で決める項目（捏造しない）
各指標の合格閾値／評価事例数／観察期間／1件あたり費用の目標／日次・月次予算の再配分／原文の保存期間・サイズ上限／切替判定の基準。いずれも測定可能なベースラインを得てから提案し、ユーザー承認で確定する。

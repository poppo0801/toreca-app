# Stage 4C 追加: 確認待ち候補の再評価

X画像解析・マスター照合が改善されたため、過去に確認待ちになった候補を再評価する。**全件を無条件にAIで再解析しない**（無料の再照合を先に行い、AI/X が必要な候補だけを優先順位順に、件数と予算の上限内で処理）。

## 分類（`src/lib/collector/reevaluate.ts` の `judge`。AIを呼ばない純関数）
| 分類 | 条件 | 処理 |
|---|---|---|
| A | 受付中・情報が十分・特定でき・重複なし（解析時に特定済み） | 自動登録 |
| B | マスター照合の失敗だけが理由（締切は明確） | **AI再解析なし**。現在のマスターで再照合し、確実に特定できれば登録。できなければ確認待ちのまま理由を更新 |
| C | X投稿が情報源で、締切不明・店舗/商品の特定不可 → 画像などの追加取得で補える可能性 | X公式API＋統合AI解析（上限内） |
| D | 情報不足（締切不明・取得元の再確認が必要）／登録に必要な情報は揃うが注意が残る | 取得元を再取得して再解析（上限内）／追加取得で解決しないものは確認待ちのまま理由を更新 |
| E | 受付終了（締切を過ぎている）・既存の抽選と重複しない | 除外（理由「受付終了（履歴登録不要）」。候補は残す。除外一覧から戻せる） |
| F | 既存の抽選と同じ店舗・商品・締切（または同じ情報源URL）／収集条件の対象外 | 重複は既存の抽選に紐付けのみ（既存の抽選は変更しない）。対象外は除外（条件を記録） |

- 重複の判定は除外・受付終了より先。応募・当落・購入のある既存の抽選は一切変更しない。
- 自動登録は、解析時の注意（矛盾など）が残る候補・複数商品の応募方式が不明な候補・照合が曖昧な候補には行わない（確認待ちを維持）。
- 登録した抽選は自動収集の印（source_kind=auto・NEW表示）つき、★管理対象にせず応募記録も作らない（通常の自動登録と同じ）。
- 優先順位: 1 受付中で締切3日以内 → 2 マスター照合失敗 → 3 X画像 → 4 その他の受付中 → 5 受付終了 → 6 対象外・重複。

## 実行（CRON_SECRET 必須。通常の定期実行には組み込まない手動の運用操作）
`POST /api/cron/reevaluate`（Bearer CRON_SECRET）
- `{"execute": false}` … 判定のみ。DBを一切変更しない（分類・件数・理由・X画像の取得状況を返す）。
- `{"execute": true, "aiMax": N, "ids": [...], "classes": ["C"]}` … 実行。aiMax=AI/Xで再解析する最大件数（既定0）。既存のAI利用上限（時間・日・月額予算・自動停止）でさらに制限され、X API は収集設定のX予算・APIキーの範囲内でのみ呼ぶ（0円・未設定なら本文のみ）。
- `{"restore": true, "ids": [...]}` … 変更前へ戻す。

## 記録・復元
候補の `draft.reeval` に、実行日時・分類・処理・解決手段（rematch/ai/x_image/refetch/rule）・**変更前の status/job_state/reasons/lottery_id/draft** を保存。候補は物理削除しない。再評価で新規登録した抽選は復元では削除しない（`registeredLotteryId` を返すので、必要なら抽選を取り下げる）。

## X画像の状況（区別）
投稿本文取得済み／画像あり・未取得（本文のみ）／画像一部取得／画像なし（本文のみ）／X API 経由。保存された `notices` から判定。X API・トークンが使えない場合は原因を理由に残し、候補を保持する。

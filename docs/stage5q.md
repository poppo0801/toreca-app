# Stage 5Q: UI改善・表示不具合・アニメーション

**iPhone 実機（ホーム画面PWA）では未確認。** 確認したのはコード・単体テスト・モックE2E（Chromium の iPhone 14 / Pixel 7 エミュレーション）。

## 下部メニュー（2つの不具合を同じ設計で扱う）
- 症状A: キーボードを閉じたあと下部メニューが途切れる（Stage 5P の `--vv-shift` で対処済み）。
- 症状B: 最下部でさらに下へスクロール（オーバースクロール）すると、移動量に応じて下部メニューが浮き上がる。
- 原因B: `--vv-shift` は `visualViewport.offsetTop + height − innerHeight` を毎フレーム測って反映していた。ゴム紐のバウンス中は `offsetTop` が動くだけで「ずれが残った」状態ではないのに、その動きを補正値として拾い、メニューがバウンス量だけ動いた（Stage 5P の補正の過剰適用）。
- 修正（`src/lib/viewport-insets.ts` の `stabilizeShift`、`app-shell.tsx`）:
  - 指が触れている間（touchstart〜touchend/cancel）は補正値を更新しない。
  - 0 に戻った測定値はすぐ採用。0 以外は **同じ値が10フレーム（約0.17秒）連続したときだけ**採用（キーボードを閉じたあとに残る静的なずれは安定した値なので採用され、バウンスは毎フレーム変わるので採用されない）。
  - `html { overscroll-behavior-y: none }` でバウンス自体も抑える（iOS 16+）。
- 両立: Aの対処（静的なずれを採用）とBの対処（動いている値を採用しない）は条件が排他なので、片方が他方を壊さない。単体テストで両方を確認。
- 実機で戻らない場合は `?diag=1` の診断（`vvTop`/`vvH`/`navCoveredBy`）を共有してください。

## 退場アニメーション・スワイプ
- 応募済みへ変更: 状態は即時更新 → 1秒保持 → 0.55秒で右へスライドしながらフェード（時間の60%＝幅の約6割で完全に透明）→ 一覧を詰める（0.35秒）。Undo・状態絞り込みで応募済みも表示している場合（カードを残す）は従来どおり。
- スワイプ確定: 一覧から外れる操作（スルー・★解除・応募済みタブの当落・当選タブの受取）は、指を離した位置から同じ方向へ流れてフェードアウト（`leavesListOnCommit`）。残る操作・不成立は元の位置へ戻る。確認ダイアログ・2段階の購入/受取・Undoの制約は従来どおり。
- シンプルカードの横はみ出し: 一覧の `li` が `display:grid`（高さを詰めるアニメーション用）で列幅が `auto` のため、折り返さない中身の最小幅で列が広がっていた。列を `minmax(0,1fr)` にし、一覧の横方向をクリップ。

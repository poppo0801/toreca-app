# Stage 7N（店舗）: 店舗マスター・店舗選択式応募の改善

## 1. 店舗選択式のフリーズ対策（原因調査）
- 実機（iPhone）は未確認のため、コードから特定できた原因を修正した。
  1. **スワイプカードがダイアログ内の操作を拾っていた**（確定した原因）: 店舗入力シートは Portal で描画されるが、Reactのイベントは親の `SwipeCard` に伝わる。シート内のドラッグ・スクロール・タップがスワイプ判定に入り、`setPointerCapture`・offset更新・クリックの握りつぶし（350ms）を起こしていた（入力欄・selectだけが除外されていた）。DOM上でカードの外の要素のイベントは無視するよう修正（`swipe-card.tsx`）。
  2. **OS標準のプルダウン（`<select>`）**: キーボードが出ている入力欄の直後に標準ピッカーを開くと、キーボード分の持ち上げ（`--kb-inset`）とピッカーの表示が重なる。シート内の一覧（`PrefecturePicker`）に置き換え、標準ピッカーを使わない。他のフォームの `<select>` は変更していない。
- 対策は1・2の両方。フリーズが再発する場合は、iPhoneで再現する操作手順を共有してほしい。

## 2. 応募済み処理のスピナー
- 「応募済みにする」押下直後からスピナー（処理中…）・ボタン無効・二重送信防止。完了後に閉じ、失敗時はエラーを表示して再操作できる（ダイアログを閉じない）。カードのボタン・スワイプ操作の両方。

## 3. 応募時に入力した店舗のマスター自動登録
- 応募の記録が成功した後にだけ登録（`registerAppliedStore`）。失敗しても応募の記録は有効（名前のみ）で、不整合は生じない。
- 同じ系列の既存店舗は再利用（全半角・空白・系列名の接頭・末尾の「店」の差を吸収）。都道府県が空なら補う。新規は確認済み（`is_provisional=false`）。架空の店舗名は登録しない。
- 応募後の店舗変更（`setAppliedStore`）も同様。プロフィール別の応募店舗は従来どおり（他のプロフィールに影響しない）。
- 購入記録には店舗IDが引き継がれるようになった（これまでは名前のみ）。

## 4〜6. 店舗マスター画面
- 系列別の折りたたみ一覧（初期は全て閉じる・五十音順）。系列カードに「系列名・N店舗・●M・展開」。展開すると店舗1行（店舗名・●・都道府県・直線距離・編集）。並びは 未確認 → 距離が近い順 → 距離不明。末尾に「＋店舗を追加」（系列は自動設定）。
- 通販（営業形態=オンライン専用、または名前に通販・オンライン）は距離・交通費を出さず「通販」。住所・交通費は編集画面で確認。
- 検索（店舗: 系列名・店舗名・都道府県／系列: 系列名・別名）。該当した系列は自動展開。
- 「仮」バッジを廃止し、小さなオレンジの●（編集画面は「● 未確認」）。系列・商品の一覧も同じ表示。
- 登録状態: 自動収集の新規店舗=未確認／手動・応募時入力=確認済み／未確認を編集して保存=確認済み（変更なしでも）／確認済みは自動収集で変えない。既存の仮登録は未確認（●）として引き継ぐ。
- 「応募時に店舗選択」の仮の店舗（店舗選択式の既存仕様）は一覧に出さない。

## 7. 架空の店舗
- 今後: 自動収集は店舗を特定できないとき、店舗を未設定のまま登録する（「店舗未確認」を作らない。不足情報の注意は従来どおり）。
- 既存データ: `scripts/cleanup-fake-stores.mjs`（既定は調査のみ）。本番の対象は未確認の「店舗未確認」12件（抽選16件が参照）。事前に `npm run backup` を取得し、承認のうえ `--execute` で実行（抽選の店舗を未設定にしてから削除。抽選・応募履歴は残る）。
- 残課題: 店舗選択式の仮の店舗「応募時に店舗選択」は既存の店舗選択式の設計（テスト・判定）に組み込まれているため、今回は作成を止めず一覧から隠すだけにした。

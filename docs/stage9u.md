## 2. 変更
1. **登録の阻害の解消**（`intake-check.ts`）: 店舗名の照合で、系列名の有無だけの違いを同じ店舗とみなす（別の店舗は一致しない。テスト追加）。
2. **調査履歴によるミッション選択**（`discovery/session.ts`）: ミッションごとに「次に選べる時刻」を記録。AIが終了時に `revisit_hours`（再調査までの時間。1〜168）を決める。示さなければ成果ありは12時間・なしは24時間。同じ対象を成果なく繰り返さない。
3. **次の調査対象の待ち行列**: AIが終了時に `next_missions`（系列・商品・保留の手がかり＋理由）を提案できる。**保留した手がかりは自動で「確認のための調査」の対象**になる（`lead` ミッション）。期限7日・上限20件・重複除去。形式のみ検証（https・個人情報らしき文字列の除外）。固定の巡回順ではなくAIの提案が次の調査対象になる。
4. **`resolve_name` ツール**: 見つけた名称を既存マスター（別名・過去の学習を含む）に照合（読み取りのみ）。
- 変更しないもの: 安全の共通基盤（日額・月額・1ミッションの費用上限、回数・時間・アクセス頻度の上限、重複の抑制、robots・認証の尊重、人間確定データの保護、検証層、履歴と元に戻す手段）。
- マイグレーションなし（`discovery_strategy.memory` はJSON）。従来方式への切り替え・既存の登録経路は変更しない。

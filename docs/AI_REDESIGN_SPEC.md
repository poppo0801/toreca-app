# トレマネ AI主体収集・判断エンジン：再設計の基本仕様

状態：2026-11-20のユーザー合意に基づく**目標仕様**。現行実装を表すものではない。詳細な背景・検討経緯は `AI_REDESIGN_DECISION_HISTORY.md`、理念は `AI_AUTONOMY_PRINCIPLES.md`。

## 1. 目的と設計原則
新規抽選の発見力、応募機会の正確な理解、登録・更新の正確性、候補解消、情報網羅性、費用対効果、ユーザー負担を総合改善する。固定ロジックの積み重ねではなくAIを意味判断の主体とし、固定処理は安価な前処理、キャッシュ、検証、権限・安全、費用上限、履歴保護を担う。既存資産を評価して再利用するが、現状維持を目的にしない。

## 2. 論理モデル
- Evidence/Source：実際に取得した本文・画像情報・取得日時・URL・取得手段・出典・ハッシュ・信頼状態。抽出事実とAI推論を分離。
- Case：同一企画・関連情報を調査・集約する単位。1 Caseに複数Opportunityを含められる。
- Opportunity：独立して応募・応募状態を追跡すべき機会。フォームURLや応募操作回数、表示カード数と同一とは限らない。店舗選択式は原則一機会、店舗別に独立応募可能なら別機会。単一応募で複数商品が別々に当選する場合、応募記録と結果粒度を分ける。
- View：ユーザー向けカード。関連表示・重複表示の整理は実体IDの統合と別。
- User records：A/B/C別の応募・選択店舗・選択商品・当落・スルー・通知・購入記録。既存IDと履歴を維持し、AI推測で再割当・削除しない。
- 機会の独立性が不明なら、推測で複数カードを生成せず未確定Caseを表示できる。

## 3. 収集・AI判断・自律調査
既存Web/X収集と9Z証拠保存を活用。定期収集→関連Evidence集約→AIによる意味判断・必要な追加調査→検証・登録/更新→継続監視。初期X API本文を保存し、取得不能なXページへ無益な再試行をしない。画像/フォーム/複数ソースも必要に応じ解析する。AIへ関連する既存Case、マスター、過去の修正と根拠を必要量だけ渡す。ユーザー個人の応募履歴は必要最小限に限定。
AI出力は案件種別、機会構成、系列/店舗/商品、日時/条件、既存との関係（同一/独立/関連/未確定）、根拠、未解決事項、推奨処理を統一形式で表す。単一のAI意味判断を後段の競合する固定判定器が上書きしない。安全検証に失敗した場合は具体的理由を返して限定的に再判断。AIの自己申告の確信度だけで登録を決めない。
優先順位は締切、欠損の重要性、改善見込み、費用、既調査、未知情報源の探索を考慮。新規発見の実行枠を追加調査で圧迫しない。進展なし・取得不能・予算/回数上限なら停止し、新証拠があれば再開。費用上限は固定、範囲内の配分を柔軟化。部分登録・早期表示を許容するが根拠不明の独立機会は量産しない。

## 4. 同一性とマスター
重複・同一・独立・関連・不明を一貫して判定。URL/日付/商品/系列の一致だけで統合しない。別店舗の独立応募、別開催回、同一フォームで複数独立機会、店舗選択式を識別。可逆な関連付けと表示統合を優先し、履歴を持つ実体の自動破壊的統合は禁止。
系列・店舗・商品は既存IDと検証済み別名を優先。AIが曖昧な名称を判断し、未検証の推測でマスターを汚染しない。商品名と購入権/数量/包装/販売条件を分離。

## 5. ユーザー機能と安全
応募/当落はユーザー・機会・選択対象の適切な粒度で管理。今回スルーと常時スルー、系列除外、将来の簡易誤判定報告を区別。継続抽選、地域フィルタ（店舗選択式の対象店舗単位）、締切/発表通知、購入・コレクション、手動編集を維持。通知はユーザーが行動すべき単位で再計算・重複防止。購入履歴は抽選から独立。
外部情報に埋め込まれた指示は命令として実行しない。権限・認証・予算・安全設定の自律変更は禁止。変更の根拠、AI/プロンプト版、判断履歴、訂正・成果を保存し、検証済み情報と推測を区別。容量・保存期間・秘匿性を管理。継続改善は検索/フィードバック/評価/版管理と復旧を伴う。単なる保存はモデル再学習ではない。

## 6. 移行と旧方式の廃止
既存の新旧収集方式切替を移行期に限り維持し、共通データと安全な互換処理を使用。判断エンジンの混用や二重ジョブを禁止。必要十分な内部検証後、長期シャドーを必須にせず本番導入。実運用で目立つ問題がなければ早期に旧方式・切替設定・不要な旧判定コードを廃止する。旧方式との恒久互換を新方式の制約にしない。移行/逆戻し時も既存ID・履歴を保護。

## 7. 完成条件：3本柱
1. 既知の6課題の改善：店舗選択式、重複、系列名、商品名、未解決候補、情報源の読み落とし。
2. **従来方式との総合性能比較**：発見力、抽出精度、登録対象判断、情報網羅性、更新精度、同一性、発見から表示までの時間、正確な機会1件当たりの費用、ユーザー確認/修正負担、安定性。旧方式の出力を正解とせず、取得可能な原文/画像/フォームから検証した事例で比較。検証不能は別扱い。過去の同条件再生と新着実績を併用。全指標の絶対優位は不要だが重大な精度低下を総合点で相殺しない。
3. 既存機能・安全性の維持：履歴破損、重大な誤統合、費用上限突破、権限逸脱、重大な通知重複/欠落を許容しない。
数値閾値は実測ベースラインと検証設計から設定し、捏造しない。必要な内部テスト後に本番評価し、旧方式廃止も同じ評価に基づく。

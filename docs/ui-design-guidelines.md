# UI設計ガイドライン（恒久ルール）

画面を追加・変更するときは必ずこの指針に従う。**メインコンテンツの表示面積を最優先**し、機能を足す前に、既存の操作へ統合できないかを検討する。

## 1. 説明文を出さない
- 見出し・ボタン名・項目名から分かる説明は書かない。同じ意味の文を繰り返さない。ボタンの役割を文章で説明しない。
- 初期状態で長いヘルプを出さない。必要な説明は、詳細の展開・ヘルプ・要確認の詳細・ツールチップへ移す。
- 設定の一覧は見出しだけ（説明は項目を開いた先で）。

## 2. 操作ボタンを増やしすぎない
- 同じ目的の操作は1つに統合する（例: 抽選管理の登録は「＋登録」だけ。まとめて登録・AI読み取りは登録画面の中）。
- 関連操作はコンパクトに並べる。頻度の低い操作はメニュー（⋯）・設定へ移す。大きなボタンを画面上部に何個も並べない。

## 3. 検索・フィルターは省スペースに
- 検索は虫眼鏡アイコン→タップで展開。フィルターはアイコン1つに集約し、条件は展開して表示。並び順・列数はコンパクトな選択ボタン。
- 設定項目を常時何行も表示しない。操作UIは原則1行にまとめ、コンテンツ（画像・一覧）をできるだけ上から見せる。
- 集計は1行で見せ、タップで詳細を展開する。

## 4. スマートフォン優先
- iPhoneの画面幅を基準にする。横スクロール・不必要な縦スクロールを避ける。少ない操作で必要な情報に届く。コンテンツより操作UIが目立たないようにする。

## 5. 必要な情報は省略しない
省略するのは不要な説明文・装飾だけ。次は必要なときに必ず確認できる状態を保つ（常時の文章でなく、印・展開で可）:
抽選締切／応募条件／AI解析の不確実性（要確認・原文）／登録時のエラー／重要な確認事項／削除・上書きの警告／金額・集計対象に関する注意（未設定は0円にしない、一部のみの集計 等）。

## 6. 一貫性
- 同じ操作には同じボタン・アイコン・表示方式を使う（★お気に入り、要確認の印、ボトムシートのスワイプ操作、期間選択 など）。
- 新しいページにもこの指針を適用する。既存の部品（`settings-parts`・`review-flag`・`ui/sheet` など）を再利用する。

## 7. 固定配置・Safe Area
- 下部メニュー・ヘッダー・ボトムシートの固定配置とSafe Areaの計算（AppShell）は、専用の工程以外で変更しない。診断モード（`?diag=1`）は実機確認まで残す。

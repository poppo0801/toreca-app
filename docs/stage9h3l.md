# Stage 9H-3L: 先行実装（一次情報リンク・イオン系列・費用の可視化）

開発環境のみ。マイグレーションなし。本番DBへの書き込み・デプロイ・mainへのマージなし。実AIは使っていない。9H-3Kの評価データ・評価ツールは変更していない。

## 1. 一次情報リンク（`lib/source-links.ts`・`components/source-link-list.tsx`）
- 抽選詳細: 応募方法・受取方法の2列の直下、発表方法より上に「種類｜ドメイン」の文字リンク（青緑の下線・外部リンクアイコン・別タブ）。最大3件。下部の情報元リンク一覧・「発表ページ」は従来どおり。URLが無いときは何も描画しない。
- 種類は事実だけから判別: 当落発表URL欄と一致＝「当落発表」／livepocket.jp＝「LivePocket」／x.com・twitter.com＝「X」／店舗マスターに登録された店舗URLのホストと一致（サブドメイン可）＝「公式サイト」／それ以外＝「外部サイト」。**Xは公式アカウントかを示すデータが無いため「公式」と付けない**。公式アプリはURL・名称のデータが無いため対象外。
- 優先順位: 当落発表ページ → 公式の抽選情報ページ → LivePocket → その他（同順位は保存順・同じURLは1つ）。新しいURLの収集はしない。
- `Store.storeUrl`（既存の `stores.store_url`）をアプリのデータに追加（読み取りのみ）。
- 編集画面: 上部に情報元リンクを読み取り専用で表示（当落発表URL・情報源URL）。情報源URLの入力欄は、URLがあるときは「情報源URLを修正する」の折りたたみの中（編集機能は残す）。URLが無い（新規の手動登録など）ときは従来どおり入力欄を出す。リンクは別タブ（iPhoneのホーム画面アプリでは外部で開く）。シートは閉じず、入力内容・一時保存（既存の「編集を再開」）は維持される。

## 2. イオン関連の独立系列（`lib/chain-normalize.ts` の `INDEPENDENT_CHAINS`）
- 独立管理: イオンオンライン／イオンビッグ（ザ・ビッグ・ザ・ビッグエクストラ）／イオンキッズリパブリック（キッズリパブリック）／イオンスタイルオンライン。正規化の最初（チャネル語の除去・「イオン」への寄せの前）に確定。
- イオンオンラインとイオンスタイルオンラインは**別キー**（運営元・応募先URLを確認するまで同一としない）。単独の「ビッグ」・ビッグカメラは独立系列にしない（「ザ」「イオン」が付くときだけ）。
- 系列マスターの照合（`lottery-match.ts`）: 入力か候補のどちらかが独立系列で、キーが異なるものは照合の対象外＝部分一致・類似でも「イオン」へ寄せない。マスターに独立系列があれば表記違いで紐付く。アカウント表示名からの系列特定（`store-identity.ts`）も同様。
- 重複系列の検出スクリプト（`find-duplicate-chains.mjs`）も同じ規則に更新。
- 既存DBの誤登録候補（読み取り専用）: `npm run prod -- scripts/find-aeon-chain-candidates.mjs --yes-production`（利用者が実行）。系列「イオン」の店舗が独立系列名／「オンライン」の抽選を一覧にし、修正はしない（手順は出力に表示。応募・当選履歴は付け替えのみ）。**本番は未実行**（開発DBでは0件）。

## 3. 費用・収集処理の可視化（`collector/cost-report.ts`）
- 既存の記録だけを集計（新しいテーブル・列なし）: 候補（段階・解析回数）・AI利用ログ（モデル・トークン）・調査の記録（検索）。**費用はAI利用ログだけから算出**（候補・日別統計の費用は足さない＝二重計上なし）。
- 表示: 自動収集の「日別の統計」の中に「処理段階と費用（30日）」。収集件数・AI解析件数・地域外／商品対象外／重複（AI前／AI後）・取得失敗・保留、AI費用（回数・モデル別・トークン）・1回あたり平均・検索API（記録が無ければ「未記録」）。
- 費用が不明（モデル・トークン数が不明）な呼び出しは0円にせず「不明N回」。平均は推定できたものだけ。
- 既知の限界: 日別統計（`collection_daily_stats.cost_jpy`）への加算は、費用を推定できないとき0円で加算している（既存の仕様。スキーマ変更が必要なため今回は変更せず、利用ログ基準の集計で不明を区別）。

## 4. 有料AIの前後（調査結果。事前除外は新設していない）
- AIの前（費用なし）: 収集元の除外ルール・信頼性なしの系列・一覧の見出しによる事前除外（`preScreenFromList`。Xの投稿・更新検出は対象外）・同じURLの再処理防止・受付終了。
- AIの後: 抽出された店舗による地域判定（地域外の除外）・商品の対象外（別ゲーム）・内容による重複判定・抽選の告知でない判定。
- 将来の最適化の余地: AI後に除外・重複と分かった件数を表示（`afterAiDiscarded`）。精度・網羅性を下げる事前除外は、人間評価後に検討する。

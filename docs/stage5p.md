## 1. 下部ナビゲーションの表示不具合（キーボード開閉後に途切れる）
### 原因（コードと既存の診断から）
- 下部メニューは `position: fixed; bottom: 0`。fixed は**レイアウト上の表示領域（layout viewport）の下端**が基準だが、iOS はキーボードの開閉で **見えている領域（visual viewport）の位置・高さだけ**が変わり、閉じたあとも古い値（`offsetTop` のずれ・縮んだままの高さ）が残ることがある。このとき、レイアウト上の下端と実際に見える下端がずれ、メニューが途切れる（上に浮く／下へはみ出す）。
- これまでの補正は「起動直後の高さの差（`--vp-gap`）」と「キーボードの高さ（`--kb-inset`、ボトムシート用）」だけで、**キーボードを閉じたあとに残るずれ**を下部メニューに反映していなかった。
### 修正（構造）
- `--vv-shift`（新規・符号あり）= `visualViewport.offsetTop + visualViewport.height − innerHeight`。入力欄の編集中（キーボード表示中）は 0。下部メニュー・ボトムシート・浮かぶ通知の `bottom` を `0 − vp-gap − vv-shift (+ kb-inset)` にして、**常に実際に見える下端へ合わせる**（`src/lib/viewport-insets.ts` の `visualShift`／`isEditingElement`、`app-shell.tsx`）。
- 測定は既存の仕組み（イベント後に一定時間フレームごとに測り直す）に乗せたが、**補正の中身が「単発のタイマー」ではなく、見えている領域の実測値から毎回決まる**ため、ずれが残っても自動で外れる。
- Tailwind の `calc` は演算子の前後を `_`（空白）で区切る（詰めて書くと無効になり `bottom` が効かなくなる。開発中にボトムシートで発生し、E2Eで検出して修正）。
- 確認: 単体テスト（`visualShift` の各場面）・モックE2E。**実機（キーボードを開閉して下部メニューが戻る）は未確認。** 戻らない場合は `?diag=1` の診断（`vvTop`/`vvH`/`navCoveredBy`）を共有してください。

## 2〜3. 設定・購入記録
- 設定: 「会員番号」を「ユーザー管理」の直下へ。
- 支出を登録: 開いた直後のフォーカスを入力欄ではなくパネルにして、日付ピッカー・キーボードを自動で開かない。購入日と購入方法は「上段=項目名／下段=入力」で同じ高さに固定。数量単位に「個」（`piece`）を追加（DB の購入明細の制約を `box/pack/set/piece` へ。定価からの仮計算は「個」＝単品・セット定価、未設定なら推測しない）。売却は元から「個」あり。Excel の入出力は抽選明細（BOX/パック/セット）のみで購入明細を含まないため、影響なし。

## 4〜6. 抽選一覧
- **状態の絞り込み**（現在のプロフィール基準）: 受付中・未応募（全情報／★管理対象の既定）／受付中／受付終了／未応募／応募済み／当選／落選／すべて。絞り込み項目の一番左。応募済み・当選タブの既定は状態で絞らない。タブを変えると、そのタブの既定へ戻る（全情報↔★管理対象は選択を保つ）。
- 「受付中」は受付前を含む。継続抽選・招待制販売は有効期限（`validUntil`）を過ぎたら受付終了として扱う。
- ★管理対象は★付きだけ（状態が「すべて」でも★なしは出ない）。系列・商品・店舗の条件と組み合わせ可能。
- 旧「応募済み表示（含む／含まない）」と、全情報の「履歴（終了）」は状態の絞り込みに統合して廃止。
- タブ: 「NEW」の文字をやめ、小さな件数バッジに。赤丸は文字のすぐ右上。タブの高さは1行のまま。

## 7〜9, 11. カード
- 応募済み: 左=発表日（曜日つき・時刻なし）／右=購入期間（購入・受取が分かれていれば受取期間）。応募締切はカードに出さない（詳細で確認）。期間が未設定なら「未定」（応募締切を代用しない）。発表日不明ならカウントダウンを出さない。ボタンは左=落選（グレー）／右=当選（オレンジ）。
- 当選: 「期限超過」だけを表示。**通販・発送**の抽選は「購入を記録」「受取を記録」を並べ、押した方が「✓購入済」「✓受取済」になる（現在のプロフィールの応募だけ。購入記録は応募ごとに1件）。期間を分けていない通販は、購入後の受取を「受取待ち（発送）」とし、購入の期限を受取の期限として扱わない。
- 詳細カード: 余白を少し増やし、★をより左上の隅へ。日付は「11/4（水）」形式（日本時間）。左=抽選締切（時刻あり）／右=購入期間（時刻なし）。距離は受取方法の行へ（店頭のみ。通販・受取方法が不明・位置情報なしは非表示）。締切までの残り日数は下段の操作ボタンの隣。応募状況アイコンは少し小さく、未応募はモノクロ（灰色の丸＋「未」）、応募済みはプロフィールの色。
- シンプルカード: 画像を少し右へ。未応募は丸の中に「未」（モノクロ）。
- 距離が出ない原因（調査）: 実装は正しく、本番の店舗 85 件のうち**位置情報（緯度・経度）が登録されているのは 0 件**（住所だけある店舗は 51 件、自宅の位置は設定済み）。位置は店舗マスターの「住所から位置を取得」（利用者が押したときだけ国土地理院へ送信）で保存すると表示される。候補の自動採用（推測）はしていない。

## 10. 応募済みに変更したあとのアニメーション
- 原因: 退場時に「右へ移動・フェード・高さ0」を**同時に0.3秒**で行い、親の `overflow` で右へのはみ出しも隠していなかった。
- 修正: 保持 2.5秒 → 右へスライド（0.9秒・途中40%からフェードアウト・高さは変えない）→ 消えたあとに一覧を詰める（0.35秒）。退場中だけ一覧の横方向をクリップして残像・横スクロールを防ぐ。Undo／解除は従来どおり退場をキャンセルして元の位置に戻る。動きを減らす設定では待たずに処理。

## 12. メイン／サブユーザー
- DB（追加のみ）: `profiles.kind`（`main`/`sub`、既定 `main`＝既存ユーザーはすべてメイン）。サブの対象系列は既存の `profile_target_rules`（`mode='allow'` かつ店舗なし）を使う。
- 判定（`src/lib/profile-scope.ts`）: サブは対象系列のみ表示・操作。**対象系列が未設定のサブは何も表示しない**。系列の別名（統合前の名前）は同じ系列として扱う。
- 表示: 一覧・マトリクス・継続抽選・新着件数・通知・タブの赤丸が対象系列だけ。他のユーザーから見た応募状況アイコンは、サブの対象系列のカードにだけ出し、対象外の系列ではアイコン自体を出さない（未応募扱いにしない）。
- 更新処理（サーバー）: 応募・当落・購入/受取・取り消し・商品別当落・★・スルーは、サブの対象外の系列を拒否（`subScopeError`）。
- 保存: ユーザー管理の編集で種別と対象系列（複数選択）を保存。種別・対象系列を変えても応募・当落・購入の履歴は変えない。メインへ戻すと対象系列の許可リストを外す（全系列）。メインのまま保存しても既存の許可リストは消さない。
- 既存の許可リスト（例: 以前の「C」の対象設定）はメインのまま従来どおり。サブにしたい場合は編集で「サブ」を選ぶと、現在の対象系列が初期値になる。

## 追加: 店舗住所からの位置情報の自動取得（migration 51）
- DB: `stores.geo_status`（none/pending/ok/failed/incomplete）・`geo_attempts`・`geo_address`・`geo_error`・`geo_checked_at`。トリガー `stores_geo_reset` が、**住所の登録・変更・削除のどの経路（画面・Excel取込・AI自動収集）でも**、古い座標を破棄して取得待ち（住所なしは none）にする。住所と同時に座標が指定された場合（手入力）は手入力を採用。
- 取得: `src/lib/server/geocode-service.ts`（国土地理院の住所検索API・無料・APIキー不要。既存の位置取得と同じAPI）。取得待ちを小分け（1回最大6〜20件・1件ずつ約1.1秒あける）で処理。保存は「保存時と同じ住所」のときだけ（取得中に住所が変わったら古い結果を捨てる）。
- 採用ルール（`src/lib/geocode.ts`）: 住所の先頭と一致する最も細かい候補のみ。市区町村止まり・一致なし・離れた複数候補は**保存せず「取得失敗」**（推測しない）。都道府県・市区町村・番地の手がかりが足りない住所は「住所不完全」（APIを呼ばず、補完すると自動で取得待ちに戻る）。一時的エラーは3回まで再試行。
- 起動: 店舗の保存直後（応答のあと）・自動収集の定期実行（/api/cron/collect）・`/api/cron/geocode`（CRON_SECRET必須）。
- 管理画面: 店舗一覧の上に取得中／失敗／住所不完全の件数と「取得失敗を再取得」。各店舗に状態を表示（取得済みは非表示）。
- 距離表示は従来どおり（店頭のみ・通販／座標なしは非表示）。

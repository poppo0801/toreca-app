# Stage 5X・5Y・5Z

## 5X: 自動収集の補完と「要手動確認」の削減

### 原因（本番の28件を分類した結果）
- 最大の原因は**一覧（まとめサイト）の抽出不足**。pokeso はカード（article）の先頭に「商品名・店舗名」、末尾に応募リンクがある。旧実装は「リンク直前の HTML 400文字」だけを文脈にしていたため、長いタグ属性に文字数を消費され、店舗名・商品名が欠落し、タイトルが「¥7,200 11/4(水) 21:00まで …」のような断片になっていた。
- 取得制限（t.co / e-starbox）は仕様どおり回避しない。ただし、一覧に店舗・商品・締切があれば、それを二次情報として読み取れる。
- 抽選ではないリンク（Googleカレンダー購読・アプリ配布）が候補になっていた。

### 実装
- `listing.ts`: リンクを含むカード（article / li）全体の文章（`card`）と、構造から読む店舗名・商品名（`fields`。pokeso=価格見出しの直前2つ、トレカ日和=強調表示と商品ページへのリンク。読めなければ未設定で推測しない）を保存。calendar.google.com / apps.apple.com / play.google.com は候補にしない。
- `run.ts`: 取得制限のとき、`店舗:`・`商品:` の見出し付きでカード全文をAIへ渡す（一覧由来の二次情報であることは従来どおり明示・記録）。
- `enrich.ts`（ワーカー前に毎回）: 旧版で保存済みの要手動確認／自動再調査の候補について、一覧を1回だけ取得して該当カードを補完し、再解析待ちへ戻す。登録済みの抽選と **店舗・商品・締切日の3つがそろって一致**したときだけ、AIを使わず重複として整理（一致の根拠を記録。商品と締切だけの一致では同一にしない）。一覧から消えた候補・補完済みの候補は `cardChecked` を付け、同じ確認を繰り返さない。
- `crossref.ts`: 同一抽選判定（純関数）。複数の抽選に一致するときは断定しない。名称の部分一致は短い方が6文字以上のときだけ。
- X収集元に `@pokecayoyaku` を追加（OnchainOutlaw・pokecachan は既に有効）。初回の取得（ユーザーID解決）は次回の定期収集で行う。

### 取得不可・要手動確認の画面
- 見出しは「要手動確認：N件」（N=締切が7日以内の今すぐ確認だけ）。赤色は本日・明日締切があるときだけ。
- 区分: 今すぐ確認 / 締切に余裕あり・不明（折りたたみ）/ 自動再調査中（折りたたみ・対応不要）/ 終了・対象外・対応済み（折りたたみ・直近）。
- 各候補は系列・店舗、商品、短い理由、締切、元情報の1ブロック。操作は「詳細・対応」を開いたときだけ（元情報を確認／編集して登録／再調査／対象外にする／対応完了）。ポップアップを閉じただけでは対応済みにしない（従来どおり）。

### ブラウザ描画（Playwright等）の採否: 不採用
- 取得失敗の実態は、ほとんどが robots.txt による制限（t.co / e-starbox）。制限回避に使わない方針のため効果がない。
- JavaScript 描画が原因の候補は1件（yappli.plus）のみ。Vercel のサーバーレス関数でのヘッドレスブラウザは、実行時間・メモリ・費用の検証が別途必要で、外部ブラウザサービスは未承認の有料サービスになる。今回は未実装・利用不可として扱う。

## 5Y
- 商品マスターに一致しない商品は、自動収集では確定登録しない（`PRODUCT_UNREGISTERED`）。要手動確認（商品確認待ち）に入り、「編集して登録」（既存商品の選択・新規登録）、「対象外にする」、「再調査」で処理する。確認後は従来の登録処理が元の候補を登録する。手動登録時の仮登録は変更しない。
- スルー表示（非表示（通常）／含む／のみ）は全タブに適用。応募・当選・購入・受取の記録は消えない。NEW バッジもスルー中の抽選を数えない。当選済みの手続き通知は、スルーの影響を受けない（回帰テスト）。
- 応募済み・当選にした時点で★を自動追加（サーバー・モック両方）。応募取消・落選・購入済み・受取済みでは外さない。既に★なら何もしない。

## 5Z
- `FitLine`: 日付行（応募締切・当落発表・購入期間・受取期間）を実測して1行に収める。順序は ①余白（gap）と字間を詰める ②行全体の文字サイズを同じ比率で縮小（最小8px。アイコンは em 指定で同じ比率）。
- E2E: 320/375/390/430px の詳細・シンプル全タブで、日付行の高さ（折り返し）・右端（はみ出し）・内容幅を検査。検査行数が0件なら失敗にする。狭い幅の強制縮小テストもある。

# Stage 7B: 抽選管理UI・操作性の改善

DB変更なし（既存の列・`profile_settings` の JSON を利用）。Stage 7A（自動収集・注意付き登録・地域判定）には手を入れていない。

## 1. 店舗選択式の応募店舗（`applied-store-dialog.tsx` / `lib/applied-store.ts`）
- 店舗選択式かどうかは、抽選に保存済みの `storeMode=select_on_apply`（Stage 6N・7A）を参照する。系列名による独自判定は追加していない。
- 「応募済み」（カードのボタン・スワイプ・複数商品の選択後）で、**小さなボトムシート**を開く。系列名・店舗の候補（タップで選択）・入力欄（絞り込みと自由入力）・確定・キャンセル。確定した時点で応募済みになり、キャンセルでは何も変わらない。店舗固定の抽選では開かない。
- 候補（`recentStoreCandidates`）: ①現在のプロフィールが同じ系列の抽選で応募した店舗 ②そのプロフィールが過去に使った、この系列の店舗（店舗マスターの系列で確認できるものだけ） ③系列マスターの店舗（または抽選に取得済みの店舗一覧）。履歴は利用回数→新しい順。同名は1つ。別の系列の店舗は出さない。先頭5件を並べ、残りは入力で絞り込む。履歴が無ければ通常の入力欄。新しいマスターは作っていない（応募履歴と店舗マスターを利用）。
- 店舗は原則入力する。「店舗を決めずに進む」は Stage 6N の仕様（応募時点で店舗未定の抽選・あとで変更可）を残した例外で、小さく表示する。編集（詳細の応募店舗の変更）は店舗が必須。
- 保存は Stage 6N の `applications.applied_store_*`（プロフィールの応募アカウントごと）。AとBは別々の店舗を持ち、Aの変更はBに影響しない。
- カード（`selectStoreDisplay`）: 応募前は「店舗選択式」、応募後は現在のプロフィールが応募した店舗（なければ表示範囲内の応募者）。カードは1枚のまま、ユーザーを切り替えるとそのユーザーの店舗が出る。複数の応募者がいるときは店舗名の `title` に「ユーザー: 店舗」を並べる。

## 2. 日付表示 A/B（`lottery-card.tsx`）
- 設定: 表示設定 > 抽選カード > 日付表示。プロフィール別設定 `dateLayout`（`a` 既定 / `b`）。既存の設定は変わらない（未設定=A）。コピー対象に追加。
- B（詳細表示のカードのみ。シンプル表示は変更なし）: 日付項目（締切・購入/受取期間。応募済みは発表日と期間、当選は購入・受取）を左の列に左寄せ、受取方法・距離（応募方法・発表方法を表示する設定のときはそれも）を右の列に置く。左右を同じグリッドの行に入れ、右の列の開始位置がそろう。右が無いときは左が全幅。長い文字は省略。NEW・★・注意アイコンとは別の行で干渉しない。表示条件（`cardDisplay`）はAと同じ。設定変更は即時反映。

## 3. スワイプ操作のモード（`use-tab-swipe.ts` / `lib/tab-swipe.ts`）
- 設定: 表示設定 > スワイプ操作。プロフィール別設定 `swipeMode`（`card` 既定 / `tab`）。保存は `profile_settings`（別端末でも同じ）。
- `card`: 従来のカードスワイプ（端末のON/OFFも従来どおり）。`tab`: カードの横スワイプを無効にし、画面の横スワイプで 全情報→要チェック→応募済み→当選 を切り替える（左で次、右で前、端では動かない）。小さなスライドで切り替え（再読み込みなし・「視覚効果を減らす」では無効）。
- 競合の防止: 縦スクロール優勢・移動量不足・900ms超の操作は無視（既存の軸判定を共用）。画面の左右28px以内から始まる操作（iOSの戻る）、ダイアログ/ボトムシート表示中、入力欄・タブ列・横スクロール要素の中、2本指は対象外。タップ・詳細・ボタン・長押しは従来どおり。★・応募済みなどはカードの詳細やボタンから実行できる。

## 4. 当選タブ
- **受取済みを一覧から外す**: 当選タブは「受取が済んでいない当選」を持つ抽選だけ（`hasActiveWon`）。受取済みの抽選は当選タブにも要チェックにも出ず、全情報に戻る（既定の「受付中・未応募」では受付終了のため見えない）。当選・購入・受取の記録、収支、BOX、プロフィール別履歴は変更しない。
- **●バッジ**（`wonNeedsAction` / `tabDots`）: 購入期間中の未購入・受取期間中の未受取・期限超過の未処理だけ。期間の開始前、完了、**期間がまったく未設定**（対応が必要と確実に言えない）は出さない。開始日が分かっていて期限が未確認のものは出す。判定範囲は当選タブの対象ユーザーの絞り込み（サブを含む）に従う。購入・受取を記録すると即時に消える。見た目は既存の小さな丸（件数なし）。

## 5. 注意点
- **挙動の変更**: 期間が未設定の当選は、以前は●が出ていたが出なくなる。受取済みの当選は当選タブから消える。
- 日付表示はプロフィール別設定（既存の「カード表示」と同じ保存方式）。世帯共通ではない。

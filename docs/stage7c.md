# Stage 7C: iPhone復帰時のエラー対策・UI改善・集計更新

DB変更なし。

## 1. iPhone PWA の復帰時エラー

### 調査結果（コードと構成から。実機のログは取得できていない）
再現ログ（Vercelの実行ログ・実機のコンソール）はこの環境から取得できないため、原因は**コード・構成の調査に基づく推定**で、次の根拠による。
1. **エラー境界が一つも無かった**（`error.tsx` / `global-error.tsx` なし）。画面の描画・サーバー呼び出しが一度失敗すると、Next.js 標準の「Application error / Reload to try again」画面になる。ホーム画面アプリを別アプリから戻すと、凍結中に切れた接続での再取得、古いJavaScriptの読み込み失敗、デプロイ更新後の古い画面から新しいサーバーへの呼び出し（Server Action の不一致）が起きうるが、いずれも「再読み込みを求める画面」に直結していた。
2. **認証確認の通信失敗がログイン画面への遷移になりうる**: `(app)/layout.tsx` が `getUser()` の失敗（通信エラー含む）で `/login` へリダイレクト、`proxy.ts` も `getClaims()` の通信失敗を未ログイン扱いにしていた。復帰直後の不安定な通信で、ログアウトしたように見える。
3. **復帰時の再取得・復旧処理が無かった**: `visibilitychange` はキーボード位置の追従とAIジョブ確認だけ。通信失敗は 1 回で失敗扱い（起動時は全画面のエラー）。
4. Service Worker は通知専用（ページ・APIをキャッシュしない）で、キャッシュ起因ではない。
5. 再読み込み後にタブ・フィルターが初期化されていた（`sessionStorage` のみ。iOSがバックグラウンドのPWAを破棄して再起動すると失われる）。

### 実施した修正
- **エラー境界**（`app/error.tsx`・`(app)/error.tsx`・`global-error.tsx`、`recoverable-error.tsx`）: アプリ全体のエラー画面にしない。`(app)` のエラーはヘッダー・下部メニュー・データを残したまま画面の中身だけを再取得（`router.refresh()` + `reset()`）。
- **自動復旧の段階**: ①一時的な通信失敗は少し待って自動で再取得（60秒に2回まで） ②古い画面（JS読み込み失敗・Server Action不一致）は最終手段として全画面を再読み込み。**10分に1回・1日3回まで、ダイアログ/ボトムシート表示中（入力中の可能性）は行わない** ③直らなければ「もう一度試す」「アプリを再読み込み」の操作ボタン。全画面の再読み込みは最終手段。
- **データ取得の再試行**（`app-provider.tsx`）: 通信エラー（`Load failed` 等）は最大3回（0.8秒・2.5秒後）やり直してから失敗扱い。時間切れ（25秒）は繰り返さない。バックグラウンド更新の失敗は通知を出さない（`reload({silent})`）。
- **復帰時の処理**（`resilience-watcher.tsx`）: 30秒以上離れたあと、または最後の取得から10分以上たっていれば、**データだけ**を静かに再取得（20秒以内の重複・取得中は取得しない）。オフラインなら取得せず、`online` で1回取得。タブ・プロフィール・フィルター・スクロール・開いている詳細・入力中のダイアログは作り直さない。`pageshow(persisted)` も同様。
- **ログアウトさせない**: 認証確認の通信失敗（`AuthRetryableFetchError`・5xx・ネットワーク）はログイン画面に送らない。`proxy.ts` は `sb-` Cookie があれば通し、`(app)/layout.tsx` は例外にしてエラー境界の自動再試行に任せる。認証の拒否（401・セッション無し）は従来どおりログイン画面。
- **新バージョンへの移行**: `NEXT_PUBLIC_BUILD_ID`（コミット短縮ID）と `/api/version`（認証不要・ビルドIDのみ）。復帰時に差を検出、または古いJSの読み込み失敗を検出すると小さな通知「新しいバージョンがあります［更新］」を出す。**利用中の画面は突然リロードしない**。次の画面移動のとき、入力中でなければ回数制限つきで自然に切り替える。Service Worker は変更なし（通知専用・`skipWaiting`＋`clients.claim` の現行構成が安全で、キャッシュ削除・強制更新は不要）。
- **画面の維持**: 復帰で作り直さない（上記）。加えて、`readSession/writeSession` が端末の `localStorage` にも12時間の控えを残し、iOSによる破棄・再起動後も直前のタブ・フィルターに戻れる。
- **エラーの記録**: 端末内に最大30件（設定 > 表示設定の「接続の記録」で確認・消去）。項目は 日時・種別（古い画面／バージョン不整合／通信／時間切れ／認証／その他）・画面（IDを除いたパス）・復帰直後か（20秒以内）・オンライン状態・ビルドID・発生箇所・整理済みの文言。URLのクエリ、トークン状の文字列、メールアドレスは除く。同じエラーは60秒に1回、1回の起動で最大8件までサーバーへ送信（`/api/client-log`。ログイン済みのみ、Vercelの実行ログに1行出すだけでDB保存しない）。有料の監視サービスは使わない。

### 自動テストで確認したこと / 実機が必要なこと
- 自動（単体・画面・実Supabase E2E）: エラー分類、再試行の回数制限、再読み込みの制限（入力中・回数）、復帰時の再取得の条件（短い切替では取得しない／数分・数時間後は取得／取得中・直後は重ねない／オフラインは待つ）、データ取得の通信失敗からの復旧、認証の通信失敗の判定、ログの整理（トークン・メールを含まない）、新バージョン通知（突然リロードしない）、ダイアログと入力が復帰で消えない、タブが保たれる、オフライン→復帰、再起動を想定したタブ復元。
- **実機でのみ確認できる**（未確認）: ホームバーで別アプリへ移動して戻る実際の挙動（iOSのページ凍結・破棄・ネットワーク復帰のタイミング）、数時間後の復帰、本番デプロイ直後の古い画面、Safari/PWA固有の通信中断。

## 2. UI
- 自動収集設定の「①動作状況」は初期に折りたたみ（`defaultOpen` を外した。既存のアコーディオン）。
- コレクション詳細（保有状況の展開）: 余白を拡大（左右・行間・セクション間）。「収録パック別」の集計表示と「一部のカードだけの集計です…」の説明文を削除（収録パック情報・マスターとの紐づけ・自動判別・入力はそのまま。DBは変更なし。「一部」の小さな印は集計に残る）。BOXの注記は対象外。
- 収支の取引カード: 金額を右端の専用列（最小幅・右揃え・tabular-nums）に分離。桁数が違っても右端がそろい、長い商品名は省略されて金額と重ならない。独立カード・分類色・符号/色分けは従来どおり。

## 3. 相場更新後の集計
- 相場の更新（一括・CSV・個別）の完了後、`onDone` を待って**必要なデータだけ**を再取得（画面のリロードなし）。更新ダイアログは再計算が終わるまで「更新しています…」のまま。
- `useLatestLoader`: 取得の順序を保証（遅れて届いた古い応答で新しい集計を上書きしない）、取得中は集計を薄く表示（`aria-busy`、更新途中の値を確定表示しない）、失敗時は1回取り直し、それでも失敗したら**今の（整合した）表示を保ちエラーを知らせる**。カード・BOXの両方に適用。手動価格・BOX価格・CSVの保存後も同じ経路。
- 計算式は変更なし。ヘッダーの「購入」は実購入金額、「買取」は手動で確定した買取価格×状態倍率、取得した相場（`card_market_prices`）は「参考価値（販売）」の状態別価格に使われる（詳細）。過去の購入価格・収支記録は書き換えない。

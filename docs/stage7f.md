# Stage 7F: カード・BOX相場取得の改善

DB変更は追加のみ（`20261201000079_stage7f.sql`、`20261201000080_stage7f_purge.sql`）。既存の行・列・手動の価格・購入/収支のデータは変更していない。新しい外部サービス・有料API・自動の定期取得は入れていない（取得元は従来どおりの公開CSV 1つ）。

## 1. 価格の優先順位（カード・BOX共通の考え方）
販売・買取は独立に判定する。取得した相場で手動の相場を上書きしない。取得に失敗しても既存の価格は消さない。
- **カードの基準相場**: ①手動の参考相場 → ②取得した基準相場（状態A）→ ③価格なし（0円にしない）。
- **カードの状態B・C**: 取得した状態別の実際の販売相場があれば、倍率による推定より優先（実価格 > 推定）。なければ基準相場×倍率（A100/B85/C65。既存の設定値）で、画面には「基準×85%の推定」と示す。CSVに状態別の掲載が無いのに実価格として扱わない。
  - 補足: 指示書の優先順位「手動 > 実価格 > 基準×倍率」のうち、手動の参考相場は状態Aの基準として扱い、手動があっても状態B・Cの所持分は実価格を使う（Stage 6K〜7Cの既存動作・テストを維持）。手動の基準相場そのものは、取得した相場で上書きしない。
- **BOXの買取評価**: ①手動の相場（状態別 → 基準×倍率）→ ②取得した相場の状態別の実価格（CSVにシュリンクの有無が明示されたもの）→ ③取得した基準相場×倍率（シュリンクあり100%・なし85%・「－」は基準そのまま）→ ④未取得。倍率は既存のBOX設定。
- 「購入」（上部）は実際に支払った金額、「買取」「参考価値」は参考相場の評価。意味は変えていない。購入金額・収支・数量・状態には触れない。

## 2. カード
- 取得した状態Aの相場（`card_market_prices`）を、手動の参考相場が無いカード・種別の評価額に使う（`summarizeCards`）。上部の「買取」「参考価値（販売）」、並び替え、一覧の「買取参考」、差額に反映。相場更新後は画面全体を再読み込みせず集計を更新（Stage 7Cの仕組みのまま）。
- 価格の出所は行ごとに持つ（`saleSource` / `buybackSource` = 手動 / 取得 / なし）。最終取得日（上部の日付）は取得日時も対象。
- **取得状況**（`market_status`・カード単位で1行）: 取得成功 / 販売のみ / 買取のみ / CSVに対象カードなし / 商品照合失敗（照合未確定・情報不足）/ 掲載はあるが価格なし / 手動価格のみ / 未取得。一覧は未取得・一部のみ・古いときだけ小さな印（詳細で理由を確認）。詳細は「手動／取得・取得日・店舗数（1店舗のみは明示）」「価格の状況」。
- **古い価格**: 取得から7日以上たった価格は「古い」と示す。更新に失敗しても取得済みの価格は消さず、最終取得日時を保つ。
- **更新の実行履歴**（`market_update_runs`、直近30件）: 成功・失敗と失敗の分類（通信・取得元の応答・データ形式・保存）。更新ダイアログに「前回の更新は失敗しました。取得済みの価格は消さず…」を表示。未掲載（出典に無い）と更新失敗は別物として扱う。

## 3. BOX（`lib/box-market.ts`）
同じ公開CSVの `type=box` 行を、同じ「相場を更新」1回の操作で照合する（BOX専用の追加アクセス・定期取得なし。提供元の再利用条件は未確認のため、画面操作での取得／CSV取り込みのみ）。
- **正規化**: 空白・記号を除き、名称の**先頭**のシリーズ名・パックの種類（MEGA／スカーレット＆バイオレット／ソード＆シールド／拡張パック 等）と、**末尾**の「BOX」「未開封」だけを除く。名称の途中・末尾のシリーズ名（例「プレミアムトレーナーボックス ソード＆シールド」）は商品の違いなので除かない。シリーズ名が両方にあって食い違えば別商品。
- **照合の順序**: ①商品コード（名称内の括弧つき「(M1S)」）→ ②商品名の一致 → ③別名（`product_aliases`）→ ④部分一致は**候補**として示すだけ。複数商品に当てはまる／限定版・セット・デラックス等の語がCSV側だけにある場合は自動確定しない。
- **異常検知**: 自動照合の結果、買取（基準）が販売（基準）の1.2倍を超えるときは確定せず、要確認にする（別商品を拾っている可能性）。
- **利用者の確認**: 自動で確定できず候補がある商品（BOXコレクションにある商品）は、更新結果に「CSVの商品名・販売・買取・店舗数・判定理由」を示し、「この商品として登録」で確定。対応は `box_market_links`（CSV名キー→商品、1つのCSV名は1商品・同じ商品に複数の表記可）に保存し、次回以降は自動より優先。CSVから消えた対応は「再確認」として数える。確定できないものは価格を登録せず未照合のまま。
- **価格の保存**（`box_market_prices`: 商品×販売/買取×根拠で1行）: 根拠は `base`（未開封・新品＝シュリンクの有無を断定しない基準）／`shrink`・`no_shrink`（CSVに明示されたものだけ）。「状態A-」など傷み・中古は集計に使わない。販売は在庫あり、同じ店舗は販売=最安・買取=最高の1件、3店舗以上は外れ値除外、中央値。店舗数・取得日時・照合の根拠（商品コード／商品名／別名／手動）を保存。手動の `box_prices` は変更しない。再取込は上書き（増えない）。取得できなかった種類は前回の価格を残す。
- **画面**: BOXの相場ダイアログに「ポケカ価格比較から取得」→ 更新ダイアログ（カードと共通）。詳細に「取得した相場」（販売・買取・状態、店舗数、1店舗のみは注意色、最終取得、照合の根拠）、状態別の買取に「手動／取得相場（n店舗）」。上部は取得相場で評価したBOX数を注記。
- **商品マスターの統合・削除**（`delete_product` / `merge_products` に数行を追加）: 確定した対応は統合先へ付け替え、取得相場は統合先に無い種類だけ引き継ぐ。参照の無い商品の削除では、その取得相場・対応も消える（再取得で作り直せる派生データ）。

## 6. 制限事項
- 提供元（ポケカ価格比較）の再利用・保存条件は確認できていない。画面操作での取得とCSV取り込みに限り、自動の定期取得・公開配信はしない。
- 収録外（旧弾・特殊番号）のカード、BOX名の表記ゆれが大きい商品（セット商品など）は取得できない／要確認になる。手動の参考相場で補う。
- BOXの「未開封」「新品」はシュリンクの有無を断定しない基準として扱う（シュリンクありの実価格は取得できない）。
- バックアップ対象外のまま残る表: 収集（collection_*）・通知の実行履歴・X連携のトークン類など（機密または一時データ）。

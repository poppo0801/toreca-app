# Stage 6M: BOXコレクション

実機（iPhone）では未確認の項目は「実機未確認」と明記する。

## 1. 画面
- コレクションののページは **左右スワイプだけ**で カード｜BOX を切り替える（切替ボタンは置かない。横へ滑るアニメーション）。URL は `?tab=box`。一覧・集計・並び順・絞り込みはページごとに独立。カード側の既存機能・並び設定は変えていない。
- 右上のボタンは［相場更新］［＋登録］（「＋カード登録」を「＋登録」に変更）。表示中のページ（カード／BOX）に対して働く。登録フォームの上部の **カード／BOX** で切り替えられ（どちらもボトムシート）、どちらも手動登録できる。
- スワイプは、ダイアログの中・入力欄・長押しドラッグ（並び替え）の最中は切替に使わない。縦の動きが大きいとき・短い動きも無視（横60px以上、かつ縦の1.6倍以上）。
- カードの集計行は **購入／買取／枚数** の順（「購入額→購入」「参考買取→買取」「一部のみ→一部」）。価格の右に最終価格取得日（例: `12/1`）を小さく表示。BOXは同じ形式で「○BOX」。種類数などはタップで開く詳細に移した。
- BOX一覧はカードと同じ基本デザイン（画像のグリッド／テキスト一覧、1行の操作列）。商品画像を中心に、所有数（×N）と状態未確認の印を重ねる。並び順は **価格の高い順（初期）**／安い順／発売日の新しい順／古い順。価格・発売日が未取得の商品も表示し、末尾に並べる（同値は 発売日→名前→ID で決め、順序が揺れない）。

## 2. データと在庫
- `box_lots`（購入ロット）: 商品（既存の `products`。商品情報は二重管理しない）・購入日・購入元・実購入価格（1BOX）・購入時点の市場相場（1BOX・取得元・基準日）・手動登録／購入記録連動の区別。
- `box_movements`（在庫の履歴・追記のみ）: 購入・受取・売却・開封・手動調整。現在の所有数＝ロット×状態（シュリンクあり／なし／未確認）ごとの履歴の合計。更新・削除は不可（service_role も不可）。取り消しは逆向きの行を足す。
- `box_prices`（参考買取相場・追記のみ）: 基準相場（状態指定なし）と、状態別の実際の相場。現在の値は確認日が最新の行。`box_settings`: 補正倍率（あり100%・なし85%が初期値）と自動連動の開始時刻。
- 書き込みは検証つきのDB関数（`box_add_manual` / `box_adjust` / `box_update_lot` / `box_open` / `box_revert_op` / `box_import_purchase_item`）と連動トリガーだけ。履歴・ロットを利用者が直接書き換えることはできない。

## 3. 評価（BOXの「購入」「買取」）
- **購入**＝現在所有するBOXの購入時点の評価額の合計。購入時点の市場相場があればそれ、なければ実購入価格。どちらも無いロットは「未取得」として別に数え、0円として合計しない。収支の支出（実際に支払った額）は変わらない。
  - 例: 実購入5,400円・購入時の市場相場12,000円・現在の買取10,000円 → BOXコレクション: 購入12,000円／買取10,000円、収支の支出: 5,400円。
- 購入時点の市場相場は履歴として固定する。現在の相場で上書き・代用しない。入力するときは取得元と基準日が必須（出所の分からない価格を履歴にしない）。AIによる推測、新規の有料API、無断スクレイピングは使っていない。
- **買取**＝現在の参考買取相場の合計。無料で使える取得元がないため **手動更新**（［相場更新］で所有商品ごとに基準相場を入力、商品の詳細で状態別の実際の相場も入力）。最終更新日（基準日）を保存・表示する。相場が無い商品は「未取得」で、取得済みとして表示しない。
- 状態別の評価: 状態別の実際の相場があればそれを優先。なければ基準相場×補正倍率（あり100%・なし85%。メニューの「シュリンク状態の評価倍率」で変更）。状態未確認は基準相場のまま表示し、未確認であることを明示する。参考評価で、買取の保証額ではない。
- 詳細（下から開くパネル）: 状態別の数量・1BOXあたりの買取・合計、購入ロット（購入日・購入元・購入記録連動／手動・実購入・購入時の市場相場）、在庫の履歴。

## 4. 購入・受取・売却・開封との連動
| 操作 | 在庫への反映 |
|---|---|
| BOXの購入記録（新規・編集・削除） | 状態未確認で数量を加算。編集は差分だけ。再保存しても二重加算しない。購入記録の論理削除・復元・明細の削除にも追従。パック・個の購入は対象外。**抽選の当選だけでは加算しない**（購入記録を作った時点で加算。当選→受取済みで自動作成される購入記録も同じ） |
| 受取のシュリンク状態（6L） | 未確認から実際の状態へ移す。購入と受取で二重加算しない。混在（あり2＋なし1）も数量が一致。購入数量を減らすと追従（受取の合計は購入数量を超えない） |
| 売却記録（BOX・減らす状態を選択） | 古いロットから順に減らす。編集・削除（論理削除）で戻して取り直す。所有数を超える売却は拒否（売却記録も作られない）。状態を選ばない売却は在庫に反映しない。取得原価・購入時相場の履歴は保持し、収支は実際の取得原価と売却金額を使う |
| 開封済みにする | 状態・数量を指定して減算。売却とは別の在庫移動。履歴の「取り消し」で戻せる（1度だけ）。カードへの自動変換はしない |
| 手動調整 | ロット・状態・増減を指定。履歴に残り、取り消せる |

- **過去の購入記録は自動で取り込まない**（売却・開封済みの可能性）。migration 適用時刻より前に作られた購入明細は、メニューの「購入記録から取り込む」で選んだものだけ入る（受取の記録があればその状態、なければ未確認。取り込みは1度だけ）。適用時刻前の明細は編集しても自動では取り込まれない。
- 売却が所有分を減らしている状態で、購入記録の数量・受取の状態をそれ以下に変える操作は拒否される（売却・開封済みの分は変えられない）。

## 5. 整合性（二重計上・同時操作）
- 目標との差分だけを書く方式（購入記録の同期・売却の同期）なので、何度保存しても二重に動かない。操作ID（開封・手動登録・調整）で再送・多重タップを無効化。
- ロット・購入明細・売却・商品ごとにアドバイザリロックで直列化し、状態ごとの残数が負になる追記を拒否（`insufficient box stock`）。複数端末から同時に在庫を超える開封を送っても、所有数分だけ成功する（結合テスト）。
- 世帯分離: 全表にRLS。関数は世帯の所属を確認。他の世帯の商品・購入明細を参照できない（複合FK）。

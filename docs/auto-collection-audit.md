## 0. 先に結論（要点）

1. **【重大・本番確認済み】cron（サービスロール）で実行したAI解析の利用ログが、1件も保存されていない。** `ai_extraction_logs.user_id` が `NOT NULL DEFAULT auth.uid()` で、ログインなしの cron では挿入が失敗し、`run.ts:207` は挿入結果を検査しない。結果、**月額予算の判定・予約・1時間の速度制限がすべて実績の約1/9しか見ていない**（今月：ログ基準 16.75円 ／ 日別統計基準 156.46円）。実費はまだ予算 3,000円の約5%なので実害は出ていないが、上限が機能していない（§7, §10-A）。
2. **【本番確認済み】朝6:00の定期収集は、直近2回とも収集元をほぼ取得していない。** 手動実行の翌朝は「前回試行から24時間未満」で全収集元がスキップされる（`run.ts:564-566`）。cron の収集実行は2回とも Web取得0件（§6, §10-B）。
3. **要手動確認・保留の主因は「照合の失敗」ではなく「情報の欠落」。** 確認待ち58件のうち30件は、AIが**店舗名を読み取れていない（空欄）**。うち17件がXの投稿（添付画像に店舗名がある可能性）。マスター照合の調整では減らない（§8, §10-C）。
4. **複数情報源の統合は「項目単位の補完」ではなく「候補単位の再解析」。** 1回の解析の中では本文・リンク先・画像を統合して項目ごとに根拠（出典ラベル・原文抜粋・検証済み）を持つが、候補をまたいだ項目補完は行わない。例外は一覧のカード由来の補完（締切・受取方法・店舗名「オンライン」）のみ（§4）。
5. **代替情報源は「登録だけ」ではなく一部は実働しているが、自動探索はない。** 実働しているのは ①まとめサイト一覧のカード文章による代替解析（`viaList`）、②登録済み抽選との3点一致による重複整理（`enrich.ts`）、③解析後の重複検出。X公式アカウントや別サイトを**検索して補完する処理はない**（§6）。
6. 費用は現状小さい（AI今月 約156円推定／X API 今月 約451円推定／月間予算 AI 3,000円・X 2,000円）。ただし1件の自動登録あたりの AI 呼び出しは約14回（361回／26件）と多く、削減余地は「AI回数」にある（§7, §10）。

### 4.5 複数情報源の統合：項目単位か候補単位か **[コード]**（質問への明確な回答）

## 5. 自動登録・除外・保留・手動確認の判定

### 5.1 判定フロー（`processCandidate`, `run.ts:347-522`）

```
AI結果 ─┬─ not_lottery / nothing_found ───────────────────────────────→ 除外(skipped)  "抽選の告知とは判断できませんでした"
        ├─ 取得失敗/AI失敗 ──→ fail(): 失敗の分類 ──→ §6
        └─ 成功 → buildDraft → 一覧補完(secondary) → 収集元除外ルール(店舗/系列) ─一致→ 除外
                        │
                        ├─ 既存抽選の更新(q.changed ∧ 抽選あり) → 新抽選回 / 変更なし / 更新提案(review)
                        ├─ 重複 high ───────────────────────────────→ duplicate (URL追記)
```

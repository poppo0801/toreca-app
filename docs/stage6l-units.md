# Stage 6L（続き）: 商品の単位・シュリンク目安・受取状態・数量入力

## 1. 商品区分と数量の単位
| 商品区分 | 単位 |
|---|---|
| 拡張パック（または未分類） | パック／BOX |
| 構築済みデッキ・プレミアムセット・その他商品 | 個 |

- 商品マスターに「商品区分」（`products.product_kind`。未分類は NULL）を追加。**未分類は推測で決めず**、従来どおりパック／BOX から選べる（販売形態が「単品・セット」と分かっている商品だけ「個」）。
- 1BOXあたりのパック数は既存の `products.packs_per_box`（商品ごと。一律の換算値は持たない）。
- 抽選の商品明細の単位に「個」(`piece`) を追加。**既存の box / pack / set の行は変換しない**。保存済みの単位が選択肢にないとき（旧データの「セット」など）は、その単位を選択肢に残す。商品を選び直したときだけ、その区分で使えない単位を使える単位に直す。
- 購入・売却の単位の選択肢も同じ規則（`src/lib/product-kind.ts` の `unitOptions` / `unitForProduct`）。受取済みにしたときの金額の仮計算は、単位「個」も単品・セット定価で計算（`mark_purchased`）。

## 2. 系列のBOX販売形態の目安
- 系列マスターの登録・編集に「BOX販売形態」（シュリンクあり／なし／パックのみ／不明・未設定。`chains.box_shrink_hint`）。**応募判断の目安であり、実際の受取状態ではない。**
- BOX商品の抽選カード詳細で、商品名の下に小さなラベル「シュリンクあり（目安）」を表示。不明・未設定は表示しない。
- 個別の抽選で確定している場合に備えて `lotteries.box_shrink_hint` を持つ（画面での入力はまだ無い）。値があれば系列の目安より優先し、「（目安）」を付けない。
- 系列の目安を変更しても、過去に記録した受取の状態（`box_receipts`）は変わらない（別の表）。

## 3. 受取時のシュリンク状態
- 表 `box_receipts`: 購入明細（BOX）ごとに、状態（シュリンクあり／なし／その他・不明）ごとに1行。商品・系列・店舗・受取日・数量を記録時点の値で保存（将来、系列・店舗ごとの実績を集計できる）。統計の画面は未実装。
- 記録方法: ①当選カードの「受取を記録」のあと（BOXの購入があるときだけ）に開くダイアログ、②購入履歴の編集画面のBOX明細の「受取の状態」。複数BOXで状態が違うときは状態ごとに数量を入力（合計は購入数量以下。受け取っていない分は記録に含めない）。
- 保存は RPC `record_box_receipt`（その購入明細の記録を渡した内容にまとめて置き換える。何度保存しても結果は同じ。購入数量の超過・BOX以外・他世帯は拒否）。購入明細を削除すると記録も消える（cascade）。

## 4. 数量入力
- `CountInput`（`src/components/count-input.tsx`）: 入力中は文字列のまま保持して**空欄を許可**し、数字を消して別の数字に置き換えられる。フォーカスが外れたとき空欄は 0（上限回数・原価にする数量などは 1）。負数・小数・数字以外は入力できない。スマホは数字キーボード。保存時は従来どおり「数量は1以上」で検証。
- 適用: 抽選の数量・上限回数、購入の数量、売却の数量・原価にする数量、応募ルールの上限回数。

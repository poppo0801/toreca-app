# Stage 9H-3S-2: 自律型AIによる再調査・再判定と情報抽出能力の改善

9H-3S の一括再評価は固定ロジックだけで判断していた。今回、**固定ロジックの提案を「暫定」とし、AIが実際の情報源を調べて確認するまで適用しない**構造にした。本番は未変更（PR #4 への追加コミット）。

## 1. 固定ロジックとAIの役割（修正後）
| 区分 | 固定ロジック（安全・整合性・費用の補助） | AI（調査・判断の主体） |
|---|---|---|
| 候補の洗い出し | 期限切れ・地域外・重複の**暫定**判定（計画） | — |
| 日付の補完・期限切れの確認 | 値の形式・既存値/人の確定値の保護・根拠の原文の有無・補完の等級 | 情報元URLの取得・文脈の理解（開始/締切/当選発表/購入期限の区別）・追加検索・終了判断（調査エンジン `investigateCase`） |
| 地域 | 確認済み（公式の店舗一覧に番地までの住所）だけを確定とする検証層 | 店舗の実所在地のWeb調査（公式店舗一覧の探索・取り違え防止。店舗所在地エージェント） |
| 抽選どうしの関係 | 事実と矛盾する主張だけを安全側へ直す（`verifyRelation`） | A重複／B同系列別店舗／C独立／判断不能の判断（`relation-judge`） |
| 別名 | 追加条件（根拠・自己強化の防止・人の確定値の保護） | 調査中に見つけた表記を、情報源・根拠つきで渡す |
| 適用 | AI確認済み（調査済み＋判定 confirm）だけを対象にし、直前に保護を再確認 | — |

**固定ロジックの結果だけで完了扱いにしない**: `master_reeval_items.ai_state` が `investigated` で、かつ判定が `confirm` のものだけを適用できる。未調査（`not_investigated`）・取得できなかった（`failed`）・判断に足りない（`insufficient`）は、いずれも適用されず「AI未調査／判断できず」として画面に残る。実際に情報源を取得できなかった調査は調査済みにしない。

## 2. 実装
- `src/lib/agent/reeval-ai/assess.ts`（純関数）: 調査結果と既存の登録の照合（補完・差分・不明・締切の判断）、店舗所在地の判断、別名学習の材料。補完は **既存が空欄**・**人が確定した項目は対象外**・**根拠の原文あり**・矛盾なしのときだけ。等級は `confirmed`（調査の台帳が確認済み）と `stated_on_registered_source`（**登録済みの情報元URLに明記**された二次情報。確認済みとは区別し、公式での再確認を促す）
- `src/lib/agent/relation-judge.ts`: AIの関係判定＋検証。同一抽選と主張しても、店舗が違えば別店舗（B）、締切が3日超ずれれば独立（C）、根拠がなければ判断不能に直し、理由を残す。人が確認した抽選が絡むときは自動の統合の対象にしない
- `src/lib/server/agent/reeval-ai-service.ts`: 実AI・実Webの接続（`realReevalDeps`。関門＝開発環境・許可・開発専用キー・費用上限100円以下・確認）、調査単位の処理、**別名学習の実接続**（`learnFromInvestigation`）、**店舗所在地の蓄積**（`accumulateStoreLocation`＝確認済みのときだけ `stores` へ都道府県・住所・根拠を保存）
- `src/lib/server/agent/reeval-ai-run.ts`: DBつきのバッチ（`runAiReevaluation`）。未調査の項目を、費用の上限の範囲で調査。1回の単位数で区切って再開でき、調査済みは再調査しない。結果（取得できた情報源・補完・差分・不明・判定・費用・時間）を項目に記録し、補完は `fill_fields` の項目として別に作る
- `reeval-service.ts`: 適用は **AI確認済みのみ**。`fill_fields` は、計画の後に値が入った項目を変えず、元に戻せる。画面は区分ごとに「AI確認済み／AI未調査（暫定）／AIが否定／判断できず」を表示
- 通常収集: 調査結果（案件ファイル）から系列・商品の表記を根拠つきで名寄せ機構へ渡す（`case-learning.ts`。収集の調査フックから）。名寄せ・別名学習は `saveLottery` で全経路に適用済み（9H-3S）
- DB（マイグレーション106に追記・本番未適用）: `master_reeval_items` に `ai_state`・`ai_result`・`ai_cost_jpy`・`ai_at`、`stores` に `location_evidence`・`location_verified_at`

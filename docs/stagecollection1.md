# Stage Collection-1: 151図鑑・相場調査メモ

ブランチ `collection-1`（`ui-1` から分岐）。情報収集AI・抽選候補判定・自動登録・Stage 9H-3Kの評価データには触れていない。本番DBへの書き込み・デプロイ・mainへのマージなし。**マイグレーション `20261222000104_collection1.sql` は開発DBにだけ適用（本番未適用）**。

## 設計の要点
- 両機能は**独立した新規テーブル**。既存の購入記録（purchases）・コレクション（card_masters / card_holdings）・支出には書き込まない（二重計上の防止。既存の購入と連携すると二重計上の恐れがあるため、独立実装を選んだ）。
- すべての行に `profile_id`。`(profile_id, household_id)` で profiles に紐づく複合外部キー（cascade）。RLSは世帯単位（家族が1ログインでプロフィールを切り替える設計のため）。**プロフィール間の分離は、アプリ側の profile_id 絞り込みと複合外部キー**で担保（他世帯のプロフィールには紐づけられない）。
- 既存のコレクションは世帯共通（card_holdings に profile_id が無い）。今回は要件に合わせ、新機能はプロフィール別。
- 151匹のマスターはコード定数（`src/lib/zukan/pokemon151.ts`。公式の日本語名称・No.001〜151）。DBには図鑑番号（1〜151）のみ。
- 状態ランクは既存のコレクションと同じ A+/A/B+/B/C。

## テーブル（マイグレーション104）
| 表 | 内容 |
|---|---|
| `zukan_cards` | 収集カード（図鑑番号・カード名・収録商品・番号・レアリティ・枚数・入手日・入手方法・購入金額・店舗・状態・メモ）。`acquire_method` と `purchase_amount_yen` の整合を CHECK で強制（単品購入＝金額あり／パック開封＝金額なし。金額は null=未入力・0=明示的な0円）。`price_record_id` は一意（1つの価格記録から1回だけ購入） |
| `zukan_price_records` | 151図鑑専用の価格調査（ポケモン・カード・店舗・系列・調査日・状態・価格・備考） |
| `market_cards` | 相場調査メモのカードマスター。(プロフィール, セット, 番号, レアリティ) が一意（番号とセットがあるカード） |
| `market_prices` | 店舗価格の記録（履歴。カードを `on delete restrict`） |
| `market_purchases` | 購入済みの記録。`price_id` が一意（二重購入防止）。価格・カードを restrict（購入済みの価格・履歴のあるカードは削除不可） |
- RPC: `zukan_buy_from_price_tx`・`market_buy_from_price_tx`（価格記録の内容を引き継いで原子的に購入。二重は 23505）。RLS: 5表すべて有効・世帯メンバーのみ。

## 151図鑑
- 一覧: No.001〜151・日本語名・収集済みは緑の背景＋チェック。上部に「収集済み/151・達成率・未収集」（タップで登録カード枚数・単品購入金額合計）。すべて／収集済み／未収集の絞り込み。JSONエクスポート。
- 収集済み: 所有枚数の合計≥1。同じポケモンの複数カードは1匹。
- 詳細: カードの登録・編集・削除（削除は確認つき。購入履歴・価格調査には影響しない）。購入金額が空欄＝パック開封（null）、入力あり＝単品購入、「0」＝0円（未入力と区別）。明示した入手方法と金額が矛盾するときは保存前にエラー（画面・サーバー・DBの3層）。
- 単品購入金額合計: 金額あり（null以外）のカードの 金額×枚数 の合計。
- 価格調査（図鑑専用）: ポケモン・カード・セット・番号・レア・店舗・調査日・状態・価格・備考。初期は状態の良い順→価格の安い順、「価格の安い順」に切替。30日超は「参考価格」（最安の強調から除外・履歴は残す）。同じ店舗の価格推移を展開。「この価格で購入」→確認→収集カード（単品購入・価格・店舗・状態を引き継ぎ）を登録。購入後も記録は残り、購入済みは再購入できない。

## 相場調査メモ
- カード一覧（最安値・記録件数・購入済み印）・検索・各行の「＋」と左スワイプで価格追加（スワイプなしでもボタンで同じ操作）・右上の「＋」でカードと価格を一度に登録・JSONエクスポート。購入済みは既定で非表示（チェックで表示）。
- カードの同一性（`matchCard`）: セット・番号・レアリティが一致＝同じカード（価格を追加。新規作成しない）。名前だけの一致・識別情報不足・レアリティだけ違う＝**曖昧→「既存のカードに追加／別のカードとして登録」を選ばせる**。別セット・別番号は別カード。
- 価格記録: 店舗（過去の入力をタップで再入力）・系列（任意）・調査日（初期値=今日）・状態ランク（5ボタン・よく使うものに印）・価格・備考。自動フォーカス・プルダウンの自動展開なし。保存後は元の一覧へ。
- 比較・参考価格・推移は図鑑の価格調査と共通（`price-list.tsx`）。購入: 購入日・店舗・価格・状態を引き継いだ購入済みの記録を作成（二重不可）。購入済みの価格記録・履歴のあるカードは削除不可。
- 店舗は抽選用の系列・店舗マスターと統合せず、入力した店舗名の履歴から候補を出す。

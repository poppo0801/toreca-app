# Stage 5R: 系列別抽選条件管理・プロフィール別の資格状況

条件は応募資格の**目安**です（応募記録は禁止しない。カードの注意表示のみ）。**AI解析・自動収集は系列共通条件を追加・変更・削除しません**（手動の操作だけ）。

## データ設計（4層を分離）
1. 系列共通の条件: `chain_conditions`（migration 52。種類・内容・購入条件の数値 `params`・補足・前の条件との関係 `join_prev`・並び・`archived_at`）。物理削除せずアーカイブ。
2. 抽選ごとの条件: 既存の `lotteries.requirement_tags / requirement_details / conditions_text`（二重管理しない）。標準カテゴリは `src/lib/chain-conditions.ts` の `COND_KINDS`（13種）で、既存タグとは `kindOfRequirementTag` で対応づけ。
3. プロフィール別の達成状況: `chain_condition_states`（手動の 達成済み/未達成/未確認 ＋最終確認日）。条件をアーカイブしても行は残る。
4. 購入履歴から算出した資格状態: **保存しない**。既存の `purchases` を正として、表示のたびに計算（購入の追加・訂正・取消が自動で反映）。

## 標準条件（13種）
購入履歴／会員証・ポイントカード／提携クレジットカード／メルマガ／公式アプリ・会員アカウント／LINE友だち登録／本人確認／地域・店舗制限／指定決済方法／イベント参加／公式大会参加／ジムバトル参加／その他。イベント・大会・ジムバトルは自由記述＋プロフィール別の達成状況のみ（参加日・回数の管理は無し）。会員番号の登録有無だけで達成と断定しない（会員番号とは連携せず、手動で設定）。

## AND / OR
グループ方式。条件は上から並び、各条件に「すべて必要（かつ）／どちらかでOK（または）」を設定（先頭は常にかつ）。「どちらかでOK」は直前の条件と同じグループ。グループ間は AND、グループ内は OR。グループ内に未確認が残る場合は未確認。

## 購入履歴条件
- 基準日 = 抽選開始日の N日前、対象期間 = 基準日から過去 W日間（両端を含む）。共通関数 `purchaseWindow`。例: 開始 2026/11/10・3日前・365日 → 2025/11/7〜2026/11/7。
- 金額と回数は、設定されているもの**両方**を評価（どちらも未設定なら1回以上）。対象店舗の指定（未指定=系列の全店舗）。
- 購入者はプロフィールごと（抽選からの購入=応募アカウントのプロフィール、抽選外の購入=記録したプロフィール）。系列は店舗または抽選の系列で判定し、別系列を混同しない。
- 当選しただけでは購入にならない（記録された購入だけ）。金額・日付・店舗が不明な記録だけでは達成と断定せず「未確認」。
- 資格の残り期間（目安）: 「仮に今日新しい抽選が始まった場合」。古い購入から順に対象期間を外れるとして、金額・回数・店舗の条件を維持できなくなる時期を求める（古い1件が外れただけでは切れとしない）。31日以内=まもなく資格切れ、以降は月単位（あとNヶ月）、情報不足=資格要確認。他のグループ内に期限のない達成済み条件（手動の会員など）があれば出さない。ⓘで「将来の応募資格の保証ではない」ことを説明。

## 画面
- 設定: ユーザー管理 → 会員番号 → **抽選条件管理**（`/settings/conditions`）。一覧は系列ロゴ・系列名・条件アイコン＋短いラベル（折り返し）・残り期間・各プロフィールの状態。**行全体をタップ**して詳細・編集（個別の編集ボタン無し）。登録済み／すべての系列の切替。
- 詳細・編集シート: 資格状況（プロフィール別の手動切替・最終確認日・180日超は要再確認）と条件の編集（種類・内容・購入条件・AND/OR・外す・追加）。
- 抽選カード: 問題があるときだけ小さなマーク（未達成=警告／未確認=確認／登録条件と今回の応募条件が異なる=相違）。応募済み・受付終了では出さない。
- 抽選詳細: 系列の資格（プロフィール別）、条件ごとの状態、相違は展開して確認（「登録条件と今回の応募条件が異なります」）。
- サブユーザー: 対象系列だけ表示・変更（サーバー側 `subScopeError`）。他ユーザーの達成状況は変更不可。

## AI解析との比較
今回の抽選の条件（金額・購入期間・標準カテゴリ）と系列登録を比較し、差を表示するだけ（例: 系列 365日／3,000円以上 → 今回 5,000円以上）。今回の抽選固有の最低金額・明示期間を優先して参考判定。AIが読み取れなかった項目は「条件なし」と扱わない（比較しない）。系列条件は一切書き換えない。

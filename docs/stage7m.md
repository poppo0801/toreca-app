# Stage 7M: 抽選管理・通知・購入記録・BOX管理の改善

## 1. 抽選詳細のレイアウト
- 日付4項目（応募開始・応募締切・当選発表・購入受取期間）は2列のまま、個別の枠なし・細い区切り線。
- 応募方法・受取方法・発表方法・応募条件・応募制限・本人確認などは、外側を角丸枠で囲み、項目間は細い区切り線（枠は1つ）。
- 確認が必要な点は折りたたみ式（初期は閉じる・見出し「要確認（○件）」・開くと全文）。保存時の解析結果ではなく、現在の登録内容から再評価する（`src/lib/live-cautions.ts`）。補った項目は自動で消え、0件なら表示自体が消える。カードの注意アイコンも同じ再評価。情報元どうしの相違（締切・方式の矛盾）など現在の内容だけでは解消を判断できないものは残す。

## 2. 抽選候補と要手動確認の統合
- 抽選候補ページに状態の絞り込みを追加（全状態／新着／情報不足／要確認／確認済み。件数つき。`src/lib/collector/candidate-state.ts`）。1つの候補が複数の状態に該当しうる。
  - 新着 = 取得から36時間以内 / 情報不足 = 不足情報バッジがある / 要確認 = 要手動確認の案件（triage=manual・open）・情報の矛盾・解析結果が無い候補 / 確認済み = 要手動確認を対応済みにした、または不足も要確認も無く新着でもない。
- 要手動確認の案件（collection_candidates の triage=manual）は同じ候補データなので、抽選候補ページにそのまま出る。設定の自動収集の要手動確認には、抽選候補ページへのリンクを追加（再調査・対応完了などの既存操作は残す）。
- 重複表示の防止: 抽選候補は `status ∈ (pending, failed)` かつ `lottery_id` が空のものだけ。登録済み・統合済み・除外済みは出ない。登録済み抽選に確認事項があるときは、抽選詳細の「要確認」から確認・修正する（候補には戻さない）。

## 3. 通知
- ベルの通知は期限に関するものだけ（応募締切・当選発表後の結果未登録・購入受取期限・資格の期限）。抽選候補・要手動確認・Xブックマークの未解決・自動収集の結果履歴は件数にも一覧にも含めない。
- 起動時の自動収集ポップアップは「新しい抽選候補・自動登録・重複／除外」の3項目だけ。新着候補を最大3件、「抽選候補を確認」ボタンで候補ページへ。警告色は使わない（取得できなかった情報は目立たない一文で）。

## 4. 購入記録の開封状態
- 「開封状態が未確認：N件」。BOXコレクション未登録の購入BOXは、商品名・BOX数・BOXコレクション詳細へのリンク（`/collection?tab=box&open=商品ID`）を表示。
- 開封累計は、開封済みとして記録したBOXだけ（`boxOpenings`）。未開封・未確認は含めない。開封済み0なら0BOX。
- 現在の未確認1件の原因（本番を読み取り専用で確認）: 30th CELEBRATION 1BOXの購入明細が、BOXコレクションのロットと未連携（購入だけでコレクションに未登録）。判定の誤りではなく、データが未連携。削除・初期化はしていない。

## 5. BOXコレクション詳細
- 上部: 保有数と開封済み数（`保有 7BOX ｜ 開封済み 0BOX`）。開封した分は保有数から減っているため二重計上しない（開封済み数は開封の記録のうち取り消されていないもの。`openedQtyOf`）。
- 保有状況の表: 状態・数量・買取単価・買取合計＋最下段に合計行。表の下に「購入総額：○○円」（保有BOXの実購入価格×数量。評価額・市場相場は使わない。価格未取得のロットは含めず「N BOXは購入価格が未取得」、1つも無ければ「未取得」。`actualPurchaseTotal`）。長い「購入（評価額）…」の説明文は削除。
- 操作ボタン: 開封済みにする／相場を入力／シュリンク変更／数量調整。
- 購入ロットは折りたたみ（「購入ロット（○件）」。1行: 購入日・シュリンク状態・BOX数・購入金額、購入元は2行目。市場相場・評価価格の採用方法は「詳細」ダイアログ）。在庫履歴も折りたたみ（「在庫履歴（○件）」・1履歴1行・取り消しは維持）。

## 6. 複数商品抽選の商品別応募
- 対象: 抽選方式「商品ごとに当落」（multiMode = all）と「当選は1商品まで」（one_win）で、商品が2つ以上の抽選（`isPerItemApply`）。抽選カードは1件のまま、応募・当落はプロフィール（応募アカウント）ごと・商品ごとに管理する。他の方式（単一商品・1商品を選んで応募・商品ごとに応募手続きが独立・店舗ごとに独立）は従来どおり。
- 応募済み操作: 商品選択ダイアログ（初期は全商品を選択・外せる・0件では確定できない）。単一商品はワンタップのまま。スワイプ操作でも同じダイアログ。
- 全情報・要チェックタブは全商品。応募済みタブは応募した商品だけ、当選タブは当選した商品だけ（`itemsForTab`）。詳細では商品ごとの当落（応募した商品のみ）・「購入済み」の表示。
- 応募商品の変更（詳細の「応募商品」行）: 現在のプロフィール自身の応募だけ。当落が登録済みの商品は外せない。全商品を外すと応募を取り消し、応募済みタブから外れる。
- 当落の登録は応募した商品だけ。応募商品の一部だけ登録済みなら、当選が無い限り全体は結果待ちのまま。
- 既存データ: 既存の複数商品の応募は応募商品が未指定（null）。勝手に全商品応募と確定せず、全商品を暫定表示し「応募した商品が未確認です」と案内、「確認する」から確定する。当選・購入履歴との関連は変更しない。
- 商品別の受取状態: 購入は当選した商品の購入記録（purchase_items.lottery_item_id）から商品ごとに「購入済み」を表示。購入・受取の処理自体は従来どおり応募単位（当選した商品をまとめて1件）。

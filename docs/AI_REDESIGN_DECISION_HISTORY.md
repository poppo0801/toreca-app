# トレマネ 情報収集・判定エンジン再設計：合意事項と検討記録

2026-11-20の設計協議に基づく決定履歴。正式な目標仕様は `AI_REDESIGN_SPEC.md`、理念は `AI_AUTONOMY_PRINCIPLES.md`。古い節の「検討中」より新しい明示決定を優先する。

## 調査の出発点
Stage 9Xでは88件中、情報源を再取得できたものは33件。X/t.co再取得不能と取得済み原文の喪失が大きな障害。9Zで取得原文・出典・時刻を保存し、手動再評価で再利用可能になったが、通常収集への接続は未完。Stage 10A/10Bの読み取り専用監査で、AI判断の後に複数の固定判定器が上書きし、店舗選択式・重複・系列・商品・候補保留に問題があることを確認。9Hのcase-model/investigator/integrationはlocal-only制限で本番動作していない。収集計画・統合判断の未接続資産がある。旧 `CLAUDE.md` は古いStage履歴が肥大化し、正本仕様への参照も不十分。

## 合意した設計
- **意味判断の主体をAIへ移す。** 固定処理は前処理、キャッシュ、制約検証、権限、費用、履歴保護。既存機能は再利用価値で選別し、温存を目的としない。
- **Evidence → Case → Opportunity → View → User records** を論理的に区別する。必ずしも同数の新規DBテーブルを作るわけではない。
- Opportunityは応募操作やフォームURLではなく独立して応募・追跡すべき権利。1フォームから複数独立応募、1応募から商品別当落も表現。案件の構造不明時は未確定Caseとして表示し、推測で機会を増殖させない。
- 同一・独立・関連・未確定の判断を統合し、URL/系列/日付の一致だけで統合しない。表示の整理と実体統合を分離。既存IDとユーザー応募/当落/購入履歴を保護し、AI推測による移動・削除を禁止。
- 系列/店舗/商品の名称解決を統一。既存マスター・確定別名を使い、AIの未検証推測を確定マスターに混入させない。商品名と「購入権」等を分離。
- X初期取得原文、フォーム、画像、複数ソース、過去の判断/ユーザー修正を根拠として再利用。AIは不足情報に応じて自律的に追加調査するが、失敗済み取得の反復を避ける。
- AI出力は抽出事実と推論、根拠、未解決事項、同一性、処理提案を区別。後段固定判定器による競合上書きを廃止。安全検証は独立。
- 軽微な不一致は自律解消し、必要性の低いユーザー確認を減らす。追加調査・部分登録・期限切迫時の早期案内を優先。
- 調査予算は固定上限内でAIが配分。締切、重要性、費用、改善見込み、新規情報源探索を考慮。新規発見枠を圧迫しない。進展なし/取得不能/上限で停止し、新証拠で再開。
- 判断と根拠・版・ユーザー修正・結果を蓄積し、明示的な検索・フィードバック・評価・版管理によって継続改善する。容量・保存期間・プライバシーを管理。将来、既存の除外操作を活かした簡易誤判定報告UIを検討するが初期実装必須ではない。
- A/B/C別の応募・店舗/商品選択・当落・スルー、地域判定、継続抽選、通知、購入・コレクション、手動編集は維持。通知はユーザーの行動単位で管理し、締切/結果変更時に再計算。購入履歴は独立。
- 外部コンテンツのプロンプト注入、AI再試行無限ループ、費用暴走、誤更新、秘密情報漏洩を防止。
- 内部検証は必要十分に留め、一定の成果と重大安全条件を満たしたら本番導入。移行期のみ新旧方式を設定で切り替え可能にし、長期併存はしない。**新方式の実運用に目立った問題がなければ旧方式・切替設定・不要コードを早期廃止**。旧方式維持のために新設計を制約しない。

## 主要な完成条件（後から明示追加）
最初の6課題の改善だけでは不十分。**(1)既知6課題改善、(2)従来方式との総合精度・性能比較、(3)既存機能と安全性の維持**を三本柱とする。比較軸は発見力、抽出、登録/対象判定、網羅性、更新、同一性、遅延、正確な応募機会当たり費用、手動対応、安定性。旧方式を正解扱いせず、原文で検証可能な事例と新着運用実績で測る。重大な誤統合・履歴破損・費用突破・権限逸脱・通知事故を許容しない。根拠のない閾値を設定しない。

# Stage 10P 本番移行の準備（新シャドー＝応募機会の判断プレビュー）— 接続設計・適用/復旧計画

**本書は準備であり、本番稼働の許可ではない。** 本番DBの変更・マイグレーション適用・デプロイ・cron有効化・シャドー起動は、利用者の個別の明示承認の後にのみ行う。実測は `docs/reports/2026-11-21-stage10p-evidence-first-shadow-readiness.md`。

## 1. 判断の原則（10Pで確定）
- **公式性は登録・候補・通知・補完の条件ではない。** `decision.ts` は公式判定・情報源の種類を読まない（静的検査で固定）。公式性は、抽選詳細の任意「公式」バッジの表示にだけ使い、確認できなければ何も表示しない（否定的なラベルは付けない）。
- 判断は、情報の具体性・整合性・原文確認・独立性・応募単位・対象条件・重複リスク・期限で行う。**非公式の単独の情報源でも、実行可能な最低限の情報が原文で確認できれば自動登録（プレビュー）可能**。
- 通知に使える締切は、役割が締切・年が明示または曜日で確認・時刻あり・原文確認済みのものだけ（`notifiable`）。

## 2. 新シャドーのワーカーへの接続設計（**未接続**・ローカルで無書き込み検証済み）
```
通常収集（旧方式・変更なし）
   └─ 確定後に shadow_enqueue（既存・10K）
shadow ワーカー（専用cron・既定OFF）
   ├─ 判断ジョブ（10K）  → shadow_judgments
   ├─ 一覧ジョブ（10M）  → shadow_list_items
   └─ 応募機会プレビュー（10P: src/lib/server/shadow/opportunity-job.ts）→ shadow_opportunities   ← 追加の接続点（未接続）
        入力: shadow_list_items・保存原文・既存の登録（読み取りのみ）・マスター・収集設定（読み取りのみ）
        AI: 呼ばない（費用0）。ページ取得・AIを使う補完の調査（10N/10O）は別ジョブとして後から追加（予算は CallBudget に合算）
        書き込み: shadow_opportunities のみ（冪等）。既存の登録・応募・当選・購入・通知・候補・★へは書かない（統合テストで全表の内容が不変であることを確認）
```
- 接続の最小変更: ワーカーの1回の実行の最後に `runOpportunityPreview({db, householdId, now})` を1回呼ぶだけ。現時点では呼び出しを追加していない（cron・ワーカーは本番で未起動のため、追加しても本番に影響しないが、承認前に接続しない）。
- 停止: 既存の停止スイッチがそのまま効く（`shadow_settings.enabled=false`／`SHADOW_WORKER_KILL=1`／`SHADOW_WORKER` を外す）。プレビューはAIを呼ばず読み取り＋1表の書き込みのみで、止めても他に波及しない。
- 再実行: 冪等（`household_id, cluster_id` で上書き。同じ入力なら行数・判断は不変＝統合テストで確認）。
- 費用上限: プレビュー自体は費用0。AIを使う工程を足す場合は、ワーカーの既存の日次・月次・1件の上限と `CallBudget`（既定 30回・¥12／回）に合算する。

## 4. 監視（運用開始後・承認後）
- `shadow_stats`（キュー滞留・失敗・費用）に加え、`shadow_opportunities` の判断別件数（auto_register_preview／candidate_with_gaps／needs_review／excluded／update_proposals）と、確認待ちの理由の分布（応募単位不明・地域/TCG不明・重複の疑いなど）。
- 警戒: 確認待ちの急増・excluded の急増（誤除外の兆候）・`readErrors`（保護の確認ができず全登録を保護扱いにした）・費用の上限接近。
- **誤除外の監査**: excluded の行は理由コードつきで保存される。定期的に代表例を人が確認する（`scripts/review-10o-local.mjs` の B 欄）。

## 5. 新旧方式の比較の定義（同一期間・同一対象設定）
| 指標 | 定義 | 旧方式 | 新シャドー | 備考 |
|---|---|---|---|---|
| 発見 | 親投稿から出た抽選の候補数 | 1候補＝最大1抽選 | 一覧の全項目→応募機会 | 分母＝親投稿数。経路が違う（旧は他の収集経路も拾う） |
| 対象判定 | 地域・TCG・除外系列に合う件数 | 登録時の判定 | `eligibility`＋理由 | 不明は別枠 |
| 登録可能 | 登録してよい件数 | 自動登録された数 | auto_register_preview | **プレビュー**。実登録ではない |
| 確認待ち | 人の確認が要る件数 | 保留候補 | needs_review＋理由 | |
| 重複/誤統合 | 重複・別応募の混同 | 名寄せ結果 | contested／重複の疑い | **正解は人の確認が必要** |
| 更新 | 既存の登録への補完・訂正 | 手動・再解析 | update_proposals（非実行） | |
| 遅延・費用 | 収集から判断まで／AI費用 | 本番の集計 | ワーカー実行ログ・CallBudget | ワーカー未接続のため新方式の遅延は未測定 |
- **手動の正解（人の確認）が無い限り、精度の比較・合格の宣言はしない**。比較は件数・理由の分布・不一致の列挙まで。

## 6. 本番切替の判断に必要なもの（別承認）
1. 人による代表例の確認（補完・登録判断・除外）の結果と、利用者が決める合格基準。
2. 応募単位の不明の解消（新規収集分の `linkMap` による応募先の別・同一の確認が貯まること）。
3. マイグレーションの本番適用・ワーカー接続・シャドー起動を、段階（投入のみ→少数世帯→拡大）で承認。

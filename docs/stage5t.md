# Stage 5T（自動収集の自律化・情報源の信頼性管理・要手動確認の最小化）

## 1. 費用制御
- 日次のAI解析件数上限と、その設定UI（ワーカー1日の上限・今日だけ引き上げ）を廃止。制御は **月額予算（日本時間の月単位）** が中心。旧列（worker_daily_ai_limit など）はDBに残るが未使用。
- 1時間あたりの速度制限（既定120件。`COLLECTOR_AI_HOURLY_LIMIT`）は外部APIへの負荷対策であり、費用・日次上限ではない。
- 予約: `reserve_ai_budget`（SECURITY DEFINER・世帯単位の advisory lock）。「今月の実費＋有効な予約＋今回の見込み ≦ 予算」のときだけ許可。見込み＝今月の実測平均×3（2〜8円）。完了後30秒で失効。実費（ai_extraction_logs）と予約（見込み）は別の値。予算不足の候補は解析せず、除外・完了にもしない（待機に戻し、試行回数も戻す）。
- 予算到達時は停止理由を記録し、ヘルスの警告で「翌月に自動再開」を表示。X APIの予算管理は従来のまま独立。

## 2. 即時再調査 → 保留 → 要手動確認
- 取得失敗: 即時の再試行（15分→1時間→4時間）を使い切ると、恒常的でなければ長い間隔の保留へ。恒常的（取得制限・ページ削除・JS描画）は代替（一覧の表示）を試した後に判定。
- 登録できない候補: 低コストの再照合（別名辞書・マスター・収集条件・重複・受付終了。AIなし）→ 取得元の再確認（本文の変化があるときだけ再解析）→ 保留（30分→2時間→6時間→12時間→24時間→24時間）。6回で要手動確認。回数・間隔は内部管理で、設定画面には出さない。
- 締切が24時間以内（優先収集メモ一致は48時間）で情報が揃わなければ、規定回数前でも要手動確認。締切不明は低優先度にしない（並びは本日→明日→近い→締切不明→余裕あり）。
- 実行: 5分間隔のワーカーが保留候補を次回調査時刻以降に処理（朝6時を待たない）。
- 内部ログ: fail_kind / hold_count / fetch_methods / last_good / triage_reason / manual_reason / next_run_at。
- 4分類: triage = auto_register / auto_exclude / auto_retry / manual。

## 3. 情報源
- 元の情報源・短縮URL・応募サービス・まとめサイト・Xを区別（`hostRole`）。取得制限は回避しない。
- 代替: 取得制限・JS描画のページは、まとめサイトの一覧の表示（二次情報）から解析（成功した方法は次回優先）。X投稿由来のt.coは、X APIの展開先URLを使用（実装済み）。まとめサイト由来のt.coは展開先を取得できない。公式Xの自動検索は未実装（店舗とXアカウントの対応マスターがないため）。
- 取得困難の記録 `collection_hard_sources`: 系列/店舗×応募サービスのキーで記録（共通サービスの失敗で店舗全体を一律に取得不可としない）。

## 4. 通知
- ポップアップ最上部に赤い警告「取得不可：N件／要手動確認」＋一覧（系列・店舗／商品／理由／締切／元情報）。閉じても対応済みにならず、通知センターと設定の一覧に残る。案件の集合が変わったときだけ起動時に再表示。
- 設定 > 自動収集の最上部に一覧（元URL・編集して登録・再調査・対象外・対応完了）。優先収集メモとは別の一覧。

## 5. 信頼性管理
- 抽選詳細の「登録経路」アイコン（チェック／ロボット）と詳細。manual / manual_ai / auto / auto_confirmed。確認済みは確認履歴であり正確性を保証しない旨を明示。
- 除外: 「この抽選を除外」（アーカイブ＋理由。応募・当落履歴・★管理対象のある抽選は除外不可）、「今後この収集元を除外」（店舗・系列・Xアカウント・個別サイト・投稿元を明示して選択。X全体/まとめサイト/短縮URL/共通応募サービス全体は不可。応募資格・条件・地域・重複の理由は収集元全体の除外に使えない）。世帯共通・設定 > 収集元の管理で一覧/理由編集/解除。AIが独断で追加することはない。理由 → 反映先は `feedbackTarget`（明示的なルール・フィルタ・AIフィードバックのみ。自動学習とは扱わない）。

## 6. カードボックス
- 採用: 系列を「直営／その他／所属未確認」に分割し、`chains.brand_group` で共通ブランドを保持（`operation_kind`）。理由: 系列別の抽選条件・会員番号（Stage 5R）が自然に分離し、既存統計・履歴は系列IDを維持できる。
- 既存の系列（ID維持）を「カードボックス（所属未確認）」に改名し、別名「カードボックス」を付与。「（直営）」「（その他）」は空で作成。
- 照合: 店舗マスターに一致する系列（確認済みの直営/その他）→ なければ所属未確認。ブランド名だけで確定しない。
- 公式情報で直営/その他を確認できなかったため、既存3店舗（オーサカ・京都・日本橋店）は所属未確認のまま。

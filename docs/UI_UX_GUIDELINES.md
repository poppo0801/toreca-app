# UI/UX 設計ガイドライン

UI を追加・変更する前に読む。出典は、利用者の指示（`CLAUDE.md`・旧 `docs/ui-design-guidelines.md`）、`ui-spec.md`、Git 履歴（Stage 4.5〜7S）、各 `docs/stage*.md`。旧 `ui-design-guidelines.md` の内容は本書に統合した（同ファイルは本書への案内のみ）。

**読み方**: 「原則」は利用者の明示的な方針（確定）。「現状の実装」は参考例であり、**現在の画面にあるからという理由で理想的な設計とは限らない**。「実機未確認」は、iPhone 実機で確かめていないことを指す。

## 1. 原則（確定）

### 1.1 メインコンテンツの面積を最優先する
機能を足す前に、既存の操作へ統合できないかを考える。操作 UI よりコンテンツ（一覧・画像）を目立たせ、できるだけ上から見せる。
- 例: 抽選管理の登録導線は「＋登録」の1つ（まとめて登録・AI 読み取りは登録画面の中）。コレクションも「カード/BOX 切替ボタン」を廃止してスワイプのみ、登録ボタンを「＋登録」に統一（Stage 6M 後）。
- 例: マスター管理の種類ボタンは1行目に主要4つ（プロフィール／系列／店舗／商品）、他は「その他 ▼」に折りたたみ、選択中の種類名を常に表示（Stage 7S。`MAIN_MASTER_KEYS` in `src/lib/masters-tabs.ts`）。

### 1.2 説明文・ラベル・余白を減らす
- 見出し・ボタン名・項目名で分かる説明は書かない。同じ意味の文を繰り返さない。長い説明は展開・ヘルプ・要確認の詳細へ移す。
- 説明は「ⓘ」に移す（Stage 5O。`ui/info-tip.tsx`）。設定一覧は見出しだけで、説明は開いた先に置く。
- 余白・装飾のためにカードを縦長にしない（`ui-spec.md`）。ただし**詰めすぎない**: 詳細パネルの余白は逆に拡大した例もある（Stage 7C のコレクション詳細）。判断基準は「情報の読み取りやすさ」。

### 1.3 操作を増やさない／低頻度は隠す
- 同じ目的の操作は1つに統合。低頻度の操作はメニュー（⋯）・設定へ。大きなボタンを上部に並べない。
- 検索は虫眼鏡アイコン→展開。フィルターはアイコン1つに集約し、条件は展開式（絞り込みはボトムシート。Stage 5S）。並び順・列数はコンパクトな選択ボタン。操作 UI は原則1行。集計は1行＋タップで詳細。
- 不要な画面遷移・タップを増やさない。確認ダイアログは「取り返しのつかない操作」と「データに影響を与える操作」にだけ使う（★ON は即時、★OFF のみ確認）。

### 1.4 情報の重要度で強弱をつける
- 締切までの残り時間は右上のバッジ（3日未満=オレンジ／24時間未満=赤。塗りで強調）。店舗・商品名・締切を最も目立たせ、補助情報（登録経路・確認済み印）は小さく。
- 色だけで状態を伝えない（記号・ラベル併用。`ui-spec.md`）。要確認は共通の印（`caution-mark.tsx`・`review-flag.tsx`）で示し、原文・理由を確認できる状態にする。
- 抽選カードは**コンパクト/詳細を切り替える**。複数商品は先頭1種＋「＋他N種」。商品名は最大2行。

### 1.5 必要な情報は省略しない
省略してよいのは説明文・装飾だけ。次は**必要なときに必ず確認できる**状態を保つ（常時の文章でなく、印・展開でよい）: 抽選締切／応募条件／AI 解析の不確実性（要確認・原文）／登録時のエラー／重要な確認事項／削除・上書きの警告／金額・集計対象に関する注意（未設定は 0 円にしない、一部のみの集計、など）。
- 例: 店舗の削除ダイアログは削除前に参照件数（抽選・応募・購入…）を表示し、参照がなければ削除、あればアーカイブ（Stage 7S。`store-delete-dialog.tsx`）。

### 1.6 一貫性
- 同じ操作には同じボタン・アイコン・表示方式。★お気に入り、要確認の印、ボトムシートのスワイプ操作、期間選択、退出アニメーション（★・応募・スワイプで共通。Stage 6L）。
- 新しいページにも適用する。**既存の共通部品を再利用**する（下表）。新しい見た目の部品を作る前に、既存部品の拡張で足りないか確認する。

### 1.7 スマートフォン最優先
- iPhone 幅（390px 前後）を基準にする。横スクロール・無駄な縦スクロールを避ける。タップ領域は 44px 目安。モバイルでは下部メニュー、PC では左ナビ。PC にも最適化するが、モバイルを犠牲にしない。
- テーマ（ライト/ダーク）は両対応。新しい色を足すときは両方で確認する。

### 1.8 固定配置・Safe Area は触らない
下部メニュー・ヘッダー・ボトムシートの固定配置と Safe Area の計算（AppShell）は、専用の工程以外で変更しない。診断モード（`?diag=1`）は実機確認まで残す。

## 2. 配色（現状のトークン。`src/app/globals.css`）
- 白/黒基調。ライトは背景 `#f4f4f5`・カード/ヘッダー `#ffffff`・入力 `#f0f0f2`。ダークは背景 `#08080a`・ヘッダー `#17171b`・カード `#212127`・入力 `#30303a`。カードは無彩色。
- **オレンジ** `--primary`（ライト `#dd7400`、ダーク `#fb923c`）は「主要操作」と「現在の選択状態」にだけ使う。ライトは白文字が乗る濃さに調整済み（Stage 5K）。
- 情報の区別: `--info`（青緑 `#0f766e`）、成功 `--success`、危険 `--danger`、注意 `--warn`。プロフィール識別色 `--p-*`、支出分類色 `--cat-*`。
- ★の縁取りは廃止（Stage 5K）。**情報の区別に使う色は、操作（オレンジ）と混同しない。**
- 注: `ui-spec.md` の色コード（ダーク背景 `#0b0b0d` など）は Stage 3.5 時点の値で、現行トークンと異なる。色は `globals.css` を正とする。

## 4. iPhone Safari / ホーム画面アプリ（PWA）
ここは**実機でしか確かめられない**ため、事実と未確認を分けて書く。

### 確立している事実
- **下部メニュー**: 「測定して補正する」方式（`--vp-gap`・`--vv-shift` 等）は5回修正して再発した。現行は**構造で解決**: 画面全体を固定の入れ物にし、スクロールするのは内側の `#app-scroll` だけ。下部メニューは入れ物の最下段（`position: fixed` ではない）（Stage 6J）。`window` / `document` をスクロールさせない。
- **ステータスバー**: 真因は `appleWebApp.statusBarStyle: "black-translucent"`（描画領域が下59px短くなる）。**`"default"` を維持**し、`ThemeColorMeta` が theme-color をアプリのテーマに合わせ続ける（Stage 6L。実機で確認）。
- **キーボード**:
  - 自動フォーカス・自動選択は全面廃止（Stage 7D。ダイアログを開くと最初の入力欄が選ばれてキーボードが出るのを防ぐ。`ui/initial-focus.ts`）。
  - キーボードの出入りでページ全体が押し上げられたままになる問題（タップ位置のズレ）への補正は Stage 7P。
  - 入力欄がキーボードに隠れないよう、`visualViewport` で**アプリ内のスクロール領域だけ**を動かす（`use-scroll-input-into-view.ts`。ページの `transform` は使わない。閉じたあとのスクロールジャンプを起こさない）。ボトムシートはキーボード分を `--kb-inset` で持ち上げる。
- **復帰**: 別アプリから戻ったときにエラー画面にしない（エラー境界は画面の中身だけ置き換え、ヘッダー・メニューは残す）。通信失敗でログアウトさせない。復帰時の再取得は静かに・遅らせて行う（Stage 7C・7D・7O）。
- **重い画面**: マスター管理は40件ずつ描画（Stage 7D）。一覧は最初の24件を描画し、残りは空き時間に追加（Stage 7O）。

### 実機未確認（直ったと断定しない）
- Stage 7S のキーボード対応（検索欄の自動スクロール、閉じた後のジャンプ、タップのズレ）は、PC 上のテストのみで、**iPhone 実機では未確認**。
- 7D の「Safari のプロセス終了」の原因は**特定できていない**（改善は負荷の低減と記録の追加）。
- 実機の確認手順は `docs/stage7p.md`・`docs/stage7d.md`・`docs/ios-viewport-fix.md`（旧構造の記述を含む。現行の構造は `docs/stage6j-viewport.md`）。

## 5. 再発防止表（過去に直した不具合）
| 症状 | 原因（確認できた範囲） | 再発防止 |
|---|---|---|
| 下部メニューが欠ける／浮く／ずれる（5D〜6K で再発） | 測定値で fixed 要素を補正する構造。最終的な真因は `black-translucent` で描画領域が短くなること | 構造（固定の入れ物＋内部スクロール）と `statusBarStyle: "default"` を維持。補正値・タイマーによる位置合わせを足さない。AppShell を専用工程以外で触らない |
| ダイアログを開くとキーボードが出る | Radix の初期フォーカス | 自動フォーカスを使わない。検索欄の `autoFocus` を使わない |
| キーボードを閉じたあとタップがズレる | iOS がページを押し上げたまま戻らない | 7P の補正を維持。入力欄の追従はアプリ内スクロール領域だけで行い、ページの `transform`・window スクロールを使わない |
| 設定の切替が遅れて何度も切り替わる／二重保存 | 保存の競合・連打 | 保存は順番に1件ずつ。連続操作ゲート（300ms）。`useBusy`。保存中は古い再取得の結果で上書きしない |
| 操作のたびに画面が重い | 保存ごとの `revalidatePath`、全データ再取得、全件描画 | `revalidatePath` を使わない。構造共有（同じ内容なら再描画しない）。段階描画。★のみ楽観的更新（応募・当落・購入など重要データは楽観的に切り替えない） |
| 復帰時にエラー画面・ログアウト | エラー境界なし。認証確認の通信失敗をログアウト扱い | エラー境界、再試行、通信失敗はログアウトにしない、復帰は遅延して静かに再取得 |
| 抽選が二重に出る | 店舗未確定・表記ゆれ・並行収集で判定が漏れた（Stage 6C・7P・7Q） | 重複判定は共通関数 `findDuplicates` に集約。DB の一意キー＋登録直後の再判定。UI 側で個別に判定しない |
| 「通販」「オンライン」の表記ゆれで店舗が増える | 店舗名の正規化が無い（7S） | 店舗名は `store-online.ts` で正規化（標準名「通販」） |
| 実データに触れる操作のミス | 本番直結 | 安全ルール（`CLAUDE.md`）。dry-run 既定、事前バックアップ |
| 同じ UI 改善依頼の繰り返し（説明文・ボタン・余白・統一感） | UI 方針が設計知識として残っていなかった | 本書と `CLAUDE.md`。実装後に iPhone 幅で画面確認 |

## 6. 実装後チェックリスト（UI を変えたとき）
1. 説明文・見出し・ボタンが増えていないか。既存の操作に統合できなかったか。
2. 390px 幅で、横スクロール・不要な縦スクロール・操作 UI がコンテンツを押しのけていないか（画面キャプチャで確認）。
3. 既存の共通部品・トークンを使ったか。同じ操作が他の画面と同じ見た目か。
4. ライト/ダーク両方。オレンジは主要操作と選択状態だけか。
5. 締切・応募条件・不確実性・エラー・警告・金額の注意は、必要なとき確認できるか。
6. 入力欄があるなら、キーボードで隠れないか。自動フォーカスしていないか（実機未確認なら未確認と明記）。
7. AppShell・固定配置・`statusBarStyle` を変えていないか。
8. 新しい原則・例外・再発防止策があれば `docs/DEVELOPMENT_LOG.md` に記録したか。

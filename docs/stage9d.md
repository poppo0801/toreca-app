# Stage 9D: 自律型情報収集エージェントの実行（調査の実行・記録・自己評価・情報源の発見）

開発環境のみ。本番DB・本番データには触れていない。**新しい有料API呼び出しなし（費用0）**。マイグレーション103は**開発DBのみ**（本番未適用）。グループ化（8F）・9C の9項目の修正は変更なし。

## 1. 実行構造（`src/lib/agent/collection-planner/`・`src/lib/server/agent/`）
手がかりの分析 → AIが対象・方法を選ぶ → 読み取り専用ツールで取得・解析 → 既存抽選と照合 → 不足なら追加調査 → 検証層が提出を確認 → 自己評価 → 次回へ反映。
- `executor.ts`: 実行と記録（ツールごとに目的・調査先・成否・所要時間・費用・発見・次に使える情報）。`controls.ts`: 上限（AIは変更不可）。`evaluate.ts`: 自己評価。`discovery.ts`: 情報源の評価。`adaptive.ts`: 実APIなしの方針。
- `investigation-run.ts`（入口）・`investigation-world.ts`（実取得・解析・照合）・`investigation-service.ts`（記録・日次使用量・自動適用）。画面は `/settings/investigation`（開発専用・本番は404。通常の抽選一覧には影響しない）。
- **接続済みのツール**: `get_signals`・`check_official_site`・`follow_external_link`（既存の `fetchRespectingRobots`＝SSRF対策・robots尊重・サイズ/時間上限）・`analyze_page_for_lottery`（既定は無料の `RuleExtractor`＝本文の記載とマスター照合のみ。解析エンジンは差し替え可）・`assess_source_candidate`・`match_existing_lotteries`。
- **未接続（理由）**: X投稿の取得（有料API・本番のBearerのみ。承認が必要）／公開検索（有料。未承認）／画像解析（外部AI・費用。未承認）。ツールは世界に無ければ登録されない。
- **AIの方針**: 実APIは未承認のため `adaptive-scout`（取得結果を見て次を決める適応型の方針。モデルの判断力の評価ではない）。`AgentLLM` 互換なので実AIと差し替えられる。

## 2. 安全制御
上限は凍結した `FIXED_CONTROLS`＋日次の使用状況から決まり、ツール入力に上限・権限・ホストを変える項目は無い（テストで検査）。1日6回・費用30円（実API時）・1回の解析3件・ツール12回・取得6回・同一サイト3回/1.5秒間隔・リンク追跡の深さ2（**取得済みページ内のリンクだけ**）・時間90秒。**既存の1日の解析上限（既定30）と当日だけ有効な一時引き上げを読み取り、残りの範囲でだけ解析**（設定は変更しない）。失敗が続く情報源は3日避ける（回避せず停止）。外部の命令は実行せず記録（`injectionFlags`）。

## 3. 判定と適用
- `dry_run`（既定）: 記録以外に何も書かない。`execute`（`TOREMANE_ENV=local`のみ）: ①検証済みの公式Webを監視へ追加（Xは候補のみ）②新規（系列・店舗/店舗選択式・商品がマスターと確実に一致・重複なし）は**日時が不明でも**注意付きで登録（`deadline_unknown`）③補完は既存の `autoCompleteLottery`（手動編集・手動登録は更新しない）④重複・更新・追加調査は何も変えない。同じ調査内の同一抽選は情報の多い解析だけ適用。応募・当選・購入の記録は変更しない。

## 4. 実測と未測定
- 実サイト（キデイランド・ポケモンカード公式、dry-run、計約2.3秒・費用0）で、取得→解析→リンク追跡→情報源評価まで動作。公式Xへのリンクを公式候補として検出。**課題**: ポケモンカード公式のトップを「抽選」と誤認識（ナビの語。登録条件で止まるがプレビューは新規と表示）。ルール抽出は精度評価前。
- **未測定**: 実データでの新規発見率・誤登録率（人の確認が必要）・実APIの費用/精度。9項目の再評価は9Cの評価（`npm run eval:9c`、再実行で7/7）が現状で、**実際の本番データでの再評価は本番の読み取り分析の承認後**。

# Stage 5C: 商品・店舗マスターのExcel一括管理

画面: マスター管理 → 「商品・店舗をExcelで取り込み・出力」（`/settings/masters/import`）。PCを主、iPhoneでも操作可能。

## 流れ
1. テンプレートをダウンロード、または「現在の商品／店舗を出力」（どちらも `GET /api/master-import?kind=products|stores&type=template|export`、ログイン必須）
2. ファイルを選ぶと自動で内容を確認（`POST /api/master-import` mode=preview。何も保存しない）
3. 新規／更新／変更なし／エラーの件数、行ごとの変更前→後、エラー（行・列・理由）を確認。エラー一覧はCSVでダウンロード可
4. 「適用する」（mode=apply）。ファイルを読み直し、確認時と同じ内容（指紋の一致）のときだけ、1トランザクションで反映

## テンプレート（.xlsx）
- シート: `使い方`（規則・列の説明・版）／`商品`（または`店舗`）／`セット構成`（商品のみ）／`記入例`（取り込み対象外）。ブックのキーワードに種類と版（`toremane-master-import:products:v1`）を持つ。種類・版が違うファイルは拒否
- 商品: 管理番号・商品コード・コード種別（公式/独自）・正式名称・略称（`|`区切りで複数）・商品グループ・発売日・カテゴリ・BOX入数・BOX定価・パック定価・メモ
- セット構成: セット商品の管理番号・構成商品の管理番号・数量
- 店舗: 管理番号・系列・店舗名・都道府県・住所・店舗URL・往復交通費・応募方法・受取方法・メモ（自宅の住所・緯度経度は含まない）
- 列は見出し名で対応づけるので、列の並び替えや余分な列があっても読める（管理番号・必須列の見出しが無い場合は拒否）

## 更新の規則
| セル | 動作 |
|---|---|
| 空欄 | 変更しない |
| 値 | その値に変更（略称は入力した内容に置き換え） |
| `#CLEAR` | 削除（商品コード・商品グループ・発売日・BOX入数・定価・メモ・略称／店舗の都道府県・住所・URL・交通費・応募方法・受取方法・メモ）。正式名称・カテゴリ・店舗名などの必須項目は不可（エラー） |
| 行がファイルに無い | 変更も削除もしない。行の削除はできない |
エクスポートしたファイルをそのまま取り込むと、全行が「変更なし」になる。セット構成は追加と数量変更のみ（既存の構成は削除しない）。

## 管理番号
商品 `PR000001`・店舗 `ST000001`。内部ID(uuid)とは別。世帯・種別ごとの連番で、`management_counters` を `INSERT … ON CONFLICT DO UPDATE`（行ロック）で採番するため同時実行でも重複・欠番が出ない。既存の商品・店舗には作成順で付与済み（更新日時・操作履歴は変更していない）。DBの一意制約と、付与後の変更を禁じるトリガーで保護。ファイルに無い番号を書くとエラー。新規行は空欄にして自動採番。復元時に番号が指定されていれば採用し、採番の連番を追いつかせる。

## 分類
- 管理番号なし → 新規（同名の商品／同じ系列・店舗名が既にあればエラー）
- 管理番号あり → 更新（差分があるとき）／変更なし
- 形式不正・未登録・無効化済み・重複・値の範囲外・コード重複（大文字小文字を区別しない）・系列の変更／未登録の系列 → エラー
- **エラーが1件でもあるファイルは適用できない**（一部だけの適用はしない）

## 保護
- 認可: ログイン必須。RPCは呼び出した本人の世帯に固定し、すべての検索・書き込みを自世帯に限定（SECURITY DEFINERだが `current_household_id()` 固定）。他世帯の番号・プロフィールは使えない
- ファイル: 4MB以下・1シート2000行以下・`.xlsx`のみ。ZIPの目録を開く前に確認（暗号化・Zip64・展開後サイズ・エントリ数・パス・外部リンク／マクロ／埋め込みを拒否）。**数式セルはエラー**（値を読まない）。外部リンクは評価しない。ファイル本体は保存しない
- サーバーで再検証（適用時にファイルを読み直して再計算し、指紋が違えば拒否）。クライアントの申告値は使わない
- 競合: 各行の取得時 `updated_at` を適用時に照合し、1件でも違えば全体を取り消す（エラーコード PT409）
- 二重送信: 画面は処理中ボタンを無効化。DBは適用内容の指紋を履歴に一意登録し、同じ内容の二重適用を拒否
- 履歴: `master_import_history`（追記専用）にファイル名・件数・変更した管理番号と項目名。変更前後の値は残さない。各テーブルの変更は従来どおり `audit_logs` にも残る
- 触れないもの: 商品画像（`product_images`・Storage）、購入履歴、抽選、既存のセット構成の削除。住所を変えると店舗の「位置情報の再確認」フラグが立つ（緯度経度は消さず、一括の位置取得もしない）

## 既知の制約・残るリスク
- 新規商品を同じファイルのセット構成で参照することはできない（管理番号が付いた後の取り込みで指定）
- ZIPの宣言サイズは信頼するが、展開後サイズの実測までは行っていない（ファイルサイズ・行数の上限と、Vercelの実行時間制限で緩和）
- `exceljs` が依存する `uuid` に中程度の勧告（v3/v5/v6 のバッファ引数）があるが、同ライブラリは `v4()` のみ使用しており該当しない見込み
- 系列の新規作成・店舗の無効化は、この取り込みでは行わない
